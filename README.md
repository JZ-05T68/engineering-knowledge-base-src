# Engineering Knowledge Base v0.3.2

一个本地优先、单用户的个人工程知识管理系统。它把 PDF 资料转化为可长期整理、检索和复用的页面级知识资产：**文档 → 理解 → 检索 → 复用 → 工程能力**。

正式服务固定监听 `127.0.0.1:8501`，核心功能可离线使用，不需要账号、VPN、云存储、API Key 或付费服务。系统不包含注册、登录、权限、OAuth、JWT 或云同步。

## v0.3.2 跨文档知识聚合与文档删除生命周期

v0.3.2 新增「知识聚合」页：以项目或标签为轴，把分散在多份资料中的结构化
笔记与证据汇总为统一、可分页、可追溯的只读视图，支持按重要程度与笔记类型
筛选，每条目可一键回到原文或证据篮；聚合为实时动态查询，不新建物化表，
删除文档后其结果自然消失。文档删除升级为完整的生命周期能力：入口移至阅读页
「文档管理」，删除前展示四类笔记、证据与知识聚合影响，证据篮条目需独立
高风险确认；删除过程采用逐操作隔离区 + manifest 记录，进程中断后重启可自动
对账——未提交的删除恢复原位、已提交的完成清理，状态不明一律保留现场并在
系统维护页提示。本版数据库仍为 schema v6，无迁移。

## v0.3.1 笔记重要程度

v0.3.1 为四类结构化笔记（文档级 / 页面级 / 文字选区 / 图片区域）增加三级
**重要程度**语义：重点 / 次重点 / 一般。创建与编辑笔记时可指定或修改等级；
阅读页与列表页以文字徽章显示等级；列表页支持按等级筛选；三级徽章的背景色
可在列表页「显示设置」中自定义并随时恢复默认（文字颜色自动适配，配色偏好
随数据库正式备份）。数据库升级为 schema v6（纯增量迁移，迁移前自动备份，
旧笔记等级默认为「一般」）。重要程度是业务语义，颜色只是展示配置。

## v0.3.0 结构化笔记基础

v0.3.0 新增四类结构化笔记的完整创建、查看、修改与删除闭环：文档级笔记、页面级笔记、
文字选区笔记（原文快照 / 用户摘录 / 个人笔记三分离，唯一命中锚定）与图片区域笔记
（拖拽框选，与原始 PNG 坐标及 SHA-256 绑定）。阅读页右栏「结构化笔记」tab 与独立
「结构化笔记」列表页是仅有的两个入口；数据库升级为 schema v5（纯增量迁移，迁移前
自动备份，既有文档、页面、检索与证据数据零改动）。同时新增导入文档的高强度确认删除
（预览影响、标题确认、隔离区两段式执行、双路径级联零残留）。不包含 AI、账号、
云同步或联网必需功能。

## v0.2.2 本地 OCR

v0.2.2 为扫描页与缺失文本层的页面补充**本地单页 OCR**：在待整理页面显式点击
“执行本地 OCR”后，由 RapidOCR + ONNX Runtime 完全离线识别当前页，模型随安装包提供，
无云端 OCR、无 API Key、无运行时下载。OCR 结果写入独立的 `ocr_text` 字段，作为
“OCR 初稿（未经人工核验）”只读展示，并进入既有全文搜索；OCR 证据导出固定显示未经
人工核验、以原始页面图像为准的警告。原始 PDF、页面 PNG、PDF 文本层、人工 Markdown 与
复核状态均不被 OCR 修改；一次只处理当前页，不提供批量或自动 OCR。仅适合印刷体文字，
手写、公式、复杂表格与图像旋转、裁边、增强不在本版范围。详见
[v0.2.2 发布说明](docs/v0.2.2-release-notes.md)，人工验证步骤与结果见
[v0.2.2 人工测试计划](docs/v0.2.2-manual-test-plan.md) 与
[v0.2.2 人工测试结果](docs/v0.2.2-manual-test-results.md)。

## v0.2.0 功能

### 超长工程文档与非标准页面处理底座

- 新增单页 PDF 处理接口，页面重新处理只渲染目标页，不再整份重新渲染，也不触碰其他页面。
- 建立 120 页真实长文档自动测试基线，覆盖页数、页码连续性、逐页 PNG、逐页文本与进度回调。
- 建立确定性页面诊断：正常、空白、短文本、横向、旋转页面由独立标志明确识别，同一页面可
  同时携带多个标志；诊断与 needs_review 共用同一份有效字符统计。
- 验证页级失败隔离：单页渲染或文本提取失败不会中断后续页面，失败页以 FAILED 状态和错误
  信息入库，文档使用既有 PARTIALLY_COMPLETED 状态，不会假成功。
- 新增文档级诊断摘要：一次导入的总页数、成功/失败/空白/短文本/横向/旋转/待复核计数及对应
  升序页码列表，聚合为纯函数，不重新计算页面事实。
- 完成 300 页混合 PDF 实际规模验收：无缺页、假成功、跨页覆盖、数据丢失或句柄泄漏。
- schema 继续保持 v4；本版本没有迁移、没有诊断 UI，也不加入 AI、OCR 模型、Embedding、
  向量/语义搜索或外部模型 API。

详细范围与已知限制见 [v0.2.0 发布说明](docs/v0.2.0-release-notes.md)，人工验证步骤见
[v0.2.0 人工冒烟测试清单](docs/v0.2.0-manual-test-plan.md)。

### v0.1.2 批量操作与整理效率

发布日期：2026-07-21

- “检索资料”支持对当前分页可见页面批量修改状态、添加或移除标签、添加或移除项目；范围最多
  10 页，不跨分页，也不提供“选择全部匹配结果”。
- “待整理页面”支持相同的当前批次批量操作；数据库队列按 `count + LIMIT/OFFSET` 分页，每批
  最多 20 页，不会先把完整队列加载到内存。
- 批量操作先预检、再明确确认，并使用一次性 action token 防止刷新或重复提交。选择范围绑定来源、
  筛选、排序、分页/批次和稳定页面 ID；条件变化后不会静默修改隐藏页面。
- 添加或移除标签、项目不会覆盖未指定的既有关系，重复执行保持幂等。批量写入使用单个 SQLite
  事务；成功、未变化、受保护、缺失、过期与回滚分别反馈，不会静默部分成功。
- 当前会话中选中页面存在未保存编辑时会阻止批量操作；另一个浏览器标签页中尚未提交到服务端的
  编辑仍无法检测。

历史边界见 [v0.1.2 发布说明](docs/v0.1.2-release-notes.md) 与

### 发布收口、数据安全与可重复验收

- “系统维护”页面提供完整本地备份。备份使用 SQLite 在线备份 API 生成一致性数据库快照，复制
  `data/raw/`、`data/pages/` 和 `data/markdown/` 中的正式资料，并保存白名单恢复配置；每个文件都
  记录大小和 SHA-256。临时目录中的全部内容通过数据库、外键、统计、文件清单和哈希验证后，才会
  原子重命名为可恢复备份。
- 每个备份都有 `manifest.json`，记录应用版本、schema、创建时间、格式版本、文档/页面/FTS/证据/
  项目/标签统计、关键目录文件数和字节数、数据库完整性、外键结果、关键相对路径及逐文件哈希。
  日志、测试数据库、浏览器验收产物、Git、Python 缓存、临时文件、WAL/SHM 和运行时缓存不会纳入。
- 恢复采用“页面完整预检 + 停服后独立脚本”流程。脚本再次验证备份，自动为现有正式资料创建
  恢复前完整备份，在同盘临时目录重建并重定位数据库路径，通过检查后切换；恢复后再次检查数据库、
  统计和文件哈希。任何前置错误都会拒绝恢复，切换后验证失败会回滚原资料。
- 一键只读诊断检查数据库完整性、外键、数量、PDF/PNG/Markdown 缺失、孤立文件、目录读写能力、
  磁盘空间、关键路径、正式监听、隔离端口和最近备份。诊断只报告问题，不自动删除、重建或修复资料。
- 可下载默认脱敏的 Markdown 诊断报告；报告不包含 PDF、Markdown、笔记或证据正文，不读取或输出
  环境变量值、API Key、代理凭据和完整用户目录，日志只保留时间、级别和记录器名称。
- 首页和所有主要页面提供可理解的首次使用或空状态入口；统一 `scripts/release_check.py` 检查版本、
  Ruff、Pytest、正式数据库、监听、Git、污染、隔离端口、关键目录及经过验证的发布前备份。

### 搜索命中理解与连续阅读

- 搜索结果默认继续使用原有“按页面显示”卡片，也可切换为“按文档分组显示”。文档组按该文档
  首个页面在当前全局排序中的位置排列，组内保持相同全局顺序；组头显示完整命中页数、最相关页、
  主要命中字段、项目和标签。为控制 URL 长度，最多保存一个展开文档组。
- 每个页面显示 1～3 个按正文、OCR、Markdown 笔记、标题、文件名、标签或项目标注来源的去重片段。
  “关键词字面命中次数”统计各来源中非重叠的实际出现次数，重叠搜索词按最长项计一次；片段数和
  命中字段数不混作出现次数。
- 结果卡片提供按需快速预览。只有用户打开某一页预览后才读取该页图像和长文本；预览可核对
  Markdown/文本、复核状态、项目、标签和证据状态，并继续使用同一证据篮接口添加证据、修改备注、
  移除证据或生成单页证据包。
- 从搜索结果进入阅读页后，可按当前筛选与排序使用“全文结果上一项/下一项”，也可按页码使用
  “本文件上一命中页/下一命中页”。阅读页显示全局位置、完整结果总数、当前加载导航范围，以及
  本文件命中页的分组列表和短摘要；普通相邻页导航继续保留并提示相邻页是否命中、是否已入证据篮。
- 搜索关键词、范围、全部筛选、快捷条件、排序、加载上限、分页、筛选面板、结果视图、一个展开组、
  一个快速预览和结果焦点均使用白名单 URL 状态。刷新、阅读页往返和浏览器前进/后退可恢复；
  不把完整结果 ID 列表写入 URL，而是在阅读页用同一搜索参数重建有序结果。
  Streamlit 页面切换前还会在当前本地会话内保存一次性、经目标页面重新校验的交接参数，避免框架清空新 URL 参数；该交接不写数据库，也不能绕过 URL 白名单。

- 导入 PDF，使用 SHA-256 检测相同内容；同名但内容不同的文件可分别导入。
- 原 PDF 保存到 `data/raw/`，每页以清晰 PNG 保存到 `data/pages/<文档编号>/`。
- 提取 PDF 文本层；扫描、手写、文本不足或失败页面进入待复核列表。
- 页面复核状态统一为 `pending`（待处理）、`draft`（草稿待复核）、
  `reviewed`（人工复核完成）、`skipped`（暂不整理）和 `failed`（处理失败）。
- 每页拥有独立 Markdown 笔记；普通保存只生成草稿，不会自动声称人工复核完成。
- 待复核页面支持保存草稿、保存并复核、保存复核后进入下一页、暂时跳过，
  以及上一/下一待处理页；队列默认包含待处理、草稿和失败页，不包含已复核与跳过页。
- 切换页面前检查未保存修改；重复保存相同内容不会重复写文件或刷新更新时间；
  保存失败时编辑框内容保持不变。
- 待复核页顶部显示文档、页码、完整中文状态、已处理数、总页数和剩余待处理数。
- 首页、浏览资料和待复核页面均提供“继续处理下一待复核页”入口。
- 可选快捷键：`Ctrl+S` 保存草稿、`Ctrl+Enter` 保存复核并进入下一页、
  `Alt+Left` / `Alt+Right` 切换待处理页；方向快捷键不会在文本输入时触发。
- 双栏阅读器同时显示可滚动/缩放的页面原图与 Markdown 编辑区。
- 文档和页面均可关联可复用标签及本地项目。
- 文档可按名称、导入时间、更新时间、标签、项目和导入状态筛选。
- SQLite FTS5 与本地字段匹配共同检索文档标题、文件名、提取文本、OCR、
  Markdown 笔记、标签和项目；继续使用 jieba 预分词支持中文连续文本。
- 搜索结果以页面卡片展示文档标题、原文件名、页码、复核状态、项目、标签、
  命中字段和关键词附近摘要；缺少可选元数据时显示稳定回退信息。
- 搜索摘要支持多个中英文关键词，并对空格、引号、括号、加减号和斜杠等字符进行
  字面量处理。高亮前完整转义页面内容，只允许程序生成的固定 `mark` 标签进入 HTML。
- 搜索页默认收起筛选面板，高频条件按文档、项目、标签、复核状态集中展示；搜索范围、
  有笔记、当前证据篮和加载上限放在低频区域，排序保持为独立的紧凑入口。
- 可按文档、项目、标签、页面复核状态、命中字段、有无笔记和当前证据篮组合筛选；多个标签
  与多个项目采用 AND 逻辑。支持相关度、文档与页码、最近查看和最近修改排序。
- 当前生效条件以可操作标签集中展示，可单独移除、撤销最近一次筛选、仅清除筛选并保留关键词，
  或清除包括关键词在内的全部条件；没有筛选时不渲染空的条件区域。
- 文档、项目、标签和复核状态显示当前搜索上下文下的候选结果数。文档和状态忽略自身 OR
  维度以避免有效候选错误显示为 0；标签和项目保留已有 AND 条件，数字直接表示再加入候选后
  剩余页数。完整分面仍由一条聚合 SQL 完成。
- 文档、项目和标签提供 Unicode 本地快速查找，支持中文、全角字符、括号、方括号、加号、
  百分号等字面量；快速查找只缩小选项列表，不写数据库，也不改变正式搜索词。
- 提供仅看已复核、仅看待复核、仅看有笔记、仅看当前证据篮、最近查看和最近修改快捷入口；
  快捷入口与普通筛选共用 `SearchFilters`、排序枚举和参数化 SQL。
- 相关度排序在 FTS5 BM25 基础上增加可解释的字段权重：标题优先，其次为原文件名、标签、
  项目、用户 Markdown、OCR 和页面文本；完整连续短语及多字段同时命中会继续提升。
- 搜索关键词、筛选、排序、加载上限、分页和面板开合使用白名单 URL 状态；刷新、浏览器
  前进/后退、进入阅读页、证据加入/移除及备注编辑后均可恢复。旧版只带 `search_query`
  的阅读 URL 继续安全可用。
- 搜索结果精确跳转到记录中的文档与页码；记录或文件缺失时停止跳转并显示中文错误，
  不回退到相邻页。无结果时区分关键词未命中、筛选过严和搜索范围过窄，并提供恢复入口。
- 每条结果可生成 Markdown 引用证据包，包含文档、原文件名、页码、命中片段、复核状态、
  项目、标签、绝对本地文件路径、生成时间和稳定内部引用；原始材料与用户笔记分区展示，
  未人工复核完成的页面会明确标记为待核对材料。
- 搜索卡片与阅读页都可编辑具体证据选区并加入持久化证据篮。相同页面的不同选区可以并存，
  相同规范化选区不会重复加入；关闭浏览器或重启服务后证据仍保存在本地 SQLite 中。
- 证据篮支持来源统计、稳定排序、上下移动、删除单条、显式确认后清空、编辑用户备注、返回
  原始页面，以及按当前顺序生成单文档或多文档 Markdown 证据包。
- 每条证据保存来源记录、加入时元数据、选区哈希和原始文本 SHA-256。选区能在 PDF 文本层或
  OCR 文本中匹配时标记为“已匹配原始材料”；无法匹配时明确标记为“用户摘录（未经原文匹配
  确认）”。导出前重新校验文档、页面、页码、PDF、页面图像和原始文本哈希，任一不一致即停止。
- 多页面证据包分别展示原始材料、用户摘录、用户笔记以及系统生成或用户提供的上下文；每条
  非 `reviewed` 证据都有警告，存在两条及以上未复核证据时还会在包顶部显示整体警告。
- 记录导入状态、进度、总页数、已处理页、文本页、待复核页、失败页和错误。
- 单页失败不会撤销其他已经完成的页面。
- 一键后台启动/停止、重复启动检测、PID 身份校验、本机健康检查和轮转日志。
- 可选的 Windows 当前用户登录后自动启动；优先使用任务计划程序，受系统策略限制时回退到当前用户“启动”文件夹。

v0.2.0 继续保留 OCR 文本字段，但不接入云端 OCR，也不直接调用任何大模型 API。
证据包与外部 AI 提示词都只是用户主动复制的本地文本。

## 检索、证据篮与引用证据包使用方法

1. 打开“检索资料”，输入一个或多个中英文关键词。多个关键词采用 OR 召回，结果卡片会列出
   实际命中的全部字段；输入中的 FTS 操作符和特殊字符不会直接成为查询语法。
2. 高频操作可直接使用“仅看已复核”“仅看待复核”“仅看有笔记”“仅看当前证据篮”或
   两个最近排序入口。需要组合条件时展开筛选面板；文档、项目、标签上方的小搜索框只过滤
   候选项，点击“搜索 / 应用筛选”后才更新正式结果。
3. 结果上方会显示全部已生效条件。点击任一“移除”按钮只取消该项；“仅清除筛选”保留
   关键词，“清除所有条件”同时清除关键词。项目和标签继续采用 AND 语义；括号数字表示
   选中候选后可保留的页面数。
4. 点击“打开页面”进入精确文档和页码。阅读页顶部显示原搜索词和“返回检索结果”按钮；
   返回后恢复关键词、筛选、排序、加载上限、当前结果分组和面板状态。
5. 如只需引用单页，可点击“生成 / 复制证据包”，在展开的 Markdown 代码框右上角复制。PDF 和页面图像
   使用绝对本地路径，不生成公开链接；项目、标签或笔记不存在时不会输出成组空白项。
6. 证据包的“原始材料内容”和“用户笔记”是独立章节。`pending`、`draft`、`skipped` 和
   `failed` 页面会附带尚未人工复核完成的提示，引用前应回到页面图像核对。
7. 如需收集多页证据，在结果卡片展开“编辑加入证据篮的选区与备注”，或在阅读页展开
   “将当前页选区加入证据篮”；复制/填写具体段落后点击“加入证据篮”。
8. 系统使用 Unicode 与空白规范化后的精确包含关系核对 PDF/OCR 原文。匹配成功的选区归入
   “原始材料”；没有文本层、文字经过整理或无法匹配时归入“用户摘录”，不会冒充验证原文。
9. 搜索结果卡片或阅读页可直接编辑已有证据备注、移除单条证据；这些操作不会改变搜索 URL。
   打开“证据篮”还可调整顺序或返回来源。清空证据篮必须显式勾选确认，
   且只删除证据条目，不修改原 PDF、页面图像、页面笔记、标签或项目。
10. 点击“生成证据包”后可复制或保存 Markdown。用户输入使用缩进代码块隔离，标题和元数据会
   进行 Markdown 转义，不能通过 `#`、反引号、链接或表格符号破坏固定证据结构。

搜索仍是字面量全文检索，不会自动理解同义词、工程语义或问题意图。扫描件没有文本层时，
可先在待整理页面对单页执行本地 OCR，识别出的 OCR 初稿会进入全文搜索；未执行 OCR 且
尚未人工补充笔记的扫描页仍只能通过文档标题、文件名、标签或项目元数据找到。

## 数据库升级、完整备份与安全恢复

### 升级

v0.2.0 继续使用 schema v4，**没有数据库迁移、字段变更或新增索引**。从 v0.1.x 升级不会
触发数据库备份、重建 FTS 或重写文档、页面、标签、项目、复核状态及证据篮数据；已有 v4
数据库会经过幂等初始化并继续执行完整性与外键检查。

历史上首次从 schema v3 升级到 schema v4 时，程序使用 SQLite 在线备份 API 创建一致性
备份，文件形如：

```text
data/database/backups/knowledge.v3.<时间戳>.db
```

schema v4 只新增 `evidence_baskets` 和 `evidence_items`，不重建 `documents`、`pages` 或 FTS5。
证据篮与条目通过外键关联；删除文档或页面时对应证据条目级联清理，删除证据篮时只级联其条目。
条目使用 `(basket_id, page_id, selection_sha256)` 防重复，并使用 `(basket_id, position)` 保证
顺序唯一。备注限制为 4000 字符；表结构已经支持多个证据篮，v0.2.0 界面默认使用一个篮子。

迁移事务会比较迁移前后的文档数、页面数、FTS 行数、五种复核状态计数、PDF 路径和页面图像
路径，并执行 `integrity_check` 与 `foreign_key_check`。任何一步失败都会回滚整个 schema v4
事务，原 schema v3 数据库和迁移前备份均保留。程序也继续支持从更早 schema 依次安全迁移。

从 v0.1.1 升级不需要移动 `data/`、重导 PDF 或重建索引。先停止旧服务并保留现有 `data/`，
更新程序后再启动 v0.2.0；确认首页、检索、阅读、证据篮和系统维护页的真实统计。历史
`knowledge.v3.<时间戳>.db` 只用于 schema v4 迁移故障恢复，不包含完整 PDF、PNG 和 Markdown，
不能替代完整资料备份。

### 创建和验证完整备份

打开“系统维护”，确认“备份目标目录”位于正式 `data/` 之外，然后点击“创建并验证完整备份”。
默认目标为项目根目录的 `backups/`。已有同名目录不会被覆盖；失败的临时目录会清理，无法清理时
会保留 `INCOMPLETE.txt`，且因为没有合法 `manifest.json`，不能用于恢复。

备份目录结构：

```text
backups/ekb-v0.2.0-<时间戳>/
├── manifest.json
├── config/
│   └── settings.json
└── data/
    ├── database/
    │   └── knowledge.db
    ├── raw/
    ├── pages/
    └── markdown/
```

`config/settings.json` 只保存恢复需要的路径根和本地运行白名单配置，不复制 `.env`，也不会保存
API Key 或代理凭据。`manifest.json` 中的所有可复制路径必须是受限相对路径，不能包含绝对路径、
反斜杠或 `..`；恢复不会跟随备份中的符号链接。

### 正式恢复

1. 在“系统维护”选择备份并点击“验证所选备份（只读）”，核对备份时间、文档、页面和 FTS 数。
2. 双击 `停止工程知识库.bat`，确认正式服务和 8501 端口已经停止。
3. 在项目根目录 PowerShell 执行页面给出的命令，例如：

```powershell
.\.venv\Scripts\python.exe scripts\restore_backup.py `
  --backup ".\backups\ekb-v0.1.2-<时间戳>" --confirm RESTORE
```

4. 脚本会再次校验格式、版本、schema、数据库、外键、清单、大小、哈希和文件引用；通过后先创建
   `pre-restore-v0.1.2-<时间戳>` 完整备份，再在临时目录中恢复。数据库路径会安全重定位到当前
   正式目录，不会把备份数据库中的绝对路径直接当作写入目标。
5. 恢复后脚本重新检查数据库统计和文件哈希。成功后启动服务并再运行一次只读诊断。

正式服务仍在运行、manifest 缺失/损坏、应用版本或 schema 不兼容、数据库损坏、文件缺失、大小或
哈希不一致、路径逃逸、符号链接和恢复前备份失败都会中止恢复。系统不提供绕过验证的“强制恢复”。
若切换后的检查失败，脚本会恢复原正式目录；恢复前完整备份仍保留。

隔离验收可增加 `--target-data-dir <隔离目录>`，此模式不会替换正式资料，也不要求停止正式服务。
隔离目标不得是磁盘根目录、用户主目录、项目根目录或正式 `data/`。

### 系统诊断和脱敏报告

“系统维护”中的诊断按钮只读检查正式数据库、文件、路径、目录访问、磁盘空间、正式监听、常用
隔离端口和最近备份，不创建探测文件，也不自动修复。诊断完成后可下载 Markdown 报告；该报告
默认脱敏，适合在排障时主动提供，不应替代完整备份。

## 删除行为

- 清空笔记只处理所选页面笔记，不改变原 PDF、页面图片或提取文本。
- 删除标签只删除标签及关联。
- 删除项目只删除项目及关联。
- 删除单条证据或清空证据篮只修改 schema v4 证据表，不删除或改写任何用户资料。
- 删除文档需要输入文档标题二次确认；只清理该文档自己的记录、原 PDF、页面 PNG 和 Markdown，不会删除其他文档。
- 关键关联和元数据修改使用 SQLite 事务。

## 常见故障排查

| 现象 | 处理方式 |
| --- | --- |
| 提示虚拟环境不存在 | 按“首次安装”创建 `.venv`，不要复制其他机器的虚拟环境 |
| 8501 端口被占用 | 运行 `查看运行状态.bat` 并关闭占用程序；正式服务不支持改用其他端口 |
| PID 文件过期 | 再次启动或查看状态会自动识别并清理；PID 在 `runtime/` |
| 服务异常退出 | 查看 `logs/server-console.log` 和 `logs/service-manager.log` |
| 数据库不可写/迁移失败 | 停止服务，检查 `data/database/` 权限；保留主库并查看 `backups/`，不要删库重建 |
| PDF 损坏、为空或受密码保护 | 导入页会显示中文错误；原始输入不会覆盖其他资料 |
| 单页处理失败 | 在“待复核页面”查看失败原因并重试，其他页面不受影响 |
| 页面图片缺失 | 从完整 `data/` 备份恢复对应 `data/pages/<文档编号>/` |
| 笔记保存失败 | 页面会显示“保存失败”；检查数据库与 `data/markdown/` 写权限 |
| 证据包停止导出 | 按错误提示检查对应文档/页面记录、PDF、页面图像或原始文本是否变化；重新核对后再加入，不要绕过校验 |
| 计划任务 Access denied | 启用脚本会自动使用当前用户启动文件夹，不需要管理员权限 |

健康检查地址为 `http://127.0.0.1:8501/_stcore/health`，只返回简单状态，不包含用户资料。

## 质量检查

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest
```

发布前使用统一检查；该命令会额外创建一个经过完整验证的发布前备份：

```powershell
.\.venv\Scripts\python.exe scripts\release_check.py
```

发布提交与 tag 收口阶段若服务按流程尚未启动，可复验同一个正式发布备份而不重复创建：

```powershell
.\.venv\Scripts\python.exe scripts\release_check.py `
  --existing-backup ".\backups\release-v0.1.2-<时间戳>" `
  --expect-service-stopped
```

输出逐项标记 `PASS`、`WARNING` 或 `FAIL`。数据库损坏、外键违规、版本不一致、测试失败、非本机
监听、残留隔离端口、误暂存 `AGENTS.md`、未追踪验收产物或备份失败都会使进程返回非零退出码。

## 当前限制

- v0.2.2 起提供本地单页印刷体 OCR；仍不执行手写识别、公式 OCR、复杂表格结构识别或批量 OCR。
- 不包含向量数据库、Embedding、向量搜索或语义搜索。
- 不执行大模型自动问答；只能手动复制证据包或受约束提示词。
- 不联网搜索资料，不抓取聊天记录或未获授权的第三方材料。
- 字面量搜索不会自动扩展同义词；没有文本层的扫描页需先经本地 OCR 或人工补充笔记后才能按内容检索，否则只能通过元数据找到。
- 选区匹配是规范化后的字面量包含检查，不做语义对齐；改写、概括或只存在于页面图像中的文字
  会作为未确认用户摘录保存。
- 不注入浏览器原生鼠标选区 JavaScript；用户通过文本框复制、填写或编辑证据段落。
- 每次最多加载 100 个搜索结果卡片；完整匹配数仍会显示，更多结果需继续筛选后查看。
- 批量操作只覆盖当前可见范围：搜索页当前分页最多 10 页，待整理页当前数据库批次最多 20 页；
  不支持跨分页、跨批次或选择全部匹配结果。
- 另一个浏览器标签页中尚未保存的编辑无法被当前会话检测；执行批量操作前仍应先保存其他标签页。
- 待整理队列使用 `OFFSET` 分页，超大资料库的深分页性能仍需观察；分类元数据每次 rerun 明确执行
  文档、标签、项目三次查询。
- 全局和本文件命中导航只覆盖当前加载上限内的有序结果；超过上限时界面明确显示“已加载 / 完整
  匹配”范围，不会把当前 10 条页面分页误作完整导航范围。
- Streamlit 没有可靠的原生滚动位置恢复接口。v0.2.0 会恢复结果焦点并显示“返回位置”文字标识，
  但不会注入脆弱 JavaScript 强行恢复像素级滚动位置。
- 文档分组和快速预览分别只在 URL 保存一个展开文档 ID 和一个预览页面 ID；切换到其他组或预览时
  替换旧值，以避免 URL 随结果数量膨胀。
- 文档、项目和标签的快速查找依赖 Streamlit 本地页面重跑，不是浏览器端虚拟列表；数千个
  筛选项时仍受 Streamlit 组件渲染速度影响。
- schema 支持多个证据篮，但 v0.2.0 界面只操作一个默认篮子；命名和切换多个篮子留待后续版本。
- 正式恢复必须停服并使用独立脚本；Streamlit 页面只做预检查，不在数据库仍被占用时尝试在线覆盖。
- 完整备份是本地目录格式，不压缩、不加密，也不提供云同步；备份介质的访问控制由用户负责。
- 诊断中的目录“可读写”使用操作系统权限判断，不会为了测试权限而写入正式数据目录；统一发布检查
  才会创建并立即删除零字节探测文件。
- Streamlit 使用内置 `/_stcore/health`，没有引入第二个后端或网络服务。
- Windows 计划任务受系统策略控制；启动文件夹是普通用户回退方案。
