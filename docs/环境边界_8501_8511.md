# EKB 环境边界：8501 正式服 / 8511 测试服

更新日期：2026-09-05

## 角色定义（长期不变）

| 实例 | 端口 | 角色 | 运行的代码 | 数据根目录 |
|---|---|---|---|---|
| 正式服（Stable） | 8501 | 比赛演示、正式历史数据 | `D:\Projects\ekb-runtime\stable`（只读稳定快照） | `D:\Projects\ekb-runtime\stable\data` |
| 测试服（Preview） | 8511 | v0.7.x 开发、人工模拟、破坏性测试 | canonical workspace `D:\Projects\ekb-dev` | `D:\Projects\ekb-dev\staging-data` |

8511 永久滚动为下一版本 Preview。

## 为什么 8501 必须脱离 canonical workspace

2026-09-05 发生过：开发侧把 `SCHEMA_VERSION = 13` 先写入、migration 函数与
`import hashlib` 尚未写完，而 8501 直接热加载 canonical workspace，Streamlit
rerun 自动尝试迁移，出现“缺少迁移函数 / 缺少 hashlib”。事务回滚和迁移前备份
保住了正式数据，但这证明正式服不能观察正在被编辑的源码树。

因此 8501 只从稳定快照启动：

- 快照由 `python scripts/export_stable_runtime.py` 从**已 commit + push 的
  checkpoint** 导出（脚本拒绝 dirty / 未 push 的工作区）；
- 快照不是 clone、不是 worktree、不是第二开发工作区，禁止人工编辑；
- 正式数据只在快照内演进，导出脚本遇到快照中已有数据库时**永不覆盖**；
- 快照通过 `.venv` junction 复用项目解释器，源码仍然完全独立。

## 启动入口（全部已纳入 Git）

| BAT | 作用 |
|---|---|
| `启动工程知识库.bat` | 启动 8501（自动定位 stable 快照；快照缺失时拒绝启动并提示导出命令） |
| `停止工程知识库.bat` | 停止 8501 |
| `查看运行状态.bat` | 8501 状态 |
| `启用/关闭开机自启.bat` | 登录自启指向 stable 快照 |
| `启动工程知识库_测试服_8511.bat` | 启动 8511 测试服（canonical workspace + 独立 staging-data） |
| `停止工程知识库_测试服_8511.bat` | 停止 8511（不影响 8501） |

服务管理器统一入口：`scripts/service_manager.py`（`--staging` 管理 8511）。

## 数据隔离

- 8511 的全部可写路径（database / raw / pages / markdown / agent-readings /
  backups / logs / runtime）都在 `staging-data/` 下，与正式数据零共享；
- 进程级开关 `EKB_STAGING_INSTANCE=1` 让应用进程整体使用 staging 配置；
- 8511 页面侧栏顶部显示“测试服 · 8511”，不显示 schema / 路径 / 版本细节，
  普通用户模拟不受干扰；
- 两个实例可以同时运行：端口、pid、日志、数据库文件完全分开，不存在锁竞争。

## 种子策略（scripts/preview_seed.py，只允许 8501 → 8511 单向）

| 种子 | 命令 | 用途 |
|---|---|---|
| EMPTY | `python scripts/preview_seed.py empty` | 全新首次使用（Novice）测试 |
| FORMAL_SNAPSHOT | `python scripts/preview_seed.py formal-snapshot` | 用正式历史（SQLite backup API + 资产目录复制）测试迁移 / 经验 / 长期记忆 |
| DIRTY_LONG_TERM | 后续 fixture 建设 | 多版本、冲突、重复、删除、错误历史（v0.8 Reliability 用） |

脚本在构造上只写 `staging-data/`，正式数据只读；生产数据永远不会成为写入目标。

恢复流程：`seed empty → 做破坏性模拟 → 再次 seed（empty 或 formal-snapshot）`
即可回到已知起点。

## Promotion 流程（比赛结束后）

1. v0.7 Stable 通过全部 Gate（focused + full regression + Human Gate）；
2. canonical workspace commit + push，ahead/behind 0/0；
3. `python scripts/export_stable_runtime.py`（首次会对正式数据做一次性种子；
   之后的 Promotion 需按脚本提示迁移正式历史并执行正式 migration，不用
   8511 测试库覆盖）；
4. 用 `启动工程知识库.bat` 重启 8501（运行新 Stable 快照）；
5. 8511 继续作为 v0.8.x Preview。
