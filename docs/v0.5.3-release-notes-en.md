# EKB v0.5.3 — Audited AI Integration (Release Notes)

- Status: officially published as GitHub Release `v0.5.3`.
- Positioning: builds on the v0.5.2 Knowledge Foundation with auditable, citation-constrained, on-demand AI assistance.

## Overview

v0.5.3 gives users on-demand AI assistance over knowledge they explicitly select or retrieve: Ask AI / RAG Answer and read-only experience-candidate organization. Every AI capability is citation-constrained, auditable and traceable; AI never writes knowledge automatically and is not a dependency of core features.

## Highlights

- ContextItem and KnowledgeContextPackage unify read-only context projection and packaging;
- Ask AI / RAG Answer answers only from the selected context;
- runtime citation-integrity validation, fail-closed;
- read-only AI experience candidates;
- AI call ledger with a read-only dashboard;
- Knowledge Export and AI Ledger Export, two structured export packages;
- schema-v8 legacy backup isolated upgrade;
- all offline core features keep working without an API Key.

## AI workflow

```
user selects or retrieves knowledge → ContextItemProjector → KnowledgeContextPackage
        → Prompt Builder → AI Provider → auditable output (answer or experience candidate)
```

- The provider input always comes from a KnowledgeContextPackage and never bypasses the Context/Evidence layer.
- Only the context the user selected this time is processed; context never expands automatically.
- No background, scheduled or continuous calls; no session memory.

## Citation integrity

- Every citation in an AI answer (stable_id or #N marker) must belong to the current context package.
- Unknown, forged, out-of-range and empty citations fail closed without showing a half-finished answer.
- Citations are deduplicated in first-seen order; the UI shows the validated citations explicitly.

## Experience candidates

- The user selects "Organize Experience with AI" to generate a structured candidate on demand: title, problem, context, action, result, root cause, lesson, applicability, limitations and citations.
- A candidate is only an AI-organized draft, not confirmed experience; the page provides no automatic save or one-click write.
- Fields that cannot be confirmed from the context stay empty or are marked "insufficient evidence".

## AI call ledger

- ai_calls records capability (completion/embedding/rerank), source feature (rag_answer / experience_model / others), status, model, tokens and target references.
- The ledger is read-only and never stores full prompts, context text or model answers; Mock offline demos never write the ledger.
- Schema v12 already expresses the call semantics; this version adds no schema v13.

## Export and backup

- Knowledge Export: lossless export of knowledge objects, sources, relations, revisions and memories with a manifest, per-file SHA-256 and one Markdown file per object.
- AI Ledger Export: a standalone audit export of ai_calls metadata (JSON/JSONL authoritative), without content or credentials.
- Schema-v8 legacy backup isolated upgrade: the original backup stays byte-identical; the upgraded product is verified through a second isolated-directory restore drill.

## Data and schema compatibility

- application_version=0.5.3; schema_version=12; backup_format_version=1; config_format_version=1.
- Normal restore still requires exact schema match; schema-v8 artifacts are handled only through the dedicated isolated upgrade entry point.

## Offline behavior

- `ai_mode="manual"` by default; without an API Key, PDF import, search, reading, notes, evidence, deletion/recovery and backup all keep working.
- Without an API Key the UI falls back to a clearly labelled Mock offline demo; it never impersonates a real model result.

## Security and privacy boundaries

- No automatic knowledge writes; no modification of user originals; no Agent, tool calling, long-term session memory or automatic scanning.
- No full prompts, context or answers are stored; no API Key is recorded; provider, token and cost are never guessed.
- The official service listens only on `127.0.0.1:8501`.

## Upgrade notes

- Upgrading from v0.5.2: stop the service → run the release check → back up → start v0.5.3.
- Legacy schema-v8 database snapshots: `python scripts/upgrade_backup.py <legacy_backup> <output_dir>`.
- See docs/windows-recovery.md and the backup/restore entry points for the complete recovery flow.

## Verification

- Full pytest: 1762+ tests collected, exit 0.
- Ruff, `git diff --check`, schema v12 backup/restore roundtrip, release_check, production `127.0.0.1:8501` health HTTP 200 and a read-only Smoke Test across all official pages.

## Known limitations

- Agent, tool calling and long-term session memory are not implemented.
- Local OCR targets single-page printed text; handwriting, formulas and complex tables are unsupported.
- Search display and batch operations have load-range limits.
- Complete backups are local directory structures, not encrypted archives.

## Statement

This version is officially published as `v0.5.3`. It does not claim automatic experience learning, an existing Agent, the ability to bypass the evidence layer, AI outputs automatically becoming knowledge, or validated business success or PMF.
