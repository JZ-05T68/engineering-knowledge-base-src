## 一、Lexical Retrieval

### 1.1 调用链与查询构造

- 入口：`pages/4_检索资料.py` → `SearchService.search`（`src/search_service.py:91-113`）→ `Database.search`（`src/database.py:1085-1191`）。
- 查询侧分词：`extract_search_terms`（`src/text_utils.py:84-135`）：NFKC 规范化；按 `[\w\u3400-\u4dbf\u4e00-\u9fff]+` 抽取可检索组（标点与 FTS5 语法字符不会存活）；连续 CJK 组先整体保留为 phrase term，再追加 `jieba.cut_for_search` 子词；term 级 casefold、去 `_`、截断 128 字符、去重、上限 16 个 term；FTS 操作符 `and/or/not/near` 被排除。
- FTS5 表达式：`"term" OR "term"`，全部双引号包裹，操作符安全（`src/search_service.py:86-104`）。
- **关键结构事实：FTS5 只负责打分，不负责过滤。** `Database.search`（`src/database.py:1122-1148`）在 CTE 里算 `bm25(page_search, 1.0, 0.9, 1.1)`，但行过滤是 `LEFT JOIN` + 字面 `LIKE %term%`（`_search_match_clause`，`src/database.py:1845-1895`，参数化 + `ESCAPE '\'`）。推论：
  - title/filename/tag/project 的元数据命中不需要任何 FTS 行；
  - FTS tokenizer 不匹配不会排除 LIKE 命中；
  - 多 term 查询是 OR 语义，任何一个 token 命中即入候选，排序交给 bm25+boost。
- 索引侧：`page_search` FTS5 表（`search_extracted_text / search_ocr_text / search_markdown_content`，`tokenize='unicode61 remove_diacritics 2'`，`src/migrations.py:991-998`），由 `pages_fts_insert/delete/update` 触发器同步（`:1001-1044`）；写入前经 `jieba.cut_for_search` 预分词（`_tokenize_for_fts`，`src/database.py:1661-1667`）。title/filename/tag/project **不在** FTS 表内。
- 安全网：FTS `OperationalError` → 警告 + 返回 `[]`（`src/database.py:1189-1191`）。

### 1.2 打分与排序

- `relevance_score = COALESCE(bm25,0) − 元数据/内容加权`（`_relevance_expression`，`src/database.py:2000-2024`）：title −30、filename −18、tag −14、project −12、markdown −7、OCR −5、extracted −4（逐 term LIKE 判断）+ 首 term（CJK 整组）phrase 命中额外 −10。分数越低越好。
- 排序白名单（`_search_order_by`，`src/database.py:1978-1997`）：
  - `RELEVANCE`：`relevance_score ASC, p.document_id, p.page_number`；
  - `DOCUMENT_PAGE` / `VIEWED_DESC` / `UPDATED_DESC`：**完全不含 relevance_score**，相关度加权被整体丢弃；
  - 未知 sort 值静默归并为 RELEVANCE。
- 每行 `SearchResult.rank` 存复合 relevance_score；文档分组视图取 `min(rank, page_number, page_id)` 为代表（`src/search_navigation.py:161-164`）。

### 1.3 空结果行为

- 服务层：无 term 或 `limit<=0` → `[]`（`src/search_service.py:101-103`）。
- UI（`pages/4_检索资料.py:759-798`）：查询无可检索文字 → `st.warning`；有效查询零结果 → 用 facet 计数诊断出 4 种原因之一 + 撤销/清筛选恢复按钮。**不存在任何「弱结果 / 低置信」表达。**

### 1.4 筛选与排序回退

- 筛选维度（`SearchFilters`，`src/models.py:271-281`；SQL `src/database.py:1898-1957`）：document / project / tag / review status / match_fields / has_note / evidence basket，全部 AND 组合。无页码范围筛选。
- 任何筛选或非 RELEVANCE 排序时 `hybrid_is_allowed` 为 False（`src/search_mode.py:25-49`），执行路径退回关键词（`pages/4_检索资料.py:169-172`）。该回退对当次搜索**无逐次提示**（见 §五）。

### 1.5 上限

- UI 最多加载 10–100（默认 50）；`SearchService.max_results=100`；DB 硬上限 100；展示分页 10/页；查询 500 字符 / 16 term。

### 1.6 已观察边界情形

- 引号/括号/加减号/斜杠/LIKE 通配符均被中和（有测试）；超长查询有界返回 `[]`（有测试）；单字 CJK 仅在存在更长 CJK term 时丢弃；数字查询无专门测试；单 term 128 字符截断与 16 term 上限的边界行为无测试；`VIEWED_DESC/UPDATED_DESC` 的实际行序无断言；bm25 列权重与 boost 数值本身无测试（只测相对偏好）。

## 二、Vector Retrieval

### 2.1 fresh embedding 读取（两道闸）

1. SQL 配置过滤：`Database.list_page_embeddings(model, dimensions, config_version)`（`src/database.py:1568-1595`）——model/dimensions/config_version 不匹配的行在 SQL 层被排除，不会被解码。
2. 逐候选指纹校验：`PersistentVectorRecallSource.recall_scored`（`src/ai/vector_recall.py:202-209`）重算 `prepare_page_text`（strip、空跳过、截断 8000 字符、SHA-256，`src/ai/page_indexer.py:94-111`）并与存储 `source_text_sha256` 精确比对；不一致或无法重算（页面缺失/内容为空）→ 静默 `continue`。
- 「fresh」= `(page_id, source_text_sha256, model, dimensions, config_version)` 五元组完全一致。
- 更严的单页读取 `get_fresh_page_embedding`（`src/database.py:1534-1566`）只被 indexer 复用判断使用（`src/ai/page_indexer.py:351-357`），recall 不用。

### 2.2 相似度与排序

- 余弦：`math.fsum` 点积/范数，长度不符/空/非有限/零范数全部 fail-closed（`src/ai/vector_recall.py:62-84`）。
- query vector 预检：恰好 1 条、维度精确匹配、全部有限、非零范数（`:223-245`）。
- 排序：`(-similarity, page_id)`（`:220`）；top-k `scored[:limit]`（`:221`），截断后重排 1..N。
- **无相似度阈值**——显式设计决定（docstring `:20-21`，`test_recall_has_no_similarity_threshold` 锁定）。

### 2.3 stale / missing / mismatch 行为

| 情况 | 行为 |
|---|---|
| stale（sha 不匹配）/ 无法重算指纹 | 静默跳过，**不在任何 outcome 计数中出现** |
| 缺 embedding | 本来就不是候选（零 API 成本；补索引是 indexer 的事） |
| model/dims/config 不匹配 | SQL 层过滤，从不解码 |
| blob 损坏 | `DatabaseError` 向上传播 → hybrid 层兜底为 lexical-only `FAILED` |
| 单条非法存储向量（如零向量） | 警告日志 + 跳过，recall 继续 |

### 2.4 测试覆盖

自动化覆盖充分：`tests/test_ai_vector_recall.py`（30 tests，余弦正确性/拒绝、配置过滤、freshness、排序、并列、limit、无阈值、零向量、query 预检、降级、端到端持久召回）、`tests/test_ai_embedding_store.py`、`tests/test_schema8_embeddings.py`、`tests/test_ai_page_indexer.py`。
缺口：stale 跳过的不可观测性（无计数）只有行为测试，没有「stale 数量对用户/日志可见」的断言；真实 Qwen 余弦排序质量只有人工证据（`docs/v0.5.0-phase10c-retrieval-evidence.md` §七还记录了 page 19 排在 page 17 前的已知排序质量观察）。

## 三、Hybrid Fusion（RRF）

### 3.1 并集与公式

- lexical 侧直接用 `SearchService.search` 的顺序作为 1-based rank（`src/ai/hybrid_search.py:105-111`），不从 relevance_score 重导。
- `rrf_fuse`（`src/ai/retrieval.py:113-163`）：`RRF(page) = Σ_sources 1/(k+rank)`，**k=60**（`DEFAULT_RRF_K`，`:41`）。双来源页累加两项；单来源页保留。
- 同一来源内重复 page_id → `ValueError`（契约违反；vector 侧预检后降级 lexical-only，`src/ai/hybrid_search.py:158-167`）。跨来源同页是正常 merge。
- **最终 top-k 截断：没有。** `rrf_fuse` 返回完整排序并集；`HybridSearchService.search`（`:172-186`）全部水合并返回，结果数可达 `2*limit`。只有每个输入分支被 `limit` 截断。
- vector-only 候选只读水合成引用完整的 `SearchResult`（`match_type="语义召回"`、`snippet=""`、`rank=0.0`，`:202-238`）；页面/文档已不存在者跳过并计入 `invalid_vector_candidates`。

### 3.2 确定性

- recall 排序键 `(-similarity, page_id)`；`math.fsum` 保证浮点跨平台一致；embedding 列表 SQL 按 `page_id ASC, id ASC`。
- RRF 排序键 `(-fused_score, best_rank, page_id)`，page_id 唯一 → 全序，输出确定。输入排列不变性有测试。

### 3.3 测试覆盖

自动化充分：`tests/test_ai_retrieval.py`（18 tests）、`tests/test_ai_hybrid_search.py`（18 tests，含降级==纯 lexical 恒等）、`tests/test_ai_real_hybrid_fusion_probe.py`（离线复算冻结 probe 的 RRF 数值）。
缺口：**无测试锁定「融合结果无最终 top-k 上限」**（`2*limit` 行为既未被断言为预期，也未被断言为缺陷）；跨文档融合排序只有小夹具单文档测试 + v0.5.0 人工证据。

## 四、Application Runtime（付费边界）

### 4.1 query embedding 触发链

唯一运行时付费路径：「搜索 / 应用筛选」按钮（`pages/4_检索资料.py:714-715`）→ `_activate_state`（`:237-257`）→ `_search_with_state`（`:161-180`）→ `hybrid_is_allowed` 门（`:169`）→ `_run_hybrid_search`（`:197-216`，服务在函数内惰性解析）→ `HybridSearchService.search`（`src/ai/hybrid_search.py:132-156`）→ `vector.recall` → `_query_vector`（`src/ai/vector_recall.py:223-245`）→ **全运行时 vector 路径唯一 `embed()` 调用点（`:226`）** → `QwenProvider.embed`（`src/ai/qwen_client.py:241-275`）→ `urllib_transport`（仅在 `src/runtime.py:129` 注入）。

- 免费不触发：输入框打字（Enter 只引起 rerun，不执行搜索）、筛选/排序/模式控件变更、分页、视图切换、预览、证据篮操作。
- 其他 embed 调用点只在 scripts（page indexer / 实验 / probe），应用页面不 import PageIndexer。
- `complete` 从未被应用调用；`rerank` 恒 `raise AIUnavailableError`（`qwen_client.py:277-289`）。

### 4.2 「一次显式搜索至多一次 query embedding」

结构性保证（非缓存）：每次 `search` 恰好一次单文本 `embed`；点击后 `st.rerun()` 不会重执行（URL-restore 块比较 `search_executed_projection`，`auto_execute_allowed(..., already_executed=True)=False`）。**注意：运行时无 query-vector 缓存，同一查询点两次会 embed 两次**（「每次显式动作一次」，不是「每个唯一查询一次」）。覆盖：`tests/test_search_hybrid_lifecycle.py`、`tests/test_search_hybrid_ui.py`。

### 4.3 retry

- 库默认 `MAX_EXTRA_ATTEMPTS=2`（`qwen_client.py:69`），可重试错误 = 网络层失败 / HTTP 429 / HTTP≥500（`_is_transient`，`:157-164`）。
- **production runtime 硬编码 `max_extra_attempts=0`（`src/runtime.py:128`）**，由 `tests/test_ai_runtime.py::test_application_provider_forces_zero_retry` 锁定。真实付费 scripts 全部强制 0。

### 4.4 降级矩阵

| 失败 | 结果 |
|---|---|
| 无 vector source（manual/无 key） | lexical-only，`DISABLED` |
| `AIUnavailableError` | lexical-only，`UNAVAILABLE` |
| 网络/HTTP/超时（`AIExecutionError`） | lexical-only，`FAILED` |
| query vector 非法（`ValueError`） | lexical-only，`FAILED` |
| 意外异常 | lexical-only，`FAILED`（带 traceback 日志） |
| vector 路径返回空 | lexical-only，`EMPTY` |
| `DatabaseError` 读存储 embedding | 传播 → 页面 `st.error("检索失败：…")`，空结果 |

所有降级保留 lexical 结果的 identity/count/order（有测试恒等锁定）。

### 4.5 deep-link 不自动付费

`pages/4_检索资料.py:386-408`：URL 恢复的 hybrid 状态被 `auto_execute_allowed` 拦截（`src/search_mode.py:99-116`），恢复控件 + 提示「请点击"搜索 / 应用筛选"执行」。keyword deep-link 自动执行（免费）。门本身有单测；**「URL 恢复 → 0 embed」无专门 AppTest 端到端用例**（由 lifecycle 测试 + 门单测组合覆盖）。

### 4.6 AI 模式门控

- `ai_mode="manual"` 默认；无 key → `application_ai_provider` 返回 `None`（`src/runtime.py:115-120`）→ vector=None → 全部 `DISABLED` 降级；manual 模式甚至不构造 QwenProvider（有测试）。
- 默认 transport `_unconfigured_transport` 任何调用即 `AIUnavailableError`（纵深防御）；provider 层缺 key 在 transport 调用前 fail-closed。

## 五、Search UI

### 5.1 模式门控与解释

- `st.radio("检索方式")`（`pages/4_检索资料.py:682-692`）：关键词检索 / AI 混合检索，默认 KEYWORD。help 文本披露「点击搜索时按需调用一次语义向量检索（当前仅支持无筛选、按相关度排序）」；静态 caption 说明筛选/非相关度排序自动退回关键词。
- radio **从不在控件层隐藏/禁用**；门控全部在执行时。

### 5.2 回退 UX（两类回退待遇不同）

| 回退类型 | 用户可见性 |
|---|---|
| 筛选/排序驱动的 gate 回退 | **当次静默**：`_run_keyword_search` 主动删除 hybrid note（`:192-194`）；只有事先的静态 caption |
| AI 侧降级（DISABLED/UNAVAILABLE/FAILED） | 可见：`st.caption`（`:755-757`），文案见 `src/search_mode.py:66-75`；OK/EMPTY 静默（EMPTY 是刻意设计） |

**不一致**：结果标题由 gate 而非 outcome 驱动——即使 vector 路径完全降级为 lexical，标题仍显示「混合检索结果（已载入 N 条）」（`:752`、`:811-812`、`:1329-1330`），只有小 caption 揭示降级。

### 5.3 provenance 标签

- `result_source`（`src/search_mode.py:52-63`）：双来源→`混合匹配`；vector-only→`语义召回`；lexical-only 或 page_id 不在 meta map→`关键词匹配`（fail-safe 默认可能误标，不省略）。
- 渲染：page view `:992-1004`（`命中字段 / 来源：…`，semantic-only 追加「该结果由语义相似度召回…」并抑制关键词命中计数 caption）；grouped view `:1220-1234`。
- 不向用户暴露 raw rank/cosine/RRF 分数（设计决定）。
- 降级全 lexical 时，页面呈现「混合检索结果」标题 + 全部「关键词匹配」标签的组合。

### 5.4 无结果 / 弱结果表达

- 零结果有 4 原因诊断 + 恢复按钮（有测试）；不可分词查询有 warning（**无测试**）。
- **全系统不存在弱结果/低置信表达**：vector recall 无阈值（测试锁定），UI 无任何结果质量指示。

### 5.5 测试覆盖缺口（UI）

- 降级 note 的实际页面渲染无 AppTest 断言（文案只有单测）。
- `混合匹配`/`语义召回` 标签出现在结果卡片上无 AppTest 断言。
- 「已恢复 AI 混合检索条件，请点击…」恢复提示无断言。
- 标题 vs outcome 不一致无任一方向的测试锁定。
- 跨文档融合、negative query、弱结果信号：无测试（弱结果功能是 greenfield）。

## 七、对 Phase 1B/1C 的直接输入

1. benchmark harness 可以直接复用 `SearchService` / `HybridSearchService` / `PersistentVectorRecallSource` 的真实组装（fake EmbeddingProvider 注入），无需改生产代码。
2. fixture embedding 可用独立 `(model, dimensions, config_version)` 三元组与真实索引完全隔离（SQL 层过滤保证）。
3. 「无相似度阈值」+「无弱结果表达」意味着 negative query 在 hybrid 模式下必然返回某个 Top1——这不是 bug，是必须在 evaluation contract 中单独处理的产品边界。
4. 「融合结果无最终 top-k 上限」与「gate 回退当次静默」「标题-outcome 不一致」是 baseline 阶段需要带出的候选 defect/observation。
5. staging 真实数据（1 doc / 78 pages / 5 fresh embeddings）无法支撑 D（跨文档）与 F（negative）评测——必须由 synthetic corpus 承担。
