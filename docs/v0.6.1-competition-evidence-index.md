# v0.6.1 Competition Evidence Index（比赛证据索引）

制定日期：2026-08-30。用途：**声明 → 证据**快速对照。每条证据记录权威来源、
精确位置、新鲜度与使用许可；报告/答辩引用事实时按 ID 挂钩。

新鲜度状态定义：

- `CURRENT_SOURCE`：当前源码事实（随 HEAD 有效）。
- `CURRENT_DOC`：当前有效文档陈述。
- `FROZEN_BASELINE`：冻结基线记录（内容不再变动）。
- `HISTORICAL_VERIFICATION`：历史执行的验证结果（引用必须带时间与基线限定）。
- `PLANNED_NOT_EXECUTED`：已计划、尚未执行（**不得**表述为已验证）。
- `EXTERNAL_ARTIFACT`：仓库外工件（DR 包等），以只读方式引用。

使用许可：`报告`=可写入书面报告；`答辩`=可口头引用；`限定`=必须带限定词；
`否`=不得使用。

## 使用方法

1. 先在 Fact Pack §21 声明矩阵确定声明的分类与措辞级别，再回到本索引找 EV-* ID。
2. 写报告句子时在句末或脚注挂主证据 ID；答辩口头引用至少记住主证据的"权威来源"列。
3. 一条声明至少一个 `CURRENT_SOURCE` 或 `CURRENT_DOC` 证据；只有 `HISTORICAL_VERIFICATION`
   支持的声明必须带历史限定；只有 `PLANNED_NOT_EXECUTED` 支持的声明只能用计划语态。

## 家族导读（每族证明什么 / 不证明什么 / 更新规则）

### EV-GIT（Git 基线）

- 证明：锚点、冻结点、发布点、提交内容边界的不可变事实。
- 不证明：任何运行时行为质量（那是 EV-CODE/EV-TEST 的职责）。
- 更新规则：Git 历史不可变，一般不更新；新增基线时追加新 ID，不改旧 ID。

### EV-CODE（源码事实）

- 证明：当前代码状态的实现事实（版本、端点、工具、内核语义、演示契约、UI 文案、
  AI 数据边界）；执行时以 `git rev-parse HEAD` 实测为准。
- 不证明：测试通过与否、人工验收结论。
- 更新规则：任何 src/pages 变更后必须复核相关条目；演示语义冻结期应保持稳定。

### EV-TEST（测试证据）

- 证明：自动化测试的存在性与历史执行结果。
- 不证明：未执行过的验证；历史计数不等于新代码的新执行结果。
- 更新规则：新增全量/聚焦执行记录时追加新条目并标执行日期，不得覆盖历史条目。

### EV-DEMO（演示呈现）

- 证明：冻结期望值、口播/截图契约、画面核验记录。
- 不证明：九月战役实际采集的截图（那是 EV-DEMO-05，执行前禁用）。
- 更新规则：截图采集完成后把 EV-DEMO-05 更新为 EXTERNAL_ARTIFACT 并注明目录。

### EV-DOC（文档）

- 证明：仓库文档陈述的当前事实与边界。
- 不证明：文档之间矛盾时谁对——以冻结文档与本 Fact Pack 的一致性核对为准。
- 更新规则：文档修订后复核引用该文档的条目。

### EV-DR（灾备）

- 证明：DR 包的验证结论与工件校验和；空库快照事实。
- 不证明：异地冗余（第二副本 PENDING）；DR 包内容只读，不得修改。
- 更新规则：仅在维护者重建/补副本时由维护者更新。

### EV-QA（人工验收）

- 证明：计划统计（已制定多少用例）与执行状态。
- 不证明：执行结果——执行记录出现之前，任何"已通过"表述都被本索引禁止。
- 更新规则：九月战役每轮会话记录后追加 EV-QA-03… 记录条目。
