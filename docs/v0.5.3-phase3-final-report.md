## 2. AI Provider 接口

```
用户问题 → 检索结果 → ContextItemProjector → KnowledgeContextPackage
        → RagPromptBuilder → CompletionProvider → AuditedAIOutput
```

- Provider **不直接访问数据库**：只接收 prompt 文本（测试断言 provider 无 database 属性）。
- Provider 输入必须是 `KnowledgeContextPackage`；`RagPromptBuilder` 只做格式转换、来源说明、
  引用要求与输出格式约束，不做知识判断、不补知识、不改检索结果。
- 输出进入审计结构：
  - 每次真实调用自动写入 `ai_calls`（Phase 2-A 台账），并按次携带
    `source_feature="rag_answer"` 与 `target_refs=使用知识的 stable_id`；
  - 每次输出返回 `AuditedAIOutput`（output_id/query/context_package_id/provider/model/
    generated_at/answer/citations/warnings/token_usage/context_stable_ids/excluded/confidence）。

## 3. Provider 实现

| Provider | 说明 |
|---|---|
| `MockCompletionProvider` | 离线演示；无网络、无 Key、明确标注"未调用真实 AI 模型" |
| 真实 API Provider | 复用 Phase 2-A 的 Qwen + `AuditedAIProvider`（配置独立，Key 经 `SecretStr`） |

- Provider 异常 fail-safe：`AIUnavailableError`/`AIError` 在 UI 层被捕获并提示，
  **检索功能完全不受影响**；服务层不吞异常、不伪造回答。
- 无 API Key 时 UI 回退到 Mock Provider 并明确标注（离线可演示完整链路）。

## 4. Fail-closed 规则（新增回答链路）

| 场景 | 行为 |
|---|---|
| 空上下文 | `RagPromptBuilder` / `RagAnswerService` 拒绝 |
| 全部知识项无来源 | `RagAnswerError("无来源上下文…拒绝生成")` |
| 部分无来源 | 允许回答，但 `warnings` 明确标注 |
| Provider 缺失 | `AIUnavailableError`（UI 提示，检索不受影响） |
| Provider 调用失败 | 异常上抛，UI 捕获提示，检索不受影响 |

## 5. UI 第一阶段（`pages/4_检索资料.py`）

- 页面检索与个人知识检索两个 scope 均新增 **Ask AI（受控回答）** 区域。
- 展示：AI 回答、引用映射（`#N → stable_id`）、使用的知识（上下文范围）、Warning、
  排除项（AI 未使用的内容与原因）、模型/生成时间/Token 用量。
- 不是聊天机器人：单次提问、单次回答、无会话记忆、无自动选择。
