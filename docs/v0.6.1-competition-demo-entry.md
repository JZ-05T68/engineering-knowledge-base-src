## Product Goal

v0.6.1 不增加新的 Agent 能力，而是把已有能力变成评委在 3–5 分钟内
**能看懂、能相信、能记住** 的比赛演示产品。

突出 EKB 是 Engineering Knowledge Base，不是普通聊天机器人：

- 答案必须可回源（grounded + citations + source viewer）；
- 系统能判断来源是否可靠（integrity / warnings）；
- 无依据时诚实说"没有资料"，失败时诚实失败，不伪装成功。

## Backend/Public Contract Inventory

**以下契约本轮冻结（frozen），前端只依赖它们，不改后端架构：**

### `POST /v0.6/agent/run`（Mode 1 真实链路）

- 请求：`{"text": string, "correlation_id"?: string}`；correlation_id 匹配
  `^[A-Za-z0-9._-]+$`，≤128 字符；成功时从 `X-Correlation-ID` 响应头回显。
- 成功响应 `AgentRunResponse`：`request_id, status("completed"|"failed"), answer,
  grounded(bool), citations(string[]), warnings(string[]), error(null|{code,message})`。
- HTTP 失败 `HTTPFailure`（413/422/429/503/500）：`request_id, status:"failed",
  error:{code,message}`；错误码与文案为封闭目录（`public_error`）。
- 语义必须同时检查：HTTP 状态、业务 `status`、`grounded`、`error`。
  `200 + grounded=false` 是合法的"无证据完成"，不是成功答案；
  `200 + status=failed` 是业务失败，必须展示失败状态。

### `GET /v0.6/sources/{stable_id}`（来源元数据）

- 响应 `SourceResponse`：`stable_id, type(page|knowledge_object|knowledge_memory|
  evidence), title(string|null), label(string|null)`；title/label 可为 null。
- 仅元数据：无正文、无 excerpt、无文件路径、无下载 URL、无指纹 payload。
- 错误：422 invalid_source_id / 404 not_found / 429 / 503。

### stable_id 语法

`<kb_uuid>:<type>:<local_id>`（小写 hex UUID / snake_case 类型 / 正整数）。
ID 不是文件路径，不得当作路径展示或解析。

### 已知公开契约缺口（本轮明确记录，不在本轮擅改）

1. **citation display index / anchor label 未公开**：HTTP `citations` 只保留已校验
   stable_id 集合（first-seen order），不保留 `#N` 编号映射，也没有 anchor label。
   Mode 1 前端只能渲染"独立已验证来源列表"（citations 数组逐项 `/sources` 查询），
   **不得猜测正文 `#N` 与数组序号的对应关系**。正文可点击 `#N` 映射仍属 P1
   （原 DEMO-03），需先经显式安全映射契约评审。
2. **来源完整性状态未公开**：真实 API 的 warnings 被投影为统一文案
   "来源存在限制，请核对引用资料。"；`/sources` 无指纹状态字段。Mode 1 不能显示
   "已篡改/已验证"级别结论。Per-source integrity 徽标是候选 hosted contract 扩展，
   需 maintainer + DeepSeek 评审后才可进入真实 API。
3. **无 trace / 无 SSE**：Agent 内部 decision/tool 过程不公开，也不应伪造（见下文
   Agent Activity Presentation）。

## Citation Contract

演示 UI 对 citation 的 P0 要求（不修改 backend）：

- 以 `AgentRunResponse.citations` 为**独立已验证来源列表**，顺序即数组顺序；
  每项 stable_id 通过 `GET /v0.6/sources/{stable_id}` 补全 `type/title/label`；
- 展示标题时必须容忍 `title=null / label=null`（回退为 stable_id 短格式展示）；
- `/sources` 404/429 时，答案展示与来源加载状态分离：显示"该来源暂时不可检查"，
  不隐藏答案、不猜测替换来源；
- **Mode 2（mock）专用增强**：mock 响应携带 `citations_detail`（含 display_index、
  anchor_label、title、label），使正文 `#N` 在 mock 模式下可以正确点击。该字段是
  demo 扩展（`DemoAgentRunResponse` 是 `AgentRunResponse` 的校验过的超集），Mode 1
  真实链路没有该字段，前端必须按"字段缺失 → 回退列表渲染"实现。

## Agent Activity Presentation

后端没有公开 trace，也不允许为了动画开放。演示 UI 只能做
**coarse-grained deterministic presentation states**：

- 已提交 → 正在等待服务响应 → 返回结果（答案/无证据/失败）→ 来源加载中/完成。

"正在理解问题 / 正在检索知识 / 正在核对依据 / 正在生成回答" 若要使用，必须实现为
纯前端的进度演示动画，并满足：

- 不得声称真实暴露逐步 chain-of-thought 或真实工具调用事件；
- 在返回前不得声称"检索完成/指纹核对完成"等未经上报的事实；
- 代码与文档中明确标注这是 presentation 状态，不是内部推理 trace；
- 禁止生成 fake chain-of-thought、fake model reasoning、fake Tool trace 文本。

模式切换规则：

- mock 必须有清楚的 demo/dev semantics；**真实请求失败后不得自动伪装成真实成功答案**；
- 请求代次（correlation_id/请求序号）必须随结果保留，晚到响应不得覆盖新题或 mock 结果；
- 运行中禁止重复提交。

## Security / Privacy Boundaries

- 本轮全部演示内容为 synthetic sanitized fixture；不使用生产 `data/database/knowledge.db`，
  不从生产 DB 生成语料，不提交 DB/源材料到 Git；
- 实际比赛语料的人工批准（内容/版权/隐私）仍 PENDING（v0.6.0 RC-02/03 独立进行）；
  mock fixtures 的文案是占位演示内容，不冒充已批准语料；
- API key 不进前端浏览器、不进 fixtures、不进日志；mock 无 env/network 依赖；
- 不暴露：内部 trace、ToolResult、Decision、token usage、provider response、
  filesystem path、raw SQL、private absolute path；
- Local Streamlit 仍绑定 127.0.0.1:8501（`.streamlit/config.toml` 不改）；Local UI 与
  Hosted FastAPI 是两套入口，不得互相回退或耦合；
- 不恢复 Zeabur / WP6B / 公网 Agent；不登录平台、不购资源、不上传语料、不配真实 key。

## Testing Strategy

`tests/test_demo_contract.py` focused tests 覆盖：

1. fixture schema compatibility（每个 mock 响应可被真实 `AgentRunResponse` /
   `SourceResponse` 校验；error 来自封闭目录）；
2. citation rendering mapping（citations_detail 与 citations 一一对应、display_index、
   anchor/title/label 一致、stable_id 合法）；
3. source lookup mapping（get_source 元数据与 citation detail 一致；未知 id 报
   not_found；knowledge_source 类型不可解析为来源详情）；
4. success/partial/failed/empty 状态语义；
5. mock determinism（同输入逐字节一致；未知问题 → empty）；
6. no-network / no-env / no-DB 行为（socket 禁用 + env 哨兵下运行不变）；
7. preset 完整性（3 主 + 2 备 + 1 排练；期望来源与 fixture 一致；问题唯一）；
8. real-vs-mock separation（`mode="mock_demo"` 恒定；demo 专用字段缺省 None；
   `src/demo/` 不 import src.runtime / src.database / src.hosted（组合根）/
   src.ai / streamlit / 网络库；`src.hosted_api` 冻结 DTO 允许复用）；
9. JSON 快照与代码 fixtures 同步（重新导出 == 提交文件）。

本轮仅 fixtures/mock/docs（无 backend contract 改动）→ focused regression 足够；
若后续改动 hosted 契约则必须 full pytest。
