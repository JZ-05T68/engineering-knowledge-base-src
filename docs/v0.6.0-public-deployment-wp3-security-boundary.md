Explicit constructor injection may use tuples/lists for allowlists. Comma-separated

it never becomes trust-all or a Local fallback. New fields use init/env only,
retain WP1's disabled dotenv source, and do not introduce a token/credential field.
AI SecretStr remains excluded from repr and masked in serialization.

## Client-IP Authority

`src.hosted.security.effective_client_ip` uses the ASGI immediate peer by default.
Forwarded and X-Real-IP are always ignored. X-Forwarded-For is considered only
when the immediate peer belongs to an explicit trusted network.

IP keys use canonical address strings, including canonical IPv6 spelling;
IPv4-mapped IPv6 keys share the IPv4 bucket. Invalid/missing peers share a fixed
`unknown-peer` bucket, never a fresh bucket derived from arbitrary input.
Scope IDs are rejected. No IP, peer port or forwarded header is returned or logged.

## Trusted Proxy Model

For an explicitly trusted immediate peer:

1. Require exactly one XFF header value; duplicates fall back to direct peer.
2. Bound parsing to 4,096 bytes and 32 hops. Reject controls/non-ASCII/invalid IPs.
3. Validate the complete bounded chain, then traverse right to left.
4. Skip trusted proxy hops and select the first untrusted address.
5. An invalid, missing, oversized or entirely trusted chain falls back to direct peer.

An untrusted peer cannot rotate its quota using forged XFF/Forwarded/X-Real-IP.
A forged address left of the first untrusted hop is not authoritative. Operators
must allowlist actual immediate proxies, not arbitrary public networks.

**Deployment prerequisite for WP5:** the application assumes `scope.client` is
the transport peer supplied by the ASGI server. An outer server proxy-header
rewriter must not replace it using a broader trust policy before WP3 sees it.
Disable such rewriting or explicitly preserve this peer-authority contract in
server/edge composition. WP3 does not add a Uvicorn production command or cloud
proxy configuration; middleware cannot reconstruct a peer already discarded by
an upstream component.

## Agent Rate Limit

`RateLimiter` uses 60-second windows anchored at the first admitted request for
each `(category, effective IP)` key. Requests 1..N are allowed; N+1 returns 429
`rate_limited` with integer Retry-After >=1. Rejections do not extend the window.
At expiry the next request starts a new window. This is a fixed window, not a
sliding-window or token-bucket guarantee.

Default Agent quota is 10 POST requests/min/IP. The middleware runs before body
parsing, DTO validation, readiness, semaphore admission or Agent calls. Malformed
JSON/extra fields and body rejection still consume admission quota. No retry or
application dependency call occurs on a rate rejection.

Rate classification follows router root_path semantics, including server-mounted
prefixes, so a valid mounted route cannot escape rate classification. Server
root_path is not read from a client header.

## Source Rate Limit

Default source quota is 60 GET requests/min/IP, separate from the Agent category.
The source namespace is counted before stable-ID validation, including invalid
and missing identifiers. An over-limit call never reaches the metadata reader.
Existing invalid-ID/not-found semantics remain unchanged when under quota.

Health and readiness are exempt; OPTIONS does not consume either business quota.
No per-source ID bucket or persistence is introduced.

## Request Body Byte Limit

`IngressSecurityMiddleware` is pure ASGI. The limit is exactly **512,000 bytes**,
including JSON envelope/whitespace, not 512 KiB and not a text-character count.
The independent existing AgentRequest limit remains 120,000 characters.

- A clearly numeric Content-Length above the cap is rejected before receive.
- Missing, understated or malformed Content-Length cannot bypass actual counting.
- Each http.request chunk is checked before appending to a bounded accumulator.
- On overflow, return safe 413 `request_too_large`, stop receiving further body
  chunks, and never invoke the downstream router/DTO/readiness/Agent.
- On acceptance, release the mutable accumulator and hand off the accepted bytes
  once through receive. No BaseHTTPMiddleware or Request.body() middleware read
  is used; no second full-body parser/consumer exists in the middleware.
- The accumulator never contains more than 512,000 bytes. The bytes handoff has
  bounded transient copy overhead; an ASGI server may itself supply a large chunk,
  but an overflowing chunk is not copied into an application body buffer.
- A disconnect before completion does not start business execution.

This bounded pre-parser admission also checks bodies on routes that would not
normally consume them (including GET). Ordinary bodyless GET requests are
unchanged. This controls per-request bytes, not connection count, header size or
slow-client timeouts; those remain server/edge deployment responsibilities.

## Agent Concurrency Admission

Each app owns a `threading.BoundedSemaphore`, default 4 permits, configured 1..8.
The route first performs WP2 validation and readiness. Immediately before
`SingleStepAgentService.run`, it calls acquire(blocking=False). A full semaphore
returns HTTP 429 `concurrency_limited` without calling Decision/Tool/Final/provider.

Only actual synchronous Agent execution holds a permit. A try/finally releases it
on success, returned FAILED outcome or exception, before response projection.
There is no semaphore wait, application queue, background execution, retry or
fallback provider. Existing ASGI/framework thread-pool scheduling is not replaced.

## CORS Policy

Standard Starlette CORSMiddleware uses explicit origins, default empty, exact
matching and allow_credentials=False. HTTPS origins are supported; explicit HTTP
loopback origins are allowed for development. Wildcard/null/scheme-less/file
origins, credentials, paths (including a trailing slash), queries, fragments,
wildcard subdomains, controls and malformed hosts/ports fail configuration.

- Allowed methods: GET, POST, OPTIONS.
- Configured request header: Content-Type. Starlette additionally includes the
  standard CORS safelist Accept, Accept-Language and Content-Language.
- Exposed response header: X-Correlation-ID only.
- No wildcard origin/header grant and no credential flag.

Allowed preflight is handled by CORSMiddleware before rate/body/DB/readiness/Agent.
Disallowed preflight keeps standard 400 CORS behavior. Disallowed simple requests
may execute, but receive no matching Access-Control-Allow-Origin; that is normal
CORS behavior, not an authentication bypass. Allowed-origin 413 and both 429
variants retain the exact CORS allow header.

## Middleware Ordering

FastAPI add_middleware prepends; the factory deliberately registers in reverse.
Observed and tested effective user-middleware order:

```text
RequestIdentityMiddleware (fresh server UUID4)
  -> CORSMiddleware
    -> IngressSecurityMiddleware
       effective peer -> rate -> declared/actual body byte admission
      -> WP2 route / strict DTO / existing AgentRequest
        -> Hosted readiness
          -> non-blocking Agent permit
            -> existing SingleStepAgentService.run
          -> finally release
        -> existing explicit public response projection
```

The middleware class order and observable precedence are tested: the first
oversized request can return 413, while a subsequent over-quota request returns
429 without body processing; both retain CORS and distinct server request IDs.

## Public Error Semantics

Only three codes were added to the existing closed PublicError catalog:

| HTTP | Code | Meaning |
| --- | --- | --- |
| 413 | request_too_large | received/declared request body above the byte cap |
| 429 | rate_limited | request-frequency quota or bounded active-key capacity exceeded |
| 429 | concurrency_limited | all Agent execution permits occupied |

`src.hosted_api.errors.failure_response` shares the WP2 envelope and catalog
between routes and ASGI middleware: request_id, status=failed, error{code,message}.
No exception detail, prompt, settings, raw header, IP chain or secret is serialized.
Unexpected pre-response security exceptions become sanitized 500 internal_failure;
fixed logs contain only request_id and category, without traceback/exception repr.
Already-started responses are not rewritten into a second response.

WP2 Agent COMPLETED/FAILED remain HTTP 200 when the pipeline returns normally.
No internal trace/token_usage/model/context_stable_ids/error.detail is exposed.

## Thread Safety

The limiter lock covers monotonic clock/window arithmetic and bounded in-memory
updates only. It is never held during Agent, DB, network or body receive work.
Threaded tests prove exactly N admissions for one shared key under contention.
The semaphore is the standard synchronous thread-safe primitive; deterministic
Event-based HTTP tests fill four permits, reject the fifth before release, then
prove subsequent requests can execute. No sleep-based concurrency simulation.

## State Isolation

Every factory invocation constructs its own limiter and semaphore. No module
singleton or persistent state is used. The factory optionally accepts a trusted
`security_clock` callable for deterministic tests; clients cannot supply it.

Windows contain a count and expiry, not per-request history. Expired keys are
removed on admission or explicit prune; rejected requests do not refresh expiry.
An additional fixed cap of 10,000 active category/IP keys bounds burst memory.
At capacity, a new key receives 429 until an existing window expires; live
buckets are not evicted/reset. No background cleanup thread or DB is needed.
Two-app tests prove that one app's occupied permits and exhausted quota do not
affect another app.
