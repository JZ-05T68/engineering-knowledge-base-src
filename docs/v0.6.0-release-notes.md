# EKB v0.6.0 — Agent Foundation（Release Notes）

- 状态：v0.6.0 发布候选（Release Candidate）；发布时作为 GitHub Release `v0.6.0` 正文。
- 版本定位：在 v0.5.3 可审计 AI 接入之上，建立 Agent Foundation 与托管部署基础。
- 发布窗口：2026-08-29 ~ 2026-08-30（维护者目标；以实际发布日为准）。

## 概述

v0.6.0 引入本地单步只读 Agent 与受控 HTTP 服务入口，为后续个人经验 Agent 打底。
Agent 一次请求内只能完成一次决策、至多一次只读工具调用和一次最终回答；一切写能力、
多步循环与自主重试都被排除在外。公开 HTTP 合同冻结，错误使用封闭文案目录，
内部对象不外泄。

**公开部署范围变更（2026-08-28 维护者决策）：** 原 v0.6.0 规划要求实际公网部署完成
方可发布。维护者现已变更发布标准，实际公开暴露从 v0.6.0 发布门槛推迟（DEFERRED）。
这是发布 scope 决策，不是部署验收结论：WP6A 仍为 PARTIAL / PAUSED，WP6B 仍未启动，
本版本不包含、也不声称任何公网部署完成。

## 亮点

- 单步只读 Agent：Decision → 0/1 Tool → Final Answer，无循环、无自主重试；
- 7 个 READ_ONLY Tool 覆盖页面检索、知识检索、对象/记忆读取、来源与完整性检查；
- Final Answer 只基于 Tool 证据生成，引用校验 fail-closed；
- 来源完整性语义：valid / changed / missing / unknown，过期来源不静默充当可靠事实；
- Hosted HTTP Agent API（/health、/ready、/v0.6/agent/run、/v0.6/sources）与冻结公开 DTO；
- Hosted 安全边界：限流、并发、请求体上限、CORS 精确来源、预算拒绝、错误净化；
- Hosted SQLite 存储安全：schema v12 exact 校验、链接/sidecar 拒绝；
- Linux 容器与 non-root（UID/GID 10001）打包；
- 无 API Key 时全部离线基础功能保持不变，本地运行端点不变。

## Agent Foundation

```text
用户请求 → AgentRequest
        → Decision（≤1 次结构化决策）
        → 0/1 个 READ_ONLY Tool（Registry 策略强制只读）
        → Final Answer Stage（rag_answer，非 Tool）
        → 引用校验（fail-closed）→ AgentResponse
```

- Agent 自主重试 = 0；引用修复重试 = 0；没有多步规划、循环或 agent loop。
- 决策、工具与最终回答各 ≤1；逻辑模型调用合计 ≤2。
- 运行 trace 仅存进程内存：不落库、不写文件、不进入日志或响应。
- 7 个 READ_ONLY Tool：`page_search`、`knowledge_search`、`get_knowledge_object`、
  `get_knowledge_memory`、`inspect_provenance`、`inspect_source_integrity`、`get_evidence`。
- Registry 只允许 READ_ONLY；未知、越权或非只读工具 fail-closed。
- `rag_answer` 是 Final Answer Stage 而非 Tool：最终回答只能基于 Tool 证据与
  KnowledgeContextPackage 生成；无证据时诚实返回"未找到可支持资料"，
  不编造答案或引用。
- 引用校验复用 v0.5.3 既有运行时校验：未知、伪造、越界和空引用一律 fail-closed。

## 来源完整性

- `inspect_source_integrity` 只读取已捕获的来源指纹状态，不刷新、不重算、不写库。
- 状态语义：`changed` 表示来源快照与记录指纹不一致，`unknown` 表示无法充分确认；
  都不等于"造假"，也不自动触发任何修复。
- 读取路径不产生隐藏写入；指纹重采仍是显式的人工操作。

## Hosted 部署基础（WP1–WP5）

- WP1 Runtime Profile：独立 Hosted 运行档；禁止与 Local 运行时混用或自动回退。
- WP2 HTTP Agent API：`/health`、`/ready`、`POST /v0.6/agent/run`、
  `GET /v0.6/sources/{stable_id}`；公开 DTO（`AgentRunResponse`、`SourceResponse`、
  `HTTPFailure`）冻结；错误文案封闭目录；不暴露内部 trace、ToolResult、token 用量
  或模型原始响应。
- WP3 安全边界：限流与并发上限、请求体上限、CORS 精确来源、预算拒绝、空代理信任
  默认；错误净化，密钥不进入日志、响应或测试快照。
- WP4 存储安全：独立 Hosted SQLite 引导、schema v12 exact 校验、符号链接与 sidecar
  拒绝；不读写 Local 生产数据库。
- WP5 部署打包：Linux 容器与 non-root（UID/GID 10001）运行时打包，集成测试通过；
  云上实际部署验证保持 PAUSED。

  AI key 有效或模型调用成功。

## 数据与 schema 兼容

- 应用版本推进至 0.6.0；数据库保持 **schema v12**，不新增 migration。
- v0.5.x 用户数据无需任何转换；升级只改变应用版本展示与新增能力。
- 正式恢复仍只接受与当前版本兼容且同为 schema v12 的完整备份。

## 离线行为

- AI 默认手动模式（`ai_mode="manual"`）；无 API Key 时应用可启动，全部离线基础功能
  （导入、检索、阅读、笔记、证据、删除/恢复、备份）完整可用。
- Agent 能力不改变既有本地工作流；未配置 AI 时 Agent 相关服务不可用是预期行为，
  不是功能退化。

## 安全与隐私边界

- Agent 无任何写能力；不能修改、删除或覆盖用户资料与知识资产。
- HTTP 层不公开内部 trace、ToolResult、Decision 对象、token 用量、provider 响应、
  文件系统路径或内部数据库主键。
- API key 只通过服务端环境变量读取；不进入前端浏览器、日志、备份或测试快照。
- 无注册、登录、账号、多用户或云同步；正式 Local 服务固定绑定 `127.0.0.1:8501`。
