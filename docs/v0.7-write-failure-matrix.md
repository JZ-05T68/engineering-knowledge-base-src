- **关联：** `docs/v0.7-personal-experience-agent-architecture-prestudy.md`（架构主文档）、

## 0. 边界前提（继承 ADR-010/011，不由失败处理放宽）

写入是 Agent Tool Registry 之外的确定性 WriteCommand；现行七个 Tool 保持
`READ_ONLY`，single-step Agent 不变。Personal Experience 复用
`knowledge_memory_entries(kind=experience)`；草稿 session-only，批准绑定精确
`approved_draft_sha256`。Local-only 写、Hosted READ_ONLY；无持久聊天、无多步 autonomous
mutation，prompt/来源/模型内容的 write authority 为零。成功命令必须把经验、来源、FTS、
审计和持久幂等结果原子提交；undo/restore 使用 schema v13 tombstone，不 hard purge。

## 1. 错误分类（按域分组；名称为概念名，实现时沿用各域 `XxxError` 风格）

### 草稿域（draft — 全部发生在会话内，零持久化）
| 错误 | 触发 | 用户语义 | 可重试？ |
| --- | --- | --- | --- |
| `DraftValidationError` | 必填缺失（title/outcome）、长度超限、区块结构非法 | "草稿不完整：请填写/缩短…" | 是（编辑后） |
| `ProviderFailure` | 草稿模型调用失败（网络/5xx 等，经 transport ≤2 后仍失败） | "AI 服务暂不可用，可稍后重试" | 是 |
| `BudgetFailure` | 预算门拒绝（AIUnavailableError 家族） | "AI 调用被预算限制拒绝" | 否（预算期） |
| `DraftAbandoned` | 用户取消/刷新 | （静默，草稿随会话消失） | — |

### 批准域（approval — 会话内一次性）
| 错误 | 触发 | 用户语义 | 可重试？ |
| --- | --- | --- | --- |
| `ApprovalMissing` | 提交时无批准令牌（未确认就提交/UI 异常） | "请先确认草稿" | 是（确认后） |
| `ApprovalMismatch` | 提交载荷哈希 ≠ approved_draft_sha256（批准后草稿被改） | "草稿已变化，请重新确认" | 是（重新确认） |

### 命令域（commit — 应用服务 + DB）
| 错误 | 触发 | 用户语义 | 可重试？ |
| --- | --- | --- | --- |
| `IdempotencyConflict` | 同幂等键 + 不同 payload_hash | "保存请求异常：键被复用，请刷新后重试"（bug 信号） | 否（须换键=新请求） |
| `AlreadyCommitted` → **重放成功**（非错误） | 同键 + 同 payload_hash | "已保存（重复请求已忽略）" + 原 stable_id | — |
| `SourceReferenceInvalid` | 提交事务内链接目标不存在/类型不支持 | "引用的资料已失效：…"（指出具体引用） | 是（移除失效引用后） |
| `StorageUnavailable` | DB 锁超时 / 事务前错误 / 事务内错误（含审计写失败） | "保存失败，未写入任何数据，请重试" | 是（同幂等键） |
| `WriteNotAllowed` | 命令类型不在 allowlist | （架构上不可达；触达即 bug） | 否 |

**TD-06 状态更新（2026-08-30）**：提案链路的子串错误分类已完成类型化改造并落地
（commit `d6c4022`：`AIBudgetExceededError`、`RagAnswerErrorCode`、FinalAnswerStage
按 type/code 映射）；`BudgetFailure` / `ProviderFailure` 语义现可结构化流转到写 UI，
不依赖消息文本匹配。本域错误名仍为概念名，实现沿 TD-06 确立的"域基类 + 闭合 code
枚举"模式（见 `docs/v0.7-post-remediation-readiness-review.md` §5/§25）。

## 2. 状态机

### 2.1 会话内（草稿）状态 —— 不持久化
```
idle ──生成草稿──▶ drafting ──成功──▶ draft_ready
  ▲                  │失败(Provider/Budget/Validation)     │
  │                  ▼（回 idle，附原因）                  ▼
  │                                            editing ◀──用户编辑──┘
  │                                                │
  │                                                ▼（内容定稿，计算哈希）
  │                                            approval_ready
  │                                                │ 用户点击确认（一次性令牌）
  │                                                ▼
  └────────────────────────────────────────── saving
```

### 2.2 持久化状态（已提交实体：`knowledge_memory_entries.status`）
```
                ──提交成功──▶ active ──undo──▶ deleted ──restore──▶ active
   （v0.7 前状态）              ▲                                  │
                                └──────────── 用户手改（既有 update_entry）────┘
```
- `APPROVED` 不持久化：批准是会话内一次性人类意图（令牌消费即消失）。
- 非法迁移：`deleted → deleted`（重复 undo：幂等重放/已是墓碑的提示）；
  `saving → saved` 之外的任何落库路径（不存在无命令日志的写入）；
  未批准 → 任何持久状态。

### 2.3 失败迁移
| 从 | 事件 | 到 | 持久化副作用 |
| --- | --- | --- | --- |
| drafting | 模型失败/预算拒绝/校验失败 | idle 或 editing（保留已填内容） | 无 |
| approval_ready | ApprovalMismatch | editing | 无 |
| saving | 事务失败（StorageUnavailable） | editing（草稿保留） | 无（事务回滚，含审计/幂等行） |
| saving | 成功 | saved | 经验行+链接+审计+幂等行 |
| saved | 幂等重放 | saved（重复提示） | 无新行 |
| saved | undo 失败 | saved + 错误提示 | 无 |
| saved | undo 成功 | undo_available（→ undone） | status='deleted' + 审计行 |

## 3. 失败矩阵（规格 §45）

列：**前置状态 | 操作 | 期望结果 | DB 效果 | 用户消息 | 允许重试 | 幂等行为 | 审计行为**

| # | 前置状态 | 操作 | 期望结果 | DB 效果 | 用户消息 | 重试 | 幂等行为 | 审计 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | draft_ready | 生成草稿时模型不可用 | 回 editing/idle + 原因 | 无 | "AI 服务暂不可用" | 是 | 不适用（未到命令） | 无（AI 账本照常记账 error，hash-only） |
| 2 | draft_ready | 生成草稿被预算拒绝 | 同上 | 无 | "被预算限制拒绝" | 否（预算期） | 不适用 | 账本记 rejected/budget |
| 3 | draft_ready | 模型返回非法草稿（解析失败） | 回 idle + 原因 | 无 | "无法生成有效草稿，可手动填写" | 是 | 不适用 | 账本记 error（parse） |
| 4 | draft_ready | 用户取消 | 回 idle | 无 | （静默） | — | 不适用 | 无 |
| 5 | approval_ready | 提交时批准令牌缺失 | 拒绝，回 editing | 无 | "请先确认草稿" | 是 | 不适用 | 无 |
| 6 | approval_ready | 批准后草稿被改再提交 | 拒绝（ApprovalMismatch） | 无 | "草稿已变化，请重新确认" | 是 | 不适用 | 无 |
| 7 | editing | 提交前某来源被删除 | 拒绝（SourceReferenceInvalid），指出具体引用 | 无（预检或事务内校验回滚） | "引用的资料已失效：…" | 是（移除失效引用） | 不适用 | 无 |
| 8 | saving | DB 锁超时（并发写） | 失败，草稿保留 | 无（未进入事务） | "保存失败，请重试" | 是 | 不适用 | 无 |
| 9 | saving | 事务开始前 DB 错误 | 同 #8 | 无 | 同上 | 是 | 不适用 | 无 |
| 10 | saving | 事务中途 DB 错误 | 整笔回滚（经验+链接+FTS+审计+幂等行） | 无残留 | "保存失败，未写入任何数据" | 是（同键） | 键未入库→正常首写 | 回滚=无审计行（应用日志留痕） |
| 11 | saving | **commit 成功、响应丢失** | 重试→重放原结果 | 首次已提交；无第二条 | "已保存（重复请求已忽略）"+stable_id | 是（同键） | 同键同哈希→重放 | 首次审计行即为全部记录 |
| 12 | saved | 同键重复提交 | 重放成功 | 无新行 | 同 #11 | — | 重放 | 无新审计行 |
| 13 | saved | 同键不同内容提交 | 拒绝（IdempotencyConflict） | 无 | "保存请求异常，请刷新重试" | 否 | 冲突检测 | 无（bug 信号，应用日志） |
| 14 | saving | 审计写失败 | **整笔回滚**（同事务） | 无 | "保存失败，未写入任何数据" | 是 | 键未入库 | 不存在"无审计的成功写" |
| 15 | saving | FTS 触发器失败 | 整笔回滚 | 无 | 同 #10 | 是 | 同 #10 | 同 #14 |
| 16 | saved | undo 失败（DB 错误） | 状态不变 | 无 | "撤销失败，请重试" | 是 | undo 命令亦幂等（操作键） | 回滚=无 |
| 17 | saved/undone | 备份/恢复后重试旧命令 | 重放原结果或如实"条目已不存在"（恢复点早于提交时） | 无新行 | 相应提示 | — | 日志随库恢复，语义自洽 | 随库恢复 |
| 18 | saving | UI rerun / 刷新发生在提交期间 | 会话重建后命令未重发→草稿丢失提示；若命令已发出，后端照常完成或失败 | 按实际事务结果 | "页面已刷新；请检查知识记忆页确认是否已保存" | 是（先查记忆页/按键重放） | 命令若已提交→重放；未发出→无影响 | 随事务 |
| 19 | saved | 备份创建失败（与写无关的运维失败） | 写不受影响 | 写已提交 | （备份页提示） | 运维层 | — | — |
| 20 | approval_ready | 提交前被"支持"关联的来源**未删除但内容漂移**（提交时重算指纹 ≠ 批准载荷中的指纹快照） | 拒绝（SourceReferenceInvalid·陈旧），指出具体引用 | 无（事务内校验回滚） | "引用的资料已更新，请重新审阅后确认" | 是（重新审阅/重新批准） | 不适用 | 无 |
| 21 | saved/undone | undo/restore 目标资格不符（无 create 命令日志行 / restore 目标非墓碑） | 拒绝（typed validation），零副作用 | 无 | "该条目不在可撤销范围内" / "该条目不在可恢复范围内" | 否（资格为静态事实） | 不适用 | 无 |
| 22 | approval_ready | 支撑关联提交时新鲜度证明不可用（目标未删未变，但指纹无法计算/revision 缺失——"无法校验"） | 拒绝（SourceReferenceInvalid·无法校验），指出具体引用 | 无（事务内校验回滚） | "引用的资料暂时无法校验，请移除或更换后重试" | 是（移除/更换引用后重试） | 不适用 | 无 |

**矩阵要点**：①没有任何路径能产生"无审计的成功写"；②没有任何路径能产生第二条
同键经验；③一切事务内失败对用户呈现为"未写入任何数据"且真实如此；④commit-unknown
由持久幂等日志闭环（#11）。#20/#21 为 2026-08-30 复审增补（来源指纹陈旧防护与
undo/restore 资格判定）；#22 为 N-6 关系语义更正增补（支撑关联的新鲜度证明不可用）。
关系语义其余失败面映射入既有行，不另立新行：**批准后改动 relation_kind**（它参与
批准哈希）= #6 ApprovalMismatch；context 引用提交前被删 = #7；无效 relation_kind /
歧义双关系 = 草稿域 validation（#3 同族）。依据见
`docs/v0.7-post-remediation-readiness-review.md` §16/§20/§25 与
`docs/v0.7-controlled-write-schema-detailed-spec.md` §0/§10/§12/§13；
既有行 #1-#21 编号与语义不变。

## 4. 幂等精确语义（规格 §14/§15 的规范定义）

- **键生成**：UI 在命令首次构造时生成 `uuid4`，保存于会话；重试（确认对话框、按钮
  重发）复用同键；用户主动"再次沉淀"= 新草稿 = 新键。
- **唯一约束**：`experience_command_log.idempotency_key UNIQUE`。
- **插入协议**：`INSERT … ON CONFLICT(idempotency_key) DO NOTHING` →
  冲突时 SELECT 既有行 → 同 `payload_sha256`：返回既有 `target_stable_id`（重放）；
  异 `payload_sha256`：`IdempotencyConflict`。同一事务内完成（§主文档 §11）。
- **成功重放返回**：`{status: "duplicate_replay", experience_stable_id, first_committed_at}`。
- **保留**：append-only，永不清理（行小；兼具审计职能）。
- **禁止**：以 AI 生成值、内容哈希、时间戳派生值作为唯一幂等权威。
