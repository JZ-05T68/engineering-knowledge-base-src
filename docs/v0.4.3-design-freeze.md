## 6. Evidence Validity Semantics（冻结语义）

**没有 persisted validity state。**

数据库不保存 valid / invalid 状态。validity 是在导出、追溯、指纹计算等使用点按需执行的 source validation：

- 文档/页面记录存在、页归属一致、页码未漂移且在范围内
- 原始 PDF 文件存在于磁盘
- 页 PNG 文件存在于磁盘
- text_selection：当前页源文本 hash 必须等于快照 `source_text_sha256`
- image_region：当前页 PNG SHA-256 必须等于锚定值，且坐标仍在界内
- page：仅做存在性校验（页文本编辑不会使整页证据失效，为设计意图）

任一校验失败 → 抛出 `EvidenceSourceError`，fail closed。不得把该语义错误描述为"数据库保存有效/无效状态"。

## 7. Severity Model（冻结）

- **BLOCKER**：数据损坏；原始资料被错误修改/删除；stale Prompt 被当作 fresh 使用；unconfirmed evidence 进入最终 Prompt；evidence 指向错误来源；citation/source 身份错配；source validation 可被正常工作流绕过；已知 invalid confirmed evidence 仍生成完整 Prompt；无法判断 Prompt 中事实来自哪个来源。
- **HIGH**：关键 evidence 无法可靠回原页；多文档证据来源混淆；invalid evidence 被静默忽略；图片区域被包装成不存在的文字事实；user note 被表达为 source fact；freshness 明显漏判；正常真实流程无法完成且无合理 workaround。
- **MEDIUM**：真实流程明显摩擦；UI 语义不清但不导致错误 grounding；环境/文档约定漂移；有人工 workaround 的非完整性问题。
- **LOW**：cosmetic；文案轻微问题；不影响真实性、追溯性、数据安全的小问题。
- **OBSERVATION**：非严重程度附记（HD-05 批准）。OBSERVATION 不能覆盖正式 severity；凡实际影响 grounding integrity / source traceability / data safety / workflow completion 的问题，必须分配 BLOCKER/HIGH/MEDIUM/LOW。

## 8. Human Gate（H1-H7，Kimi 不得代签 PASS）

- **H1**：一个真实工程问题从检索到 Prompt Package 的完整闭环。
- **H2**：至少一个跨文档问题。
- **H3**：Prompt evidence → 原始页人工追溯。
- **H4**：用户笔记与 source fact 能否被真人清楚区分。
- **H5**：stale Prompt 真人体验。
- **H6**：Prompt Package 复制给外部 AI 后，用户能否理解并检查 grounding 内容。
- **H7**：整体工作流是否已足够支撑进入 v0.5.x。

Kimi 可以准备步骤、启动隔离实例、生成测试记录模板、收集机器证据，但不得写 "HUMAN PASS"，除非收到真人明确结果。

## 9. v0.5.0 Decision Rules（冻结）

### A. V0.5.0 GO

- BLOCKER = 0
- HIGH = 0
- Mandatory automated gates PASS
- Mandatory Human Gates（H1-H7）PASS
- source traceability PASS
- confirmed boundary PASS
- fail-closed PASS
- stale guard PASS
- real multi-source workflow PASS
- no unresolved data-safety concern

### B. V0.5.0 CONDITIONAL GO

只允许存在明确记录、不破坏 grounding integrity / source traceability / data safety 的 MEDIUM / LOW debt。必须逐条列出：debt、impact、workaround、why non-blocking、target future version / candidate。不得用 CONDITIONAL GO 绕过 HIGH。

### C. V0.5.0 NO-GO

任一 BLOCKER → 直接 NO-GO。任一 unresolved HIGH → 原则上 NO-GO；先在 v0.4.3 范围内修复并完成规定回归，不得带着 grounding integrity HIGH 问题进入真实 AI 接入。

补充规则（与验证计划 Exit Criteria 一致）：未解决的 BLOCKER / HIGH 不得通过 waiver、exception、risk acceptance、"重新决策"等措辞绕过。唯一例外路径是有证据链支持的正式 reclassification——即新证据证明原 severity 判断本身不成立，并记录 original severity、new evidence、reasoning、new severity、reviewer / human decision。reclassification 不是 waiver。若 BLOCKER / HIGH 仍真实存在且未解决，最终 Decision 必须为 V0.5.0 NO-GO。

## 10. Defect Correction Discipline（冻结）

任何修复必须形成完整证据链：

FAIL evidence → root cause → minimal fix → targeted regression → full regression → human re-test if applicable

历史症状无法复现时：

- 不得写 "FIXED"
- 应写 NOT REPRODUCED / ROOT CAUSE NOT PROVEN

只允许修复：BLOCKER、HIGH、明确阻断 Decision Gate 的 MEDIUM，或非常小且与本 Gate 直接相关的测试/诊断缺口。不得借修 bug 扩大 scope。
