# EKB v0.5.3 Phase 6 — Export & Backup Format Contract

- 生成日期：2026-08-25
- 性质：Phase 6 冻结契约（本阶段允许新增的文档）
- 冻结值：见下表；本阶段不提升任何版本号，不新增 v13

## 1. 四个版本维度（不可互相替代）

| 维度 | 当前值 | 来源 | 含义 |
|---|---|---|---|
| application_version | `0.5.2`（发布冻结） | `src/config.py:app_version` | 应用/发布版本；本阶段不改 |
| schema_version | `12` | `src/migrations.py:SCHEMA_VERSION` | 数据库结构版本；本阶段不升 v13 |
| backup_format_version | `1` | `src/backup_service.py:BACKUP_FORMAT_VERSION` | 目录备份容器格式版本；**不等于 schema v8** |
| config_format_version | `1` | `src/backup_service.py:CONFIG_FORMAT_VERSION` | 备份内恢复配置格式 |
| knowledge_export_format_version | `1`（新增） | `src/knowledge_export_service.py` | 知识导出包格式 |
| ai_ledger_export_format_version | `1`（新增） | `src/ai_ledger_export_service.py` | AI 台账导出包格式 |

## 2. 冻结规则

1. schema v8 旧备份升级 **不等于** 修改 backup_format_version。
2. 正式 restore 入口继续 schema 精确匹配、fail-closed；schema v8 只能走独立隔离升级入口。
3. Knowledge Export 与 AI Ledger Export 是两类不同导出包，互不混入。
4. Knowledge Export 不得混入 AI 调用台账、embedding vector、prompt、回答或 API Key。
5. AI Ledger Export 只导出 ai_calls 审计元数据，不解析、不附带 target_refs 指向的知识正文。
6. SQLite 整库备份天然包含 ai_calls 表；备份与业务导出不是同一种能力。
7. AI 完整回答与 Experience Candidate 未持久化，因此不被任何导出伪造。
8. 所有导出格式具有明确版本号、manifest、文件哈希和确定性排序。
9. 现实中的 schema v8 旧备份是数据库快照文件（`data/database/backups/*.v8.*.db`），
   不含 raw/pages/markdown 资产目录；隔离升级产出为当前 schema 的数据库快照 +
   `upgrade_report.json`，或当调用方提供只读资产源时产出可恢复的完整 BackupService
   目录备份。两种形态均不得直接恢复到 production。

## 3. 各导出包结构（摘要，详见各服务模块）

### Knowledge Export
`manifest.json` / `knowledge_objects.json` / `knowledge_object_sources.json` /
`knowledge_relations.json` / `knowledge_memory_entries.json` /
`knowledge_object_revisions.json` / `markdown/ko_<id>.md` /
`markdown/memory_<id>.md` / `files.json`（SHA-256 清单）。

### AI Ledger Export
`manifest.json` / `ai_calls.json` / `ai_calls.jsonl` / `files.json`。
JSON/JSONL 为权威无损格式；不实现 CSV（可选能力，不在本阶段范围）。

### Legacy v8 upgrade 产物
`<migrated database>` + `upgrade_report.json`；或完整目录备份（若提供只读资产源）。
