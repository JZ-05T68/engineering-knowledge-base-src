# EKB v0.5.3 — 可审计 AI 接入（Release Notes）

- 状态：已作为 GitHub Release `v0.5.3` 正式发布。
- 版本定位：在 v0.5.2 Knowledge Foundation 之上，增加可审计、引用约束、按需触发的 AI 辅助能力。

## 概述

v0.5.3 让用户可以为明确选定或检索出的本地知识，按需获得 AI 辅助：Ask AI / RAG Answer 与
只读经验整理候选。所有 AI 能力都受引用约束、可审计、可追溯；AI 不自动写知识，也不是基础功能依赖。

## 亮点

- ContextItem 与 KnowledgeContextPackage 统一只读上下文投影与打包；
- Ask AI / RAG Answer 只依据所选上下文回答；
- 回答引用的运行时完整性校验，fail-closed；
- 只读 AI 整理经验候选；
- AI 调用台账与只读仪表盘；
- Knowledge Export 与 AI Ledger Export 两类结构化导出；
- schema v8 旧备份隔离升级；
- 无 API Key 时全部离线基础功能保持不变。

## AI 工作流

```
用户显式选择或检索知识 → ContextItemProjector → KnowledgeContextPackage
        → Prompt Builder → AI Provider → 可审计输出（回答或经验候选）
```

- 输入必须来自 KnowledgeContextPackage，不绕过 Context/Evidence 层。
- 只处理用户本次明确选择的上下文，不自动扩大范围。
- 无后台、定时或连续调用；无会话记忆。

## 引用完整性

- AI 回答中的每个引用（stable_id 或 #N 编号）必须属于本次上下文包。
- 未知、伪造、越界和空引用一律 fail-closed，不显示半成品回答。
- 引用去重并保持首次出现顺序；UI 展示“回答实际引用（已校验）”。

## 经验候选

- 用户点击“AI 整理经验”后按需生成结构化候选：标题、问题、背景、处理方式、结果、根因、
  经验教训、适用范围、限制与引用。
- 候选只是 AI 整理结果，不是已确认经验；页面不提供自动保存或一键写入。
- 无法从上下文确认的字段保持为空或标记“不足以判断”。

## AI 调用台账

- ai_calls 记录调用类型（completion/embedding/rerank）、来源（rag_answer / experience_model /
  其他）、状态、模型、Token 与目标引用。
- 台账只读，不保存完整 prompt、上下文正文或模型回答；Mock 离线演示不写入台账。
- schema v12 已足够表达调用语义，本版本不新增 schema v13。

## 导出与备份

- Knowledge Export：知识对象、来源、关系、修订和记忆的无损导出，含 manifest、逐文件
  SHA-256 与每对象独立 Markdown。
- AI Ledger Export：ai_calls 审计元数据独立导出（JSON/JSONL 权威），不含正文与密钥。
- schema v8 旧备份隔离升级：原始备份字节不变，升级产物经第二隔离目录恢复演练验证。

## 数据与 schema 兼容

- application_version=0.5.3；schema_version=12；backup_format_version=1；
  config_format_version=1。
- 正常 restore 仍保持 schema 精确匹配；schema v8 只能通过独立隔离升级入口处理。

## 离线行为

- 默认 `ai_mode="manual"`；无 API Key 时 PDF 导入、检索、阅读、笔记、证据、删除恢复、
  备份等全部离线功能保持不变。
- UI 无 API Key 时回退到明确标注的 Mock 离线演示，不伪装为真实模型结果。

## 安全与隐私边界

- 不自动写知识；不修改用户原文；无 Agent、工具调用、长期会话记忆或自动扫描。
- 不保存完整 prompt、上下文或回答；不记录 API Key；不猜测 provider、Token 或费用。
- 正式服务仅监听 `127.0.0.1:8501`。

## 升级说明

- 从 v0.5.2 升级：停止服务 → 运行发布检查 → 备份 → 启动 v0.5.3。
- schema v8 旧数据库快照：使用 `python scripts/upgrade_backup.py <旧备份> <输出目录>`。
- 完整恢复流程见 docs/windows-recovery.md 与备份/恢复入口说明。

## 验证

- 全量 pytest：1762+ tests collected，exit 0。
- Ruff、`git diff --check`、schema v12 备份/恢复 roundtrip、release_check、production
  127.0.0.1:8501 health HTTP 200 与全部正式页面只读 Smoke Test。

## 已知限制

- Agent、工具调用、长期会话记忆尚未实现。
- 本地 OCR 面向单页印刷体；不支持手写、公式或复杂表格。
- 搜索展示与批量操作有加载范围限制。
- 完整备份为本地目录结构，非加密归档。
