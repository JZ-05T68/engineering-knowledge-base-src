## 3. One-Sentence Product Positioning（一句话定位）

**主定位（对外统一口径）：**

> 普通 AI 帮你调用世界的知识，EKB 应该帮你调用过去的自己。

**操作级短句（Operational）：**

> EKB：调用过去的自己，把零散的信息转化为长期可复用的经验。

**边界（必守）**：当前 v0.6.1 展示的是方向的基础——可回源的检索、经验复用场景、
信任边界；**不是**完整的长期 Personal Experience System，不得暗示"已经能自动
积累/写入一生经验"。

## 4. 30-Second Project Explanation（30 秒讲稿）

> 通用 AI 擅长调用世界的公开知识，但一个工程师自己踩过的坑、做过的决策、
> 积累的经验，散落在笔记和文档里，很难在需要时找回来。EKB 要做的，
> 就是把这些个人积累变成可检索、可复用、可回源的知识资产——
> "调用过去的自己"。当前版本先把地基打牢：可靠的知识检索、带来源引用的
> 回答、历史问题解决记录的找回复用，以及来源变化提醒与"没有依据就不编造"
> 的诚实边界。自动把新经验沉淀回知识库，是我们的下一步规划，尚未实现。

（约 170 字，全程无夸张声明；"尚未实现"一句必须保留。）

## 5. Problem Definition（问题定义）

- 公开信息日益丰富、可被通用 AI 检索；**个人长期积累的工程经验是稀缺资产**：
  决策背景、排障路径、失败教训、返工原因。
- 这些经验以碎片形式散落：笔记、页面标注、聊天记录、个人文档——
  时间一长就找不回、不可信、不可复用。
- 工程场景对答案的要求高于聊天：结论必须能**回到来源**核对，来源变化必须
  能被发现，没有依据时宁可明说没有。
- EKB 的长期价值来自 **用户 × 知识 × 经验 × 结果** 的积累与复用，
  而不是一次性问答。

## 6. Why Not Just Another RAG（为什么不只是又一个 RAG）

- RAG 是基础设施，不是 EKB 存在的理由——我们不贬低 RAG，它可靠地跑在本产品里。
- 通用 RAG 解决"从文档里找一段相关文本"；个人工程经验复用还要求：
  **来源可追溯、版本可审计、完整性可感知、结论可核验**——这些是检索之上
  的信任层（来源指纹、修订历史、证据定位、知识记忆结构）。
- 这一层不是为演示而造：它是未来 Personal Experience Agent（受控经验写入）
  的前置条件。没有可靠的"读"，就不可能有可信的"写"。
- 不得声称：当前已解决"终身个人化学习"。（FUTURE_DIRECTION）

本机 Streamlit Local UI —— 127.0.0.1:8501（app.py + pages/，管理面 + 比赛演示页）
        │
        ├─ Mode 2（比赛默认，预置离线演示）

        │     确定性 fixtures；零网络 / 零 AI / 零 API Key / 零生产 DB

                    │  HTTP，默认 http://127.0.0.1:8000（hosted_port 默认 8000）
                    v
              Hosted Agent API：/health、/ready、POST /v0.6/agent/run、
                                GET /v0.6/sources/{stable_id}
                    │
              SingleStepAgentExecutor（单步内核：决策≤1、工具≤1、重试=0、无循环）
                    │
              ToolRegistry（Phase1ReadOnlyPolicy：非只读工具 fail-closed 拒绝）
                    │
              7 个 READ_ONLY Tool（见 §9）
                    │
              rag_answer Final Answer Stage（最终回答只能基于工具证据 + 引用校验）
                    │

要点：Local UI（8501）与 Hosted 服务（8000）是**两个独立端口、独立运行档**，
禁止互相回退；Hosted 指本项目的 API 组合形态，**不等于**公网 SaaS 部署。

## 9. Agent Foundation（Agent 基础）

已机械化核对（EV-CODE-03/04/05；README/CHANGELOG v0.6.0）：

- **恰好 7 个 READ_ONLY Tool**（`Phase1ReadOnlyPolicy` 拒绝一切非只读注册/解析）：

| Tool | 用途 | 报告安全措辞 |
| --- | --- | --- |
| `page_search` | 检索页面资料 | 页面级全文检索 |
| `knowledge_search` | 跨知识检索 | 页面/知识对象/知识记忆的统一检索 |
| `get_knowledge_object` | 读取知识对象 | 读取概念/原理/决策等知识单元 |
| `get_knowledge_memory` | 读取知识记忆 | 读取结构化的问题解决/经验记录 |
| `inspect_provenance` | 溯源检查 | 查看知识条目的来源构成 |
| `inspect_source_integrity` | 来源完整性 | 读取已捕获的来源指纹状态（valid/changed/missing/unknown），不刷新不重算 |
| `get_evidence` | 读取证据 | 读取整页/选区/区域级证据定位 |

- **单步执行内核**：一次请求内 Decision → 0/1 个 Tool → Final Answer；
  决策调用 ≤1、工具调用 ≤1、Agent 自主重试 = 0；无循环、无多步路径；
  运行 trace 仅存进程内存。
- **逻辑模型调用 ≤2 次**（决策 1 次 + 最终回答 1 次）。
- `rag_answer` 是 Final Answer Stage 而非 Tool；最终回答逐条校验引用，
  未知/伪造/越界引用 fail-closed，不输出半成品回答。
- Agent 无写能力、无自主重试、无长期会话记忆。

## 10. Retrieval / Grounding / Source Inspection（检索 / 依据 / 来源查看）

- 两级检索离线可用：页面资料检索（FTS）与个人知识检索（跨对象/记忆）。
- 「有依据回答」的准确含义：**回答由当前可用资料支撑并给出引用**；
  ≠ 保证正确，≠ 100% 准确。
- 引用两层事实要分开表述：
  1) 回答内可见的引用编号/引用列表；
  2) 来源详情 viewer（元数据：标题/类型/位置/支持说明/来源状态）——
  不展示文件路径、原始 ID、正文全文、模型原始响应。
- Mode 2（演示）提供 `citations_detail` 显式 #N 映射；Mode 1（真实链路）
  无该字段，回退为独立已验证来源列表，`#N` 保持字面不猜测——
  这是已知限制的正确表现，不得在 UI 伪装修复。

## 11. Experience Reuse Scenario（经验复用场景，B）

- 演示问题：「编码器接线错误导致 PID 震荡的那次问题，最终是怎么定位和解决的？」
- 展示事实：结构化的知识记忆（问题解决记录：根因 / 定位过程 / 处理方式 /
  复用条件）可被检索、查看、回到来源。
- **正确措辞**：「历史问题解决记录可找回、可复用」；
  「遇到类似问题时，可以重新调用过去沉淀的工程经验」。
- **禁止措辞**：「系统已经自动学习并沉淀所有经验」「终身记忆」「自动成长」。
- 比赛演示使用预置演示语料（页面有标识）；产品能力（知识记忆服务）真实存在。

## 12. Integrity / Trust Boundary（完整性 / 信任边界）

- 本地内容指纹：来源登记时记录规范化 SHA-256 快照指纹，读取时与当前内容比较；
  状态：valid / changed / missing / unknown。
- `changed` = **快照不一致**（可能是正常更新）；不联网、不做真伪判断。
- 演示固定措辞（必须保留）：「来源内容与登记时的快照不一致。这不代表造假或
  被篡改，只表示应回到原文重新核对后再采信。」+「演示预置状态：……不是实时
  核验结果。」
- 三分语义必须保持：**changed ≠ tampered ≠ fake**；禁止「已被篡改」「来源造假」
  「不可信」级断言。
- 信任是支撑机制，不是产品最终定位——主叙事始终是"经验复用/调用过去的自己"。

## 13. Failure / Fallback Design（失败 / 兜底设计）

| 状态 | 触发 | 评委看到 |
| --- | --- | --- |
| 无证据（○） | 问题超出知识范围 | 「未找到可支持资料」+ 不编造说明 + 换题建议 |
| 失败（×） | 排练卡 / 工具失败 | 「本次请求未完成」+ 封闭错误文案 + 重试 |
| 限流（⏳） | 请求过于频繁 | 「请求过于频繁」+ 稍后再试 |
| 服务不可用（⏻） | Mode 1 无服务 | 「本机 Agent 服务当前不可用」+ 显式切换按钮 |

- 铁律：**无静默回退**——Mode 1 失败绝不伪装成 Mode 2 成功；「切换到预置离线
  演示」是显式动作（重跑当前问题并明示模式）。
- 兜底层级：Mode 2 确定性演示 → Mode 3 预录视频（概念/排练备份，非应用模式）。
- 错误文案为封闭目录；UI 不出现 traceback / JSON / 内部 ID / 路径 / provider 信息。

## 14. Local-First / Offline Boundary（本地优先 / 离线边界）

- **安全说法**：核心知识管理能力（导入/检索/浏览/笔记/证据/对象/记忆）与比赛
  预置演示可在本地离线运行；正式服务固定绑定 `127.0.0.1:8501`。
- **不安全说法**：「整个产品永远不需要联网」——真实模型功能（Mode 1 配置云端
  模型时）需要网络与 API 配置。
- 允许口径：「核心知识管理能力和比赛预置演示可在本地离线运行；真实 Agent 模式
  在启用云端模型时需要网络和 API 配置。」（禁说「全程无需联网」）
- 用户资料存本地；比赛演示语料为 synthetic 预置案例，与生产 DB 零读取零派生。

## 26. Report Paragraph Building Blocks（报告段落积木）

每块 80–180 字，可直接改写组合；不得添加本包之外的事实。

1. **项目背景**：工程经验是个人最稀缺的知识资产。通用 AI 能检索世界知识，
   却无法保存"我为什么这样决策、这次故障怎么定位"。EKB（工程知识库）把
   个人主动导入的资料、记录的经验和可核验的来源组织为本地知识资产，
   目标是让积累可以被未来可靠地调用。
2. **问题陈述**：散落的经验难以检索、难以信任、难以复用：聊天记录会被清空，
   笔记缺少来源，文档过时无人知晓。工程场景要求结论能回到依据——
   没有依据的流畅回答在工程上没有价值。
3. **系统目标**：EKB 的长期方向是"调用过去的自己"——把零散信息转化为
   长期可复用的经验。当前阶段先构建可靠地基：检索、来源、引用、完整性
   与诚实边界。
4. **当前架构**：系统由本机 Streamlit 应用（127.0.0.1:8501）与可选的
   本机 Hosted Agent API（默认 127.0.0.1:8000）组成。比赛演示走预置
   离线演示通道，零网络、零 AI 依赖；真实 Agent 链路为显式切换模式。
5. **Agent 设计**：单步只读 Agent——一次请求内完成决策、至多一个只读工具
   调用与最终回答生成。七个只读工具覆盖页面检索、知识检索、对象、记忆、
   溯源、完整性与证据；非只读工具在注册层即被拒绝（fail-closed）。
6. **知识检索**：页面级检索与跨知识检索离线可用；回答基于检索到的资料
   生成，附可点击引用；引用逐条校验，未知或伪造引用会使回答整体降级，
   不输出无依据文本。
7. **经验复用**：知识记忆以结构化方式保存问题解决记录（根因、定位、处理、
   复用条件）。历史记录可被检索并重新调用，使"老工程师解决问题的经验"
   成为新人可直接复用的资产。
8. **来源与完整性**：每个来源在登记时记录内容快照指纹；读取时与当前内容
