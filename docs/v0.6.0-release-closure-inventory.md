### 4.2 前端应消费的已冻结契约

| 接口 | 当前事实 | 前端必须处理 |
| --- | --- | --- |
| `POST /v0.6/agent/run` | 请求仅 `text` 与可选 `correlation_id`；同步返回 `request_id,status,answer,grounded,citations,warnings,error` | 不发送 tool/model/provider/key/budget/path 等权力字段；不直连模型；不用浏览器持有 AI key |
| `GET /v0.6/sources/{stable_id}` | 仅 `stable_id,type,title,label`；title/label 可为空；支持 page、knowledge_object、knowledge_memory、evidence | 缓存/去重读取 metadata，合理处理 404/422/429/503；不把 ID 当作文件路径 |
| `/health` | liveness；正常 200，不证明 AI 可用 | 不展示“真实 AI 已验证” |
| `/ready` | readiness；缺 AI 配置等时 503，完整配置才 200 | 进入真实模式前预检；不能用作唯一 kill/restart probe；ready 200 仍不证明 key 有效或模型成功 |
| 业务失败 | AgentRunResponse 可在 HTTP 200 中 `status=failed`；`grounded=false` 的正常 no-evidence 也可能 completed | 必须同时检查 HTTP 状态、响应形状、业务 status/error 和 grounded；不能将所有 200 画成成功 |
| 传输失败 | HTTPFailure 只有 `request_id,status,error`；可能 413/422/429/503/500 | 不能假定失败也有 answer/citations；错误只用安全码/固定文案，保留非敏感 request_id |
| CORS / correlation | exact origin；credentials=false；allow_headers 只有 Content-Type；expose X-Correlation-ID | correlation_id 放 JSON；不自造需额外 CORS 权限的请求头；跨域错误页也须联调 |

**Citation 编号缺口：** RAG validator 可接受正文 `#N` 或 canonical stable_id；HTTP 投影只保留
已验证 stable_id 集合，不保留 `package.citations` 编号映射。回答可能只引用 `#3`，也可能乱序引用。
**不能把 citations 数组第 1 项当作 #1**。短路径是独立“已验证来源”列表，按 stable_id 打开卡片；
正文保留原编号，只有有明确身份的 stable_id 可以直接关联。若需所有 `#N` 可点击，先经评审确定
显式安全映射契约，不能靠前端猜测或硬编码模型输出。该增强列为 P1，基本引用可检查能力仍是 P0。

### 4.3 必须先决定的展示边界

1. **Evidence/source viewer：** 当前 `/sources` 是 metadata-only，没有正文、excerpt、路径、
   下载 URL、原 PDF/PNG、完整 fingerprint payload。单靠标题卡片不满足“检查证据”的完整叙事。
   推荐先审定“metadata 抽屉 + 独立人工批准的静态证据摘录包”：摘录按实际 corpus 的 SHA/UUID/
   stable_id 绑定并逐条校验，标明“预置公开演示证据”，不冒充 API 实时回源；不读取本地文件。
   这只是候选方案，**维护者与 DeepSeek 未接受前，该项保持 OPEN**。前端静态资产公开也必须
   经过相同内容/权利/隐私审批；不默认向 Git 放入源材料或 DB。若验收必须实时正文/原件查看，
   需显式变更 ADR-007 的暴露范围和安全审查，不能在本清单中偷偷新增 endpoint。
2. **Agent activity：** HTTP 没有 trace、ToolResult、token_usage、model，也无 SSE/WebSocket。
   可以真实显示“已提交 → 等待服务响应 → 返回有依据答案/无证据/失败 → 引用资料读取中”。
   请求返回前不能声称已观察到“检索完成/检查指纹完成”。泛化等待动画必须标为等待，不能展示
   虚构思维链或未经上报的阶段进度。精确事件流不是本次发布 P0。
3. **Trust：** `grounded=true` 表示回答依据 Tool evidence 且通过引用校验，不等于材料事实必然正确，
   也不等于全部来源未变化。当前公网 warnings 被投影为统一“来源存在限制，请核对引用资料”。
   不能据其存在就显示“已篡改”，或据其缺失就显示“完整性验证通过”。

## 5. 三个比赛场景与数据前提

共同前提：独立授权材料，非 production DB；exact schema v12；有效 FTS/stable IDs；公开可用标题；
明确资料版本及权限；每个问题绑定期望证据/允许结论/不应声称的内容。以下题目是**候选文案**，
不是实际语料已存在、已获批准或真实模型稳定通过的证据。

| 场景 | 候选问题与单步路径 | 数据前提 | 当前可支持性 / 缺口 |
| --- | --- | --- | --- |
| A：grounded answer + citations | “PID 调整时，比例项与积分项分别影响什么？”；一次 page_search 或 knowledge_search → Final → validated citations | 至少一组授权的短页/知识对象，文本足够支撑结论；FTS 可稳定命中；标题/页码/摘录与 ID 对应；不依赖在线 embedding | 后端具备机制；真实问题命中、模型决策稳定性、UI 点击证据均 NOT VERIFIED |
| B：历史经验 / 根因 / 解决 | “示范案例中的编码器接线问题，表现、根因、处理方式和结果是什么？”；一次 knowledge_search 或对已知对象/记忆的 get | 独立撰写或授权的工程案例，明确背景、症状、原因证据、措施、结果、适用条件/限制；相关信息须可由**一个 Tool 结果**提供，不靠 Agent 连续查多次 | 可以支持基于案例的回答；旧“AI 整理经验”页面不是此 Agent 链；没有已批准案例和稳定题卡 |
| C：来源变化 / 不确定性 | “检查示范知识对象〔实际 approved knowledge_object stable_id〕的来源是否仍可信，说明限制。”；一次 inspect_source_integrity | 已知 KO ID；受控构造的 VALID 与 CHANGED/UNKNOWN 对照，stored fingerprint 与当前 DB source 内容的关系真实可解释；构造完成后才锁定 SHA/批准 | adapter、mapper 和局部测试支持机制；完整比赛 HTTP+UI+真实模型未验收，warning 仅泛化文案 |

场景 C 的具体限制：

- 单步 Agent 不能在一次请求内先搜索 ID，再自动调用 integrity Tool。预置题卡需引用已批准的
  **knowledge_object ID**，在用户可理解的题卡/详情里解释所检查对象；request 仍只有 text，
  不加隐藏 tool override。也可以由观众显式发起第二个独立检查请求，但不能包装成自动多步 Agent。
- 虽然 Tool 接受 `knowledge_source` stable_id，Final context mapper 不支持该 type，source HTTP
  endpoint 也不提供该 type。比赛主路径选 KO 为检查目标，引用 KO；不假设单 source ID 一路可用。
- fingerprint 是 DB 行的 canonical content 比较，读取时在内存计算、不写回；不是重新读取磁盘
  PDF 的二进制完整性证明。CHANGED 表示快照不一致，UNKNOWN 表示无法充分确认，不等于造假。
- 不在比赛线上修改数据来造 warning，不调用 fingerprint recapture，不让 UI 提供修复/重置写面。
  对照状态在候选 artifact 制作阶段完成；任何后续内容变化需重新审批、记录 SHA。
- 稳定验收覆盖“单独有 warning 的合法回答”与“无法形成合法引用而 fail closed”；不强迫失败链
  显示一个看起来成功的答案。详细状态徽标若需要新增公开字段，同样先审契约。

**3–5 分钟主叙事建议：** 0:00–0:30 说明个人知识资产与预置公开材料；0:30–1:40 场景 A
提问、真实等待状态、答案与引用；1:40–2:40 场景 B 复用工程经验；2:40–3:50 场景 C 与证据检查；
3:50–4:30 解释限制、本地优先及信任边界，留下约 30 秒缓冲。不是在台上导入资料、配置 key 或排查部署。

## 6. Failure-safe 三模式与失败处理

| 模式 | 当前状态 | 发布/比赛前所需 |
| --- | --- | --- |
| Mode 1：Real local Agent | 服务基础存在，无已集成的本地比赛入口；不是现有 Streamlit Ask AI | 同一比赛 UI 调用本机受控的 Agent HTTP 入口；显式 loopback 绑定，使用独立批准 corpus 和隔离 DATA_ROOT，不复用 Local production DB；key 服务端、预算有限；实际配置/CORS/端口与 browser E2E 记录。公网模式另外通过 WP6B 验收 |

| 失败 / 状态 | 预期 UI 与操作 |
| --- | --- |
| 空问题 / 无上下文 / grounded=false | 明确提示问题或资料不足；不展示“已证实”；无假引用；保留重新选择题卡能力 |
| provider 未配置、runtime 未 ready、预算拒绝 | 固定安全文案；保留问题；用户显式切至 mock/视频；不把缺 key 自动伪装成真实模式成功 |

| citation_invalid | 隐藏无效答案成功状态，不补造引用、不自动再问模型 |
| source 404/429/空 title/旧 fixture ID | 答案与来源加载状态分离；显示该来源暂不可检查，不猜另一来源；缓存按 origin+corpus identity+stable_id 隔离 |
| 重复点击 / 换题 / 切模式 / 晚到响应 | 运行中禁止重复提交；保留请求代次与结果所属模式；晚到响应不能覆盖新题或 mock 结果 |
| 浏览器中止等待 | 不声称取消了服务端调用；一次请求可能仍在完成/计费，禁止自动重发或并发补发 |
| 模式回退 | 由操作者明确选择并告知观众；不把 fixture/录像冒充实时模型输出；全部 fallback 必须离线可用 |

只做有限请求，无无界轮询、自动 paid retry、自动多次“直到答案满意”。真实模式 A/B/C 校准与
人工演练涉及的付费调用需要独立有限次数/预算批准；不能把后文“一次部署 smoke”解释为无限授权。

## 8. WP6A 恢复点及 WP6B 出口

恢复锚点为 [WP6A 暂停记录](v0.6.0-public-deployment-wp6a-target-validation.md) 中既有
Standard 工单 `6a91903f19d208af60b18288` 的回复/受支持解决方案，不是重新购买、重新开服务或
直接注入 AI key。历史截图只证明维护进程报告 UID/GID 0:0、挂载 `/data` owner 0:0、mode 0777，
与 Dockerfile 的 USER 10001:10001 不一致；根因尚未确定。不能称平台一定强制 root。
