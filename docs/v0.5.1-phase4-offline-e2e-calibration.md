# EKB v0.5.1 Phase 4 — Offline End-to-End Retrieval Calibration

- 日期：2026-08-17
- 分支：`kimi/v0.5.1-retrieval-stabilization`
- 性质：**严格离线评估**。0 paid API、0 Qwen、0 生产/暂存 DB 写、不改 frozen
  benchmark、不改生产检索行为。
- 目标：判定**当前真实 hybrid 检索架构**（而非 fixture 理想化模型）在冻结
  benchmark 与 Phase 3 真实 embedding 证据面前，究竟支持什么。

## 4A — 生产路径审计（file:line 证据）

### 1. lexical recall

- `src/search_service.py:91-117` `SearchService.search(query, limit)`：
  `extract_search_terms` → FTS5 OR 表达式 → `Database.search`。
- `src/search_service.py:105` `safe_limit = min(limit, self._max_results=100)`。
- 调用上限来自 `src/search_state.py:67` `limit: int = 50`（默认 50，UI 分页）。

### 2. vector recall

- `src/ai/vector_recall.py:187-193` `PersistentVectorRecallSource.recall`：
  返回 `tuple(RankedHit(page_id, rank) ...)`，rank 由 similarity 降序 + page_id 升序 tie-break。
- `src/ai/vector_recall.py:195-221` `recall_scored`：对每个 freshness-valid 已存
  embedding 算 `cosine_similarity(query_vector, stored.vector)`，最后
  `scored.sort(key=lambda hit: (-hit.similarity, hit.page_id)); return tuple(scored[:limit])`
  （line 220-221）。

### 3. fusion / ranking

- `src/ai/retrieval.py:113-163` `rrf_fuse`：`RRF(page) = Σ 1/(k+rank)` 对 lexical 与
  vector 双侧**等权累加**，`k = DEFAULT_RRF_K = 60`（line 41）。
- 排序键：`(-fused_score, best_rank, page_id)`（line 162），确定且 source-neutral。

### 4. `vector_weight`

- **生产代码中不存在 `vector_weight`**。`rrf_fuse`（retrieval.py:150-152）对两个
  来源做**等权**累加，无任何权重系数。
- `vector_weight` 只存在于 Phase 2 ablation 脚本 `scripts/retrieval_ablation.py`
  的 `rrf_fuse_variant`（约 line 187-250），是**实验参数，非生产行为**。

### 5. vector-side `top_k`

- **生产代码中不存在独立的 vector `top_k`**。`recall_scored` 用 `scored[:limit]`
  （vector_recall.py:221），`limit` 由 `HybridSearchService.search(query, limit=...)`
  传入（`hybrid_search.py:145`），即 UI 的 `state.limit`（默认 50）——与 lexical limit
  **相同**，无独立的向量候选截断旋钮。
- Phase 2 的 `GatedVectorRecallSource`（top_k 参数）同样是实验包装器，非生产。

### 6. final result construction / bounding

- `src/ai/hybrid_search.py:132-186` `search`：`lexical_results`（limit 条）+ `vector_hits`
  （limit 条）→ `rrf_fuse` 取并集 → 逐个 hydrate → `HybridSearchOutcome.results`。
- **无独立的最终结果数 bound**：结果数是 lexical ∪ vector 并集后 hydrate 成功的数量，
  上界 ≤ lexical(≤50) + vector(≤50) = ≤100，但无显式的 product-level 上限。
- `src/search_service.py:105` 的 `max_results=100` 只约束 lexical 单侧。

### 7. partial embedding coverage behavior

- 无 embedding 或 freshness 不匹配的页在 `recall_scored` 内被 `continue` 跳过
  （`vector_recall.py:207-209`）——**从未进入向量候选**，但**不影响 lexical 资格**
  （lexical 是独立路径 `hybrid_search.py:135-137`）。
- 因此 partial coverage 的页仍可经 lexical 命中进入融合，只是缺 vector 侧贡献。

### 8. score / rank normalization 与 RRF 语义

- RRF 用 rank 的倒数 `1/(k+rank)`，**不消费原始 cosine / BM25 分数**（retrieval.py
  模块 docstring 明确：两个 score 尺度不可直接相加，只传 rank）。
- `VectorScoredHit.similarity`（原始 cosine）保留在 recall 层供调试，但**不进入 RRF**。

### 运行时可观测量（无 benchmark label 即可得）

来自 `HybridHit` / `HybridSearchResult`（`retrieval.py:52-76`、`hybrid_search.py:86-93`）：
- `fused_score`（RRF 融合分）
- `lexical_rank` / `vector_rank` / `best_rank` / `source_count`
- 结果顺序（top1/top2/top3 的 `fused_score` 差、相邻 rank gap）

这些是 production runtime 天然暴露的字段，可作为 D-02 候选信号，无需 label。

## 4B — Replay 证据完整性

- 核实 raw evidence SHA-256 = `965d8ede0d96b6ceeec6a5f64ffe9ebfdf54b7870efaa6e820e16cb6405ea5e1`
  ✓（与 Phase 3 记录一致）。
- 文件 `logs/v0.5.1-phase3-calibration.json`，9271 bytes。

**决定性 evidence gap**：

- raw evidence 每 pair 仅存 **`similarity` 标量**（`{"query","page","category","similarity"}`），
  **未保存任何 1024 维 embedding 向量**（已逐字段确认 `any vector stored = False`）。
- 覆盖仅 23 query × 28 page 的 **53 个预计算 cosine**，非全 42 页、非完整相似度矩阵。

因此：

- **无法用真实 embedding 向量 replay 生产的 `PersistentVectorRecallSource.recall`**
  （它需要完整 query/page 向量做逐页 cosine，vector_recall.py:211）。
- 无法对"任意 query × 任意 page"重建相似度，无法构造 full-coverage replay。
- **不另做 API 调用**（0 paid 硬约束）；**不合成 fake "real" embeddings**。

→ 4C/4D/4E/4F 的**真实 embedding 端到端 replay 在当前证据下不可行**，记录为
evidence gap，不降低标准用 fixture 冒充真实语义。

## 4C — D-01 coverage ablation

**真实向量 replay 不可行**（见 4B：无向量、无 full-coverage 矩阵）。

**但 Phase 3 相似度分布已给出强证据**（无需 replay）：

- partial-coverage 页（真实未嵌入页，如 J1→stm32/p3=0.758、A4→comm/p3=0.841）在真实
  模型下呈**强语义相似度（0.52~0.84）**，与 true-relevant（median 0.716）同一量级。
- 证明这些页"未被向量召回"的原因**不是相似度低**，而是**索引侧未写入 embedding**
  （`recall_scored` 的 freshness/存在性 gate 直接跳过，vector_recall.py:207-209）。

**Conclusion（D-01）**：Indexing coverage is confirmed as the primary remediation
direction; the magnitude of end-to-end improvement remains to be validated after
implementation. 提高 embedding 索引覆盖率会把高相似度页纳入向量候选（方向性明确），
但 Phase 4 无法 replay 真实生产向量路径（Phase 3 raw evidence 只存 pairwise cosine
标量、非完整 1024 维向量），故**端到端改善幅度尚未实测**，需实现后再验证。

## 4D — Runtime-observable D-02 信号

可评估的运行时可观测量（无 label）仅来自 `HybridHit`/`HybridSearchResult` 字段：
`fused_score`、`lexical_rank`/`vector_rank`、`best_rank`、`source_count`、相邻 rank gap。

**关键约束**：

1. Phase 3 的 `relevant − labelled distractor`（+0.082~+0.321）**不是**可部署的运行时
   feature——production 运行时无 labelled distractor。
2. 真实 embedding 无法 replay（4B），故无法在真实相似度层面评估 top1−top2 / score ratio
   等信号的判别力。
3. Phase 3 已证明**绝对阈值**不可靠（paraphrase 0.458~0.676 与 lexical-overlap
   0.266~0.554 重叠），故"相似度绝对阈值"作为 D-02 边界**在真实分布下无足够判别力**。

**Conclusion（D-02）**：

- **NO-GO for an eligibility rule**：当前 benchmark + 现有证据**不能**支撑一个足够稳健的
  production-observable eligibility / weak-evidence 边界规则。
- 这是**有效结论**，不等于"失败"。D-02 的 weak-evidence 产品边界仍需 Phase 5 从产品
  层设计（诚实提示），而非从相似度分布强行提炼阈值。
- 未冻结任何 production threshold / margin。

## 4E — vector_weight 端到端校准

**前置事实**：生产代码**没有 `vector_weight` 参数**（4A 第 4 点），`rrf_fuse` 等权累加。

- Phase 2 fixture ablation 覆盖了 `vector_weight ∈ {0.25, 0.5}`，结论：w=0.25 有害
  （稀释 H2 多页语义收益，imp 2→1），0.5 在本语料无害。但这是 **fixture 向量**结论，
  不代表真实模型。
- Phase 3 真实分布：paraphrase / partial-coverage 相似度（0.46~0.84）与 true-rel 差距
  不大，**暗示语义信号本身足够强，radical 衰减（0.25）可能过度稀释**；但这只是间接
  证据，未在真实 hybrid 端到端验证。
- 真实 embedding 无法 replay（4B），故 **`{0.00, 0.25, 0.50, 0.75, 1.00}` 网格无法在
  生产融合行为上做真实端到端校准**。

**Conclusion（vector_weight）**：

- `0.5` 的 fixture 依据被 Phase 3 削弱，但**未证伪也未证成任何值**。
- production-optimal vector weight **仍 UNDERDETERMINED**。
- **不预选 1.0**；任何真实校准需在"将 `vector_weight` 作为显式参数引入 `rrf_fuse` 之后"
  才能进行——而引入该参数本身是 Phase 5 的 remediation 决策，Phase 4 不做。

## 4F — top_k 与 final-result bounding

**前置事实**：生产代码**没有独立 vector top_k**（4A 第 5 点），向量候选截断 = `limit`（50）。

- Phase 2 fixture ablation 已覆盖 `top_k ∈ {3,5,10}`，结论：B 系平坦，检索质量对 K 不敏感
  （仅结果数有界化）；这是 fixture 结论。
- 真实 embedding 无法 replay（4B），故 `{1,3,5,10}` 网格无法在真实相似度层面复跑。

**分开两问**：

1. **vector candidate bound**：Phase 3 间接支持"向量候选有界"（per-query relevant
   margin 全正，bounded top-k 不会伤害排序）；但这是方向性，非数值校准。真实 top_k 值
   需在生产引入独立向量 top_k 参数后才有意义。

2. **final output bound**：生产**无**独立 final-result bound（4A 第 6 点），结果是
   lexical ∪ vector 并集，上界由两侧 limit 决定。**不推断 `vector top_k=N ⇒ final ≤ N`**。

**Conclusion（top_k / D-03)**：

- 证明：向量候选池**可以**有界，且（fixture 上）对质量不敏感。
- 未证明：**final result 是否 bounded**。D-03 的 final-result product boundary 是一个
  **独立的**、尚未存在的产品层决策，与向量 top_k 无涉。

## 结论总表

| 维度 | disposition |
|---|---|
| D-01 | indexing coverage 确认为首要修复方向；端到端改善幅度待实现后验证 |
| D-02 | **NO-GO**：无足够稳健的 production-observable eligibility rule；需产品层诚实提示 |
| D-03 | 向量候选可 bounded（fixture 质量不敏感）；final-result bound **未证明、独立待决** |
| vector_weight | 生产无此参数；0.5 依据被削弱，optimal 值 **UNDERDETERMINED** |
| top_k | 生产无独立向量 top_k；5 作为"向量候选有界"方向合理但未在真实层面校准；勿与 final count 混淆 |

## 建议 Phase 5 remediation scope（若获支持）

1. **D-01**：优先修复 **indexing coverage**（把未嵌入但语义相关页纳入 embedding 索引），
   而非融合侧 eligibility hack。
2. **D-02**：产品层 weak-evidence 诚实提示（无 LLM / rerank / 二次调用），不提炼阈值。
3. **D-03**：评估是否引入**独立 final-result bound**（产品层），与向量 top_k 分开。
4. **vector_weight / top_k**：若要在真实层面校准，需先在生产 `rrf_fuse` 引入
   `vector_weight` 参数、在 recall 层引入独立 `top_k` 参数（当前不存在），此改动需
   单独评审，Phase 4 不实施。

## 边界确认

- 未修改 `src/ai/`、未改生产检索行为。
- 未改 frozen `benchmarks/*.json`。
- 0 paid API、0 Qwen、0 DB 写。
- 未合成 fake real embeddings。
