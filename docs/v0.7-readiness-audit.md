# v0.7.0 Personal Experience Agent — Readiness Prerequisite Matrix

- **日期：** 2026-08-29
- **性质：** 只读前置条件审计。本文档 **不是** v0.7 架构设计，不给出实现方案，
  只回答一个问题：在当前 v0.6.1 冻结基线（HEAD `7e7a293`）上启动
  「Personal Experience Agent」之前，哪些前提已具备、哪些缺失、哪些被阻塞。
- **审计方式：** 静态阅读 + 既有测试证据，0 真实 AI 调用，未改动任何生产代码。
- **关联文档：** `docs/repository-architecture-risk-audit-2026-08-29.md`（总审计）、
  `docs/technical-debt-backlog-post-v0.6.1.md`（技术债清单）、
  `docs/adr/ADR-006-agent-foundation.md`、`docs/adr/ADR-007-public-deployment-foundation.md`。

## 结论

**CONDITIONAL_READY。**

v0.7 的核心判断：**Agent 侧的"写"不是从零开始，而是给已经存在的、事务化的人类写路径
（`KnowledgeMemoryService.create_entry / update_entry / set_status / delete_entry`，
`src/knowledge_memory_service.py:82-177`）加一个受控的 Agent 入口。**
数据模型、写事务、撤销基础（内容修订）、备份/迁移机制全部 READY；
真正缺失的是 **批准门（approval gate）、写类 Tool 契约、持久化写审计（schema v13）、
undo 语义** 四件事，以及两个必须在 v0.7 开工前修复的已知缺陷
（多态来源孤儿链接 P2、字符串式错误分类 P2）。

阻塞项都不是架构性的，而是**尚未设计**：ADR-006 已明确
"写类 Tool 需要后续独立 ADR 才能进入 allowlist"（Decision 1 Consequences），
v0.7 开工的第一步就是这份 ADR，而不是代码。

## 前置条件矩阵

状态定义：READY = 已存在且可直接复用；PARTIAL = 存在基础但缺口明确；
MISSING = 完全不存在，需要新设计；BLOCKED = 存在但被已知缺陷/决策阻塞。

| # | 前提 | 状态 | 证据 | 缺口说明 |
| --- | --- | --- | --- | --- |
| 1 | 数据模型（记忆/经验表） | READY | schema v10/v12：`knowledge_memory_entries`（`src/migrations.py:1334-1358`）、`knowledge_object_revisions` append-only（`migrations.py:1206-1240`）、FTS 影子列同步触发器（`migrations.py:1536-1583`） | v13 若新增 Agent 写审计表，沿 v10-v12 已验证的 rebuild+fingerprint 模式即可（`tests/test_database.py:354-466` 已覆盖失败回滚） |
| 2 | 服务层写路径 | READY | `KnowledgeMemoryService.create_entry/update_entry/set_status/delete_entry`（`src/knowledge_memory_service.py:82-177`），全部经 `knowledge_transaction`（`BEGIN IMMEDIATE`，`src/database.py:1642-1658`）；知识对象 12+ 变更点同模式 | Agent 复用这些方法即继承同一事务边界；无需新写路径 |
| 3 | 工具副作用声明机制 | PARTIAL | `ToolSideEffect` 含 `WRITE_REVERSIBLE / WRITE_DESTRUCTIVE`，`Phase1ReadOnlyPolicy` 在注册时拒绝非 READ_ONLY（`src/agent/tools/registry.py:63-70`；ADR-006 Decision 1） | 机制在，但写类 Tool 的**输入契约、幂等性、确认语义**从未定义过——需要 ADR |
| 4 | 批准门（approval gate） | MISSING | 全仓库无任何"Agent 提议 → 用户确认 → 执行"流程；执行器只有 decision→tool→answer 三态（`src/agent/execution/executor.py:98-146`）；AGENTS.md 自动化边界要求"修改用户笔记必须显式确认" | v0.7 的核心新设计。注意：单步架构下批准天然发生在 run 之间（提案-确认两段式），不必引入循环 |
| 5 | 写类执行器策略 | PARTIAL | 执行器已区分 `TOOL_NOT_ALLOWED` / `UNKNOWN_TOOL` / `TOOL_EXECUTION_FAILED`（`executor.py:168-256`），trace 不落盘、不存正文（`execution/contracts.py:160-166`） | 写操作失败后的"部分生效"语义、写后 final answer 的引用语义均未定义 |
| 6 | 经验捕获（experience capture） | PARTIAL | `ExperienceModelService.generate`（AI 辅助经验建模，经 `AuditedAIProvider` 审计，`src/ai/experience_model_service.py:71-115`）；`src/experience_ui.py` 已有确定性 mock 回退（`rag_answer_ui.py:71-81` 同模式） | 目前只有"人发起、AI 辅助建模"；Agent 主动发起的经验捕获（何时触发、去重）完全未设计 |
| 7 | 去重（deduplication） | MISSING | 记忆/经验无内容指纹；`source_fingerprint.py` 只覆盖来源文件指纹 | 重复经验写入会直接堆积；需在 ADR 中定义去重键（如 prompt_sha256 式内容哈希 + 语义相似度阈值） |
| 8 | 溯源（provenance） | PARTIAL | `knowledge_object_sources` 多态来源表 + `ContextItemProjector` + source fingerprint 状态机（changed/missing/unknown） | **被 P2 缺陷阻塞**：单条 note/evidence 删除不清除来源链接（`src/note_service.py:631-649`、`src/evidence_basket_service.py:303-314`，见总审计 R-01）。Agent 写记忆必然产生更多此类链接，先修后建 |
| 9 | 写操作持久审计 | MISSING | 现有审计 = `ai_calls` 账本（append-only，hash-only，`src/database.py:2580-2683`）+ **内存态** execution trace（run 结束即消失，ADR-006 Decision 9 有意推迟 schema v13） | 写能力下"内存态 trace"不够：谁在何时批准了什么写、写入前后值，必须落库。这正是 ADR-006 预留的 schema v13（`agent_runs/agent_steps/tool_calls`）的触发条件 |

## v0.7 开工前必须完成的事（非本文档授权执行）

1. **写能力 ADR**（ADR-006 Decision 1 已预留）：定义写类 Tool 契约、批准模型、
   幂等与重试语义（沿用 autonomous retry = 0）、undo 语义、审计字段。
2. **修复 R-01（多态来源孤儿）**：P2，Agent 写记忆会放大它（见技术债清单 TD-01）。
3. **收紧 AI 审计边界**：`AuditedAIProvider.wrapped` 私有化或加能力门（TD-05），
   防止写时代码路径绕过账本/预算。
4. **错误分类改结构化**（TD-06）：`final_answer.py:150-185` 的中文子串匹配
   在错误类型增多（批准拒绝、写冲突）后不可维护。
5. **schema v13 设计评审**：对照 ADR-006 冻结的 `agent_runs/agent_steps/tool_calls`
   草案与真实写语义，确认列集与最小审计数据原则兼容。

## 明确不需要为 v0.7 做的事

- 不需要 Postgres/多进程：Hosted 单 worker 硬约束与 Local 单进程假设不变（ADR-007 Decision 6）。
- 不需要引入 Agent 框架：单步 + 批准两段式仍在"纯 Python 100-300 行"范围（ADR-006 Decision 5）。
- 不需要重写 RAG/检索：Agent 检索 lexical-only 的差距（总审计 R-04）是质量问题，
  不是写能力的前提，可并行或延后。
- 不需要动比赛冻结面：批准 UI 可以先做在记忆页/维护页，Agent 页冻结解除后再接入。
