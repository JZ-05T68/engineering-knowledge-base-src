# Engineering Knowledge Base v0.2.1 发布说明

发布日期：2026-07-25

## 版本定位

v0.2.1 是 v0.2.0 之后的小范围稳定性补丁版本。它不加入新功能，只修复一个并发稳定性问题：
多个并发首次访问同时创建默认证据篮时，可能生成重复篮，并使部分证据进入不再被界面使用的
“影子篮”。Windows 本地、单用户、离线优先的产品定位不变。

## 修复内容

- 修复并发首次访问下重复创建默认证据篮的问题。
- 修复后，无论多少并发调用同时首次访问，最终只存在一个默认证据篮，所有调用返回同一个篮 ID。
- 既有证据篮、证据条目和证据包内容不受影响。

## 技术实现

- 根因：应用层此前按“先查询是否存在、不存在再插入”两步执行，两步之间没有写事务保护，
  `evidence_baskets.name` 又没有唯一约束，并发首访时两个连接可能同时判定“不存在”并各自插入。
- 修复：在 `get_or_create_basket()` 首次查询前执行 `BEGIN IMMEDIATE`，把“检查是否存在 +
  必要时创建”置于同一个短事务中，由 SQLite 写锁串行化并发首次创建。
- 事务范围为一次查询加可选的一次插入，持锁时间极短；异常路径回滚并关闭连接，不残留事务。

## 数据与兼容性

- 数据库 schema 保持 v4，本版本没有任何 schema 变更。
- 不需要数据迁移，升级后直接启动即可。
- 不修改、不合并、不清理任何既有证据篮与证据数据。
- 如果历史上已经存在重复默认篮，本版本不会自动合并；界面始终使用 ID 最小的同一个篮子。

## 验证情况

- Ruff 全量检查通过。
- 自动化测试 336 项全部通过，其中新增一项基于真实线程与真实 SQLite 连接的并发回归测试，
  覆盖“两个线程同时首次访问默认证据篮”的竞争场景。
- 隔离人工冒烟测试九项全部通过，详见 `docs/v0.2.1-manual-test-results.md`：并发首访只创建
  一个默认证据篮，证据操作与证据包无回归，数据库 schema 保持 v4，主机绑定与离线边界不变。
- 人工验证全程未触碰正式数据库与正式工作区，正式服务 8501 未受影响。
- 2026-07-25 正式发布；schema v4，无迁移，为小范围稳定性补丁。

## 已知限制

- 与 v0.2.0 相同：schema 支持多个证据篮，但界面默认只操作一个篮子；命名和切换多个篮子留待
  后续版本。
- 并发回归测试为制造确定性竞争窗口，每次运行固定占用约 5 秒同步等待，属于测试耗时而非
  功能限制。

## 升级说明

- 停止旧版本服务，替换为 v0.2.1 程序后正常启动即可；无需备份恢复或数据迁移操作。
- 首次启动后可在“系统维护”页确认应用版本显示为 v0.2.1，schema 仍为 v4。
