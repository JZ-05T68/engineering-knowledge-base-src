## 4. What v0.7 Is（North Star）

**Personal Experience Agent**：用户解决真实工程问题 → 检索已有知识 → Agent 把
"用户结局 + 已有依据"组织成经验草稿（逐块 origin 标注）→ **用户审阅完整草稿并显式
批准** → 应用服务执行确定性受控写（create / undo / restore）→ 幂等、可撤销、可审计、
写后立即可被现有 FTS / 检索 / Agent 只读工具复用。

模型只提议；用户显式批准；应用服务执行受控写。经验复用
`knowledge_memory(kind='experience')`；草稿与批准均 session-only；命令日志
SUCCESS_ONLY；单一 BEGIN IMMEDIATE 事务；要求幂等 / 审计 / provenance / 软删除。

## 5. Frozen Architectural Invariants（实施时不可重新设计；不得重新推导）

1. **Agent**：single-step（≤1 decision、≤1 READ_ONLY tool call、retry=0、无循环）；
   registry 恰 **7 个 READ_ONLY** tools。
2. **写形态**：WriteCommand **不是** Agent Tool——本地应用层确定性服务
   （`ExperienceWriteCommandService`，三显式方法，无泛型分发）；allowlist 仅
   create / undo / restore。
3. **边界**：写仅 Local（唯一构造点 `src/runtime.py`）；**Hosted 永远 READ_ONLY**
   （不 import / 不构造 / 不暴露；无写路由）。
4. **存储**：复用 `knowledge_memory(kind='experience')`；无平行实体、无草稿表、
   无批准表、无持久聊天。
5. **session-only**：草稿与 ApprovalToken 均不持久化、不跨会话。
6. **N-6**：`relation_kind ∈ {support, context}` 持久化并参与批准哈希；
   support=存在性+freshness 相等，context=仅存在性；**context 永不升格 support**；
   删除后 MISSING_SUPPORT 与 MISSING_CONTEXT 分立派生、永不合并。
7. **N-7**：ApprovalToken 三字段 `{approved_draft_sha256, approved_idempotency_key,
   approved_at}`；**CREATE 幂等键在批准动作时生成**（提交路径零键生成点）；服务三
   条件校验（token present ∧ payload hash match ∧ command key match）；持久幂等层
   再保证同一逻辑命令至多提交一次 ⇒ **一次批准 ≤ 一次逻辑 CREATE**。
8. **canonical V1**：确定性规范载荷 + SHA-256 永久协议；4 条黄金向量逐字节钉死；
   content 序列化 = 长度前缀文法 `【<block_key>|<N>】`（可逆，码点计数）。
9. **SUCCESS_ONLY**：命令日志只存已提交成功行；失败零库内痕迹；审计与数据写
   **同事务**（无审计的成功变异不可达）。
10. **事务**：服务拥有唯一外层 `BEGIN IMMEDIATE`（`knowledge_transaction`）；
    幂等解析先于一切语义校验；禁嵌套自开事务（N-4 连接感知低层扩展）。
11. **幂等**：键=逻辑变异意图（非授权、非内容身份）；同键同载荷=typed 重放
    （免批准）；同键异载荷/异操作=冲突 fail-closed；commit-unknown 同键闭环；
    历史重放不重执行；**无全局内容哈希去重**。
12. **provenance**：FIELD_BLOCK_LEVEL；恰 10 区块、每块恰 1 行 origin；恰 4 个持久
    origin（user_asserted / direct_observation / agent_organized / agent_inferred）；
    EXISTING_SOURCE_SUPPORTED 为派生态非第五 origin；outcome 恒 user_asserted；
    根因确认门 R1-R4；整稿批准不升格确认位。
13. **tombstone**：`status ∈ {active, archived, deleted}`（无 deleted_at、无墓碑表）；
    undo/restore 仅限 create 日志链目标；undo/restore 零改写内容/来源/provenance；
    普通读面视 deleted 为不存在（Agent Tool=NOT_FOUND）；archived 语义不变。
14. **audit/privacy**：命令日志仅标识/枚举/哈希/长度/目标/时间——零正文/prompt/
    CoT/密钥/路径；应用日志同纪律；机器语义只认 typed code（10 码 + 4 + 2 子码），
    永不解析消息文本。

**以上每条都有 ADR/详规/审计/测试四层锚点**（§6 文档地图）；与冻结文本冲突的
"改进想法"一律视为需要新 ADR 的架构变更，10 月实施期不得顺手重开。
