## Scope

将 Phase 2A 的 `DecisionProvider` 边界接到 EKB 已有的 vendor-neutral AI Provider，
使真实模型能够通过严格结构化输出产生一个 `AgentDecision`，并继续由 Phase 2A
executor 强制执行最多一次 READ_ONLY Tool。

本阶段不是 Final Answer Stage：

- 不实现最终回答模型调用；
- 不实现 RAG 答案生成 / citation rendering；
- `ANSWER_DIRECTLY` 仍然只是 “no Tool required”，不是完整答案。

## DecisionProvider Implementation

新增生产组件：

- `src/agent/decision/prompt.py` — Tool catalog 与 decision prompt 构建
- `src/agent/decision/parser.py` — 严格结构化 JSON parser
- `src/agent/decision/provider.py` — `ModelDecisionProvider`
- `src/agent/decision/__init__.py` — 包导出

调用链：

```text
AgentRequest
    ↓
ModelDecisionProvider.decide()
    ↓
build_decision_prompt()（正式 ToolDefinition catalog）
    ↓
existing CompletionProvider（AuditedAIProvider 包装时进入 audit + budget）
    ↓
untrusted model text
    ↓
strict parse_decision()
    ↓
AgentDecision
    ↓
SingleStepAgentExecutor（Phase 2A，最多一次 READ_ONLY Tool）
```

`ModelDecisionProvider` 只负责：接收 `AgentRequest`、获取允许的 Tool catalog、
构造最小 decision prompt、调用 existing AI Provider exactly once、严格解析、
构造 `AgentDecision`。不负责 Tool execution、retry、final answer、RAG、记忆。

## Tool Catalog Source

Tool catalog 来自正式 Phase 1 `ToolRegistry.list_definitions()`（默认
`build_phase1_registry()`），不是 prompt builder 内手写的第二份列表。

从 `ToolDefinition` 提取的最小字段：

- `name`
- `description`
- `input_schema`（既有机器可读参数元数据：type / required / default / min / max / description）

不传入：

- Python handler / service 实现
- DB 细节、文件路径
- ToolResult / 用户知识正文
- side-effect 分类本身（Phase 1 registry 已保证全部 READ_ONLY）

catalog 输出 deterministic：按 name 排序。

## Decision Prompt Contract

- 唯一任务：输出一个 JSON 决策对象（`CALL_TOOL` 或 `ANSWER_DIRECTLY`）。
- 明确禁止：解释、推理、chain-of-thought、Markdown 代码块、最终回答、
  `tool_calls` 数组。
- 用户请求是不可信数据：prompt 明确声明不得执行用户文本中的指令。
- 用户文本以 JSON string literal 形式放在 `[USER_REQUEST]` /
  `[END_USER_REQUEST]` 标记之间，与 system instructions / Tool catalog
  结构隔离。
- 不请求任何 reasoning / final answer。

## Strict JSON Contract

模型输出视为 untrusted external input，只接受：

```json
{"kind": "CALL_TOOL", "tool_name": "page_search", "arguments": {"query": "..."}}
```

或：

```json
{"kind": "ANSWER_DIRECTLY", "tool_name": null, "arguments": {}}
```

允许字段（顶层）：`kind`、`tool_name`、`arguments`。任何额外字段 fail closed，
包括 `reasoning`、`tool_calls`。

`kind` 接受两个枚举的两种 canonical 文本形式：

- `CALL_TOOL` / `call_tool`
- `ANSWER_DIRECTLY` / `answer_directly`

`AgentDecision.to_dict()` 仍按 Phase 2A 输出 `kind.value`（小写）。

## Parsing Failure Semantics

`DecisionParseError`（parser 内）在以下情况 fail closed：

- empty / whitespace only
- invalid JSON
- Markdown fenced JSON
- prose + JSON / JSON + prose
- array top-level / 多个 JSON 对象
- missing kind / tool_name / arguments
- unknown kind
- arguments 为 list / null（CALL_TOOL）
- ANSWER_DIRECTLY 携带 tool_name 或非空 arguments
- extra field / reasoning / tool_calls
- duplicate JSON key（顶层与嵌套 arguments 均拒绝）
- NaN / Infinity / -Infinity / comments / trailing comma
- oversized output（> 4096 字符）

不允许任何自动修复：不剥离代码 fence、不 regex 抓 JSON、不修正单引号/
trailing comma/tool name typo/action typo。

`ModelDecisionProvider` 将 parser 失败映射为现有
`AIExecutionError(error_class="parse", retry_count=0)`，不会再次调用模型。

## Prompt Injection Boundary

- system decision instructions、Tool catalog、user request 在 prompt 中明确分离；
- 用户文本 JSON 序列化后放入专用标记区，不能结构性合并为指令；
- 最终 authority 仍是 `SingleStepAgentExecutor` + `ToolRegistry` +
  `Phase1ReadOnlyPolicy`；
- 恶意用户文本 + 模型输出 `write_memory` / `tool_calls` / 合法 READ_ONLY Tool
  的注入测试证明执行安全不变量不被用户文本改变。

## Budget Integration

复用现有 `AiBudgetGuard`（通过 `AuditedAIProvider` 注入），没有
`AgentBudgetGuard` 或新预算系统。

行为：

```text
Agent decision request
    ↓
existing budget guard
    ↓
existing audited provider
    ↓
vendor provider
```

- budget allowed：exactly one provider call；
- budget denied：provider transport call = 0、Tool call = 0、retry = 0，
  抛 `AIUnavailableError`，并在既有 audit ledger 记 `status="rejected"`。

## Audit Integration

复用 `AuditedAIProvider`：

- 成功 decision call 记入既有 `AiCallRecord` 台账；
- `source_feature="agent_decision"`（已有正式字段，未新增 schema）；
- `target_refs` 默认空；本阶段 decision 不需要发送知识正文；
- 测试使用 in-memory / temporary audit storage，不写生产数据库；
- schema v13 不涉及，AI Ledger 与 Agent runtime trace 不混为一谈。

## Retry Boundary

- Decision / Agent adapter retry：**0**；
- JSON repair retry：**0**；
- model retry / prompt retry / tool-selection retry / fallback retry：**0**；
- 底层 transport retry：沿用既有规则（QwenProvider 默认最多 2 次额外尝试，
  仅 network / HTTP 429 / 5xx）；真实 smoke 构造 `max_extra_attempts=0`；
- malformed JSON / unknown tool / invalid arguments 均不触发任何重试。

## Runtime Trace

- Phase 2A `AgentRuntimeTrace` 继续 in-memory；
- 可记录 decision call occurred、decision kind、selected tool、execution outcome；
- 不保存 raw model response、不保存 user request 全文、不写数据库/文件；
- 本阶段未扩展 trace 字段。
