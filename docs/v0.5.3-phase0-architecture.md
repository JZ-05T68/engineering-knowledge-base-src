## 1. v0.5.3 ADR 总体设计

### 1.1 版本定位

- 正式名称：**Agent-Ready Knowledge Foundation（Agent 就绪的知识基础收口版）**。
- 一句话定位：v0.5.3 不实现 Agent；它把 v0.5.2 已建好的知识资产层，补齐为未来 Agent
  可以**只通过统一知识消费接口**获得可信知识、来源、状态、版本与上下文的完整基础设施。
- 版本线冻结：

| 版本 | 主题 |
|---|---|
| v0.5.x | Knowledge Foundation（v0.5.2 资产层，v0.5.3 消费层收口） |
| v0.6.x | Agent Foundation |
| v0.7.x | Personal Experience Agent |
| v0.8.x | Agent Reliability |
| v0.9.x | Agent Hardening |
| v1.0.0 | Personal Experience System |

- v0.5.3 的核心交付物（只冻结设计，本阶段不实现）：
  1. **ContextItem**：页面 / KO / Memory / Evidence 四类知识实体统一投影契约。
  2. **KnowledgeContextPackager**：显式选择的多个 ContextItem 组装为机器可读 + Markdown
     上下文包，fail-closed。
  3. **Experience Model 基础结构**：KO + Memory + Project Link 三件套，覆盖错误/方法/
     判断/项目记录/决策/结果六类长期资产。
  4. **AI 调用台账**：`ai_calls` / `ai_outputs`，只记录审计信息，实现"可追踪、可控制"。
  5. **数据安全与迁移收口**：结构化导出（ADR-07）、v8 备份升级（ADR-08）、schema v12
     纯增量迁移。

### 1.2 为什么 v0.5.3 不进入 Agent

1. **Agent 需要可信上下文，而"可信"必须先有统一的消费端**。v0.5.2 已把来源、版本、
   状态做到数据层，但页面与知识仍是两套结果模型（GAP-1）。Agent 若直接读表，就会与
   PDF/页面/笔记的内部实现耦合，违背"Agent 不需要理解内部实现"的目标。
2. **Agent 行动必须可审计，而当前 AI 调用无台账**（GAP-3/GAP-5）。没有调用审计，Agent
   的每一步都无法解释"用了什么模型、消耗多少、依据哪些知识、输出能否复查"。
3. **Agent 需要记忆可读，而经验资产尚无完整结构落点**（GAP-6/GAP-7）。错误/方法/判断/
   项目记录/决策/结果散落在自由文本里，Agent 无从可靠回忆。
4. **Agent 需要知识可迁移，而结构化导出与旧备份升级仍缺失**（GAP-8/GAP-9）。知识不能
   无损迁移时，Agent 的输入边界不成立。
5. **语义召回与自动关联尚未实现**。此时进入 Agent，只能得到"黑盒聊天"或越界自动化，
   必然违反"无用户确认不得成为知识资产"的边界。

结论：v0.5.3 是 Agent 的**地基验收**，不是 Agent 的毛坯试装。

### 1.3 为什么 v0.6.0 才进入 Agent Foundation

- v0.6.x 的核心是**上下文选择与行动解释**，其正确性完全依赖 v0.5.3 的三件交付物：
  可信投影（ContextItem）、可审计调用（AI 台账）、可读记忆（Experience Model）。
- 顺序论证：
  - 无投影 → Agent 直接读表 → 与内部实现耦合；
  - 无台账 → Agent 行动不可审计 → 无法 fail-closed；
  - 无经验结构 → Agent 只有文档没有经验 → Personal Context 名不副实。
- 范围论证：把"上下文工程"与"知识基础设施"塞进同一个版本，会使范围爆炸、无法验收。
  v0.6.0 必须是第一个"有资格讨论 Agent"的版本；v0.5.3 是最后一个"纯知识基础"版本。
- 因此：**v0.5.3 交付 Agent 的"输入契约与审计底座"；v0.6.0 才开始消费这些契约。**

### 1.4 v0.5.3 与 v0.6.x 的边界

| 维度 | v0.5.3（做） | v0.6.x（做） | 两者都不做 |
|---|---|---|---|
| 上下文 | 用户显式选择 → 组装为 ContextPackage | 自动选择上下文 + 解释为什么选 | 无中生有生成知识 |
| 知识写入 | 仅用户手写；AI 输出只做审计登记 | 才允许 `authorship='ai'` 写入路径（仍需用户确认） | 静默覆盖用户知识 |
| 关联 | 显式关系 + 离线相似建议（用户确认才建链） | 自动关联候选 + 语义召回 | 自动建图/自动推理 |
| 语义检索 | 不实现 KO/Memory embedding | KO/Memory 语义召回 | 以语义替代来源核验 |
| AI 调用 | 台账 + 成本边界 + 有界重试 | 多轮会话/工具调用/流式 | 无界重试、Agent 循环 |
| 行动 | 无任何 Agent 循环、无自动任务 | 受控行动（v0.7.x 任务执行） | 自动代替用户决策 |

## 2. ContextItem 契约（V53-ADR-01）

### 2.1 目的

ContextItem 是未来 Agent 消费知识资产的**唯一统一投影**。页面、KO、Memory、Evidence
四类实体都能投影为同一形状；Agent 只认识 ContextItem，不认识任何内部表结构。

### 2.2 冻结投影类型

| `type` | 来源实体 | 投影内容 |
|---|---|---|
| `page` | `pages` | 页面文本（extracted → ocr → markdown 优先级）、页码、文档锚点、review_status |
| `knowledge_object` | `knowledge_objects` | title/content/kind/importance/lifecycle/确认/修订号/来源/关系 |
| `knowledge_memory` | `knowledge_memory_entries` | title/content/root_cause/lesson/outcome/context_conditions/status/关联 |
| `evidence` | `evidence_items` | evidence_text/选区/来源页面/确认状态 |

### 2.3 字段契约（冻结）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `type` | `ContextItemType`（四值） | 是 | 上述四类之一 |
| `local_id` | `int` | 是 | 数据库本地主键 |
| `stable_id` | `str` | 是 | 权威引用标识（见 2.4） |
| `title` | `str` | 是 | 实体标题；缺失用占位说明，不伪造 |
| `content` | `str` | 是 | 投影正文；可为空字符串（如无文本层页面） |
| `kind` | `str \| None` | 否 | KO kind / Memory kind / evidence type；page 为 None |
| `kind_label` | `str \| None` | 否 | 中文标签 |
| `status` | `str` | 是 | KO=lifecycle；Memory=status；page=review_status；evidence=confirmation_status |
| `status_label` | `str` | 是 | 中文标签 |
| `importance` | `str \| None` | 否 | 仅 KO 有；其余一律 None，**不伪造** |
| `updated_at` | `datetime \| None` | 否 | 实体的更新时间 |
| `revision_ref` | `str \| None` | 否 | KO：`current_revision`/`confirmed_revision` 描述；Memory：`content_revision`（v12 起） |
| `source_anchors` | `tuple[SourceAnchor, ...]` | 是 | 可回源锚点（见 2.5） |
| `relation_refs` | `tuple[RelationRef, ...]` | 是 | 已存储的直接关系投影（见 2.6） |

### 2.4 稳定 ID（V53-ADR-07）

- v0.5.3 将稳定 ID 命名空间从 v0.5.2 的五类（knowledge_object/knowledge_memory/
  knowledge_relation/knowledge_source/knowledge_revision）**扩展两类**：
  `page`、`evidence`。格式不变：`<kb_uuid>:<object_type>:<local_id>`。
- 扩展理由：ContextItem 的 `stable_id` 必须对四类投影一律非空，Agent 才能统一引用；
  否则 page/evidence 将退化为"无稳定标识的附带文本"。
- 影响：仅扩展 `src/models.build_stable_id` 的已知类型集合（纯函数层，无 schema 变更）。
- 不扩展：note、document 暂不进命名空间（v0.5.3 冻结范围控制）。

### 2.5 SourceAnchor 契约

| 字段 | 类型 | 说明 |
|---|---|---|
| `anchor_type` | `document \| page \| note \| evidence \| selection \| image_region` | 锚点类别 |
| `anchor_id` | `int \| None` | 锚点本地 ID（selection/image_region 可为 None） |
| `anchor_label` | `str` | 中文可读描述（如"文档 3 / 第 12 页"） |
| `fingerprint_state` | `valid \| changed \| missing \| unknown \| not_applicable` | 来源指纹状态；不适用场景显式 not_applicable |

- KO 的 source_anchors 直接投影其 `knowledge_object_sources`（含指纹状态）；
- page/evidence 的 source_anchors 投影其文档/页面锚点；Memory 投影 KO/document/page 关联。
- 投影**只读**：不在读路径写库、不重算并回写指纹（与 v0.5.2 ADR-03 一致）。

### 2.6 RelationRef 契约

| 字段 | 类型 | 说明 |
|---|---|---|
| `relation_type` | 六类关系枚举 | relates_to/derived_from/supports/contradicts/example_of/requires |
| `direction` | `outgoing \| incoming` | 以当前 item 为视角 |
| `target_stable_id` | `str` | 关系另一端的稳定 ID |

- 仅投影**已存储的直接关系**；不做传递闭包、不做图推断、不做关系补全。

### 2.7 投影规则与禁止项（fail-closed）

- 目标行不存在 → 投影失败（返回 MISSING 错误信息），**不返回半成品**。
- 字段缺失 → `None` 或空字符串，**不推断、不补全、不生成摘要**。
- 页面无文本层 → `content=""` 且 `source_anchors` 正常；由上层决定是否纳入。
- **明确禁止**：自动选择知识、自动推理、自动生成知识、自动 OCR、自动重算指纹并写库、
  自动把相似内容合并。ContextItem 只负责可信投影。

## 3. ContextPackage 设计（V53-ADR-02）

### 3.1 目的

`KnowledgeContextPackager` 将**用户显式选择的**多个 ContextItem 组装为 Agent 可消费的
上下文包。它是 v0.6.x Agent 的输入格式的 v0.5.3 预实现，但本身不含任何选择、推理或
Agent 逻辑。

### 3.2 输入

| 输入 | 说明 |
|---|---|
| `items` | 显式提供的 ContextItem 序列（必须非空） |
| `question`（可选） | 用户问题，可写入包头部 |
| `include_archived` / `include_superseded` | 默认 False；显式开启才纳入 |
| `limits` | `max_items`、`max_chars_per_item`、`max_total_chars`（默认值由实现期冻结） |

### 3.3 输出一：机器可读 JSON（字段契约）

| 块 | 内容 |
|---|---|
| `manifest` | `package_uuid`、`generated_at`、`app_version`、`schema_version`、`kb_uuid`、`item_count`、`excluded_count`、`enums` 字典 |
| `items` | 按输入顺序的 ContextItem 全字段投影 |
| `citations` | `stable_id → item 序号` 的引用映射（权威交叉引用只用 stable_id） |
| `excluded` | 被拒绝/排除项列表：`stable_id` + `reason` |

### 3.4 输出二：Markdown（结构约定）

- 包头部：用户问题、生成时间、知识库稳定 UUID、包含/排除统计。
- 每个 item 一个区块：标题、类型/状态徽标、稳定 ID、修订号、来源列表（含指纹状态）、
  直接关系（relation_refs 的可读形式）、正文。
- 非 VALID 来源、archived/superseded、未确认/确认基于旧版 → 区块内醒目警告行。

### 3.5 必含信息（不可省略）

来源（source_anchors + 指纹状态）、版本（revision_ref）、生命周期状态（status）、
引用关系（relation_refs）、stable_id。以上五项缺一不可；无法提供的项必须显式标注
"不可用"并给出原因，不得静默省略。

### 3.6 fail-closed 规则（冻结）

| 场景 | 行为 |
|---|---|
| 空上下文（items 为空） | **拒绝生成**，抛出/返回"空上下文"错误；绝不产出无根提示 |
| 全部 item 被排除 | 同空上下文处理：拒绝生成 |
| 目标已不存在（投影失败） | 默认**整体失败**；仅当调用方显式 `allow_partial=True` 时，才把失败项放入 `excluded` 并继续 |
| 来源状态 CHANGED / MISSING / UNKNOWN | **默认保留并标注警告**，不自动删除；对象级"外部证据充分性"为否 |
| archived / superseded | 默认排除并写入 `excluded`（reason 注明）；显式包含时带"仅作历史参考"徽标 |
| 超过字符上限 | 按 `max_chars_per_item` 截断并加截断标记；截断后仍超总上限 → 拒绝生成 |
| 任何内部异常 | fail-closed：不产出半成品包，错误信息给出中文原因 |

### 3.7 明确禁止

- 不调用 AI、不生成摘要、不改写正文、不自动合并重复项；
- 不自动选择、不自动补全、不自动排序（保持输入顺序；排序是 v0.6.x 选择器的职责）；
- 不把 archived/superseded 静默当作现行知识。

## 4. Experience Model 基础设计（V53-ADR-03）

### 4.1 原则

**不新建 Experience 大表。** 用既有 KO + Memory + 新增 Project Link 三件套覆盖六类长期
资产。理由：

1. v0.5.2 已证明 KO + Memory 双实体足以承载"知识资产 vs 个人记忆"的语义分离；
2. 新建大表需要迁移历史数据、新增 UI 心智负担，收益低于增量扩展；
3. 六类资产是**内容维度**，不是**实体维度**——应由 kind/epistemic_basis/字段承载，而不是
   由表名承载；
4. 纯增量迁移（加列 + 新关联表）风险远低于重建表。

### 4.2 六类资产的落点映射（冻结）

| 用户资产 | 主落点 | 关键字段 | 说明 |
|---|---|---|---|
| 错误 | Memory `problem_solving` | `root_cause`、`lesson`、`outcome` | 错误→根因→教训→结果闭环 |
| 方法 | KO `principle` / `experience` 或 Memory `experience` | KO.content；Memory.`context_conditions` | 适用条件/边界由 Memory 承载或 KO content 约定小节 |
| 判断 | KO `epistemic_basis=personal_judgment` 或 Memory `experience` | 确认状态 + 来源链接 | 判断可与证据链接并存，basis 不因链接自动改写 |
| 项目记录 | `projects` + `knowledge_project_links` | project.status/description + 挂接 KO/Memory | 项目从"文件容器"升级为"知识容器" |
| 决策 | KO `decision`（basis=`decision_record`）或 Memory `decision` | 确认状态 + 结果回看 | 决策的后果用 Memory.outcome 或 KO supersedes 链回看 |
| 结果 | Memory `outcome`（第一等字段）或 KO supersedes 链 | `outcome`；`superseded_by_ko_id` | "一次行动的结果"与"结论被更新"分开表达 |

### 4.3 Memory 增量字段（schema v12）

| 字段 | 类型/枚举 | 默认 | 说明 |
|---|---|---|---|
| `content_revision` | INTEGER NOT NULL CHECK(>=1) | 1 | 每次内容编辑 +1；轻量版本号，供引用与"内容已变化"判断 |
| `outcome` | TEXT NOT NULL（服务层 ≤4000） | '' | 结果/后果；错误闭环的终点 |
| `context_conditions` | TEXT NOT NULL（服务层 ≤4000） | '' | 适用条件/边界/失效条件；方法/判断的可复用前提 |

- Memory **仍不建独立 revision 表**（范围控制）；`content_revision` 提供最小版本可引用性。
  完整 before/after 修订延后至 v0.6.x+ 再评估。
- 现有行回填：`content_revision=1`，`outcome=''`，`context_conditions=''`，不虚构历史。

### 4.4 `knowledge_project_links`（schema v12）

| 字段 | 类型/枚举 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `project_id` | INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE | 项目删除只删链接，不动 KO/Memory |
| `target_type` | `knowledge_object \| knowledge_memory` | 多态引用，服务层写前校验 |
| `target_id` | INTEGER NOT NULL | 目标本地 ID |
| `created_at` | TEXT NOT NULL | |
| 约束 | UNIQUE(project_id, target_type, target_id) | 防重复挂接 |

- KO/Memory 删除时级联删除其 project 链接（不碰项目本体）。
- 不提供图查询、不做自动关联；仅作为"项目 ↔ 知识资产"的显式聚合轴。

### 4.5 为什么这样设计（论证）

- 复用成熟实体，不发明新概念：用户已理解 KO 与 Memory，新增字段与一个关联表即可覆盖
  六类资产。
- 增量迁移低风险：三列 ALTER + 一张新表，不重建任何既有表。
- 语义正交：错误/方法/判断/决策由 kind + epistemic_basis 区分；结果由 outcome 字段与
  supersedes 链区分；项目由关联表聚合。
- 未来可演进：若 v0.7.x 需要更强经验语义，可在本结构上追加字段或迁移到专门表，而不破坏
  v0.5.3 数据。

## 5. AI 调用台账设计（V53-ADR-04 / V53-ADR-05）

### 5.1 原则

- 只记录**审计信息**；台账是 append-only 的事实记录。
- **禁止保存 API Key、禁止保存完整 prompt 原文、禁止保存完整响应原文、禁止自动生成知识。**
- 台账写入失败不阻断业务主流程，但必须记录 critical 日志；目标是"调用即落账"。

### 5.2 `ai_calls`（一次调用一行，append-only）

| 字段 | 类型/枚举 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `call_uuid` | TEXT NOT NULL UNIQUE | uuid4，单次调用全局唯一标识 |
| `capability` | `completion \| embedding \| rerank` | 能力通道 |
| `model` | TEXT NOT NULL | 实际使用的模型名 |
| `prompt_sha256` | TEXT NOT NULL（64 hex） | prompt/输入文本的 SHA-256，**不存原文** |
| `input_chars` | INTEGER NOT NULL DEFAULT 0 | 输入字符数（非秘密长度，用于成本估算） |
| `status` | `success \| error \| rejected` | success=调用成功；error=尝试后失败；rejected=预算/预检拒绝（未发网络请求） |
| `error_class` | TEXT NULL，枚举 `transport/http_4xx/http_429/http_5xx/parse/budget/timeout/unavailable` | 仅 error/rejected 时有值 |
| `retry_count` | INTEGER NOT NULL DEFAULT 0 CHECK(>=0) | 实际发生的额外重试次数 |
| `latency_ms` | INTEGER NULL | 总耗时（含重试） |
| `prompt_tokens` / `completion_tokens` / `total_tokens` | INTEGER NULL | 供应商报告的用量；缺失不伪造 |
| `finish_reason` | TEXT NULL | completion 结束原因 |
| `source_feature` | TEXT NOT NULL | 发起功能（如 hybrid_search/page_indexer/knowledge_context/manual_smoke） |
| `target_refs` | TEXT NOT NULL DEFAULT '[]' | JSON 数组，引用目标 stable_id/锚点 |
| `created_at` | TEXT NOT NULL | UTC ISO 8601 |

索引：`(created_at)`、`(source_feature, created_at)`、`(status)`。

### 5.3 写入位置（架构约束）

- 台账写入放在 **`src/ai/provider.py` 契约层的日志包装器**（vendor-neutral wrapper）中，
  包装 `CompletionProvider` / `EmbeddingProvider`；**不侵入** `qwen_client.py` 的供应商细节。
- 业务服务永远只依赖契约层；供应商替换不影响台账。
- `application_ai_provider()` 返回的 provider 必须经过该包装器。

### 5.4 成本控制（V53-ADR-05）

| 机制 | 设计 |
|---|---|
| 重试上界 | `config.py` 新增 `ai_max_extra_attempts`（默认 2，取值 0..2）；修正 `runtime.py` 硬编码 `max_extra_attempts=0` |
| 超时 | 沿用 `ai_timeout_seconds`（已有） |
| 单次调用上限 | 沿用 `max_completion_tokens` 调用参数；默认值由配置冻结 |
| 预算 | 新增可选 `ai_daily_token_budget` / `ai_monthly_token_budget`（0=不限制）；调用前按当日/当月累计 token 预检，超限 → `status=rejected`，**不发网络请求** |
| 货币换算 | **v0.5.3 不做**（价格随供应商浮动）；预算单位=token，与供应商解耦 |

### 5.5 `ai_outputs`（用户显式登记的 AI 输出审计锚点，append-only）

| 字段 | 类型/枚举 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `output_uuid` | TEXT NOT NULL UNIQUE | 输出登记唯一标识 |
| `call_uuid` | TEXT NULL（普通列，无 FK） | 关联调用；缺失时仍可独立登记 |
| `model` | TEXT NOT NULL | 生成模型 |
| `context_package_sha256` | TEXT NULL | 输入上下文包 SHA-256 |
| `output_sha256` | TEXT NOT NULL | 输出内容 SHA-256（防篡改、可复查） |
| `output_kind` | `imported_answer \| prompt_package` | 用户导入的 AI 回答 / 用户生成的提示词包快照 |
| `source_feature` | TEXT NOT NULL | 来源功能 |
| `target_refs` | TEXT NOT NULL DEFAULT '[]' | JSON 数组，引用的知识 stable_id |
| `recheck_path` | TEXT NULL | 本地复查路径（用户保存输出到的笔记/KO/文件位置） |
| `created_at` | TEXT NOT NULL | UTC ISO 8601 |

- **不存输出全文**：输出全文由用户通过既有笔记/KO/文件持久化；`ai_outputs` 只做审计锚点，
  复查 = 引用对象 + `output_sha256` 核对。
- **不自动登记**：只有用户显式"导入 AI 回答"或"生成/复制提示词包"时才写一行。
- **不自动生成知识**：登记 ≠ 写入 KO；写入 KO 仍需用户手动创建，v0.5.3 保持
  `authorship='ai'` 写入被服务层拒绝。

## 6. 数据安全边界（V53-ADR-08）

### 6.1 必须保持（不变量）

| # | 不变量 |
|---|---|
| S1 | Local-first：SQLite + 本地文件是唯一事实来源 |
| S2 | 单用户：无注册、无登录、无账号、无密码、无多用户权限 |
| S3 | 默认绑定 `127.0.0.1:8501`，不暴露局域网 |
| S4 | 无 API Key 泄露：Key 只存在于 `SecretStr`；不入库、不入日志、不入备份、不入测试快照 |
| S5 | AI 不可成为启动依赖：无 Key 时 PDF/搜索/阅读/笔记/证据/知识/备份全部离线可用 |
| S6 | 自动化不得静默覆盖原始资料、用户笔记或知识资产 |
| S7 | 备份/恢复/删除对新增表（ai_calls/ai_outputs/knowledge_project_links）同样覆盖 |
| S8 | AI 调用只做有界重试（网络错误、429、5xx，最多额外 2 次）；语义不满意零重试 |

### 6.2 明确禁止

| # | 禁止项 |
|---|---|
| P1 | 自动画像（不收集行为、不学习偏好、不推断用户特征） |
| P2 | 自动经验学习（未经用户确认的推断不得成为正式知识资产） |
| P3 | 自动写入知识（AI 输出不得自动成为 KO/Memory/笔记/证据） |
| P4 | Agent 循环（无多步自主行动、无自我改进循环、无自动重复付费调用） |
| P5 | 自动修改用户知识（任何持久化变更必须用户显式操作） |
| P6 | 保存 API Key、prompt 原文、响应原文到数据库/日志/备份 |
| P7 | 把 archived/superseded/未确认内容静默当作现行事实 |

## 7. schema v12 设计草案（V53-ADR-06，只设计不执行）

### 7.1 迁移原则

- **全部纯增量**：只 `CREATE TABLE` 新表、`ALTER TABLE ... ADD COLUMN` 加列；不 drop、
  不 recreate、不重建任何既有表与 FTS。
- 迁移前自动备份；迁移中事务 + 核心数据指纹；迁移后行数/id 集合/内容哈希核验。
- v12 应用后不再回改；后续结构变化只能开新版本。

### 7.2 新增表

- `ai_calls`（字段见 5.2）
- `ai_outputs`（字段见 5.5）
- `knowledge_project_links`（字段见 4.4）

### 7.3 修改表：`knowledge_memory_entries`（纯加列）

| 加列 | 类型 | 默认 | 回填 |
|---|---|---|---|
| `content_revision` | INTEGER NOT NULL CHECK(>=1) | 1 | 现有行回填 1 |
| `outcome` | TEXT NOT NULL | '' | 现有行回填 '' |
| `context_conditions` | TEXT NOT NULL | '' | 现有行回填 '' |

- 服务层增加校验：outcome/context_conditions ≤4000 字符；`content_revision` 随内容编辑 +1。
- 现有 Memory FTS（search_title/search_content/search_root_cause/search_lesson）**v12 不改**：
  outcome/context_conditions 暂不进 FTS（避免 FTS 重建风险）；其可检索性列为延后项，
  经真人验证后如需再开 v13 纯增量扩展 shadow columns + rebuild。

### 7.4 稳定 ID 命名空间扩展（无 schema 变更）

- `build_stable_id` 已知类型增加 `page`、`evidence`（V53-ADR-07，见 2.4）。

### 7.5 迁移保护核验项（冻结）

- `knowledge_objects`：行数、id 集合、业务字段内容哈希不变；
- `knowledge_memory_entries`：行数、id 集合、既有字段内容哈希不变（仅新增三列）；
- `knowledge_object_sources` / `knowledge_object_relations` / `knowledge_object_revisions`：
  行数与内容不变；
- `documents` / `pages` / `notes` / `evidence_items` / 页面 FTS：完全不变；
- 允许变化项仅：新增三张表、Memory 三列回填、`schema_migrations` 新增 version 12。
