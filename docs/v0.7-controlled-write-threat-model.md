## 1. 目的、范围与方法论

### 1.1 目的

对 v0.7 受控写能力（create / undo / restore 三个确定性 WriteCommand）做系统性威胁
建模：穷举攻击面、逐项指认拒绝层与 typed 结果、区分**已闭合**（结构性防御）、
**已缓解**（纵深降低而非消除）、**明示接受**（产品边界内的取舍）与**开放项**
（必须在实现前解决的 blocker），并映射到具体测试锚点。产出直接服务 Phase 8
对抗测试与发布门禁增补。

### 1.2 方法

1. 以 ADR-010 权威层级（六层）为轴，对每层假设"该层被完全攻陷"推演可达后果
   （权威 Walk）；
2. 以信任边界（§4）为轴做 STRIDE 式枚举（Spoofing / Tampering / Repudiation /
   Information Disclosure / Denial of Service / Elevation of Privilege）；
3. 逐项引用现行仓库事实（源码/测试/冻结规格）指认拒绝层——**没有仓库事实支撑的
   "应该安全"一律记为开放项**；
4. 继承并复核 N-7 更正后的批准/幂等组合面（§7）。

### 1.3 范围外（明示）

- 物理安全、操作系统级攻陷、磁盘加密、恶意 USB 等平台层威胁；
- Local 进程与用户之间的身份认证（产品明文无账号体系，AGENTS.md 边界）；
- 传输安全（写路径无网络传输面；Hosted 仍 READ_ONLY）；
- 供应链（依赖投毒等——独立议题，不在 v0.7 受控写增量内）；
- 防御"用户蓄意滥用自己本地的系统"（T-I 类，明示接受，§9）。

## 2. 权威模型与安全不变量回顾

### 2.1 权威层级（ADR-010 冻结；本模型的安全公理）

| 参与者 | 权威 | 明确不具备 |
| --- | --- | --- |
| 导入来源/文档/Tool 输出 | 信息（information only） | 发起、批准、提交 mutation |
| 模型 | 提案/组织 | 把输出当事实、提交 mutation、构造批准或命令 |
| Agent | 提案/编排 | mutation approval / commit；对写服务不可达 |
| 用户 | 唯一显式 mutation approval authority | 绕过应用校验或 DB 约束 |
| 应用服务 | 策略执行（allowlist/校验/哈希/键绑定/幂等） | 替用户创造批准意图 |
| 数据库 | 验证后的确定性提交 | 解释提示、推断事实、放宽 allowlist |

### 2.2 安全不变量清单（SI；本模型逐威胁引用）

| # | 不变量 | 来源 |
| --- | --- | --- |
| SI-1 | 内容对写的触发与批准权威为零；只有本地 UI 显式动作能发起 | ADR-010 §Authority |
| SI-2 | 写入载荷 ≡ 批准载荷（payload_sha256 绑定）；变化必须重新批准 | ADR-010 Approval boundary |
| SI-3 | 一次显式 CREATE 批准至多授权一次逻辑 CREATE 变异——服务级强制（N-7）：令牌在场 ∧ 载荷哈希相等 ∧ 命令键 == token.approved_idempotency_key | WriteCommand 详规 §0/§12.2（N-7） |
| SI-4 | 同一幂等键永不创建第二条经验（UNIQUE + 事务内首查） | ADR-010 Transaction boundary |
| SI-5 | 无 write audit 的成功 mutation 不可达（审计/命令日志同事务） | ADR-010 / 评审 §19 |
| SI-6 | 事务失败零残留（经验/链接/provenance/FTS/日志/幂等行） | ADR-010 Security invariants 6 |
| SI-7 | registry 恰七 READ_ONLY Tool；executor 单步；写服务对 Agent 不可达 | ADR-010 §2 / §39 |
| SI-8 | Hosted 不 import/不构造/不暴露写服务；无 HTTP 写端点；无认证体系 | ADR-010 §8 / ADR-007 |
| SI-9 | undo/restore 仅限受控 create 日志链上的目标；墓碑只属命令链 | ADR-011 §5 / 详规 A §28 |
| SI-10 | 命令日志/审计仅存标识、枚举、哈希、长度、目标与时间——零正文/prompt/CoT/密钥/路径 | ADR-010 最小审计数据 |
| SI-11 | 正确性不依赖 UI 防抖/会话正确性（服务边界兜底） | WriteCommand 详规 §31/§36.2 |
| SI-12 | 上下文关联永不派生为证据性支撑；持久 origin 不因关联改变（N-6） | 详规 A §13 |
| SI-13 | 幂等键不是授权；内容哈希不是命令身份；令牌不持久化 | 详规 A §18 / §22 |

## 3. 资产清单

| 资产 | 敏感性 | 主要载体 | 威胁方向 |
| --- | --- | --- | --- |
| 用户经验内容（含 outcome 等用户断言） | 高（用户知识资产） | `knowledge_memory_entries`、会话草稿 | 未授权写入/篡改、静默删除、泄漏进日志 |
| 区块 origin/provenance 标注 | 高（认识论真实性） | `knowledge_memory_block_provenance` | 被静默升格/洗白（AI 内容冒充用户断言） |
| 来源关联与快照 | 中高（可回源性） | `knowledge_memory_sources` | 伪造关联、失效后伪装有效、歧义关系 |
| 批准令牌（载荷哈希 + 键） | 高（授权凭证，会话内） | `st.session_state` | 复用、跨会话、伪造、范围外使用 |
| 命令日志 | 中（审计/幂等真相） | `experience_command_log` | 篡改、删除、伪造成功行、内容泄漏 |
| 幂等键 | 低（不透明标识，非授权） | 会话 + 命令日志 | 误当授权、键复用冲突 |
| AI API key | 高（付费凭据） | env/.env → SecretStr | 泄漏进日志/错误/快照 |
| 来源材料（PDF/图像/文本） | 高（用户资产） | 本地文件 + DB | 被写路径改写/删除（SI 之外的红线） |
| 预算 | 中（成本控制） | `ai_calls` + budget guard | 绕过审计的付费调用 |

## 7. N-7 闭合复核

N-7（批准一次性范围/幂等键绑定缺口）已于 `313c590` 闭合：

1. **复现确认**：原两字段令牌下，同一令牌可被异键复用为第二次独立提交（详规 §0
   数学复现）——原"哈希绑定 ⇒ 只可能提交一次"论证无效；
2. **闭合机制**：令牌三字段（+`approved_idempotency_key`）+ 服务三条件校验 +
   批准期键生成（提交路径零键生成点）；
3. **组合安全证明（更新后有效）**：令牌只授权 (P,K) 一对 ∧ 幂等层保证 (P,K) 至多
   提交一次 ⇒ 一次批准至多一次逻辑变异——不依赖 UI 约定、不依赖消费时机；
4. **规则 B 存活**：失败重试/commit-unknown 重放/双击行为全部保留（§45.1 N7-3/N7-4/N7-7）；
5. **二次扫描**：闭合后对 §6 全目录重扫——B 类其余威胁与 C/D 类不受键绑定影响；
   undo/restore 因无令牌且状态机单向（第二次异键 undo/restore 落入
   `STATUS_CONFLICT`，零状态破坏）无同类缺口。

**结论：N-7 闭合未揭示新的立即授权 blocker。**
