## 3. schema v10 变更

### 3.1 `knowledge_base_meta`（新表）

- `id INTEGER PRIMARY KEY CHECK (id = 1)`、`kb_uuid TEXT NOT NULL UNIQUE
  CHECK(length(kb_uuid)=36)`、`created_at TEXT NOT NULL`。
- 迁移时以 `uuid4()` 本地生成小写 UUID；单行约束；重复启动不改变；随备份/恢复迁移。

### 3.2 `knowledge_objects`（重建）

- 移除：`status`、`reviewed_at`。
- 新增/冻结：`authorship`(user/ai)、`epistemic_basis`(七值)、`lifecycle`
  (active/superseded/archived)、`superseded_by_ko_id`（FK → knowledge_objects(id)
  **ON DELETE RESTRICT**）、`confirmation_status`(unconfirmed/confirmed)、
  `confirmed_at`、`confirmed_revision`、`current_revision`。
- 保留：`id/title/content/kind/importance/created_at/updated_at`。
- CHECK：kind/ authorship/ basis/ lifecycle/ confirmation 枚举；`current_revision>=1`；
  confirmed 对（confirmed_at + confirmed_revision 非空，unconfirmed 时 confirmed_at
  为空）；`confirmed_revision IS NULL OR <= current_revision`；lifecycle 与 pointer
  不变量（active/archived 必须 pointer NULL，superseded 必须非空）。
- 索引：kind/importance/lifecycle 各 `(x, updated_at DESC)`、`superseded_by_ko_id`。
- 迁移方式：create-copy-validate-drop-rename（自引用 FK 经实测可正确重命名）；
  行数/id 核验 + `_core_data_fingerprint`。

### 3.3 `knowledge_object_sources`（纯增量加列）

- 新增 `source_fingerprint TEXT`（NULL=UNKNOWN）、`fingerprint_version INTEGER
  NOT NULL DEFAULT 1`、`captured_at TEXT NOT NULL DEFAULT 迁移时间`。
- 旧行 fingerprint 回填为 NULL，不伪造；Phase 2C 实现状态机。

### 3.4 `knowledge_memory_entries`（重建）

- kind 仅 `problem_solving/experience/decision`（`knowledge_change` 移除）；
- 新增 `status`(active/archived)；保留 id/title/content/root_cause/lesson/
  knowledge_object_id/document_id/page_id（FK SET NULL）/时间戳。
- 用户 Memory 行保留原 ID；旧 `knowledge_change` 行迁出。

### 3.5 `knowledge_object_revisions`（新表）

- 无 FK（`knowledge_object_id` 为普通数据列）；身份快照
  `object_local_id_snapshot/object_stable_id_snapshot/object_title_snapshot/
  object_kind_snapshot`；`revision_number`；`event_type` 九值（含 legacy_baseline/
  legacy_event）；before/after 全字段；`payload_version`；`detail`；`created_at`。
- `UNIQUE(knowledge_object_id, revision_number)`；索引 object / stable id。
- 无 update/delete API（database 与 service 层均不暴露）。

### 3.6 `SCHEMA_VERSION = 10`

- 迁移链 1..10；v10 应用后不回改（FTS 留 v11，Phase 3）。

## 4. v9 → v10 数据映射

- Knowledge Object：`draft → active + unconfirmed`；`reviewed → active + confirmed`
  （`confirmed_at=旧 reviewed_at`，`confirmed_revision=baseline 编号`）；
  `archived → archived + unconfirmed`（v9 归档时 reviewed_at 已清空，保守不宣称确认）；
  `authorship='user'`；`epistemic_basis='unknown_legacy'`（不推测）；ID/kind/importance/
  title/content/created_at/updated_at 保留；`current_revision = 旧日志数 + 1`。
- legacy 事件：旧 `knowledge_change` 按 `created_at ASC, id ASC` 编号 1..n 迁移为
  `legacy_event`（before/after 全 NULL，不伪造历史；detail 存旧日志文本；
  object 快照取迁移时值）；每对象追加 `legacy_baseline`（编号 n+1，after_content=
  当前内容，created_at=迁移时间）；孤儿日志 knowledge_object_id=NULL、
  revision_number=0、title 从日志标题解析；无日志对象 baseline=1。
- Memory：用户三类行原 ID 保留、status='active'；knowledge_change 行全部迁出。
- Source：旧行保留，`source_fingerprint=NULL`、`fingerprint_version=1`、
  `captured_at=迁移时间`。
- Relation：对象 ID 不变，关系行不变。

## 5. Knowledge Base UUID 与稳定 ID

- `kb_uuid = uuid4()` 在 v10 迁移时本地生成，写入 `knowledge_base_meta` 单行；
  数据库重复打开不改变（测试覆盖）；备份/恢复随库迁移。
- 稳定 ID：`<kb_uuid>:<object_type>:<local_id>`；共享纯函数
  `src.models.build_stable_id`；`Database.knowledge_object_stable_id` 提供 KO 便捷
  方法；Revision 写入时把稳定 ID 存入 `object_stable_id_snapshot`。

## 6. Revision 实现

- 事件：`created / content_updated / confirmation_changed / lifecycle_changed /
  supersession_changed / source_linked / source_unlinked`（+ legacy 两类）。
- before/after：内容更新保存完整 before/after title/content；确认/生命周期/替代
  保存对应 before/after 字段；source 事件保存 `source_ref`（如 `page:42`）。
- `revision_number` 为每对象事件序列（`MAX+1`）；`current_revision` 指向最新
  内容型事件编号；确认绑定该编号。
- 事务：`Database.knowledge_transaction()`（BEGIN IMMEDIATE）承载业务写 + revision
  写；任一失败整体回滚（有失败注入测试）。
- 不可变：database/service 无 update/delete；对象删除后 revision 行字节级不变
  （无 FK，测试覆盖）。

## 7. Confirmation 实现

- `confirm`：确认当前内容（`confirmed_at` + `confirmed_revision=current_revision`）；
  已确认且当前 → 幂等（不增长 revision）；旧版确认后再 confirm → 重新绑定当前版。
- `unconfirm`：置 unconfirmed + 清空 confirmed_at/confirmed_revision；幂等。
- 内容修改：`current_revision` 递增；`confirmed_revision` 保留 →
  `confirmation_is_stale`（确认基于旧版）自然成立；不自动重新确认。
- 无来源个人经验可以确认（确认与来源解耦，ADR-02）。

## 8. Lifecycle 与 supersedes

- 动作：`archive / unarchive / supersede / reactivate / repoint_supersession`。
- 不变量：active/archived 必须 pointer NULL；superseded 必须 pointer 非空（DB CHECK
  为第二道防线）；superseded→archived 必须先 reactivate（服务层拒绝直接跳转）。
- 校验：自指拒绝；后继必须 active；`_supersession_chain_reaches` 防传递循环
  （active 后继规则使其在 v0.5.2 为防御性检查）。
- 删除：`delete` 前统计 `inbound_supersession_count`，>0 拒绝并给出中文处置建议；
  DB `ON DELETE RESTRICT` 为第二道防线（DB 层翻译为中文错误）。
- 每次状态变化写 `lifecycle_changed/supersession_changed` revision。

## 9. Personal Memory

- `knowledge_memory_entries` 只保存用户主动 Memory；`knowledge_change` 已迁出且
  枚举移除（DB CHECK + 服务层双重拒绝）。
- CRUD + `set_status`（archive/reactivate）；列表/计数支持 kind/status 过滤。
- 关联 KO/document/page 写前校验；删除 KO/document/page 后按 SET NULL 保留记忆。
- 系统 Revision 与用户 Memory 完全分离；UI 不再展示系统日志。

## 10. 服务层与兼容性

- 服务层全部走新契约；`KnowledgeObjectService.create` 固定 user authorship、

- 页面 14/15 与 UI 模块做机械兼容：新建表单含“形成依据”选择；卡片显示
  kind/importance/lifecycle/确认徽标/替代徽标；状态操作含确认/取消确认/归档/
  重新启用/重新启用（解除替代）；删除预检中文报错；记忆页含归档/重新启用。
