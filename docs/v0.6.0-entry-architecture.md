# EKB v0.6.0 Entry Architecture

## 1. Context

本文档是 EKB 进入 v0.6.0 Agent Foundation 之前的架构冻结输入。它基于真实代码审计
（`src/ai/provider.py`、`src/runtime.py`、`src/ai/rag_answer_service.py`、
`src/knowledge_context_packager.py`、`src/knowledge_object_service.py`、
`src/knowledge_memory_service.py`、`src/source_fingerprint.py`、
`src/evidence_basket_service.py`、`src/ai_ledger_service.py`、`src/config.py`、
`src/models.py` 与 v0.5.3 Decision Gate），不是基于提示词想象。

配套 ADR：`docs/adr/ADR-006-agent-foundation.md`。

## 2. v0.5.x Foundation Accepted

本阶段默认接受 v0.5.x 已完成其 Knowledge / Retrieval / AI Foundation 职责：

- v0.5.3 Decision Gate 结论为 **CONDITIONAL GO**（HIGH），唯一 BLOCKER 是 Workspace
  Hygiene，已通过治理提交 `497ddc8` 解决，不再重新审查。
- 决策门已确认 9 项能力没有 NOT READY；核心事实读取能力已达服务级 READY。
- 服务层不依赖 Streamlit / `st.session_state`；UI 与 service 边界基本干净；Agent
  不需要模拟点击页面即可调用核心能力。
- 本阶段不重新打开 v0.5.x 大规模开发。

## 3. v0.6.0 Goal

v0.6.0 不从"做一个很聪明的 Agent"开始，而是建立：

> 最小、可控、可审计、可测试的 Agent execution foundation。

第一阶段只做：

- Read-only、Single-step、No loop、No autonomous write、No background execution、
  No hidden side effects、No uncontrolled retry、No unlimited token / tool calls。

## 4. Non-goals

v0.6.0 第一阶段明确不做：

- 不实现多步 / 循环 / 递归规划 / 自我重试 / 后台延续；
- 不实现任何写类 Tool（WRITE_REVERSIBLE / WRITE_DESTRUCTIVE 一律不进入 allowlist）；
- 不引入 LangChain / LangGraph / CrewAI / AutoGen / MCP framework / 队列 / 微服务 /
  事件总线 / 工作流引擎 / 向量数据库替换 / PostgreSQL；
- 不做公网部署（Public Deployment 是独立 Gate，见 §14）；
- 不做 schema v13 migration（见 §13）；
- 不修改 v0.5.x 生产行为。

## 5. Agent Execution Model

### 5.1 最小 Run

```
User Request
  ↓
Agent Decision（structured model decision，1 次 completion）
  ↓
action = CALL_TOOL | ANSWER_DIRECTLY
  ↓（CALL_TOOL）
Select One Tool（allowlist 内，READ_ONLY only）
  ↓
Execute One Tool（ToolAdapter → Existing Service → Structured ToolResult）
  ↓
Receive Structured Result
  ↓
Generate Final Response（RAG Answer stage，1 次 completion，citation 校验）
  ↓
Citation（lineage 校验，fail-closed）
  ↓
Audit（run / step / tool_call runtime trace + 既有 ai_calls 台账）
```

### 5.2 第一阶段上限

| 约束 | 值 |
|---|---|
| max tool calls / run | **1** |
| max model calls / run | **2**（1 decision + 1 final answer）|
| max steps / run | **2**（decision step + tool/answer step）|
| autonomous retry | **0** |
| loop | **禁止**（单步结构天然无环）|
| write / side effect | **禁止**（allowlist 仅 READ_ONLY）|

`ANSWER_DIRECTLY` 分支：不调用 Tool，不调用模型，返回规则化边界回答（拒绝/澄清），
step_type=`answer_direct`，model calls=1（仅 decision），tool calls=0。

## 6. Tool Contract

Agent 不直接依赖具体 service 实现。固定链路：

```
Agent
  ↓
Tool Registry / Allowlist
  ↓
Tool Adapter
  ↓
Existing Service
  ↓
Structured Result
```

### 6.1 核心概念（冻结）

| 概念 | 类型 | 职责 |
|---|---|---|
| `ToolDefinition` | frozen dataclass | 静态契约：identity、description、input_schema、output_schema、side_effect_class、timeout、permission、audit metadata |
| `ToolInput` | frozen dataclass | 一次调用的参数（`tool_name` + 校验后的参数映射），不得携带任意 dict 直通 |
| `ToolResult` | frozen dataclass | 结构化结果：status、data、references、warnings、error、metadata（见 §10）|
| `ToolError` | frozen dataclass | 结构化失败：error_code、message、retryable、detail（见 §11）|
| `ToolContext` | frozen dataclass | 执行上下文：kb_uuid、run_id、step_id、now、budget 引用；不携带 UI 状态 |
| `ToolRegistry` | 类 | 注册 `ToolDefinition`，执行 allowlist 校验；Agent 只能通过 registry 解析 Tool |
| `ToolAdapter` | 类/Protocol | 一个 Tool = 一个 Adapter；负责参数解析、调用既有 service、结果/错误映射；不得包含业务逻辑 |

命名按项目现有风格：frozen dataclass + 轻量 Protocol，不引入 ABC 框架。

### 6.2 复用与不重复造轮子

| 已有抽象 | 复用方式 |
|---|---|
| `CompletionProvider` / `EmbeddingProvider` / `RerankProvider` | Agent 的 decision 与 final answer 只依赖这些 Protocol |
| `AIError` / `AIUnavailableError` / `AIExecutionError` | Tool Adapter 与 Agent 层统一复用；ToolError 引用其 `error_class` |
| `AuditedAIProvider` + `AiCallLedger` + `AiBudgetGuard` | Agent 的 2 次模型调用全部经此包装，自动进入 `ai_calls` 台账 |
| `build_stable_id` + `*_STABLE_TYPE` | Tool 输入/输出统一使用 stable_id；adapter 负责 stable_id → local_id 解析 |
| `ContextItem` / `ContextSourceAnchor` / `ContextFingerprintState` | ToolResult 的 references 直接投影为这些类型 |
| `KnowledgeContextPackage` / `AuditedAIOutput` | Final Answer Stage 直接复用；citation 校验复用 `_validate_answer_citations` |
| `runtime.py` 工厂 | `application_*_service()` 是 Tool Adapter 唯一的 service 来源 |

禁止重复创建：新的 provider 抽象、新的 citation 模型、新的 stable_id 方案、新的台账表
（第一阶段）。

## 8. Tool Result / Error Model

### 8.1 ToolResult

```
status: SUCCESS | EMPTY | PARTIAL | FAILED
data: 结构化数据（Tool 专属 output_schema）
references: tuple[Reference]   # stable_id + anchor + fingerprint_state
warnings: tuple[str, ...]      # 非致命风险（如部分来源缺失）
error: ToolError | None        # 仅 status=FAILED 时存在
metadata: ToolMetadata         # tool_name、duration_ms、source_state 等
```

- 所有 Tool 必须返回该结构；Agent 禁止通过解析 print / Markdown / Streamlit 文本 /
  任意字符串判断结果。
- `EMPTY` 表示"合法执行但 0 命中"，与 `FAILED` 严格区分。
- `PARTIAL` 表示"部分成功但存在明确降级"，必须携带 warnings。

### 8.2 ToolError error_code（冻结全集）

| error_code | 语义 | 映射来源 |
|---|---|---|
| `tool_unavailable` | Tool 未注册 / allowlist 拒绝 | ToolRegistry |
| `invalid_input` | 参数校验失败 | ToolAdapter 层 |
| `not_found` | stable_id/local_id 目标不存在 | 既有 NotFound 异常 |
| `empty_result` | 合法执行但空（可转 EMPTY，也可按 error 返回）| Adapter 决策 |
| `stale_source` | 来源指纹 CHANGED | `compute_source_fingerprint` |
| `missing_source` | 来源 MISSING | 同上 |
| `provider_unavailable` | AI 未配置/手动模式 | `AIUnavailableError` |
| `timeout` | 工具/模型超时 | `AIExecutionError(error_class=timeout)` 或 adapter 计时 |
| `budget_exceeded` | 预算拒绝 | `AIUnavailableError`（budget）|
| `internal_failure` | 未分类内部失败 | 兜底 |
| `citation_invalid` | 引用越界（answer 阶段）| `RagAnswerError` 扩展 |

既有异常族可复用：`AIUnavailableError`（unavailable/budget）、
`AIExecutionError`（transport/timeout/parse）、各 service 的 `*NotFoundError`、
`*ValidationError`。Tool Adapter 层负责把这些异常映射为 `ToolError(error_code=…)`；
Agent 层只消费 `ToolError`，不捕获裸 `Exception`。

## 9. Read-only Boundary

v0.6.0 第一阶段 Agent 只能：search / read / inspect / retrieve / answer。

不能：创建 Knowledge Object、修改 Knowledge Memory、删除内容、修改 Evidence、
自动确认 Experience Candidate、自动 reindex、自动生成 embedding、自动执行备份、
修改配置、写文件、调 shell。

实现保障：`ToolRegistry.allowlist` 在解析 Tool 时校验
`side_effect_class == READ_ONLY`；任何 WRITE_REVERSIBLE / WRITE_DESTRUCTIVE 定义
在 Phase 1 直接拒绝注册（fail-closed）。后续 v0.6.x 需要新 ADR 才能放宽。

## 10. Agent Safety Budget

统一 `AgentBudget`（frozen dataclass，Phase 1 单实例，不过度工程化）：

| 字段 | Phase 1 默认 |
|---|---|
| `max_tool_calls` | 1 |
| `max_model_calls` | 2 |
| `max_steps` | 2 |
| `max_retries` | 0 |
| `timeout_per_tool` | 30s |
| `timeout_per_run` | 90s |
| `max_input_tokens` | 复用 v0.5.3 context 上限（120k chars 打包上限）|
| `max_output_tokens` | 复用 provider `max_completion_tokens` 默认 |
| `max_total_tokens` | 由日/月 token 预算承接（Settings）|
| `cost_budget` | 不新造货币概念；复用 `ai_daily_token_budget` / `ai_monthly_token_budget` |
| `loop_detection` | Phase 1 结构性无环（max_steps=1 工具步）；字段保留供多步阶段启用 |
| `tool_allowlist` | 只读 7 Tool |
| `side_effect_policy` | `READ_ONLY_ONLY` |

每次 run 创建一份 budget 快照；decision 前、tool 前、answer 前各检查一次；
超限即 `budget_exceeded`，不进入网络调用。

## 11. Audit Model

### 11.1 数据概念（本阶段只设计 schema / ownership / lifecycle，不 migration）

#### agent_runs

| 字段 | 说明 |
|---|---|
| `run_id` | UUID，一次用户请求一个 run |
| `started_at` / `finished_at` | ISO-8601 UTC |
| `status` | running / succeeded / failed / rejected |
| `user_request_sha256` | 用户请求的摘要，**不存正文** |
| `model` | decision/answer 所用模型 |
| `token_usage` | 汇总 token（来自 ai_calls）|
| `cost_metadata` | 与 v0.5.3 一致：token 数，不新造货币 |
| `final_status` | 与 status 一致，收敛字段 |

#### agent_steps

| 字段 | 说明 |
|---|---|
| `step_id` | UUID |
| `run_id` | 归属 run |
| `sequence` | 1-based |
| `step_type` | decision / tool_call / answer / answer_direct |
| `status` | succeeded / failed / skipped |
| `duration_ms` | 步耗时 |
| `decision_metadata` | 仅存 decision summary（action/tool_name/reason_summary），**不存 chain-of-thought** |

#### tool_calls

| 字段 | 说明 |
|---|---|
| `tool_call_id` | UUID |
| `run_id` / `step_id` | 归属 |
| `tool_name` | allowlist 内名称 |
| `input_metadata` | 参数摘要（如 query 长度、limit、stable_id），**不存完整私人正文** |
| `output_status` | SUCCESS / EMPTY / PARTIAL / FAILED |
| `duration_ms` | 耗时 |
| `error_code` | ToolError.error_code |
| `referenced_objects` | 引用的 stable_id 列表 |

### 11.2 最小审计数据原则（延续 v0.5.3）

禁止默认保存：完整用户私人正文、完整 prompt、完整 context、完整模型输出。
只保存：sha256、stable_id、状态、错误码、时长、token、决策摘要。
模型调用本身继续由 `AuditedAIProvider` 写入 `ai_calls`（call_uuid 关联
`source_feature=agent_decision|agent_answer`）。

## 12. Citation Lineage

```
ToolResult.references（stable_id + anchor + fingerprint_state）
  ↓ 投影为 ContextItem.source_anchors
KnowledgeContextPackage.citations
  ↓ final answer 校验
Final Answer citations ⊆ ToolResult.references
```

- Agent 不得生成 Tool 没返回过的来源引用。
- 越界引用：fail-closed（复用并扩展 `RagAnswerService._validate_answer_citations`
  的语义：未在 references 中的 `#n` 引用 → 拒绝输出或显式移除并告警）。
- `ANSWER_DIRECTLY` 分支不产生任何引用；若决策模型输出引用而没有任何 ToolResult，
  一律按 citation_invalid 拒绝。

## 13. schema v13 Decision

**决策：DEFERRED（Phase 1 不执行 migration）。**

理由：

1. Phase 1 是单步结构（run ≡ 1 工具步），`ai_calls` 台账 + runtime-only
   execution trace 已能完整还原执行链；
2. 现在建 `agent_runs / agent_steps / tool_calls` 三表，等于在还没有多步行为时
   提前引入 schema 与迁移成本，违反"不能因为以后可能需要就堆表"；
3. schema v13 草案在 ADR-006 冻结，待多步 Tool Execution（Phase 3）真正落地时
   在同一 v0.6.x 支版本执行 migration，届时表结构与真实执行语义一致。

Phase 1 的 runtime-only trace：内存中 frozen dataclass 链 + 结构化日志行 +
`ai_calls` 关联，不写入新表。

## 14. Public Deployment Gate

Public Deployment 与 Agent Phase 1 **解耦**，是独立 Gate。当前本地假设
（127.0.0.1、single-user、no auth、local API key、SQLite、Windows scripts）
公网后都必须重新审查。

### Public Deployment Gate Inputs（本阶段只列项，不实现、不选厂商）

| 领域 | 必须回答的问题 |
|---|---|
| auth | 无账号架构下如何认证（或明确 hosted 引入账号）|
| session isolation | 多会话/多用户隔离边界 |
| API key server-side storage | 服务端密钥托管，绝不回传客户端 |
| rate limit | 每用户/每 IP 限流 |
| per-user budget | 与 token 预算结合 |
| request size | 上传与请求体上限 |
| upload limits | 文件类型/大小/数量 |
| logging privacy | 日志脱敏（已有 `_SECRET_PATTERNS` 经验复用）|
| SQLite concurrency | 单写多读、WAL、备份窗口 |
| deployment filesystem | 数据目录持久化/挂载 |
| Windows-specific assumptions | `.bat`/`.vbs`/盘符路径如何迁移 |
| secret management | 环境变量/托管密钥 |
| abuse prevention | 提示注入、越权、批量爬取 |
| model cost guard | 与 AgentBudget 集成 |

## 15. Local vs Hosted Boundary

公网化不能推翻 Local-first 产品哲学。定义两种模式：

### Local Mode（默认）

- 全部知识资产在本地；SQLite + 本地文件是唯一事实来源；
- 核心能力离线可用；AI 是可选增强；
- 无账号、无云同步、无云端事实来源。

### Hosted / Public Mode（未来可选）

- 用户**明确上传**资料到服务端；服务端存储与本地目录**明确隔离**；
- 明确账户隔离、明确 server-side storage、明确 rate limit / budget；
- 禁止默认把用户全部本地资料上传到公网服务器。

两种模式共享同一 Tool Contract / Agent Foundation / 审计模型，但在
auth、存储、预算、隐私策略上走不同配置路径。Hosted 模式只有在 Public
Deployment Gate 完成后才允许进入实现。

## 16. Testing Strategy

第一阶段 Mock-first：不能为了跑 Agent 单测持续烧真实 API Token。

后续 Phase 1 必须覆盖的测试矩阵：

| 测试类别 | 覆盖点 |
|---|---|
| Tool contract tests | ToolDefinition/ToolInput/ToolResult/ToolError 序列化与不变式 |
| Tool adapter unit tests | 每个 adapter 的参数校验、service 调用、结果/错误映射 |
| Agent action selection tests | decision 模型输出解析：CALL_TOOL / ANSWER_DIRECTLY / 非法输出 |
| invalid tool tests | 未注册 Tool、非 allowlist Tool、WRITE 类拒绝 |
| budget exceeded tests | max_tool_calls / max_model_calls / token 预算超限即停 |
| citation lineage tests | 答案引用 ⊆ ToolResult.references；越界 fail-closed |
| empty result tests | EMPTY vs FAILED 语义 |
| provider unavailable tests | 手动模式 / 缺 key / transport 失败 |
| timeout tests | tool 超时、run 超时 |
| read-only boundary tests | 任何写路径在 Phase 1 不可达 |
| deterministic mocked model tests | decision + answer 均用确定性 mock provider |

复用已有 `MockCompletionProvider` 模式；Phase 1 测试不得真实联网。

## 17. Cost Control

架构层成本控制：

- `model call count`：AgentBudget.max_model_calls 硬上限；
- `tool call count`：AgentBudget.max_tool_calls 硬上限；
- `token budget`：复用 Settings 日/月 token 预算（`ai_daily_token_budget` /
  `ai_monthly_token_budget`）；
- `cost accounting`：所有模型调用经 `AuditedAIProvider` 进入 `ai_calls`；
  decision 与 answer 用不同 `source_feature` 区分；
- `agent_runs relation`：Phase 1 通过 runtime trace 关联 `ai_calls.call_uuid`；
  schema v13 落地后提供 `agent_runs → ai_calls` 持久关联；
- 真实模型调用必须可统计，不依赖账单事后反推。

## 18. v0.6.x Phase Plan

按 capability 划分，不预设固定支版本数量，不预设 `v0.6.3 = Decision Gate`。
Decision Gate 从 v0.7.0 入口要求倒推（§19）。

| Phase | Capability | Exit 证据 |
|---|---|---|
| Phase 0 | ADR / Contract 冻结（本轮）| ADR-006 + 本架构文档进入 main |
| Phase 1 | Tool Contract + 7 个只读 Tool Adapter + single-step read-only Agent + runtime trace + AgentBudget | 单步链测试矩阵全绿；mock-first 无真实 token 消耗 |
| Phase 2 | Agent Audit 持久化 + 成本统计集成 | schema v13 若仍需持久化则在此落地；否则以 runtime trace + ai_calls 证明可审计 |
| Phase 3 | Multi-step Tool Execution（有界，loop detection 生效）| 有界多步链 + 审计三表 + 回滚语义测试 |
| Phase 4 | Reliability / Eval / Public Deployment Gate | v0.7.0 Entry Requirements 全部满足 |

## 19. v0.7.0 Entry Requirements

从 v0.7.0 Personal Experience Agent 倒推，进入 v0.7.0 前 v0.6.x 必须完成：

1. **Tool contract stable**：ToolDefinition/ToolResult/ToolError 契约冻结且无破坏性变更；
2. **execution trace stable**：run/step/tool_call 的审计语义稳定（runtime 或持久化均可）；
3. **Agent safety stable**：budget、allowlist、side-effect 分类在真实调用中持续有效；
4. **multi-step behavior bounded**：若引入多步，必须有 loop detection 与硬上限；
5. **Agent 可以可靠读取 Knowledge Memory**：get_knowledge_memory 达到 READY；
6. **citations/provenance 保持可靠**：多步下 citation lineage 仍 fail-closed；
7. **不会把临时推断污染长期经验**：Agent 只读边界证明（无写入路径进入
   knowledge_memory / knowledge_object）；
8. **read/write boundary 清晰**：写类 Tool 若存在，必须有独立 ADR 与可逆/确认语义。

不规划具体发布日期；版本推进以契约与验证证据驱动。

## 20. First Implementation Task

**唯一首任务：实现并冻结 Tool Contract 模块（`ToolDefinition` / `ToolInput` /
`ToolResult` / `ToolError` / `ToolContext` / `ToolRegistry` + side-effect 分类 +
allowlist 校验），配 mock-first 单元测试；不含 Agent 循环、不含模型集成。**

理由：这是 v0.5.3 Decision Gate F-02 的必做项，也是所有后续 Tool Adapter 与
Agent 执行的唯一依赖。契约未冻结前，任何 Adapter 或 Agent 代码都会建立在不稳定
基础上。
