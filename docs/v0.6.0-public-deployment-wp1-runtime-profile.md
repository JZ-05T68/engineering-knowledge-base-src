## Runtime Profile Contract

`RuntimeProfile` is a `StrEnum` with only `LOCAL="local"` and `HOSTED="hosted"`.
`parse_runtime_profile(value)` is the single parser; `get_runtime_profile()` reads
only the process environment variable `EKB_RUNTIME_PROFILE`.

| Process environment state | Result |
|---|---|
| Variable completely absent | LOCAL; backward-compatible default |
| Exact `local` | LOCAL |
| Exact `hosted` | HOSTED |
| Present but empty string | `invalid_runtime_profile` |
| Whitespace-only, leading/trailing whitespace | `invalid_runtime_profile` |
| `LOCAL`, `Local`, `HOSTED`, `Hosted` | `invalid_runtime_profile` |
| `prod`, `production`, `server`, `cloud`, `test`, `staging`, other values | `invalid_runtime_profile` |

Only **absence** gets the Local default. There is no strip-and-guess, alias,
case normalization, dotenv-based profile selection, or cloud/environment heuristic.
The existing staging instance remains a Local isolation mechanism, not a third profile.

## Local Behavior

`Settings` retains its existing fields, `.env` support, AI defaults, SecretStr,
loopback/8501 validation, repo-relative layout and explicit test injection support.
Its read-only `runtime_profile` property reports LOCAL; dotenv cannot override it.

`get_settings()`, `runtime_settings()` and `staging_settings()` require LOCAL before
loading Local configuration. Selecting Hosted in a Local entrypoint raises a typed
configuration error; it does not return Local paths or start Local services.

The settings cache is retained in `_get_local_settings()`. The public
`get_settings.cache_clear()` hook remains available. Profile validation occurs before
the cache lookup, so a cache hit cannot silently accept a newly invalid profile value.
This does not introduce live profile switching for an already composed application.

Streamlit, Windows launchers, imports, filesystem services, backup/restore and AI
provider composition are not rewritten. `src/runtime.py` is unchanged.

## Hosted Behavior

Formal composition boundary for a future server:

```python
from src.hosted_config import load_hosted_settings, validate_hosted_startup

settings = load_hosted_settings()  # requires process EKB_RUNTIME_PROFILE=hosted
validate_hosted_startup(settings)
# STOP in WP1: no services, DB initialization, provider or HTTP server.
```

`HostedSettings` has only the three WP1 foundation fields:

- `runtime_profile`: explicitly HOSTED;
- `data_root`: required, canonical server storage root;
- `ai_api_key`: existing SecretStr representation, optional and excluded from repr.

It is frozen and has no raw/PDF/PNG/Markdown/quarantine/backup/export/PID paths.
Provider/model/budget composition and complete readiness are later work; no new
provider abstraction or speculative security configuration collection is added.

## Configuration Sources

| Boundary | Sources / precedence |
|---|---|
| Process profile selection | `EKB_RUNTIME_PROFILE` in process env only; absence → LOCAL |
| Existing Local Settings | Existing explicit constructor > env > configured repository `.env` > defaults |
| HostedSettings | Explicit server-side constructor injection > process env > declared defaults |
| Formal Hosted loader | First requires exact process `EKB_RUNTIME_PROFILE=hosted`, then constructs HostedSettings |

Direct `HostedSettings(runtime_profile="hosted", data_root=...)` construction is a
trusted server/test injection boundary. It is not a client request object and does not
weaken the formal loader's explicit process opt-in.

## Hosted Env-only Boundary

`HostedSettings.model_config` sets `env_file=None`. Its source customization returns
only init/env sources. Before BaseSettings constructs source objects, `__init__`
forces `_env_file=None` and `_secrets_dir=None`, even if a caller supplied them.
This matters because merely dropping the dotenv source after construction can still
let that source read a file. No repository or CWD `.env` is consulted by Hosted.

Tests place synthetic profile/root/key values in separate temporary repository/CWD
dotenv files, block the actual dotenv file reader, and prove missing process config
still fails. A dotenv `local` value cannot override explicit Hosted process config.
`DASHSCOPE_API_KEY` is not a fallback. Local dotenv parsing is separately tested with
temporary synthetic files and retains environment precedence.

## DATA_ROOT Contract

`EKB_DATA_ROOT` is required for the formal Hosted loader. There is no fallback to
repo/data, CWD/data, temp, or home. Derived paths are properties, not independently
environment-overridable Local path fields:

| Property | Value |
|---|---|
| `data_root` | Canonical configured root |
| `database_dir` | `data_root/database` |
| `database_path` | `data_root/database/knowledge.db` |
| `logs_dir` | `data_root/logs` |
| `log_path` | `data_root/logs/engineering-kb.log` |

An explicit root inside the application source tree, including the source root itself,
is rejected using resolved pathlib containment, not string prefixes.

ADR-007 does not mandate absolute input spelling. Relative input is therefore accepted
and resolved **once at settings construction against that process's CWD**. Subsequent
CWD changes cannot change the stored root. No `expanduser` or implicit alternate root
is introduced. Empty/whitespace/null-byte/non-path shapes fail validation.

The root must already exist for startup validation. WP1 does not create it or its
database/log children. This is the minimal, predictable foundation choice allowed by
the work package; creation/mounting/DB initialization belong to WP4/WP5.

## Startup Validation

`validate_hosted_startup(settings)`:

1. Requires Hosted settings.
2. Checks the configured canonical root is an existing directory.
3. Checks derived paths resolve within that root and outside the source tree.
4. Requires existing database/log directory paths to be directories.
5. Performs a uniquely named create/write/flush/close probe in the root and any
   already-existing database/log directories; each probe is removed immediately.

No mkdir, persistent log initialization, DB connection, schema inspection, migration,
seed, AI call, provider factory, network, subprocess, OCR or long task is involved.
Absent child directories are left absent. An existing DB is never opened: a test even
uses non-SQLite sentinel bytes to prove validation is a path foundation, not DB readiness.

This is a low-side-effect startup check, not a pure no-filesystem-I/O function. It is
not a complete filesystem sandbox or an ongoing permission/TOCTOU guarantee; trusted
operator configuration and later deployment/runtime checks remain required.

## Error Semantics

`RuntimeConfigurationError(ValueError)` carries a typed
`RuntimeConfigurationErrorCode` and a fixed safe Chinese message containing that code.

| Code | Meaning |
|---|---|
| `invalid_runtime_profile` | Present value does not exactly match the parser contract |
| `runtime_profile_mismatch` | Wrong profile for Local/Hosted entrypoint or missing explicit Hosted selection |
| `missing_data_root` | Required Hosted data-root configuration absent |
| `invalid_data_root` | Invalid path shape or failed path normalization |
| `data_root_in_source_tree` | Hosted root is inside/equal to application source tree |
| `data_root_not_usable` | Missing/file/unusable root, invalid existing child directory, escape or failed write probe |
| `invalid_hosted_config` | Other Hosted Settings validation/source failure |

Formal constructor/loader errors do not echo the input, key, environment dump, raw
filesystem error or whole configuration. Wrapped exceptions suppress the raw exception
chain; tests check safe repr/string and fixed error codes. Standard Pydantic low-level
validation APIs are not an HTTP error contract; there is no HTTP layer in WP1.

## Security Properties

- Explicit invalid profiles fail before loading Local config, including Local cache hits.
- Hosted config failure never triggers a Local fallback.
- Hosted ignores dotenv sources and cannot borrow a developer's Local key.
- SecretStr is retained; Hosted key is excluded from repr and masked in JSON serialization.
- Hosted mutable paths derive from a required server configuration root, not a request.
- Application source need not be writable for Hosted validation.
- Runtime/config modules remain UI/HTTP-independent; Agent core does not import the new
  profile/Hosted configuration modules. Registry, execution and citation contracts are unchanged.
