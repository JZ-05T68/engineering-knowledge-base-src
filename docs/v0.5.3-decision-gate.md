## 5. Architecture Readiness

### 5.1 Service boundaries

- 生产服务全部依赖 `Database` 与冻结模型，**不 import Streamlit**；全库仅 11 个 `*_ui.py` 模块 import Streamlit，服务层无 `st.session_state`、无 `pages/` 依赖（`rg` 验证 0 命中）。
- 依赖方向干净：`pages → runtime factories → services → database/models`；AI 层：`business services → provider.py 契约`，`qwen_client.py` 仅被 `runtime.py` 构造，业务代码不 import 供应商模块。
- Agent 加入后**不会被迫依赖 UI 状态**；现有核心能力均有独立 service 入口。

### 5.2 Service-layer callability（未来 Tool 的底子）

- 每个核心能力都有明确参数与返回模型：`KnowledgeObjectService.get/get_view/list/source_views/source_health`、`KnowledgeMemoryService.get/list`、`KnowledgeSearchService.search(query, limit, include_*) -> tuple[KnowledgeSearchResult]`、`SearchService.search`、`HybridSearchService.search -> HybridSearchOutcome`、`ContextItemProjector.project(type, id) -> ContextItem`、`KnowledgeContextPackager.build -> KnowledgeContextPackage`、`RagAnswerService.answer(query, package) -> AuditedAIOutput`、`AILedgerService.query/stats`。
- 错误语义明确：`DatabaseError` 层级、`ContextProjectionError`、`KnowledgeContextError`、`RagAnswerError`、`AILedgerError`、`AIUnavailableError`（未配置）与 `AIExecutionError`（尝试后失败）分离。
- 空结果语义明确：空 tuple / 空列表 / `None` + 类型化错误，服务层不吞异常、不伪造回答。

### 5.3 Data model

- `stable_id = <kb_uuid>:<type>:<id>`，命名空间 7 类（knowledge_object/memory/relation/source/revision/page/evidence），纯函数 `build_stable_id` 白名单校验。
- SQLite `PRAGMA foreign_keys = ON`；知识表间 FK/级联策略明确（revision 表按设计无 FK 的身份快照）。
- lifecycle/supersedes 链有环检测（`_supersession_chain_reaches`）；revision append-only。
- schema v12 承载知识资产 + AI 台账；新增 `knowledge_project_links`（多态引用由服务层写前校验）。

### 5.4 Error model / structured outputs

- 全库使用 `frozen dataclass(slots=True)` / `StrEnum`；结构化输出（`AuditedAIOutput`、`KnowledgeContextPackage`、`HybridSearchOutcome`、`AICallLedgerPage` 等）可直接序列化。
- 中文错误信息覆盖用户可读需求；密钥绝不出现在异常/日志中（负向测试固化）。

## 7. Read-only Agent Feasibility

**YES。**

理由：

- v0.5.3 明确冻结了“AI 不写知识 / 投影只读 / 打包器纯组装 / 台账 append-only / 无 Agent 循环”边界；read-only Agent 与这些边界完全一致。
- 读取链已完整：检索 → 投影（ContextItem）→ 打包（KnowledgeContextPackage）→ 引用约束回答（RagAnswerService）→ 审计（ai_calls + target_refs）。
- 所有读服务无写副作用（投影读路径零写库有字节级测试固化）。
- 唯一前提：先建 Tool 契约 + read-only allowlist + step 审计（见 F-02/F-03），确保“能读”与“不会写”都由机制而非约定保证。

## 9. Public Deployment Inputs

v0.6.0 推上公网前必须处理（本轮不修，仅登记为 v0.6.0 Public Deployment Gate Inputs）：

1. **API Key 暴露面**：当前 Key 在本地 `.env` + `SecretStr` 单进程模型下安全；公网部署后任何读取 `.env`/配置的漏洞都会直接泄露计费凭据。需要服务端密钥管理/环境注入策略。
2. **未授权烧模型费用**：无 auth、无会话隔离、无 per-user/per-session 预算 → 任何能访问端点的人都可触发付费调用。需要 auth 或 IP/访问控制 + 调用预算门。
3. **是否需要 auth**：当前产品边界明确“无账号/登录/多用户”，公网化必须重新裁决（不引入账号体系则必须靠网络层隔离/自托管网关）。
4. **session isolation**：Streamlit 多会话 + 共享 SQLite/内存 cache（`lru_cache` 单例）在公网多用户下不成立。
5. **rate limiting / request size / upload limits**：当前无请求频率、体积与上传大小限制；PDF 导入与 AI 调用都需要上限。
6. **model call budget**：现为单机日/月 token 预算；公网需要按会话/IP/租户的预算与配额。
7. **logging privacy**：本地轮转日志记录了问题/上下文字符数等；公网需审计日志脱敏策略。
8. **filesystem assumptions**：`PROJECT_ROOT` 相对路径、`data/`、`backups/`、`logs/`、`runtime/` 单机目录假设；公网需要容器化/持久卷/对象存储方案。
9. **SQLite concurrency**：单进程 `PRAGMA foreign_keys` + WAL 假设，公网并发写需评估（或维持单实例写模型并加连接约束）。
10. **Windows-specific scripts**：`.bat`/`.vbs`/PowerShell 恢复流程仅 Windows；公网部署需要跨平台服务编排。
11. **Streamlit public deployment risk**：Streamlit 面向内网/本机场景，公网暴露需前置反向代理/TLS/健康检查与安全头。
12. **local absolute paths**：备份/导出/数据库中记录的本地绝对路径在公网/多机环境下会失效，需要路径重基（已有 `_rebase_database_paths` 雏形）。
13. **user data isolation**：单用户无隔离；公网多租户需要数据隔离或明确“单实例单用户”部署形态。

## 11. Findings

### BLOCKER

- **F-01（BLOCKER / precondition）** — Workspace hygiene。
  - Evidence：`engineering-kb` detached HEAD + 未提交改动；`ekb-dev` 落后 origin/main 2 commits 且含未提交 v0.5.3 改动；唯一干净基线为 `42b1f18`（docs-fix 目录）。
  - Impact：从错误工作区启动 v0.6.0 会把未提交/历史内容混入新基线，破坏发布边界。
  - Required action：建立干净 v0.6.0 基线（fresh clone origin/main），隔离旧工作目录。
  - Target version：v0.6.0 kickoff 之前。

### MAJOR

- **F-02（MAJOR）** — 无 Tool 接口与 step 级审计模型。
  - Evidence：所有能力是“可调用的 service”，但没有统一 Tool 契约/allowlist；`ai_calls` 是单次调用级台账，无法表达 `agent_runs / agent_steps / tool_calls` 执行链。
  - Impact：Agent 直接调服务会与 UI/服务实现细节耦合，且多步执行不可审计。
  - Required action：v0.6.0 首阶段冻结 Tool 协议 + schema v13 草案（run/step/tool 三表，复用 call_uuid 关联 ai_calls）。当前 schema 可扩展，无需重构。
  - Target version：v0.6.0 M1。

- **F-03（MAJOR）** — Agent 安全控制全部缺失。
  - Evidence：max tool calls、model call limit、loop detection、recursion depth、tool allowlist、side-effect classification、per-run token 预算均不存在；现有仅单调用级重试上界与日/月 token 预算。
  - Impact：没有这些约束，Agent 一旦进入循环会烧费用并产生不可审计副作用。
  - Required action：在 v0.6.0 ADR 中冻结上述机制，未冻结前不实现 Agent 循环。
  - Target version：v0.6.0 ADR。

- **F-04（MAJOR）** — 公网化假设失效。
  - Evidence：`require_official_endpoint` 强约束 127.0.0.1:8501；无 auth/session/rate limit/上传限制；本地 `.env` 密钥、本地绝对路径、SQLite 单进程、Windows bat/vbs、Streamlit 直接暴露。

## 12. v0.6.0 Entry Preconditions

## 13. Decision Rationale

选 **CONDITIONAL GO** 而不是 GO，是因为 v0.6.0 开工前存在三个必须先落地的准备项（干净基线、Tool/审计/安全契约 ADR、公网化范围裁决），它们都不是 v0.5.3 缺陷，但跳过任何一项都会让 Agent 建在错误基础上。

不选 NO-GO，是因为：

- v0.5.3 核心事实与 Release 声明一致（代码、docs、CHANGELOG、版本号、schema v12、tag 互相印证；1762 测试收集数与发布记录一致，针对性回归全绿，ruff 通过）。
- 数据/检索/引用基础没有破坏性缺陷：fail-closed 契约在 citation、context、AI 调用、备份恢复四条链路上都有实现与测试。
- 不需要重新开放 v0.5.x：所有缺口都是 v0.6.0 的合理工作范围，且当前 schema/服务边界支持增量扩展（不是重构）。

## 14. Recommended First v0.6.0 Task

**v0.6.0 第一项开发工作：Tool Adapter 契约与最小只读执行链。**

具体：冻结统一 Tool 协议（显式参数模型、返回模型、错误类型、空结果语义、read-only 标记），把已 READY 的能力（Page Retrieval / Knowledge Retrieval / Knowledge Object Read / Knowledge Memory Read / RAG Answer / AI Ledger）包装为受 allowlist 约束的 Tool，并以 `agent_runs / agent_steps / tool_calls`（schema v13 草案）记录一次**单步、无循环**的只读执行链，跑通“请求 → 选择 1 个只读工具 → 结构化结果 → 引用/审计落账”。未跑通该最小链并冻结安全预算前，不引入多步 Agent 循环。
