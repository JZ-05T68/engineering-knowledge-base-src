# EKB v0.5.1 Phase 3 — PAID_CALL_PROPOSAL（最小真实 embedding 校准）

- 日期：2026-08-17
- 状态：**PROPOSAL ONLY，未经批准不执行**
- 前置：Phase 2 closure（`docs/v0.5.1-phase2-closure.md`）
- 目标：回答唯一问题——真实 `qwen3.7-text-embedding` 的 similarity distribution
  能否支持某种 vector eligibility strategy（D-01/D-03 落地前的心智校准）。

> 本 proposal 是为了**信息增益**而设计的受控付费实验，不是给 production 灌数据，
> 也不是改写 frozen benchmark。任何超出本 proposal 边界的调用都必须重新提案。

## 一、为什么需要真实校准（信息价值判断）

Phase 2 离线 ablation 的唯一结构性前提是 `sim > 0` 资格门，但文档已诚实记录：

> fixture 的 `sim > 0` 门在真实模型上可能近似无操作——真实 embedding 相似度几乎恒为正。

因此 fixture 结果**不能**直接用于冻结 `min_similarity` 绝对阈值、`vector_weight=0.5`、
`top_k=5` 三个参数。真实校准的价值在于回答三件事：

1. 真实相似度对「语义相关 vs 无关」是否可分（absolute similarity 是否有 gap）；
2. 相对 margin / top-k 结构是否比绝对阈值更稳健（relative ranking/margin）；
3. `vector_weight=0.5` 与 `top_k=5` 是否仍有依据（还是 fixture 平坦下的任意取值）。

若离线 + 真实分布共同表明「无绝对阈值可分、只能靠 top-k 或 score floor」，
则 D2 的资格门形态必须改变——这正是本 proposal 要提前消除的不确定性。

## 二、模型与服务边界

| 项 | 值 |
|---|---|
| model | `qwen3.7-text-embedding`（与 `src/ai/page_indexer.py` 契约一致） |
| thinking | N/A（embedding 无 thinking） |
| dimensions | `1024`（`EMBEDDING_DIMENSIONS`） |
| 端点 | DashScope `/embeddings`（批量，每批 ≤ 20 输入） |
| HTTP 上限 | **≤ 5 次** |
| retry | **0**（仅网络错误/429/5xx 之外不重试；一次 429/5xx 即停） |
| 契约 | 复用 `src/ai/qwen_client.py` 的 `embed()`，不新增 vendor 代码 |

### 请求语义约束（必须与生产 embedding 路径完全一致）

本 proposal 的每一次 embedding 请求沿用**现行生产路径**（`src/ai/qwen_client.py`
`QwenClient.embed`）的 payload 形状：

```text
{"model": chosen_model, "input": [texts...], "encoding_format": "float",
 "dimensions": 1024}   # dimensions 仅在显式传入时出现
```

禁止在本次实验中引入任何以下**非生产**字段或能力：

- `text_type`（query/document 区分）
- `instruct` / 指令式 embedding
- sparse / mixed / hybrid 输出
- reranking 或任何第二次 AI 调用
- 任何 vendor-extra 或 thinking 相关字段

若实验需要上述任一特性才能产生有效信号，则说明该特性尚未进入生产路径，
本次校准必须终止并回到生产路径口径重新设计（避免用非生产语义污染校准结论）。

## 三、输入集合（exact query/page scope）

从已有 **synthetic corpus / queries** 中选取代表性 pair，而非生产数据。
每类只取足量代表性样本，目标是分布形状，不是覆盖率。

| 类别 | 用途 | 建议样本量（query × 候选页） |
|---|---|---|
| true semantic relevant | 正例相似度下界 | 5 query × 3 页 = 15 pair |
| paraphrase relevant | 改写仍相关的稳健性 | 5 query × 3 页 = 15 pair |
| lexical-overlap distractor | 词面重叠但无语义（D-01 关键陷阱） | 5 query × 3 页 = 15 pair |
| unrelated distractor | 无关系页相似度上界 | 5 query × 3 页 = 15 pair |
| known partial-coverage regression（C3-query 型） | 覆盖率缺陷下真实相似度行为 | 3 query × 3 页 = 9 pair |

**合计：约 23 条 query 文本 + 去重后候选页文本。**

- 候选页文本使用 `page_indexer` 的 `PreparedPageText` 截断口径（≤ 8000 字符）。
- 全部文本从 synthetic 冻结语料生成，**不读取 production `data/`**。

## 四、HTTP / 重试 / 成本预算

| 项 | 值 |
|---|---|
| 精确输入规模 | **23 query 文本 + ≤60 去重候选页文本**（去重后按实际页数，≤60 兜底） |
| 最大 HTTP 请求数 | 每批 ≤ 20 输入；query 侧 1 批（23 需拆 2 批）+ page 侧按去重页数 ≤3 批；**硬上限 5 次 HTTP** |
| retry | **0**（无网络错误/429/5xx 之外的重试；一次 429/5xx 即停止） |
| dimensions | 1024 |
| token 吞吐上限 | 每文本 ≤ 8000 字符截断；总输入 < 120k 字符（≈ < 200k 输入 token 上限兜底，实际远低于此） |
| **preflight estimated paid cost** | **≤ 0.20 RMB**（按 DashScope `text-embedding` 计价 × 实际输入 token；预计实际 < 0.10 RMB，0.20 为硬止损上限） |

## 五、DB 写入 / staging / production 隔离证明

### production zero-write proof

- 脚本只调用 `qwen_client.embed()` 并**打印/落盘临时 JSON**（如 `logs/` 下的
  calibration 结果），**绝不 import 或调用** `Database` / `page_indexer` 的持久化
  write 路径、绝不触碰 `data/`、`staging-data/` 或任何 SQLite 文件。
- 结果向量只写入进程内存与 `logs/`（git-ignored 或显式不入库），不进入 embedding store。

### staging-only proof（如后续需要落地验证）

- 若本 proposal 之后要验证「真实向量 + 生产 hybrid 路径」的 D-01 真实幅度，
  必须另起一份 **staging DB**（`staging-data/` 下的临时 SQLite），只写 staging，
  production DB 零写入。本 proposal 本身**不产生任何 DB write**（无论 prod 或 staging）。

## 六、分析输出（不设 PASS/FAIL 阈值，只报告分布）

对每类 pair 计算并报告：

1. **absolute similarity**：`cosine(query, page)` 的分布（min/median/max/四分位）。
2. **relative ranking/margin**：在固定 query 下，related vs unrelated 页的排序位置
   与相邻 margin。
3. **top-k behavior**：k∈{3,5,10} 下 related 页是否稳定进入 top-k。
4. **资格门候选形态判别**：基于上述分布，判断应采用
   - absolute threshold（若存在清晰 gap）
   - relative threshold/margin（若绝对尺度漂移但相对可分）
   - bounded top-k only（若无阈值可分，只能截断）
   - score floor + top-k（若需 floor 挡掉零证据 + top-k 有界）
5. **复核 `vector_weight=0.5`** 与 **`top_k=5`**：真实分布下是否仍成立。

## 七、success criteria（本轮信息目标）

- 能明确回答「真实相似度分布是否支持某种 vector eligibility strategy」，
  并给出有真实证据支撑的候选形态（threshold / margin / top-k / floor+top-k）。
- 能对 `vector_weight` 与 `top_k` 给出保留 / 修改 / 需更大样本的明确结论。
- 全程 **0 production write、0 frozen benchmark 改动**。

## 八、stop criteria（立即停止，不循环）

- 任一次 HTTP 返回 429 / 5xx（retry=0，不重试）。
- 任一输入文本嵌入失败或维度 ≠ 1024（fail-closed，不降级重试）。
- 相似度分布明显受文本截断/噪声污染，无法区分 related/unrelated（信息价值归零）。
- 达到第 4 节 HTTP 上限仍未取齐样本。
- 累计付费估算触达 **0.20 RMB 止损线**（无论是否取齐样本，立即停止）。

## 九、不执行范围

- 不写 production / staging DB。
- 不改 frozen `benchmarks/*.json`。
- 不在真实数据上冻结 `min_similarity` / `vector_weight` / `top_k`。
- 不做 LLM answerability、rerank、二次 AI 调用。
