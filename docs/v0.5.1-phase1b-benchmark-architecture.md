# EKB v0.5.1 Phase 1B — Benchmark Architecture

- 日期：2026-08-17
- 分支：`kimi/v0.5.1-retrieval-stabilization`
- 状态：已冻结（随 corpus / queries JSON 一起版本化）

## 目标

建立可长期复用的 v0.5.x retrieval quality harness，先让缺陷自己暴露，
而不是做一个「高通过率 benchmark」。不修改任何生产代码。

## 分层证据原则

| 层 | 内容 | 效力 |
|---|---|---|
| algorithmic / offline evidence | synthetic corpus + deterministic fixture 向量 | 验证 lexical / vector recall / RRF / benchmark 机制、降级、provenance、partial coverage 行为 |
| real-model evidence | 真实 Qwen embedding（staging） | 验证真实语义质量；本阶段不新增，需单独 PAID_CALL_PROPOSAL |

fixture 向量 PASS 永远不得描述为 Qwen semantic quality PASS。

## 组成

```
benchmarks/
  corpus_synthetic_v1.json   # 冻结语料：5 documents / 42 pages / topic 权重 / embedded 覆盖标记
  queries_v1.json            # 冻结 query 集：29 queries，A–J 十类，人工 relevance set
scripts/
  retrieval_benchmark.py     # 离线 runner：建库 → 写 fixture embedding → 双模式跑 query → 出报告
tests/
  test_retrieval_benchmark.py  # harness 机制回归（不锁定质量阈值）
docs/
  v0.5.1-phase1c-evaluation-contract.md   # 冻结评价口径
  v0.5.1-phase1d-offline-baseline.md      # baseline 结果（运行后生成）
  v0.5.1-phase1e-defect-matrix.md         # 缺陷矩阵（分析后生成）
```

## Synthetic corpus 设计

- 5 个文档：STM32（10 页）、PID 控制（8 页）、机器人运动学（8 页）、电机驱动与功率电子（8 页）、嵌入式通信协议（8 页），共 42 页。
- 每页 2–3 句真实风格的工程中文文本，经过**真实的** `Database.create_document/create_page`
  → FTS5 触发器 → jieba 预分词，即 lexical 侧完全是生产代码路径，无任何 mock。
- **Latent-topic fixture 向量**：20 维，每维一个 topic；页面向量 = 该页 topic 权重（1.0/0.8/0.6…），
  query 向量同理。余弦相似度 = topic 重叠度。这是确定性的语义几何模拟，
  不为任何单条 query 写特判；改规则即改 benchmark 版本。
- **隔离三元组**：`model="synthetic-fixture-v1"`、`dimensions=20`、`config_version=1`，
  与生产 `qwen3.7-text-embedding / 1024 / 1` 不同，SQL 层天然隔离，
  且 fixture embedding 只写入 runner 的临时目录 DB，永不触碰 `data/` 或 `staging-data/`。
- **Partial embedding coverage（类别 J）**：42 页中仅 21 页 `embedded: true`（50%），
  刻意包含「相关页未嵌入」（J1/J2、B3、C3、H2、I2）与「干扰页已嵌入」（E1 的 power/p5），
  复现 v0.5.0 staging 的真实运行条件（78 页仅 5 页嵌入）。
- **Foreign topics**：`foreign_cloud / foreign_battery / foreign_ros` 三个 topic 没有任何页面使用，
  专供 F 类 negative query 使用——query 向量与全部页面余弦为 0，
  用于暴露「无相似度阈值」下向量召回的真实行为。

## Runner 设计（scripts/retrieval_benchmark.py）

1. 临时目录建 SQLite DB（`tempfile`），从 corpus JSON 建文档/页面；
2. 对 `embedded: true` 页面计算 fixture 向量，用 `SearchableContentFingerprintSource`
   算真实指纹后 `upsert_page_embedding` 写入（保证 freshness 校验走真实路径）；
3. query 侧用 `EmbeddingProvider` fake：按 query 文本查 queries JSON 的 topic 向量返回，
   计数调用次数、拒绝未知文本；
4. 每条 query 分别跑 `SearchService.search`（keyword）与
   `HybridSearchService(lexical, hydration=Database, vector=PersistentVectorRecallSource)`（hybrid）；
5. 按 Phase 1C 合同计算指标，输出 stdout 摘要 + `--json-out` + `--md-out`；
6. 硬约束：0 HTTP、0 Qwen、0 LLM、0 rerank、0 真实 page embedding、retry 不存在（无 transport）。

## 测试设计（tests/test_retrieval_benchmark.py）

只锁机制，不锁质量阈值：

- corpus/queries JSON 完整性（relevant_pages 存在、embedded 覆盖数、foreign topics 无页面使用）；
- fixture 隔离三元组不等于生产常量；
- runner 确定性：同一输入连跑两次，keyword/hybrid 排序逐字节一致；
- 指标函数单测（best_rank / RR / delta 标签 / coverage）；
- fake provider 每条 hybrid query 恰好被调用 1 次；
- **不断言任何 Hit@1 / MRR 阈值**（阈值等 baseline 证据出来后再由人工决定）。
