## App Factory

`src.hosted_api.app.create_hosted_app(settings=..., dependencies=...)` constructs
transport only. There is no module-global app or production bootstrap command.
The factory does not load settings, instantiate a Database/provider, invoke
readiness, configure logging, or call application services. Settings and
dependencies come from a trusted server-side composition root.

Formal construction requires exact process `EKB_RUNTIME_PROFILE=hosted` and a
`HostedSettings` instance. Missing, Local, empty, mixed-case and unknown profiles
are rejected. Imports are safe even with an invalid process profile: parsing
occurs at explicit construction, not import. No Local fallback exists.

## Dependency Injection

`src.hosted.application.HostedDependencies` is independent of HTTP. It holds the
existing `SingleStepAgentService`, `DecisionProvider`, the existing `AgentRequest`
class as `request_factory`, a source reader, and a readiness checker.

The extra request-class injection has a concrete reason: importing the legacy
`src.agent` package eagerly imports its Tool bootstrap and mixed read/write
service modules. Type-only references in the isolated Hosted package preserve
the Hosted import boundary without rewriting frozen Agent modules. The trusted
caller must inject the existing `AgentRequest`, not a replacement contract.
No request field can select or alter any dependency.

`src/hosted/` is separate from the Local top-level application modules and from
`src/hosted_api/`. Existing static dependency tests remain unchanged. Missing
Agent/provider/request factory/source composition makes readiness fail closed.
WP4/WP5 own actual storage/provider/server composition; WP2 does not silently
substitute a Local runtime or call a provider constructor.

## HTTP DTOs

`src.hosted_api.contracts` defines explicit Pydantic DTOs with `extra="forbid"`.
Input is strictly `text: str` plus optional `correlation_id`. Numbers, booleans,
objects, missing text, malformed JSON and extra fields are rejected.

The existing `AgentRequest` remains the authoritative 120,000-character guard.
HTTP constructs that request before checking admission or running the Agent.
Empty/whitespace text is preserved, no trimming or new minimum is added, and
Unicode characters use the same length semantics. OpenAPI does not duplicate
the application's length constant as a second independently maintained limit.
The future 512,000-byte ingress limit is not implemented in WP2.

## POST /v0.6/agent/run

1. Parse the strict HTTP DTO.
2. Generate a fresh server UUID4 `request_id` and construct the existing AgentRequest.
3. Check Hosted readiness and required composition.
4. Call `SingleStepAgentService.run(request, decision_provider)` once.
5. Explicitly project the returned AgentResponse.

`correlation_id` accepts only 1–128 ASCII letters, digits, `.`, `_`, `-`, or null/
absence. It is echoed as `X-Correlation-ID` when a run returns HTTP 200. It does
not enter AgentRequest, prompts, Tool arguments, SQL, paths, authorization or
server identity. Client `request_id` is an extra field and is rejected.

Public fields are exactly `request_id`, `status`, `answer`, `grounded`, `citations`,
`warnings`, `error`. Error fields are exactly `code` and a fixed safe `message`.
The validated final answer is retained; raw model output is never serialized.
Raw internal warnings are replaced by a generic warning when warnings exist,
because legacy provenance warnings can contain private titles/paths. The adapter
does not re-run citation validation; canonical ID syntax is checked for public
serialization, while evidence authority and citation validity remain the Agent's job.

## GET /v0.6/sources/{stable_id}

`src.source_metadata.SourceMetadataService` is a small DB-backed display facade
over explicitly injected existing read methods:

| Citation type | Existing read capability | Display fields |
| --- | --- | --- |
| `page` | `Database.get_page` + `get_document` | document title, page label |
| `knowledge_object` | `Database.get_knowledge_object` | title, kind label |
| `knowledge_memory` | `Database.get_knowledge_memory_entry` | title, kind label |
| `evidence` | `EvidenceBasketService.get_item` | document title, page label |

These are the four types accepted by the existing Final Answer context mapping.
The seven Tools' reference review also found `knowledge_source` references in
source integrity results; they are not supported citation display types here.
Well-formed unsupported types (including relation/revision/knowledge_source)
return 404 without a read or a guessed match.

Public IDs must be canonical lowercase UUID text, a lowercase type, and a positive
decimal SQLite integer no larger than 2^63-1, with no leading zero, sign, whitespace
or alias. The older Tool helper accepts whitespace/int aliases, so it is not used
as the public parser. Existing `build_stable_id` generates returned identities.
Foreign KB UUIDs return not found before any read. Missing rows and missing parent
documents return not found. The projection checks the returned identity/type.

Routes contain no SQL and do not instantiate repositories or mixed services.
Only bound read capabilities are supplied; no write method is mounted as an API.
Source reads do not depend on AI readiness; unavailable source composition returns
503, missing metadata 404, unexpected adapter/read errors a sanitized 500.

## GET /health

Always returns HTTP 200 with `{"status":"ok"}` for a constructed app. It does not
check readiness, access the database, invoke AI, inspect paths, or write files.
Missing AI or DB configuration does not turn liveness into readiness.

## GET /ready

Calls the independent Hosted readiness/composition boundary. Returns HTTP 200
with `ready=true/status=ready` or HTTP 503 with `ready=false/status=not_ready`.
Reasons are a closed enum: `runtime_invalid`, `database_unavailable`,
`schema_incompatible`, `ai_not_configured`, `budget_not_configured`,
`composition_unavailable`. No root path, key contents/length, schema internals,
exception text or provider details are exposed.

## HTTP Status Semantics

| Outcome | HTTP status |
| --- | --- |
| Successful transport returning AgentResponse COMPLETED | 200 |
| Successful transport returning AgentResponse FAILED | 200 |
| Malformed JSON, unknown/missing/invalid field, Agent text over limit | 422 (framework parsing may use another safe 4xx) |
| Syntactically invalid stable ID | 422 (unmatched path shapes may be 404) |
| Well-formed missing/unsupported source | 404 |
| Required Hosted readiness/composition unavailable | 503 |
| Unexpected adapter failure | 500, sanitized |

FAILED does not trigger any retry, fallback model, Tool rerun, or new HTTP status
taxonomy. Unknown route/method errors also use the explicit safe error envelope.

## Public Error Boundary

Validation handlers never serialize `exc.errors()` because it contains rejected
input. Error codes/messages come from a closed catalog. `error.detail`, exception
repr/traceback, SQL, paths and secrets are not returned. `_SafeRoute` catches
unexpected route/response-projection exceptions before ASGI would re-raise into
server exception logs, and emits only the server request ID and fixed category.
It does not log request text, correlation, exception text/class or settings.

This covers the HTTP adapter's own output/logging; it is not a rewrite of all
legacy service/provider logging. Production composition must preserve existing
provider redaction and storage boundaries. No production stack was instantiated.

## Source Metadata Privacy

Only `stable_id/type/title/label` are returned. No document/page body, PDF/image
path, fingerprint/hash, timestamps, revision/basket data, private notes, raw
ToolResult or DB row serialization. Path traversal, absolute paths, SQL-shaped
identifiers and noncanonical aliases cannot reach a source reader.

Display text longer than 500 characters, containing control characters or path
separators/colon is omitted. This intentionally conservative legacy-title filter
does not inspect files and is not a proof that a corpus is public. Explicit title
metadata and final answers still require the sanitized Hosted artifact selected
by later composition; WP2 does not scan/copy/sanitize production knowledge.

## Readiness Composition

`src.hosted.readiness.HostedReadiness.check` composes WP1 validation with an
injectable database check, nonblank SecretStr AI key, and a finite budget in at
least one period. `HostedDependencies.check_readiness` adds composition readiness.

`check_hosted_database` checks the configured existing path, connects with SQLite
URI `mode=ro`, reads `MAX(version)` from `schema_migrations` (not user_version),
requires exactly SCHEMA_VERSION=12, and checks that KB identity metadata exists.
Missing/unreadable DB and older/newer/unreadable schema are not ready. No Database
constructor, CREATE/INSERT/UPDATE, migration, backup, seed, audit append, completion,
embedding, rerank, content scan or journal_mode change occurs.

SQLite `mode=ro` can create/manage WAL/SHM sidecars for an existing WAL database;
this was observed on the disposable v12 fixture. The main DB bytes remain
unchanged and only SELECT statements are issued by readiness. `immutable=1` was
not used because it would ignore live WAL state. WAL/storage permissions and
artifact lifecycle belong to WP4; this probe does not claim a fully hardened
Hosted SQLite runtime.
