# Engineering Knowledge Base v0.3.2 发布说明

## 本版重点

1. **跨文档知识聚合**：新的「知识聚合」页按项目或标签汇总分散在多份资料中的
   笔记与证据。
2. **更完整的文档删除生命周期**：删除已导入文档前可看清全部影响，证据篮
   条目有独立高风险确认。
3. **crash-safe 删除恢复**：删除过程中断后重启可自动对账，状态不明一律
   保留现场。

## 用户可见变化

- 新增「知识聚合」页：选择项目或标签，即可看到该主题下跨文档积累的全部
  结构化笔记与证据；支持按重要程度、笔记类型筛选与分页；每条目显示来源
  文档与页码，可「查看原文」回到对应页面，证据条目可「查看证据篮」。
- 文档删除入口移至阅读页「文档管理」，名为「永久删除导入文档及关联数据」。
- 删除前的预览现在包含：四类笔记分别计数、证据条目数、以及**知识聚合
  影响**（该文档的内容当前出现在哪些项目/标签聚合视图中）。
- 如果文档还有证据篮条目，删除前必须额外勾选一项独立确认，明确这些摘录、
  快照与批注也将永久删除。
- 系统维护页新增「删除隔离区」区块：若有中断的删除操作，可看到其状态；
  需要人工处理的情况会明确提示。

## 数据安全

- 删除不是简单地删 PDF：它永久删除文档及其页面、笔记、证据与派生数据，
  并在执行前逐项披露。标签、项目、证据篮本体始终保留；导入记录保留为审计。
- 删除在单个数据库事务内完成并做残留校验；任何失败都会回滚数据库并把
  文件恢复原位。
- 每次删除先把文件移入带 manifest 的隔离区，数据库提交成功后才真正销毁；
  进程在删除中途被杀时，重启后系统能判定删除是否已提交：未提交则恢复
  文件，已提交则完成清理。
- manifest 损坏、路径异常、文件内容冲突等无法判定时，系统**不会**自动
  删除或覆盖任何文件，只在系统维护页报告，等待人工处理。
- 知识聚合是实时只读查询，不建副本、不做缓存；删除文档后聚合结果自然消失，
  不会出现点进去才发现来源不存在的条目。

## 已知限制

- 本版要求 **Streamlit <1.61**：已钉定的 streamlit-image-coordinates 0.4.0
  （目前最新）仍依赖 Streamlit 1.61 移除的内部接口。这是依赖兼容限制，
  不是功能回退；上游修复后可解除。
- 删除仍为永久操作：本版没有回收站 / 撤销删除。
- 知识聚合页为只读浏览层：编辑笔记、管理证据仍在各自页面进行。
- 聚合是确定性结构化查询，不包含 AI 自动总结或主题聚类。
