## 2. 答辩 Q&A 索引（按类；每答 15–30 秒；标注 SUPPORTED / ROADMAP / NOT READY）

通用答辩原则：先答结论，再给一句证据，不展开架构细节；被追问技术再翻
技术附录（final-audit Architecture Story）。

### Product（产品）
- 这是什么产品？→ 本地运行的个人工程知识库+带依据问答。（SUPPORTED）
- 和 Notion/语雀等笔记的区别？→ 它们组织文档，EKB 组织"资料+经验+依据"，
  并提供可回源的问答与来源变化提示。（SUPPORTED）
- 谁在用？→ 维护者个人在用的工具，本次以产品形态参赛；无生产客户数据可声明。
  （SUPPORTED-个人使用；大规模使用 NOT READY）

### Innovation（创新）
- 创新点是什么？→ 追溯闭环 / fail-closed / 信任边界三条（均有实现与测试）。
  （SUPPORTED，表述为"面向工程场景的工程设计"，不称学术首创）
- 别人复制难吗？→ 难在知识组织模型+证据链工程化+克制的边界设计，
  不在单个技术点。（SUPPORTED-定性）

### AI（AI 能力）
- 用的什么模型？→ 厂商中立的 Provider 契约，当前官方运行时为通义千问系列，
  可配置替换；模型与产品解耦。（SUPPORTED）
- 会幻觉吗？→ 无法承诺零幻觉；EKB 的对策是强制引用+校验+无依据不回答，
  把"可信"变成可核对。（SUPPORTED-机制；"零幻觉"禁用）
- 演示是真实 AI 吗？→ 比赛演示用确定性预置语料（页面有标识），保证可重复
  且零隐私风险；真实链路是同一界面的"本机 Agent"模式。（SUPPORTED-如实）

### Data / Privacy（数据与隐私）
- 数据存在哪？→ 只在本机（SQLite+文件），不上传、不进 Git。（SUPPORTED）
- 别人能访问吗？→ 服务仅绑定 127.0.0.1，局域网不可见。（SUPPORTED）
- 资料会喂给云端训练吗？→ 演示模式零云端调用；真实 Agent 启用云端模型时
  仅按用户配置调用，产品不做任何隐式上传。（SUPPORTED-机制）

### Technical architecture（技术架构）
- Agent 为什么单步？→ 可预算、可复现、可审计；自主多步在 v0.7+ 按可靠性
  里程碑引入。（SUPPORTED-设计；多步 ROADMAP）
- 引用怎么保证真实？→ 终答阶段逐条校验来源标识，失败整体降级为失败。
  （SUPPORTED）
- 技术栈？→ Python/Streamlit/SQLite（schema v12），本地优先；AI 调用全部
  进台账。（SUPPORTED）

### Testing（测试）
- 质量怎么保证？→ 自动化全量（CURRENT 2685 passed/4 skipped，终稿用 9/15
  冻结重跑值）+ 三人真实人工测试（用例体系见 manual-test-plan）。
  （SUPPORTED；数字终稿以 fact-freeze 为准）
- 演示稳定性？→ 确定性 fixtures+冻结场景+重置控制；八连跑零串台。（SUPPORTED）

### Deployment（部署）
- 上线了吗？→ 没有；公网部署 DEFERRED（WP6A 暂停/WP6B 未启动），按独立
  门禁推进。（NOT READY，如实）
- 能私有化部署吗？→ 本地单机即产品形态；云端多租户不在当前范围。
  （SUPPORTED-本地；多用户 NOT READY）

### Commercialization（商业化）
- 怎么赚钱？→ 当前聚焦把个人价值做实；可行方向（团队/企业内部知识库）在
  探索，无收入数据可声明。（ROADMAP；禁编造）

### Roadmap（路线）
- 下一步？→ v0.7 个人经验 Agent、v0.8 可靠性、v0.9 强化、v1.0 个人经验系统；
  语料批准与部署按门禁推进。（ROADMAP，引用既有规划，不承诺日期）

## 3. 答辩纪律

- 数字只引用 fact-freeze 表（9/15 后版本）；CURRENT 数字必须带"截至 8/29"。
- 被问到红线话题（上线/篡改/多用户/准确率）按 zhaohan-handoff §11 口径回答。
- 现场演示一律走冻结脚本（runbook）；异常按回退程序处理，不现场排障。
