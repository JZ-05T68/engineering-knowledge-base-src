# EKB v0.5.x Roadmap

## 定位

v0.5.0 建立 AI provider、受控真实调用、page-level embedding、Hybrid Retrieval、
成本边界和 production closure 的基础，但它不是整个 v0.5.x 稳定化周期的终点。

本路线不预设固定数量的 v0.5.x 支版本，也不因为 v0.5.0 发布就宣布 v0.6.0 已开始。

## v0.5.0 已完成

- 厂商无关的 Completion / Embedding / Rerank provider 契约；
- Qwen runtime 基础与 `qwen3.7-plus` 受控真实调用；
- `qwen3.7-text-embedding` 实验、页面级持久化与 SHA-256 freshness；
- lexical recall、persistent vector recall、候选并集与 RRF 融合；
- Hybrid Search UI 门控、来源标签与关键词 fallback；
- page indexing orchestration、批量限制、staging guard 与 cost guard；
- production `data/` / 8501 与 staging `staging-data/` / 8502 隔离；
- Phase 10C/10D/10E、Phase 11C/11D retrieval evidence 与最小 benchmark；
- schema v8、production closure、完整自动化与人工 Gate 证据。

这里的“完成”只指 v0.5.0 已冻结范围，不表示 retrieval 质量、误召回或 UX 已经不存在改进空间。

## v0.5.0 发布后

进入测试驱动的密集稳定化周期：

- 真人测试与 AI-assisted testing；
- retrieval quality testing 与 benchmark expansion；
- 语义改写、术语精确命中、跨文档召回和误召回案例收集；
- 缺陷修复、回归验证与稳定性加固；
- latency、调用次数、retry、token / embedding 成本行为核验；
- 搜索解释性、证据闭环、首次使用和展示体验改进。

每一个 v0.5.x 支版本都应由具体测试结果、缺陷、稳定性、retrieval quality、UX、成本行为或
展示闭环驱动。支版本数量保持开放，不为了预定版本号制造范围。

## v0.6.x Entry Condition

是否进入 v0.6.x，至少共同评估以下四个维度：

1. **Retrieval Stability**：离线回退、索引 freshness、异常路径和长时间运行可控；
2. **Retrieval Quality**：扩展 benchmark 与真人问题集提供足够证据，已知误召回可解释；
3. **Cost**：真实调用次数、索引范围、retry 与预算边界可审计；
4. **UX**：用户理解关键词 / Hybrid 差异，付费边界、来源和证据状态清晰。

只有证据支持上述条件时，才决定 v0.6.x 的正式主题与范围。当前不承诺具体功能、日期或版本数量。
