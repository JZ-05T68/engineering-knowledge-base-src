# EKB Roadmap — From Knowledge Foundation to Personal Experience System

## 定位

Engineering Knowledge Base（EKB）的长期方向是一个本地优先的个人知识系统：帮助用户把主动提供的
资料、项目决策、调试过程、错误经验、学习记录和工程实践，逐步转化为可追踪、可验证、可复用的
长期知识资产。

路线图遵守以下不变边界：

- 本地文件和 SQLite 是唯一事实来源；核心能力必须离线可用；
- 只处理用户主动提供或明确授权的资料；
- 自动化不能静默覆盖原始资料、修改用户笔记或删除文件；
- AI 和 Agent 只能作为可选增强，不能成为启动或核心知识管理依赖；
- 不引入账号、登录、多用户权限、云同步或云端事实来源。

未来版本主题是方向，不是已经完成的能力，也不构成发布日期承诺。

## v0.5.x — Knowledge Foundation

**状态：当前版本线；v0.5.2 已完成本阶段基础收口。**

目标是建立个人知识资产的可管理、可验证和可检索底座：

- Knowledge Object：概念、事实、原理、经验、问题和决策；
- Source：连接本地 document、page、note 和 evidence；
- Revision：以追加式记录保存知识演进；
- Source Fingerprint：识别来源有效、变化、缺失或未知状态；
- Evidence：保留来源定位与人工确认边界；
- Knowledge Memory：手动记录问题解决、经验和决策；
- Retrieval：使用 schema v11 FTS5 检索 page、knowledge object 和 knowledge memory；
- Provenance：从检索结果回到本地来源核验。

本阶段不包含 Personal Context Agent、自动经验学习或云同步。

## v0.6.x — Personal Context Agent

**状态：未来规划；尚未开始，尚未实现。**

方向是在用户显式控制下，围绕已有本地知识资产组织任务所需上下文。候选研究范围包括：

- 根据用户明确选择的问题和知识范围组装个人上下文；
- 解释选取了哪些知识对象、记忆和证据，以及为什么选取；
- 在来源失效、指纹变化或证据不足时 fail closed；
- 把建议与事实来源分离，并要求用户确认任何持久化变更。

该阶段不会允许 Agent 自动扫描私人资料、自动修改笔记、自动写入经验或在用户不知情时持续行动。
最终范围必须在 v0.6.x 启动前另行冻结和验证。

## v0.7.x — Experience Memory

**状态：未来规划；尚未开始，尚未实现。**

方向是增强长期经验的沉淀、确认、演进和复用。候选研究范围包括：

- 把项目决策、调试过程、失败路径和复盘记录组织为长期经验；
- 区分用户事实、来源证据、系统建议与人工确认结论；
- 在 revision 和 supersedes 关系中保留经验演进，而不是静默覆盖旧结论；
- 支持用户主动确认、修订、归档和重新激活经验记忆；
- 评估经验在新问题中的适用范围，并保留来源与不确定性。

“Experience Memory”不等于后台自动学习。未经用户确认的推断不得成为正式个人经验资产。

## v1.0 — Personal Experience System

**状态：长期方向；尚未实现。**

目标是形成完整的 Personal Experience System：让个人多年积累的资料、知识、决策和经验在本地形成
连续、可审计、可迁移、可验证和可复用的工程能力资产。

进入 v1.0 前至少需要证明：

1. Knowledge Foundation 在真实长期资料中保持完整、可恢复和可迁移；
2. Personal Context Agent 的上下文选择透明、受控且不会越过信息边界；
3. Experience Memory 的形成与修改始终保留人工确认、来源和修订历史；
4. 离线核心能力、单用户边界和本地事实来源不因可选 AI 能力而退化；
5. 备份、恢复、删除和升级路径在长期使用中持续通过数据安全验证。

## 版本推进原则

- 不为了预定版本号制造范围；每个版本必须由冻结契约和验证证据驱动。
- roadmap 内容不得在 README、CHANGELOG 或 UI 中写成已经完成的功能。
- 发现源码问题时记录为后续 issue，不在发布文档迁移阶段扩大实现范围。
- 任何未来 Agent 或自动化能力都必须尊重用户控制、信息授权和可逆性。
