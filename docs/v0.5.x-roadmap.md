# EKB Roadmap — From Knowledge Foundation to Personal Experience System

## 定位

Engineering Knowledge Base（EKB）的长期方向是一个本地优先的个人知识系统：帮助用户把主动提供的
资料、项目决策、调试过程、错误经验、学习记录和工程实践，逐步转化为可追踪、可验证、可复用的
长期知识资产。

路线图遵守以下不变边界：

- 本地文件和 SQLite 是唯一事实来源；核心能力必须离线可用；
- 只处理用户主动提供或明确授权的资料；
- 自动化不能静默覆盖原始资料、修改用户笔记或删除文件；
- AI 和 Agent 只能作为可选增强，不能成为启动或核心知识管理依赖；
- 不引入账号、登录、多用户权限、云同步或云端事实来源。

未来版本主题是方向，不是已经完成的能力，也不构成发布日期承诺。

## v0.5.x — Knowledge Foundation

**状态：当前版本线；v0.5.3 完成可审计 AI 接入、台账、导出与备份升级。**

目标是建立个人知识资产的可管理、可验证和可检索底座：

- Knowledge Object：概念、事实、原理、经验、问题和决策；
- Source：连接本地 document、page、note 和 evidence；
- Revision：以追加式记录保存知识演进；
- Source Fingerprint：识别来源有效、变化、缺失或未知状态；
- Evidence：保留来源定位与人工确认边界；
- Knowledge Memory：手动记录问题解决、经验和决策；
- Retrieval：使用 schema v11/v12 FTS5 检索 page、knowledge object 和 knowledge memory；
- Provenance：从检索结果回到本地来源核验；
- ContextItem / KnowledgeContextPackage：统一只读上下文投影与打包；
- 可审计 AI 接入：Ask AI / RAG Answer、引用运行时校验、只读经验候选、AI 调用台账；
- 结构化导出：Knowledge Export 与 AI Ledger Export；
- schema v8 旧备份隔离升级。

本阶段不包含 Agent、自动经验学习、工具调用、长期会话记忆或云同步。

## v0.6.x — Agent Foundation

**状态：未来规划；尚未开始，尚未实现。**

方向是建立 Agent 的基础工程能力。候选研究范围包括：

- Agent 的任务边界、信息授权与可逆操作模型；
- 用户显式控制下的上下文选择与工具调用协议；
- 审计、预算、重试与失败回滚的 Agent 级基础设施；
- 与既有台账、来源校验和 fail-closed 契约的集成方式。

Agent 自主选择和工具调用从 v0.6.x 才开始进入范围；本阶段之前不允许实现。

## v0.7.x — Personal Experience Agent

**状态：未来规划；尚未开始，尚未实现。**

方向是在 Agent Foundation 之上使用用户长期经验。候选研究范围包括：

- 把项目决策、调试过程、失败路径和复盘记录组织为长期经验；
- 区分用户事实、来源证据、系统建议与人工确认结论；
- 在 revision 和 supersedes 关系中保留经验演进，而不是静默覆盖旧结论；
- 支持用户主动确认、修订、归档和重新激活经验记忆；
- 评估经验在新问题中的适用范围，并保留来源与不确定性。

用户长期经验从 v0.7.x 才开始被 Agent 使用；未经用户确认的推断不得成为正式个人经验资产。

## v0.8.x — Agent Reliability

**状态：未来规划；尚未开始，尚未实现。**

方向是处理 Agent 错误行为与可靠性。候选研究范围包括：

- 错误分类、回滚、可解释失败与用户可理解的恢复路径；
- 防止越权写入、重复操作和不可逆副作用；
- 对 Agent 行为的持续验证与回归基线。

## v0.9.x — Agent Hardening

**状态：未来规划；尚未开始，尚未实现。**

方向是处理长期运行、成本、上下文、记忆污染、Eval 和工程硬化。候选研究范围包括：

- 长期运行成本与预算控制；
- 上下文增长与记忆污染防护；
- Eval 体系与回归门禁；
- 工程硬化与发布稳定性。

## v1.0.0 — Personal Experience System

**状态：长期方向；尚未实现。**

目标是形成完整的 Personal Experience System：让个人多年积累的资料、知识、决策和经验在本地形成
连续、可审计、可迁移、可验证和可复用的工程能力资产。

进入 v1.0.0 前至少需要证明：

1. Knowledge Foundation 在真实长期资料中保持完整、可恢复和可迁移；
2. Agent Foundation 的上下文选择与工具调用透明、受控且不会越过信息边界；
3. Personal Experience Agent 长期经验的使用始终保留人工确认、来源和修订历史；
4. Agent Reliability 与 Agent Hardening 的验证基线持续通过；
5. 离线核心能力、单用户边界和本地事实来源不因可选 AI 能力而退化；
6. 备份、恢复、删除和升级路径在长期使用中持续通过数据安全验证。

## 版本推进原则

- 不为了预定版本号制造范围；每个版本必须由冻结契约和验证证据驱动。
- roadmap 内容不得在 README、CHANGELOG 或 UI 中写成已经完成的功能。
- 发现源码问题时记录为后续 issue，不在发布文档迁移阶段扩大实现范围。
- 任何未来 Agent 或自动化能力都必须尊重用户控制、信息授权和可逆性。
