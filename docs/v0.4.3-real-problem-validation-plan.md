## 3. Data Isolation Model

- disposable database copy（复制数据库，绝不直接操作正式库）
- isolated document directory（专用临时文档目录）
- temporary port（8502–8512）
- temporary runtime files（独立 runtime/log 目录）
- 真实 PDF、数据库、笔记不得提交 Git
- 破坏性 / 失效制造（RPV-06 等）只在 disposable copy 上执行：
  - 不得删除用户唯一原文件
  - 不得修改正式知识库数据
- 若使用用户真实已有知识库：只允许 READ-ONLY real workflow；任何 MUTATING / invalid-source 测试必须在副本中进行

## 4. Synthetic vs Real Human Distinction

- A. synthetic / controlled verification：由自动化与受控测试完成，使用程序生成的合成 PDF 与临时数据。
- B. real human engineering problem verification：必须由真人杨洋最终确认，使用 HD-01 指定的真实工程资料。

**Kimi 不得把"测试代码跑过"等价成"真实工程问题验证通过"，不得冒充真人完成 Human Gate。**

### 4.1 Real Data — HUMAN INPUT REQUIRED

RPV HUMAN INPUT REQUIRED: REAL DOCUMENTS

具体 PDF 文件不由本计划填定。冻结的数据形态（HD-01）：同一真实技术主题下 2～3 份正式、公开、可用于隔离测试的工程资料，优先组合 Reference Manual + Datasheet + Application Note / User Manual / Technical Note。实际 PDF 由杨洋在 RPV execution 前指定。

### 4.2 Real Question — HUMAN INPUT REQUIRED

RPV HUMAN INPUT REQUIRED: REAL ENGINEERING QUESTION

真实工程问题必须由杨洋本人在测试现场提出。Kimi 不得提前写问题再用自己熟悉的答案证明系统通过。

问题资格（冻结）：

- 必须是真实技术问题
- 必须需要查阅资料
- RPV-02 的问题必须需要至少两个独立来源联合才能回答
- 答案所依赖事实必须能够回溯
- 不要求问题具有唯一标准答案
- 不允许通过开发者内部知识绕开 EKB 工作流

## 5. RPV Test Definitions

状态取值：`NOT STARTED` / `PASS` / `FAIL` / `BLOCKED`。PASS 仍必须写实际观察。

### RPV-01 单资料真实检索

- **Purpose**：针对一份正式工程资料提出一个真实技术问题，验证 问题 → 搜索 → 查看命中 → 回原页 → 选取证据 → 确认 → Prompt Package 全链路。
- **Preconditions**：ENV-PREP PASS；隔离实例运行；HD-01 真实资料已导入隔离实例；HD-02 真实问题由杨洋现场提出。
- **Steps**：
  1. 在隔离实例中对真实问题执行检索。
  2. 查看命中结果，跳回原页核对原文。
  3. 将命中内容作为证据加入证据篮（文字选区或整页）。
  4. 确认（confirm）证据。
  5. 生成 Prompt Package。
- **Expected result**：
  - 命中与原文一致
  - 来源页可回溯（返回原始页到达正确文档/页码）
  - citation 不错位（证据序号、标题、文件名、页码与来源一致）
  - Prompt 中每条证据身份明确
- **Automated evidence**：检索命中记录；证据篮记录；生成的 Prompt Package 原文；指纹值。
- **Human confirmation**：杨洋核对命中原文一致性与 citation 正确性（→ H1）。
- **Failure classification guidance**：命中与原文不一致或 citation 错配 → BLOCKER 候选；无法回原页 → HIGH 候选；流程摩擦但有 workaround → MEDIUM。
- **Result**：NOT STARTED

---

### RPV-02 多资料联合证据

- **Purpose**：验证至少两份不同文档的联合证据工作流。问题必须需要两份资料联合才能回答（HD-02 资格约束）。
- **Preconditions**：同 RPV-01；隔离实例中至少有 2 份同主题真实资料；问题满足"需两个独立来源联合"。
- **Steps**：
  1. 用同一问题分别检索两份文档。
  2. 从两份文档各收集至少一条证据。
  3. 在证据篮中排序（调整顺序并记录）。
  4. 确认全部拟用证据。
  5. 生成 Prompt Package。
- **Expected result**：
  - 可以收集跨文档证据
  - 排序稳定（重排后顺序与操作一致，重进页面不丢失）
  - 来源身份不混淆（每条证据的文档/页码正确）
  - Prompt Package 中每条证据来源可区分
  - 不出现跨来源错配（A 文档证据标注为 B 文档）
- **Automated evidence**：证据篮条目元数据；排序操作前后 position 记录；Prompt Package 原文。
- **Human confirmation**：杨洋核对跨文档来源身份（→ H2）。
- **Failure classification guidance**：跨来源错配 / 无法判断事实来源 → BLOCKER 候选；多文档来源混淆 → HIGH 候选。
- **Result**：NOT STARTED

### RPV-03 正式资料 + 用户笔记

- **Purpose**：验证问题同时涉及原始工程资料与用户结构化笔记时，笔记可以参与证据工作流，但用户备注/判断不能伪装成原始资料事实。
- **Preconditions**：同 RPV-01；隔离实例中已有杨洋现场建立的结构化笔记（text_selection 与/或 image_region 类型）。
- **Steps**：
  1. 针对一个同时涉及资料与个人判断的问题检索资料。
  2. 建立/使用一条结构化笔记并加入证据篮。
  3. 同时加入一条来自原始资料的证据。
  4. 确认并生成 Prompt Package。
- **Expected result**：
  - 笔记可进入证据工作流
  - Prompt Package 中 SOURCE FACT（`来源内容：`）与 USER NOTE（`用户备注：`）可明确区分
  - 用户备注不被表达为资料事实
- **Automated evidence**：笔记加入证据篮的记录；Prompt Package 原文中两类标签的分离。
- **Human confirmation**：杨洋判断真人能否清楚区分笔记与 source fact（→ H4）；同时观察笔记入口可发现性（→ DF-OBS-02 裁决输入）。
- **Failure classification guidance**：user note 被表达为 source fact → HIGH 候选；入口无法理解/找不到 → 结合 RPV-11 判 MEDIUM 或更高。
- **Result**：NOT STARTED

### RPV-04 三类证据联合

- **Purpose**：同一证据篮尽可能覆盖 page / text_selection / image_region 三类证据，检查三者 source semantics 是否诚实。
- **Preconditions**：同 RPV-01；隔离实例中有可用的图片区域笔记（image region 证据当前只能经由图片区域笔记进入证据篮，DF-OBS-01）。
- **Steps**：
  1. 分别向证据篮加入：整页证据、文字选区证据、图片区域证据（经由图片区域笔记）。
  2. 确认全部三条。
  3. 生成 Prompt Package。
- **Expected result**：
  - 三类证据均可确认并进入 Prompt
  - text selection 导出选中文本；page 导出当前页文本；image region 仅导出尺寸/坐标与"不含像素、不得猜测内容"声明
  - image region 不得因有坐标或用户备注就在纯文本 Prompt 中声称知道图片内容
- **Automated evidence**：三类证据的导出片段；区域声明文本存在性。
- **Human confirmation**：杨洋检查图片区域表述是否诚实、路径是否可自然理解（→ DF-OBS-01 观察）。
- **Failure classification guidance**：图片区域被包装成文字事实 → HIGH 候选；三类证据无法联合导出 → HIGH 候选。
- **Result**：NOT STARTED

### RPV-05 confirmed boundary

- **Purpose**：混合 confirmed / unconfirmed 证据生成 Prompt Package，证明只有 confirmed 进入 Prompt。
- **Preconditions**：同 RPV-01；证据篮中同时存在 confirmed 与 unconfirmed 条目。
- **Steps**：
  1. 准备至少 2 条 confirmed + 至少 1 条 unconfirmed。
  2. 生成 Prompt Package。
  3. 全文检查 Prompt 内容。
- **Expected result**：
  - 只有 confirmed 进入 Prompt
  - 未确认项不被静默包含（包括其文本、备注、来源信息）
- **Automated evidence**：既有自动化（`tests/test_evidence_prompt_package.py` confirmed-only 套件）+ 隔离实例实测 Prompt 原文。
- **Human confirmation**：杨洋逐条核对 Prompt 内容边界（→ H1 组成部分）。
- **Failure classification guidance**：unconfirmed evidence 进入最终 Prompt → **BLOCKER**。
- **Result**：NOT STARTED

### RPV-06 invalid source fail-closed

- **Purpose**：在隔离测试数据上制造来源失效，验证任一 confirmed source invalid 时整包拒绝。
- **Preconditions**：同 RPV-01；**所有失效制造只允许在 disposable copy 上执行**。
- **Steps**（在副本上分别制造）：
  1. text source changed：修改页文本使 text_selection 的 `source_text_sha256` 失配。
  2. page/document missing or invalid：移除页 PNG / 使文档来源不可达（副本内）。
  3. image anchor invalid：替换页 PNG 使 image_region 锚 hash 失配，或使坐标出界。
  4. 每种失效下尝试生成 Prompt Package。
- **Expected result**：
  - 任一 confirmed source invalid → 整包拒绝（EvidenceSourceError，UI 给出中文错误提示）
  - 不得静默跳过坏证据
  - 不得自动修复后继续
  - 不得输出部分 evidence package 并伪装完整
- **Automated evidence**：既有自动化（fail-closed 套件）+ 隔离实例实测错误表现截图/日志。
- **Human confirmation**：杨洋确认 UI 表现可理解、无误导性输出。
- **Failure classification guidance**：已知 invalid confirmed evidence 仍生成完整 Prompt → **BLOCKER**；invalid evidence 被静默忽略 → HIGH。
- **Result**：NOT STARTED

### RPV-07 stale Prompt invalidation

- **Purpose**：生成有效 Prompt 后分别改变各输入，验证旧 Prompt 立即不再作为当前结果。
- **Preconditions**：同 RPV-01；已在隔离实例生成有效 Prompt Package。
- **Steps**：生成后分别执行以下变更（逐项独立观察）：
  1. 修改 question
  2. confirmed evidence 增/删
  3. confirmation 状态变更
  4. confirmed 排序变更
  5. confirmed 用户备注变更
  6. 当前页文本变更 / 来源有效性变更（副本内）
- **Expected result**：每项变更后，旧 Prompt 立即不再作为当前结果展示（UI 提示需重新生成）。
- **Automated evidence**：既有自动化（指纹失效套件 + AppTest stale 套件）+ 隔离实例逐项操作记录。
- **Human confirmation**：杨洋体验 stale 行为是否清晰可理解（→ H5）。
- **Failure classification guidance**：stale Prompt 被作为 fresh Prompt 使用 → **BLOCKER**；freshness 明显漏判 → HIGH。
- **Result**：NOT STARTED

### RPV-08 stale resurrection defense

- **Purpose**：制造 stale 后把用户输入改回原值，验证旧 Prompt 不得自动复活。
- **Preconditions**：同 RPV-07，已制造至少一种 stale 状态。
- **Steps**：
  1. 生成有效 Prompt（记录原文）。
  2. 修改任一纳入指纹的输入 → 确认 stale（旧 Prompt 被移除）。
  3. 把输入改回原值。
  4. 观察 UI 是否自动恢复旧 Prompt。
- **Expected result**：
  - 旧 Prompt 不得自动复活，必须显式重新生成
  - 显式重新生成后内容可与原一致（这是新生成，不是复活）
- **Automated evidence**：操作序列记录；session_state 层面无残留（可由 Kimi 收集机器证据）。
- **Human confirmation**：杨洋确认体验符合预期（→ H5 组成部分）。
- **Failure classification guidance**：旧 Prompt 自动复活并作为当前结果 → **BLOCKER**（stale as fresh）。
- **Result**：NOT STARTED

### RPV-09 no over-invalidation

- **Purpose**：生成有效 Prompt 后修改不进入 Prompt 语义的内容，验证有效 Prompt 不无理由失效。
- **Preconditions**：同 RPV-01；已生成有效 Prompt Package。
- **Steps**：生成后分别修改（字段以当前实现为准，已核验不进入渲染的字段）：
  1. tag 变更
  2. project 归属变更
  3. review status 变更
  4. unconfirmed 证据的元数据（备注等）变更
- **Expected result**：每项变更后，已生成的有效 Prompt 不应失效（仍作为当前结果）。
- **Automated evidence**：unconfirmed 元数据不过度失效已有自动化；tag/project/review_status 维度当前无自动化钉住（TC-CAND-01 候选），本项以隔离实例实测为准。
- **Human confirmation**：杨洋确认无无理由失效。
- **Failure classification guidance**：过度失效导致真实流程反复重生成 → MEDIUM 候选；若导致用户误用旧/错输出则升级。
- **Result**：NOT STARTED

### RPV-10 trace-back audit

- **Purpose**：从 Prompt Package 任取多条证据，真人完成 Prompt evidence → Evidence Basket → original document/page 的追溯核对。
- **Preconditions**：同 RPV-01；已生成含多条证据（尽量覆盖多文档、多类型）的 Prompt Package。
- **Steps**：
  1. 从 Prompt Package 中任取至少 3 条证据。
  2. 逐条在证据篮中定位对应条目。
  3. 使用"返回原始页"回到原始文档/页。
  4. 核对：文档、页码、证据类型、来源定位是否一致。
- **Expected result**：每条证据的文档、页码、证据类型、来源定位与 Prompt 中的 citation 完全一致。
- **Automated evidence**：citation 元数据与数据库记录比对（Kimi 收集）。
- **Human confirmation**：**Mandatory Human Gate**——杨洋亲自完成追溯核对（→ H3）。
- **Failure classification guidance**：evidence 指向错误来源 / citation 身份错配 → **BLOCKER**；关键 evidence 无法可靠回原页 → HIGH。
- **Result**：NOT STARTED

### RPV-11 workflow integrity

- **Purpose**：完整走一遍真实问题全流程，重点观察是否存在必须靠开发者内部知识才能完成的隐藏步骤。
- **Preconditions**：同 RPV-01；杨洋以"普通当前用户"视角操作。
- **Steps**：
  1. 资料导入（隔离实例）→ 检索 → 阅读 → 建立笔记 → Evidence Basket → 确认 → 排序 → Prompt Package → 来源复核。
  2. 全程记录每一步是否可自然理解下一步操作。
- **Expected result**：
  - 普通当前用户无需开发者内部知识即可完成全流程
  - 若某步骤无法理解，记录 UX debt（不立刻扩功能）
- **Automated evidence**：无（以人工观察为主）。
- **Human confirmation**：杨洋全流程体验并记录摩擦点（→ H1、H7 输入；同时裁决 DF-OBS-01 / DF-OBS-02 的 severity）。
- **Failure classification guidance**：正常真实流程无法完成且无合理 workaround → HIGH；明显摩擦但有 workaround → MEDIUM；语义不清但不导致错误 grounding → MEDIUM/LOW。
- **Result**：NOT STARTED

### RPV-12 realistic AI handoff readiness

- **Purpose**：只验证 handoff readiness——EKB 生成的 Prompt Package 作为外部 AI 的 grounding input 是否诚实、可靠、可核验。**不是让 EKB 自动调用 AI**。
- **Preconditions**：同 RPV-01；已生成最终 Prompt Package（基于 RPV-01/02 场景）。
- **Steps**：
  1. 杨洋将 Prompt Package 完整复制给一个外部通用 AI 对话工具（HD-03：默认 ChatGPT，单实例，不做多模型比较）。
  2. 记录：tool/model（如可见）、测试日期时间、exact Prompt Package。
  3. 检查输入是否具备：question 明确；confirmed evidence 边界明确；citation/source 明确；user note 与 source fact 分离；image limitation 明确；不包含已知 stale evidence。
  4. 杨洋确认自己能否理解并检查 grounding 内容。
- **Expected result**：上述六项输入质量检查全部满足。
- **Automated evidence**：Prompt Package 原文存档；输入质量检查表。
- **Human confirmation**：杨洋确认可理解性与可检查性（→ H6）。**外部 AI 的答案质量本身不作为 EKB PASS/FAIL 的唯一标准**；v0.4.3 判断的是 EKB 是否给出诚实、可靠、可核验的 grounding input。
- **Failure classification guidance**：grounding input 六项中任一项不满足 → 按影响判 HIGH（如来源不清、备注混入事实、图片限制缺失）或 BLOCKER（如包含已知 stale evidence、来源错配）。
- **Result**：NOT STARTED

## 7. Failure Evidence Requirements

每个 FAIL 必须记录：

- run id / timestamp
- exact operation（精确操作序列）
- expected（预期结果）
- actual（实际观察）
- affected source / evidence type（受影响的来源与证据类型）
- screenshot / log where applicable
- reproduction status（可复现 / 不可复现）
- preliminary severity（BLOCKER / HIGH / MEDIUM / LOW；OBSERVATION 仅作附记，HD-05）

历史症状无法复现时写 NOT REPRODUCED / ROOT CAUSE NOT PROVEN，不得写 FIXED。

## 8. Exit Criteria

只有以下全部完成，才允许生成最终 decision record（`docs/v0.4.3-decision-record.md`）：

1. RPV-01～RPV-12 disposition complete（每项均有 PASS / FAIL / BLOCKED 结论与实际观察）
2. H1-H7 human disposition complete（杨洋明确签署）
3. BLOCKER / HIGH disposition complete，规则如下：
   - 已确认的 BLOCKER / HIGH 必须修复并完成规定回归（targeted regression + full regression + 必要时人工复测），才能支持 V0.5.0 GO / CONDITIONAL GO。
   - 如果后续新增证据证明原 severity 判断本身不成立，可以形成有证据链支持的正式 reclassification。reclassification 必须记录：original severity、new evidence、reasoning、new severity、reviewer / human decision。
   - 未解决的 BLOCKER / HIGH 不得通过 waiver、exception、risk acceptance、"重新决策"等措辞绕过。reclassification 不是 waiver：它要求原 severity 判断被新证据推翻，而不是带着仍然成立的问题放行。
   - 若 BLOCKER / HIGH 仍真实存在且未解决，可以生成 Decision Record，但最终 Decision 必须为 V0.5.0 NO-GO。

最终 Decision 只能是：V0.5.0 GO / V0.5.0 CONDITIONAL GO / V0.5.0 NO-GO（规则见 design freeze 文档第 9 节）。
