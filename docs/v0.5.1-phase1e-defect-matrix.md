# EKB v0.5.1 Phase 1E — Defect / Observation Matrix

- 日期：2026-08-17
- 分支：`kimi/v0.5.1-retrieval-stabilization`
- 证据来源：Phase 1A 代码审计、Phase 1D 离线 baseline（29 frozen queries）+ 机制 probe。
- 原则：**本矩阵只做定级与建议，不在本阶段修复。** 修复范围由人工确认后进入下一 Phase。
- 除特别标注外，baseline 类证据均为 algorithmic/offline evidence。

## 一、Defect Matrix

### D-01 · HIGH — partial embedding coverage 下 Hybrid 系统性压低至未嵌入的相关页

- category：retrieval quality / ranking
- reproduction：离线 benchmark J1、J2、A4、B4、C3、E1、I2（7 条 regression）；
  一条命令可复现：`python scripts/retrieval_benchmark.py`。
- expected：keyword 已把相关页排在第 1 时，hybrid 不应让它跌出语义无关页之后。
- actual：7 条 regression，relevant 页**全部未嵌入**；跌幅 1→2（J1/B4/C3）、1→4（A4）、
  1→5（E1）、1→8（J2）、8→13（I2）。
- evidence：Phase 1D §三/§四；probe 实测 J1/J2/A4 各 21 个向量候选中 18–21 个 sim=0 仍获 rank。
- suspected root cause：①向量召回无相似度阈值（`src/ai/vector_recall.py:20`），
  limit ≥ 嵌入页数时全部嵌入页都拿 vector rank；②RRF 双来源累加使「偶然词面命中 +
  任意 vector rank」超过「单来源 keyword rank 1」；③单来源 rank-1 平分 1/61 后由
  page_id 升序决胜。三环叠加 = 嵌入页被系统性加权，与语义相关性无关。
- v0.5.1 relevance：**核心**。当前真实 staging 恰好就是极端 partial coverage（78 页仅 5 页嵌入），
  该缺陷在真实运行条件下必然存在，只是幅度待真实模型量化。
- risk of fixing：中。引入阈值/权重会改变全部 hybrid 排序，需要 benchmark 回归 +
  现有 18+18 个 hybrid/retrieval 测试适配；阈值取值本身需要真实模型证据支撑。
- proposed next action：进入 v0.5.1 修复候选。备选方向（需人工选定）：
  a) 向量召回加相似度阈值（sim ≤ 0 或绝对阈值过滤）；
  b) RRF 对单来源低置信 vector rank 降权；
  c) tie-break 规则优先 lexical。
  先在 fixture benchmark 上对比各方案，再决定是否提交 paid-call proposal 验证真实幅度。

### D-02 · HIGH — no-good-answer 查询仍产出「语义召回」前列结果，且无任何无答案信号

- category：product boundary / retrieval quality / UX
- reproduction：F1/F2/F3（Kubernetes / 锂电池 / ROS2）。
- expected：资料中无答案时，系统不应把语义无关页包装成「语义召回」顶到前列；
  至少应存在某种「结果可能不相关」的提示。
- actual：F2/F3 hybrid Top5 出现「语义召回」标签；F1 的 21 个 sim=0 候选全部进入融合；
  全系统无 rejection / confidence / 弱结果表达。no-answer exposure = **high**。
- evidence：Phase 1D §五；Phase 1A §2.2（无阈值）、§5.4（无弱结果 UI）。
- suspected root cause：无阈值召回（同 D-01 根因①）+ 无弱结果 UX。
- v0.5.1 relevance：高。与 D-01 共享根因，可能同一次修复覆盖大部分暴露。
- risk of fixing：中。阈值方案同 D-01；UX 提示方案需定义「弱结果」判据，避免误报。
- proposed next action：与 D-01 合并评估修复方案；UX 层的「弱结果/可能无答案」提示
  是否进入 v0.5.1 由人工决定（也可 defer 到 v0.6.x 的 UX 主题）。

### D-03 · MEDIUM — hybrid 结果数膨胀，无最终 fused top-k 上限

- category：retrieval behavior / UX
- reproduction：全部 29 条 query：keyword 2–11 条 → hybrid 21–34 条（≈ limit + 嵌入页数）。
- expected：hybrid 结果集规模应与用户预期（最多加载条数）一致。
- actual：`HybridSearchService.search` 不截断融合并集；无阈值召回使几乎每个嵌入页都进结果。
- evidence：Phase 1D §六；Phase 1A §3.1（无测试锁定该行为）。
- suspected root cause：`rrf_fuse` 返回完整并集 + 服务层无截断 + 无阈值。
- v0.5.1 relevance：是。影响「已载入 N 条」语义与分页体验。
- risk of fixing：低-中。截断本身是简单改动，但与 D-01 方案交互（先过滤再截断还是先截断）。
- proposed next action：随 D-01 方案一并设计；补「最终 top-k 行为」的回归测试（当前空白）。

### D-04 · MEDIUM — RRF 单来源 rank-1 平分由 page_id 决胜

- category：ranking determinism
- reproduction：J1：keyword#1 stm32/p3（1/61） vs vector#1 stm32/p1（1/61）平分，
  page_id 1 < 3 → stm32/p1 在前。
- expected：keyword 第 1 与语义无关的 vector 第 1 平分时，应有语义上更合理的决胜规则
  （例如优先用户可见的 keyword 命中）。
- actual：决胜落到主键大小，与相关性无关；确定性但语义任意。
- evidence：Phase 1D §四机制环③。
- suspected root cause：`rrf_fuse` 排序键 `(-fused_score, best_rank, page_id)`。
- v0.5.1 relevance：是，但通常会被 D-01 的阈值方案吸收（sim=0/低 sim 页根本不进融合）。
- risk of fixing：低（改排序键），但会改变所有平分情形的既有顺序，需回归。
- proposed next action：作为 D-01 方案的子项评估；若 D-01 采用阈值，本项可降级为 OBSERVATION。

### D-05 · MEDIUM — 降级后标题仍显示「混合检索结果」，gate 回退当次静默

- category：UX honesty
- reproduction：①hybrid 向量侧降级（DISABLED/UNAVAILABLE/FAILED）时，结果标题仍是
  「混合检索结果（已载入 N 条）」（`pages/4_检索资料.py:752,811-812,1329-1330`，
  gate 驱动而非 outcome 驱动）；②筛选/排序触发 gate 回退时，当次搜索无任何提示，
  hybrid note 被主动删除（`:192-194`）。
- expected：用户应能知道「这一次」搜索实际跑的是关键词。
- actual：只有静态 caption 与小字降级 note；标题与实际执行路径可能相反。
- evidence：Phase 1A §5.2；该路径无 AppTest 渲染断言。
- suspected root cause：标题由 gate 状态而非 `HybridSearchOutcome.vector_status` 驱动。
- v0.5.1 relevance：是（Search UX 是本版主题之一）。
- risk of fixing：低。纯 UI 状态驱动改动 + AppTest 断言，不触检索逻辑。
- proposed next action：v0.5.1 修复候选（独立于 D-01，可先行）。

### D-06 · LOW — stale embedding 跳过完全不可观测

- category：observability
- reproduction：页面内容变化后旧 embedding 在 recall 中被静默 `continue`
  （`src/ai/vector_recall.py:207-209`），不计入 `HybridSearchOutcome` 任何字段。
- expected：stale 跳过数量至少可日志/计数查询，便于判断「该重建索引了」。
- actual：只有 hydration 失败计入 `invalid_vector_candidates`；stale 无迹可循。
- evidence：Phase 1A §2.3。
- suspected root cause：outcome 模型未包含 stale 计数。
- v0.5.1 relevance：边缘（Retrieval Stability 维度证据）。
- risk of fixing：低。
- proposed next action：可 defer 到 v0.6.x；若 D-01 改动 recall 层则顺手加计数。

### D-07 · OBSERVATION — keyword OR 门控对泛词产生宽候选池

- category：lexical behavior
- reproduction：F1 keyword 返回 9 条（「更新」「配置」泛词命中）；E1「时间」命中 robot/p5。
- actual/expected：现行设计即「任一 token 命中即入候选，排序交给 bm25+boost」，
  大多数字情况下排序能兜底；不是 defect，但它是 D-01 机制环②的放大器
  （偶然词面命中给嵌入页提供第二个 RRF 项）。
- evidence：Phase 1A §1.1；Phase 1D §四。
- proposed next action：不单独修；D-01 方案评估时纳入考量。

### D-08 · OBSERVATION — regression 幅度依赖 fixture 几何，需真实模型量化

- category：evidence boundary
- 事实：7 regression / MRR 差距是 latent-topic fixture 下的结果；真实 Qwen 相似度
  不会精确为 0，但「低 sim 页仍拿 rank + 双来源累加」机制不变。
- proposed next action：若人工决定修 D-01，则在修复方案选定后提交
  **PAID_CALL_PROPOSAL**：staging 扩大 embedding 覆盖（例如 78 页全量或分层子集）+
  冻结 query 重跑，量化真实幅度并验证修复效果。本阶段不执行。

### D-09 · OBSERVATION — keyword 对概括/对比型查询自身偏弱

- category：lexical quality
- reproduction：I2 keyword best_rank=8（comm/p7 对比页）；H2 keyword best_rank=4。
- note：hybrid 在 I2 上更差（13），在 H2 上更好（1）——说明该弱点不由 hybrid 单方面解决。
- proposed next action：记录为 lexical 改进的长期观察，不进 v0.5.1 修复范围。

### D-10 · OBSERVATION — 运行时无 query-vector 缓存，同一查询重复点击重复付费

- category：cost
- evidence：Phase 1A §4.2（「每次显式动作一次」，非「每个唯一查询一次」）。
- v0.5.1 relevance：成本维度观察；当前每次调用都由显式点击触发，风险可控。
- proposed next action：defer；如未来加自动触发再评估缓存。

## 二、八个必答问题

1. **Hybrid 在什么类型问题上真正有价值？**
   语义改写/模糊工程问题且**相关页已嵌入**时：C2（rank 2→1）、H2（4→1，多相关页提顶）、
   D3（跨文档 Top5 覆盖 False→True）。与 v0.5.0 Q3 的结论一致并扩大了证据面。
2. **什么类型问题 Keyword 已足够？**
   精确术语（A 类 4/4 keyword Hit@1）、专有名词（G 类）、以及**相关页未嵌入的一切场景**
   （J 类、B3、C3、E1、I2 —— keyword 全部扛住或更优）。
3. **Hybrid 是否存在明确 regression？**
   是，7 条（A4、B4、C3、E1、I2、J1、J2），且 7/7 的 relevant 页未嵌入 —— 不是随机噪声，
   是结构性偏袒（D-01）。
4. **partial embedding coverage 是否导致异常？**
   是，这是 regression 的唯一来源。50% 覆盖时 hybrid MRR 反而低于 keyword；
   当前真实 staging（5/78 ≈ 6% 覆盖）处于更极端的同一区间。
5. **cross-document union/fusion 是否符合预期？**
   机制符合：D1/D2 两模式都覆盖双文档，D3 hybrid 改善了跨文档 Top5 覆盖。
   未观察到跨文档特有的排序异常（观察到的异常全部由覆盖率问题解释）。
6. **negative query 暴露了什么产品边界？**
   系统无「无答案」概念：无阈值召回 + 无弱结果 UI，导致无答案问题仍给出
   「语义召回」前列结果（exposure = high）。这是诚实的 limitation，必须写进
   用户可见文档，不得用 benchmark 粉饰。
7. **provenance / fallback UX 是否存在误导？**
   标签归属规则本身无错误标注；但 ①sim=0 的页也戴「语义召回」标签，
   标签与用户直觉不符；②降级时「混合检索结果」标题与实际 keyword 执行相反（D-05）；
   ③gate 回退当次静默（D-05）。
8. **哪些问题值得进入 v0.5.1 修复范围？**
   建议候选：**D-01（核心，HIGH）**、**D-02（与 D-01 同根因，HIGH）**、
   D-05（独立 UX 修复，MEDIUM，低风险）、D-03（随 D-01 方案，MEDIUM）。
   D-04 作为 D-01 子项。D-06/D-10 defer，D-07/D-08/D-09 为观察项。

## 三、Decision Gate 证据留存（不做 Gate，仅归档输入）

- Retrieval Quality：本矩阵 + Phase 1D baseline 分布（29 frozen queries，可复现）。
- Retrieval Stability：Phase 1A §4 降级矩阵全部有自动化测试；stale 不可观测（D-06）。
- Cost：每条 hybrid query 恰好 1 次 query embedding（benchmark 逐条断言）；
  无缓存重复付费为观察项（D-10）。
- UX：D-02/D-05 记录；provenance 标签规则正确但语义场景有误导面。
- v0.6.0 前提倒推（初步，待收口 Gate 正式评估）：D-01/D-02 倾向 Must before v0.6.0；
  D-05 倾向 Should；D-03/D-06/D-10 倾向 Can defer。
