## 2. 问题和修改

### 2.1 原有首次选页被拉回

问题本质是 URL 中的 `page` 和 Streamlit 页码控件各自写入当前页，在同一次重新运行中争夺控制权。于是用户第一次选中目标页后，控件短暂显示目标页，又被旧 URL 页码覆盖。

修改后：

- “我的资料”中，上一页、下一页、页码下拉和直接输入最终都通过 `_go_to_page(page_number)` 更新 URL。页面顶部只从 URL 恢复一次页码控件。
- “查看识别结果”中，所有选页入口最终都通过同一个 `_go_to_page(page_id)`。它先处理未保存修改的防丢失保护，再同步 `document`、`page` 和 `page_id`。
- 新输入框只是“发出跳页动作”的入口，不是新的当前页状态。

### 2.2 测试时额外发现的资料切换错位

在“查看识别结果”切换到 3353 页资料时，筛选框已显示新资料，但当前页仍可能停在上一份资料。这会让“共 N 页”和实际内容不一致。

已修改：资料筛选改变时，立即通过同一 `_go_to_page` 进入该资料第 1 个可查页；直接打开带 `document/page/page_id` 的链接时，资料筛选也会从 URL 正确恢复。

## 6. 交叉导航

在两个页面均执行了：

1. 直接输入跳页。
2. 点击下一页。
3. 在原有页码下拉中选页。
4. 点击上一页。
5. 再次直接输入跳页。

“查看识别结果”实测路径为 `10 → 11 → 14 → 13 → 2874`；最终 URL 为 `page_id=2952&document=2&page=2874`，页码下拉和“当前页”均为 2874，已提取文字包含 `EKB-LONG-3353-002874`。

注：Codex 内置浏览器的语义定位器对 Streamlit 虚拟化下拉项执行“点击 option”时，会先滚动到目标行而不触发变更事件。这个自动化动作没有被计为产品 PASS。交叉测试改用普通用户同样可用的下拉键盘选择（方向键 + Enter）完成，且用 Streamlit 交互回归测试单次派发新值验证了首次状态转换。直接页码输入的所有验收则均为真实浏览器输入后单击“跳转”。
