## Current Process Model

**CURRENT PROCESS MODEL**：service manager 是启动/停止/状态检查工具，启动一个长期运行的
Streamlit Python 子进程。业务不是一个“前端进程 + API 后端进程”的现有组合。
`application_settings/database/document_service/ai_provider/...` 用 `lru_cache(maxsize=1)`
共享于进程，而非按浏览器会话或用户构建（E02）。多次页面 rerun 持有各自 `st.session_state`，
但落到同一个数据库、同一组受管目录与服务对象。

- `application_settings()` 创建目录并安装 root rotating log handler；不是无副作用读取。
- `Database.__init__()` 创建父目录并调用 migration；**缓存的是 Database 对象，不是 SQLite connection**。
- 普通 DB/repository 操作创建 connection，在成功时 commit、异常时 rollback、finally close。
- provider 工厂构造不发网络；账本/预算 DB 延迟到调用时解析；单次 urllib response 有 context manager。
- OCR engine 对象进程共享，首次 `recognize()` 才加载本地 RapidOCR。没有应用层初始化/推理锁。
- 首页运行一次 cached quarantine reconciliation；维护页每次执行到末段也会重新对账。
  这可恢复/完成之前已确认删除的文件操作，不能描述为纯只读维护页（E11）。
- 没有业务 worker、任务队列、scheduler、持久 job 状态或全局 shutdown/drain hook；manager 用信号停止进程，
  超时可强制结束。各 SQLite/PDF/HTTP 资源的局部 close 不等于全应用优雅排空。

**HOSTED RISKS**：多会话共享资源；多 worker 会各自建立缓存、重复初始化/迁移/对账；
长操作被进程停止打断；同一磁盘日志不能直接视为多进程安全集中日志。部署进程数、生命周期、
数据范围、同步/后台选择留给 D2/D4/D5/D13。

## SQLite / Database

**Current SQLite topology**：一个默认 SQLite 文件，包含业务数据、FTS、embedding 和审计。
`Database` 是薄数据访问对象；Evidence、Batch 另有自己的按操作 connection wrapper。
业务服务、AI 台账均写同一个 DB，不存在云 DB 或独立审计库。

| Audit item | Repository evidence / observed behavior |
|---|---|
| Connection creation / lifecycle | `Database._connection` (129–142)：connect(timeout=30.0)、row_factory、finally close；成功 commit/失败 rollback。Evidence (555–567) 同样；Batch (497–526) 单独 wrapper。 |
| WAL | `migrate_database` (72–77) 设置 WAL；未在每个业务 connection 重设。没有集中 WAL checkpoint/磁盘水位控制。 |
| Foreign keys | 普通 DB/Evidence/Batch connection 显式 ON；迁移期间 OFF，结束 ON + integrity_check/foreign_key_check。 |
| Transaction model | 普通 mutation 用 connection 默认事务；KO multi-statement `knowledge_transaction` 显式 BEGIN IMMEDIATE；Batch write 和 default basket check/create 显式 BEGIN IMMEDIATE。跨 PDF/files/DB 没有一个总事务。 |
| Thread behavior | 没有 `check_same_thread=False` 或共享 connection；connection 通常在使用它的调用线程创建并关闭。sqlite 默认线程检查未关闭。 |
| Process behavior | 多进程会打开同一文件；依赖 SQLite locking/WAL，不存在跨 worker 初始化/迁移/对账协调器。 |
| Migration | `Database.__init__ → initialize → migrate_database` 自动运行；旧非空库先 online backup；v12 保持；不是每次启动必然升级。 |
| Backup | migration backup 在 DB 同级 `backups/`；完整备份用 SQLite backup API 读快照，不是直接复制正在写的 DB 主文件。 |
| DB path selection | Settings 字段可 env override；每个子路径默认独立取 `<repo>/...`，仅改 `EKB_DATA_DIR` 不会自动重算其余字段。BackupService 还要求布局在 data_dir 内。 |
| Read-only assumptions | `Database(path)` 不是只读 opener；即便下一步只查数据，构造也会初始化。diagnostic/backup 某些函数用 `mode=ro`。 |
| Test vs production guard | conftest 禁真实 application_settings；fixtures 常用 tmp DB/显式 Settings。Database 类本身不拒绝生产路径，guard 不是全局 sqlite/network 沙箱。 |
| Index/audit detail | 当前 migration 有 `idx_ai_calls_created_at`、`idx_ai_calls_feature_created`、`idx_ai_calls_status` (1662–1669)；不能沿用旧 ledger 文档“没有索引”的说法。 |

**Single-process safe assumptions**：按操作短 connection、参数化值、局部事务回滚/关闭、已有
default basket 互斥创建、原子文件替换/manifest 补偿。标为 **LIKELY SAFE（限定已有局部语义）**，
不代表高并发容量已验证。

**Potential multi-process issues**：初始化/迁移竞争、长读写与 busy_timeout 等待、重复 quarantine
对账、多进程日志轮转、WAL 相关文件/目录权限；需 D2/D5/D6/D13。**Potential multi-user issues**：
所有记录无 ownership、跨会话更新无全局业务隔离、全局审计和预算（D4/D9）。
**Hosted persistence assumptions**：DB 及 WAL/SHM 所在目录必须支持当前运行期写入/锁语义；
快照、文件资产和恢复窗口需一致性安排。SQLite 是否继续、隔离或替换完全留给 D5；本文不判定
“SQLite 足够”或“必须 PostgreSQL”。

## Source Path Semantics

- Canonical identity：文档本地 id + SHA-256 去重；页面 document_id/page_number 与本地 id；
  已扩展知识实体引用使用 `build_stable_id(kb_uuid, type, local_id)`。kb_uuid 标识 KB，不标识用户。
- Absolute path persistence：Database 存 `str(Path(source_path/image_path))` 和 markdown_path，
  **不是强制转换所有输入为绝对路径**；正式默认根为绝对路径，因此正常产物会存绝对本机路径（E05）。
- Source/Provenance 关联通过 source_type/source_id；指纹是带版本的 canonical content hash，
  不把绝对路径当 fingerprint identity。document 指纹使用 DB 中保存的 document.sha256；
  page 指纹使用 extracted_text 或 OCR，note/evidence 使用对应内容/锚点 hash（E14）。
- `inspect_source_integrity` 不等于重读磁盘 PDF 验证全部二进制资产。引用可合法但 PNG 已丢失；
  文件存在/hash 检查在 PDF/Evidence/Note/diagnostic/backup 等具体路径，不能混为一项保证。
- ToolReference 和 Agent citation 不要求本地路径：stable_id + anchor_label/fingerprint 等；
  page_search 投影只取 ID、title、filename、snippet 等，不把 source_path/image_path 原样输出（E04/E14）。
- 传统 EvidenceService 导出的 Markdown **明确包含原 PDF/PNG 绝对路径**；UI 也显示路径。
  因此“Agent citation 不依赖路径”不代表整个产品不会泄露本地目录。
- Hosted 挂载/迁移后原路径可能失效。restore 已有 rebase，但只定位其处理的路径字段；
  不证明任意跨 OS/历史自由文本路径可无损恢复。D4/D6/D7/D11 必须裁决。

OCR 固定描述；部分 operation ID/status/count。ai_calls 是 metadata ledger；diagnostic 导出的日志

**Potential private-content logs**：Document/PDF 导入失败 LOGGER.exception；DB._connection traceback +
database_path；删除日志包含 document title/path；quarantine details；hybrid 未预期异常 traceback；
indexer 的失败 exception 文本；root sys/thread excepthook；manager 捕获 console output。
没有发现在正常成功路径直接把完整 prompt/ToolResult/model response 主动写日志的代码，
但原始 exception/用户命名/路径可进入日志，不能推广为全产品隐私已通过（E19）。

**UI error rendering**：app 初始化、导入、维护、RAG/Experience 等多处 `st.error(f'...{exc}')`。
服务异常可能携带路径、SQLite 错误/结构信息或第三方文本；不声称每条一定泄露 key/SQL 全文。
AgentResponse 是已 harden 的 safe error envelope；传统 UI 不统一经过它。

Logging/privacy risks 共 **4 类**：原始 traceback/exception；路径/标题/文件名；传统导出/维护 UI 内容；
共享日志/账本/备份缺权限与保留策略。F10 标 MAJOR，作为 sensitive-data blocker candidate 输入
供 Gate 判断；不在没有泄露证据时声称实际 secret 泄露。诊断导出脱敏不覆盖磁盘原日志。

|---|---|---|---|---|
| A. Private knowledge | DB/Markdown + UI state | 仅当进入实际 AI 输入，非自动整库上传 | 长期保留直到显式修改/删除；revision/backup 可保留历史 | D4/D7/D11/D15 |
| B. Uploaded original | data/raw | 当前 provider 不发送 PDF bytes | 保留；显式删除后历史备份不自动清除 | D6/D7/D14 |
| C. Extracted/OCR text | pages/search DB columns | RAG/Agent context 或显式 embedding 可发送相应文本 | DB 持久；没有全局 TTL | D7/D9/D11 |
| D. Page image | data/pages | 当前 Qwen client 无 image payload；OCR 本地读取 | PNG 持久，image-region hash 依赖；显式删除流程 | D6/D7 |
| E. KO/Memory | DB + revisions/links | 选入 RAG/Experience/Agent 时发送投影内容 | 长期资产；不自动写 AI candidate | D4/D11 |
| F. AI prompt/context/answer | Python memory / st.session_state | prompt 发 provider；answer 从 provider 回来 | 默认不存全文；用户可另行复制保存 | D8/D11/D15 |
| G. AI audit | ai_calls/ai_outputs | 不作为自动整库上传输入 | hashes/IDs/metadata 持久，无 TTL | D4/D11 |

真实 AI 数据链分开如下（E04/E14–E18）：

1. **Decision call**：用户 request.text + 排序后的七 Tool name/description/input schema +
   决策规则。没有先读取知识全文/DB paths/tool implementations。用户自己在问题中粘贴的私人文本
   仍会进入 prompt，不能承诺 Decision 不含私密内容。
2. **Agent Final call**：本 run ToolResult.data/references 投影的 ContextItem，经 packager 进入
   RagPromptBuilder；包括问题、选中内容/snippet 或结构化摘要、标题/来源 label、stable IDs、状态/
   revision/关系/指纹 warning。不是自动发送全部 PDF。EMPTY/FAILED/ANSWER_DIRECTLY 不调用 Final。
   正式 page_search handler 使用 SearchService **离线词面检索**，不是自动 hybrid embedding。
3. **Non-Agent RAG/Ask AI**：按钮触发，把当前传入搜索结果逐项投影；page 内容优先 extracted_text、
   再 OCR、再 Markdown；KO/Memory 走相应投影。**不是只有搜索 snippet，也不能说 UI 每项都有显式勾选**。
   packager 的正文边界、知识来源元数据和 question 一同传给 completion。
4. **Experience**：用户 multiselect 的 KO/Memory + task + context package → 单次结构化候选；
   不自动写库。字段可为空，不创造来源。
5. **Hybrid query**：显式 hybrid 搜索把 query text 发 embedding；候选向量/余弦相似度在本地处理。
   显式 PageEmbeddingIndexer 可把准备后的页文本（8000 chars cap）按 batch 发 embedding；
   未发现生产 UI/Agent 自动后台索引。Rerank 当前直接 unavailable，不发生外联。

## Backup / Restore

BackupService 验证普通文件/链接、target 不在 data 内、目标不覆盖、白名单配置；SQLite snapshot
与 raw/pages/markdown 文件复制后逐文件 SHA-256/manifest/DB integrity/FK/asset link 校验，成功才
rename 成正式目录。备份明文、无加密、无 user ACL、无自动 retention/quota。恢复配置只列路径、
host/port、text threshold、DPI，不含 `.env`/AI key；完整 DB 自然含知识与审计（E12）。

restore 是独立 CLI，要求 `--confirm RESTORE`，正式路径提供 service_is_running 检查；先校验、
stage、rebase、当前数据预备份，再切换整 data、校验/回滚。**UI 只显示恢复命令，不在线执行 restore**。
服务方法的 running callback 可不传，不能将低层方法直接当已授权在线 restore endpoint。
现有全量备份只复制列出的 raw/pages/markdown + DB/config，不将 quarantine 纳入完整恢复集。
数据/文件/隔离区处于活动修改时的快照一致性、停止窗口、多用户备份可见性、跨 OS 路径、
容量与失败域需 D5/D6/D13/D14；本文没有执行 backup/restore。

## Export / Download

- EvidenceService/证据篮：在内存生成 Markdown，页面用 `st.download_button` 交浏览器保存；
  package 含来源文字、用户备注及 PDF/PNG 绝对路径。不是统一受权 source-download API（E14/E26）。
- Diagnostic report：生成内存 Markdown bytes 下载，已有路径/凭据模式脱敏，日志只取 metadata（E20）。
- KnowledgeExportService：全库 KO/source/relation/revisions/Memory → JSON + Markdown + manifest/hashes，
  排除 AI ledger/vector/prompt/key；调用方指定目录，返回 Path。未挂页面/HTTP 下载入口（E13）。
- AILedgerExportService：过滤 query 下的全量分页结果 → JSON/JSONL + manifest；只 metadata，不解析
  target_refs 为正文；无用户 scope，返回本地目录路径，当前 UI 没 export action（E13/E16）。
- 两个 export 服务的 `export_name` 直接拼接 destination，没有与 backup_name 同等 basename/containment
  校验。当前调用方受信任；若未来原样暴露该参数则有路径逃逸候选，**不是已证实匿名 HTTP 漏洞**。
- 没有默认 server `exports/` 根、下载 token、HTTP content policy、全局导出配额或过期清理。
