## A. 产品定位（报告开篇 / PPT 首页）

EKB（Engineering Knowledge Base，工程知识库）是一个**本地运行的个人工程知识
管理系统**：把分散的工程资料（PDF 手册、页面笔记）、解决问题的历史经验组织成
可检索的知识资产，并由知识 Agent 提供带依据的问答。一句话定位：
**让工程经验可查、可复用、可回源、可核验。**

五个关键词：工程资料 · 工程经验 · AI 问答 · 可追溯来源 · 信任边界。

## B. 用户问题（为什么做）

1. 工程资料散落在 PDF、笔记和聊天记录里，查找靠记忆和翻找；
2. 老工程师解决问题的过程（现象→原因→定位→处理）很少被沉淀，人走了经验就丢了；
3. 通用 AI 能生成流畅答案，但不了解"我们自己的设备与资料"，且答案难以核验来源，
   工程场景里不敢直接采信。

## C. 核心工作流（用户怎么用）

1. **导入整理**：导入 PDF（保留原件、逐页成图、提取文本层）→ 复核标注 →
   沉淀结构化笔记与"问题解决记录"（知识记忆）；
2. **组织关联**：标签、项目、知识对象、证据篮把资料组织成可检索网络；
3. **提问复用**：向知识 Agent 提问 → 得到带来源编号的回答 → 点击来源检查依据；
4. **信任核查**：来源建档后若内容变化，系统提示"来源发生变化"，提醒重新核对。

（比赛演示展示第 3–4 步的确定性预置版本；第 1–2 步为产品既有本地功能。）

## D. 架构摘要（一页版）

- **本地优先**：Python 3.11 + Streamlit + SQLite（FTS5）；数据与代码分离，
  服务绑定 127.0.0.1:8501，核心功能离线可用；
- **知识层**：文档/页面/笔记/知识对象/知识记忆/证据等模型 + schema v12 + 内容
  指纹（来源变化检测）；
- **AI 层（可选增强）**：厂商中立 Provider 契约，AI 默认 manual，无 Key 不影响
  核心功能；全部调用进台账可审计；
- **Agent 层**：单步受控 Agent（一次决策 + 至多一个只读工具，七工具注册表，
  无重试无循环）+ Final Answer 阶段（生成带引用回答并逐条校验引用）；
- **Hosted API（基础）**：冻结的 /v0.6 公共契约（请求/失败/来源 DTO + 封闭错误
  目录），是"本机 Agent"模式的回环入口；公开部署推迟（见红线）。

## E. Agent Foundation（v0.6.0 交付）

七个只读工具：页面检索、知识检索、获取知识对象、获取知识记忆、溯源检查、
来源完整性检查、获取证据。单步执行器保证"一次决策、至多一个只读工具"，
从机制上排除自主多轮与写操作。请求上限 120k 字符。发布为 tag `v0.6.0`
（2026-08-29，RELEASED）。

## F. 证据与引用机制（产品差异化核心）

回答阶段强制引用：关键结论标注【来源 #N】；引用的来源标识逐条校验
（必须真实存在、类型合法），校验失败整个回答降级为失败——**宁可明示失败，
不输出无依据文本**。界面层：引用可点击，来源详情展示标题、类型、位置
（仅安全元数据，不含路径或内部 ID）。

## G. 来源完整性语义（措辞规范）

资料登记时记录内容指纹；读取时与当前内容比较。`changed` = 快照不一致，
**不代表造假或被篡改**（可能是正常更新），系统据此提示"重新核对后再采信"。
禁止表述："检测到篡改""来源不可信""实时完整性监控"。
比赛演示中的完整性状态为预置演示数据（页面有标识）。

## H. 本地/离线特性

核心功能（导入/检索/浏览/笔记/证据/备份/演示）零网络依赖；演示模式无需
API Key；用户数据仅存本机、与代码分离、不进 Git；不做云端账号体系
（本地单用户是产品边界，不是缺陷）。

## I. 比赛演示设计（v0.6.1 交付）

## 答辩速答卡（每题 15–30 秒，完整版见 runbook Q&A）

- **和 ChatGPT 的区别？** 通用助手答所有问题；EKB 答你自己资料里的问题，
  且每条回答有来源编号、可点开核对，无依据时明说没有资料。
- **为什么可信？** 可信≠必然正确；可信在依据可查、来源可回、变化会提示，
  判断留给人。
- **资料错了怎么办？** 系统不判对错，但保留两层防线：回答带来源可人工核对；
  资料变化会标注"来源发生变化"，提醒重新核对。
- **支持自己的资料吗？** 支持，本地版核心流程就是导入并整理自己的 PDF 与经验；
  演示为确定性使用了预置语料。
- **断网能用吗？** 能，核心功能与本次演示全部本地运行，不需要网络和 API Key。
- **上线了吗？** 产品完成本地单用户形态并在个人使用中；公网部署按规划推进，
  尚未上线（如实说）。
- **Agent 做了什么？** 查（只读工具检索）、答（只依据查到的内容）、
  证（引用逐条校验）；单步受控，不自主多步。
- **为什么不自动多步？** 工程场景要可预算、可复现、可审计；自主性按路线图
  分阶段引入。
