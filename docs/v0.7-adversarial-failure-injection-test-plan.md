## 2. Inputs / Frozen Architecture

实现测试时**禁止重开**的冻结事实（逐条给出权威出处）：

1. **写形态**：WriteCommand 在 Agent Tool Registry 之外；registry 恰七 `READ_ONLY`
   Tool；单步 executor 不变；写仅 Local，Hosted READ_ONLY（ADR-010；Task-B §2.2）。
2. **三命令**：`execute_create / execute_undo / execute_restore`，无泛型分发；
   allowlist = create/undo/restore 闭合枚举（Task-B §17-§19/§25）。
3. **事务**：服务拥有唯一外层 `knowledge_transaction`（BEGIN IMMEDIATE + 整体回滚，
   `src/database.py:1643`）；体内只允许连接感知调用；审计/命令日志与数据写同事务；
   SUCCESS-ONLY（失败零库内痕迹）（Task-B §30；schema 详规 §25/§16）。
4. **批准**：会话内三字段令牌 `{approved_draft_sha256, approved_idempotency_key,
   approved_at}`；新键 CREATE 三条件（令牌在场 ∧ 载荷哈希相等 ∧ 键相等，N-7）；
   消费规则 B（仅成功后 UI 消费）；派生式失效（Task-B §12-§14）。
5. **幂等**：命令日志 `idempotency_key UNIQUE` + 事务内首查；重放 = typed 成功
   （`duplicate_replay=True`）；同键异 (operation, payload_sha256) 任一不同 ⇒
   `IDEMPOTENCY_CONFLICT`；幂等解析先于一切语义校验（Task-B §21/§26/§29）。
6. **canonical V1**：载荷/规范化/序列化/SHA-256 永久协议；黄金向量 V-01..V-04 逐字节
   钉死；幂等键/request_id/approved_at 不入载荷（Task-B §5-§9/§44）。
7. **来源 N-6**：`relation_kind ∈ {support, context}` 持久化且参与批准哈希；
   support = 存在性 + 新鲜度相等（page/evidence 指纹、KO revision）；context = 仅存在性；
   派生 MISSING_SUPPORT / MISSING_CONTEXT 永不合并；context 永不升格支撑
   （Task-B §10/§32；schema 详规 §10/§12/§13）。
8. **墓碑**：`status ∈ {active, archived, deleted}`；undo/restore 仅限受控 create
   日志链目标；undo/restore 不删/不改内容、来源、provenance；普通读取视 deleted

9. **schema 目标形态**：`knowledge_memory_entries` 重建（+`creation_origin`/

   `knowledge_memory_sources`（typed FK ON DELETE SET NULL + 快照 + CHECK ≤1 目标 +
   N-6 跨列 CHECK）+ `experience_command_log`（跨列 CHECK）；
   物理版本号 = 参数 TARGET_SCHEMA_VERSION（G-1 未决）（schema 详规 §5/§8/§10/§17）。

## 4. Test Philosophy（冻结原则）

1. 每条安全不变量（SI-1..SI-13）至少一个负向/对抗测试。
2. 每条原子性不变量在临界持久步**之前与之后**（有意义处）各注入一次失败。
3. 断言**状态**（行数、FK、快照、FTS 可见性、日志行），不只断言异常/消息。
4. 机器语义只断言 typed code / 枚举 / 布尔字段，**永不**断言消息子串。
5. 无任何测试正确性依赖 UI 防抖/禁用（SI-11）。
6. 零真实 AI：全链 fake provider / 纯数据载荷（沿 `ExperienceModelService` mock 先例）。
7. 任何测试不得改动临时测试 DB 之外的生产仓库状态（迁移注入全在 `tmp_path` 库）。
8. 并发正确性用 `threading.Event`/`Barrier`/注入钩子做确定性同步，**禁止**以 sleep
   作为正确性机制（允许对超时上限使用超时断言）。
9. 失败注入确定性、本地可复现（固定种子的固定异常点，无随机）。
10. 每个测试把结果归类为三态之一并分别断言：**预期域拒绝**（typed 码）／**注入的
    基础设施失败**（`InjectedWriteFailure` → INTERNAL_FAILURE/STORAGE_UNAVAILABLE 族）／
    **意外内部 bug**（测试自身失败）。禁止把三类混同为"抛异常即通过"。

## 6. AFT ID Convention

- 格式：`AFT-<CLASS>-NN`（例：`AFT-B-01`、`AFT-G-06`）。NN 类内从 01 递增，**永久
  不复用**（废弃用例保留 ID 并标注 SUPERSEDED，不删除）。
- 威胁 ID（T-X#）描述攻击/风险；AFT ID 描述**可执行验证**——两者不互换、不合并。
- 每个用例回溯四元组：威胁 ID（可多个）→ 失败矩阵行（#1..#24，可无）→ 安全不变量
  （SI-1..SI-13，可无）→ 详规节（Task-B §x / schema 详规 §y）。
- 层级（LAYER）取值：`UNIT`（纯函数/零 DB）、`DB_INTEGRATION`（临时 SQLite 库）、
  `SERVICE_INTEGRATION`（服务×DB×事务）、`CONCURRENCY`（多线程同步）、`APPTEST`
  （Streamlit AppTest）、`STATIC_BOUNDARY`（AST/源码静态）、`MIGRATION`、
  `BACKUP_RESTORE`、`RELEASE_CHECK`。
- 优先级：`P0_GATE`（违反即阻断 v0.7 发布）/ `P1_GATE`（Phase 8 必须全绿）/ 
  `P2_COVERAGE`（覆盖增强，允许最后一批）。

## 16. Concurrency Tests（AFT-C-05/C-09/C-10 详细规格）

**机制（冻结）**：两个 `Database` 实例指向同一 `tmp_path` 库；两线程各持服务实例；
用 `threading.Event` 两相同步：

```text
阶段1：线程 A execute_create → 注入钩子 CW_CREATE_AFTER_IDEMPOTENCY_LOOKUP 处
       阻塞（控制器回调置 Event_A_entered 并 wait Event_A_release）。
阶段2：主线程确认 A 已持锁（Event_A_entered），启动线程 B execute_create（同键）。
       B 在 BEGIN IMMEDIATE 处等待（busy_timeout=30000ms 内必然等待，非 sleep）。
阶段3：主线程置 Event_A_release → A 提交 → B 获锁 → 幂等首查命中 → 重放。
join 两线程（join 超时=测试失败，不依赖时序假设）。
```

**AFT-C-09 断言（delta 相对基线快照）**：
experience 行 **+1**；provenance 行 **+10**；sources 行 **+N**（fixture 关联数）；
命令日志 **+1**；`Database.search_knowledge` 逻辑结果恰 1 条；一个结果
`duplicate_replay=False`、另一个 `duplicate_replay=True`；两线程一成一放。

**AFT-C-05**：同 AFT-B-01 的并发形态——B 携带同令牌+异键 K2：B 结束为
`APPROVAL_MISMATCH`·command_key_mismatch；总变异恰一次（B 不可能在 A 提交前获锁，
但测试对两种交错都断言零第二变异）。

**AFT-C-10**：异键+各自独立令牌（两会话批准）并发 → 两线程均首写成功 → 行数 +2/+20/+2N/+2。

**禁止**：`time.sleep` 作正确性机制；对 B 的等待使用轮询断言（join 阻塞即同步点）。

## 40. Failure-Injection Mechanism（裁决：单一推荐设计）

**调研结论**：迁移钩子（模块级 `_VXX_INJECTION_POINT` + `_inject_vXX_failure` +
`MigrationError`）为本仓唯一既有注入先例，测试以 `monkeypatch.setattr` 注入、
parametrize 驱动、teardown 复位——满足确定性/私有性/无环境变量/易复位/事务内精确
相位五项要求。

**冻结设计（写服务）**——`src/experience_write/service.py`：

```python
_INJECTION_POINT: str | None = None          # 模块私有；生产恒 None
_INJECTION_CONTROLLER: Callable[[str, int], None] | None = None  # 可选测试控制器

class InjectedWriteFailure(RuntimeError):
    """仅测试注入用；生产代码禁止构造、禁止按其类型特判业务语义。"""

def _inject_write_failure(point: str, index: int = 0) -> None:
    if _INJECTION_CONTROLLER is not None:
        _INJECTION_CONTROLLER(point, index)      # 控制器决定何时抛
    elif _INJECTION_POINT == point:
        raise InjectedWriteFailure(f"写入失败注入点：{point}")
```

- **调用纪律**：`_inject_write_failure` 仅出现在 §17/§18/§19 冻结点位；点 4/6 的
  `index` 为该循环内已插行计数（供 nth 控制器）。
- **分类纪律**：`InjectedWriteFailure` 属"未预期异常"→ 整体回滚 → 映射
  `INTERNAL_FAILURE`（安全文案仅含类名与注入点枚举名）；**禁止**被任何 except 子句
  捕获后归类为用户校验；**禁止**出现在 `__all__`/公共文档 API；**禁止**环境变量
  触发（仓库无先例，拒绝）。
- **复位**：全部经 `monkeypatch.setattr`（teardown 自动复位）；`write_injection`
  fixture 在 teardown 断言 `_INJECTION_POINT is None`（防跨测试泄漏）。
- 迁移钩子沿用既有模式不变（§27 点名表）；FTS 失败用临时库确定性破坏
  （`DROP TABLE knowledge_memory_search` 留触发器 → INSERT 触发器失败 →
  INTERNAL_FAILURE + 全回滚），**不**破坏永久库、**不**用脆弱 SQL 注入。

**FREEZE：以上为唯一推荐机制；实现不得另造第二注入通道。**
