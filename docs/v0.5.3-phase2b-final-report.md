## A. ContextItem 设计实现

### 数据结构（`src/models.py`，V53-ADR-01）

| 类型 | 内容 |
|---|---|
| `ContextItemType` | page / knowledge_object / knowledge_memory / evidence 四值枚举 |
| `ContextAnchorType` | document / page / note / evidence / selection / image_region |
| `ContextFingerprintState` | valid / changed / missing / unknown / not_applicable |
| `ContextSourceAnchor` | anchor_type / anchor_id / anchor_label / fingerprint_state |
| `ContextRelationRef` | relation_type / relation_label / direction / target_stable_id |
| `ContextItem` | type / local_id / stable_id / title / content / kind / kind_label / status / status_label / importance / updated_at / revision_ref / source_anchors / relation_refs |

- ContextItem 是**只读投影**，不是新知识实体，永不落库。
- `stable_id` 全部来自既有 `build_stable_id`（page/evidence 使用 Phase 2-A 扩展的命名空间）。
- `relation_refs` 只投影已存储的直接关系（outgoing/incoming），不推断、不建链。

### 四类投影（`src/knowledge_context.py`，`ContextItemProjector`）

| 投影 | 内容来源 | 状态语义 |
|---|---|---|
| Page | extracted→ocr→markdown 文本、文档标题、页码 | review_status |
| Knowledge Object | kind/content/lifecycle/revision/source 指纹状态/1-hop 关系 | lifecycle |
| Knowledge Memory | content/root_cause/lesson/outcome/context_conditions 合成正文 | status |
| Evidence | evidence_text、来源文档/页面、确认状态 | confirmation_status |

- 投影失败（目标不存在）→ `ContextProjectionError`，不返回半成品。
- 读路径零写库（测试以数据库字节对比固化）。

## B. KnowledgeContextPackager 实现

`src/knowledge_context_packager.py`：

- 输入：用户显式选择的 `ContextItem` 序列；输出：`KnowledgeContextPackage`。
- 双格式：
  - **JSON**：`manifest`（package_uuid/generated_at/kb_uuid/app_version/question/统计/enums）、
    `items`（全字段）、`citations`（stable_id→#序号）、`excluded`、`warnings`。
  - **Markdown**：包头部（生成时间/知识库标识/用户问题/统计）、每项区块（类型/状态/稳定标识/
    修订/来源/引用关系/正文）、复核提示、排除项。
- 五项必含信息：来源、版本（revision_ref）、生命周期状态、引用关系、stable_id。

### Fail-closed 规则（全部落地并有测试）

| 场景 | 行为 |
|---|---|
| 空上下文 | `KnowledgeContextError` 拒绝生成 |
| 全部被排除 | `KnowledgeContextError` 拒绝生成 |
| 不存在对象 | 投影阶段失败（`ContextProjectionError`） |
| 无来源 | 保留 + 显式"无来源"标记（warnings + Markdown） |
| archived / superseded | 默认排除（reason 注明）；显式开关才纳入 |
| 来源 CHANGED/MISSING/UNKNOWN | 保留 + 复核提示，不静默丢弃 |
| 超长内容 | 逐项截断 + 截断标记；总字符超限拒绝 |
| 异常 | 不输出半成品（构建完整后才返回） |

## C. RAG 流程变化

**Before**：页面检索（`SearchResult`）、知识检索（`KnowledgeSearchResult`）、证据（`EvidenceItem`）
三套模型并存，消费方需要分别解析。

**After**：Page / KO / Memory / Evidence 统一投影为 `ContextItem`，由
`KnowledgeContextPackager` 组装为单一 `KnowledgeContextPackage`（JSON + Markdown）。

```
用户显式选择知识 → ContextItemProjector（只读投影） → KnowledgeContextPackager → ContextPackage → 未来 AI 输入
```

本阶段**没有**改动任何 UI 或检索服务；统一消费层以服务/库形式交付，供 Phase 3+ 的 UI 与
AI 回答流接入。既有页面检索与知识检索语义、结果模型完全不变（回归测试全绿）。

---

## D. 与 AI Provider 集成情况

- 本阶段未把回答流改为 Agent 流程；未新增任何 AI 调用。
- 既有 AI 调用入口保持不变：`application_ai_provider()` 返回的 `AuditedAIProvider`
  已具备台账与预算（Phase 2-A）；embedding 路径（hybrid search）不受影响。
- 未来回答流的接入点已就绪但未接线：`ContextPackage.to_json()`/`to_markdown()` 可直接
  作为 `AuditedAIProvider.complete()` 的输入；输出可由 `ai_outputs` 登记审计
  （Phase 2-A 已提供 `Database.insert_ai_output`）。
- 本阶段包生成器**不调用 AI、不调用网络、不写数据库**（纯函数组装）。

## F. 安全边界检查

| # | 边界 | 结论 |
|---|---|---|
| 1 | 不自动写知识 | ContextItem/Packager 均为只读/纯组装；无任何 INSERT/UPDATE/DELETE 路径 |
| 2 | 不修改原始内容 | 投影只读；截断仅作用于包内副本（`dataclasses.replace`），不改库 |
| 3 | 不产生 Agent 行为 | 无循环、无自动选择、无自动推理、无 tool calling、无网络调用 |
| 4 | stable_id 不临时生成 | 全部经 `build_stable_id`；非法类型（note/document）拒绝 |
| 5 | 无隐私泄露 | 包只含用户显式选择的本地知识；无 key/凭据 |
| 6 | 未触碰 v1–v12 迁移与 FTS | 本阶段无 schema 变更 |
| 7 | 生产数据零写入 | 前后哈希一致 |
| 8 | 未 commit/push | 工作树仅预期修改 |
