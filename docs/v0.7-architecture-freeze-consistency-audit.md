## 3. Authoritative Precedence Model

对"同一话题、不同文本"的三态判定（不盲从文档新旧）：

| 类别 | 定义 | 处置 |
| --- | --- | --- |
| **AUTHORITATIVE_CURRENT_TEXT** | 实施时唯一遵循的冻结文本 | 台账引用为源 |
| **FROZEN_PROPOSED_REVISION** | 明确记录的修订候选（改 ADR 文本但不改架构语义） | 随 October 门禁批准后升级为 current；**不得**被实现提前采用 |
| **STALE_PREVIOUS_TEXT** | 被后续详规有意精化的早期文本 | 历史文档保留原文（历史纪律），以优先级链裁决；不重写 |

## 7. G-1 Schema Version Conflict（压缩门禁题面）

- **冲突本体**：ADR-006 Decision 9（ACCEPTED）曾冻结 agent 三表
  （`agent_runs/agent_steps/tool_calls`）的 schema v13 **草案**并 **DEFER** 执行
  （触发条件 = Phase 3 multi-step 真正落地，且届时还需新 ADR）；ADR-011（PROPOSED）
  又以 "v13" 指代受控写经验模型。编号相同、内容不同。
- **现行纪律**：SS 全程版本号参数化（`CONTROLLED_WRITE_SCHEMA_REVISION` /
  `TARGET_SCHEMA_VERSION`），TB/AFT 同构参数化——实现不依赖裁决结果。
- **三选项**：
  - **Option A（推荐）**：受控写取物理 v13；ADR-006 预留在其真实触发时重新编号 +
    一行勘误注记。理由：①受控写是 ADR-011 已冻结内容、被全部下游文档按"下一个
    迁移"引用；②agent 三表无触发条件，为一个未触发草案占用下一编号使"编号=内容"
    事实断裂；③ADR-006 的预留本质是 DEFERRED 草案（其触发本身要求新 ADR），
    "reservation"不应阻塞下一个已冻结内容的物理迁移；④勘误是文档最小改动。
  - **Option B**：保留 ADR-006 v13 预留；受控写取 v14。后果：ADR-011 及全部下游
    文档的 "v13" 表述需勘误为 v14；ADR-006 原文不动。
  - **Option C**：其他显式编号政策（如语义后缀）——仓内无先例，不建议。
- **裁决权**：October DeepSeek（APPROVE / APPROVE_WITH_CHANGES / BLOCK；选择
  TARGET_SCHEMA_VERSION 并裁定 ADR-006 预留处置）。**本审计不裁决。**
- **成本对称性**：三选项下 SS/TB/AFT 全部内容零改动（仅常量值与函数物理名），故
