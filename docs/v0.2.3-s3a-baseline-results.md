## 一、执行方式

全部用例通过新增探针 `scripts/run_scale_import_probe.py` 驱动，探针只做编排，
直接复用生产服务：`DocumentService.import_pdf`（真实导入管线）、`PdfService`、
`Database`、`SearchService`、`DiagnosticService`、`BackupService` + `validate_backup`，
以及 S2 的 `ScaleMetricsCollector` 与 `run_checks` 一致性检查器。
每个探针命令都是独立进程，"重启隔离环境后重读"由后续命令天然覆盖。

## 五、中断行为探测（case-int，400 页混合，真实进程强杀）

资料：`mixed-400.pdf`，400 页，201,063 字节，SHA-256 `99f623a1…0f4dfd`。

1. 真实导入进程（PID 5648）在渲染进度 44/400 时被 `Stop-Process -Force` 强杀（无 monkeypatch、无模拟异常）。
2. 中断后状态：documents=1（**import_status=processing 悬挂**，page_count=0），
   pages=0，FTS=0，PNG=46 个（含 `page_0046.png` **0 字节**，强杀时正在写入）。
   一致性（--allow-processing）：46 个孤儿 PNG（WARN）+ processing 悬挂（WARN）。
   原因：导入先渲染全部 PNG，再逐行 `create_page`，两阶段之间被杀死。
3. 再次导入同一 PDF：**失败**——`PdfProcessingError: 第 46 页已有图片不完整，
   程序不会自动覆盖`（连续两次重试均同一错误，各 0.1s 即失败）。
   恢复分支 `reuse_existing_images=True` 复用已有 PNG，但对不完整文件拒绝覆盖，
   导致同一文件永远无法重导成功；文档停留 processing，严格一致性检查 FAIL。
4. **判定：当前行为 = 无法安全恢复（无人工干预时）。**
5. 诊断实验（人工删除且仅删除 0 字节 PNG 后重导）：恢复分支成功续传，
   37.1s 完成（一次性导入 41.8s），400 页 completed，严格一致性 13/13 PASS，
   孤儿 PNG 全部被重新引用。
6. 与一次性导入终态比对：逐页 `(page_number, 文本长度, review_status)` 完全相等，
   FTS=400=400，PNG 清单与体积分布完全相等——**人工清除损坏文件后的恢复终态
   与一次性导入终态一致**。

## 六、瓶颈分类

### P0：数据安全阻断

1. **中断后无法安全重试**（第五节）：渲染阶段被强杀会留下 0 字节/截断 PNG，
   续传路径拒绝覆盖该文件并抛错，文档永久停留 processing，用户无产品内修复手段。
   证据：`case-int/probe-results.jsonl` 两条 `PdfProcessingError` 记录、
   重导失败日志、人工删除损坏文件后的成功续传对照。

### P1：正式容量阻断

无。1000 页导入完成、首中尾可访问、搜索目标页可定位、重启后可用、
峰值工作集不随页数增长（50→1000 页均为约 135-137MB）。

### P2：性能与扩展问题（本轮只记录）

1. **搜索只能访问前 100 条**：`SearchService`（max_results=100）与 `Database.search`
   （写死 100）双层上限且无 OFFSET；300 页即截断，1000 页总命中 1000 仅返回 100。
2. **list_pages 全量物化**：一次性 SELECT * 含全部页面正文；1000 页 14.3ms /
   约 161K 字符（合成文本口径，真实手册预计大 1～2 个数量级）。
3. **导入吞吐 23～24 页/秒**（逐页 create_page 独立提交 + jieba 分词同步写 FTS）：
   线性外推 10,000 页约 7～8 分钟，不阻断，但属真实成本构成。
4. **备份体积≈数据体积**，1000 页创建+自检约 6.8s：线性外推 10,000 页约 1 分钟量级。

## 七、建议的最小改造顺序（待下一阶段批准，本轮未改生产代码）

1. **P0 恢复路径**：`reuse_existing_images=True` 时，对 0 字节或无法解码的 PNG
   视为缺失并重渲染（仅限损坏页；有效文件仍绝不覆盖）；导入失败时将
   `documents.import_status` 置为 `failed`，消除 processing 悬挂口径歧义。
2. **P2 搜索分页**：服务端 OFFSET/游标分页（配合现有 `facet_counts().total`），
   满足范围文档§七"确定性后续结果访问"。
3. **P2 列表轻量化**：文档页面列表改为不含正文的投影查询 + 单页正文按需读取，
   满足范围文档§八。
