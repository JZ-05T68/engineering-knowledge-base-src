### Resolved mixed-service boundary

The WP5 architecture-detail clarification permits mixed service instances behind
these frozen adapters. **“Write services absent” means no write capability is
exposed or reachable from Hosted HTTP/tool execution**, not that private Python
objects must lack write methods. `HostedDependencies` contains Agent, decision,
request factory, source projection and readiness capabilities; it does not directly
expose a mixed service. Source metadata binds explicit reader methods only.
Requests cannot select an arbitrary service or method.

Tests execute all seven representative adapters, spy on their frozen reads and
30 mutation entrypoints across KnowledgeObjectService, KnowledgeMemoryService
and EvidenceBasketService, and compare complete synthetic DB logical dumps before
and after. Mutation calls must total zero. AI audit append is tested separately.
No Agent/tool contract, executor, bootstrap, retry, ceiling, RAG or citation logic
is changed. Decision <=1, Tool <=1, Final <=1, logical model calls <=2; Agent retry
and citation repair remain zero.

## Logging

`src.hosted.logging.configure_hosted_logging` owns existing process log handlers
only during explicit Hosted startup. A safe stderr sink covers bootstrap errors;
after storage bootstrap `attach_hosted_log_file` opens
`DATA_ROOT/logs/engineering-kb.log` after WP4 link/regular-file validation.

Logs use a closed event vocabulary: startup/shutdown/failure and generic runtime
warning/error and interruption categories. Arbitrary logger messages, arguments, exceptions,
tracebacks and extra fields are never formatted. Access records are dropped.
This intentionally sacrifices raw diagnostic detail to preserve privacy. Tests
inject prompt, response, key, Authorization, XFF and private-path markers and
verify neither file nor stderr contains them. No raw exception hook is installed.
Local logging handlers, levels, propagation and umask are restored when ownership
ends normally. The log is append-only, without automatic rotation in WP5; operator
volume monitoring/retention remains necessary.

## Graceful Shutdown

ASGI lifespan closes HostedStorage before Uvicorn re-raises a captured SIGTERM.
An outer `finally` also closes it for startup, composition or server failures.
Close is idempotent. Uvicorn's re-raised SIGINT is caught, logged as
`hosted_interrupted`, and returns 130 without a Python traceback.
Configuration/storage/composition failures return nonzero
and emit only a safe startup category. Actual Linux SIGTERM stops completed with
exit 0, no traceback and a closed-category shutdown log. An additional test-only
profiling observer saw the real HostedStorage.close return with `_closed=True`;
it did not replace the production functions or configuration. The ordinary
first-start and restart runs used the image's unmodified ENTRYPOINT.

Windows does not retain POSIX umask bits. Host tests verify the `077` call occurs
before storage and that restoration occurs. The actual Linux probe independently
verified no group/other permission bits on runtime database/log directories/files.
