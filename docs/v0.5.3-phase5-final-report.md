## 3. schema v12 AI 台账审计结论

完整审计见 `docs/v0.5.3-phase5-ai-ledger-schema-audit.md`。要点：

- `ai_calls`（v12）字段：id/call_uuid/capability(model CHECK)/model/prompt_sha256/input_chars/
  status/error_class/retry_count/latency_ms/tokens/finish_reason/source_feature/target_refs/created_at。
- `capability` ∈ completion/embedding/rerank；生成型调用一律 `completion`。
- RAG Answer → `completion + source_feature='rag_answer'`；Experience Model →
  `completion + source_feature='experience_model'`；embedding → `embedding + source_feature='application'/'page_index'`。
- `target_refs` 保存本次使用 stable_id，JSON 数组，按打包顺序去重稳定。
- 成功/失败/拒绝 → status success/error/rejected；解析/citation 校验失败发生在服务层，
  调用本身已按事实记录（模型确实成功返回）。
- Mock 不经 `AuditedAIProvider`，**不写台账**，不伪装真实付费调用。
- 台账不存 prompt/上下文/回答/API Key/私人原文。
- provider、费用、finished_at 列不存在；provider 由产品单供应商契约承载（UI 显示固定标签），
  费用禁止猜测。

## 4. 是否需要 v13 的明确裁决

**不需要。保持 SCHEMA_VERSION=12，不新增 migration。**

理由：v12 的 `capability + source_feature + status + target_refs` 已能诚实、稳定地区分
embedding / rag_answer / experience_model / 成功 / 失败 / 拒绝；"生成型调用"可由
`capability='completion' AND source_feature IN ('rag_answer','experience_model')` 精确查询；
Mock 天然不落台账。新增 v13 只会是命名美化或冗余列。

测试证据：`tests/test_ai_ledger_schema_audit.py`（7 项）与既有 `test_ai_ledger.py`、
`test_ai_rag_answer.py`、`test_experience_model.py`。

## 5. 保持 v12：现有字段如何准确表达生成调用

- 调用类型：`capability`（completion=生成调用 / embedding=向量嵌入）。
- 业务来源：`source_feature`（rag_answer / experience_model / page_index / application）。
- 结果状态：`status`（success / error / rejected）。
- 使用知识：`target_refs`（stable_id JSON 数组）。
- 真实/Mock：Mock 不写台账；台账内所有行均为真实调用（`is_real_call=True` 只读投影）。

## 7. AI Ledger 查询模型与服务契约

`src/ai_ledger_service.py`：

- `query(AICallLedgerQuery) -> AICallLedgerPage`：白名单排序、limit 1~200、offset ≥0；
  筛选 source_feature / capability / status / provider（仅 `qwen`）/ model / 时间范围；
  默认 `created_at DESC, id DESC`（确定性次排序）。
- `stats(query=None) -> AICallLedgerStats`：总调用 / 成功 / 失败 / 拒绝 / token 合计
  （仅非空可靠值，空表为 0）/ 按 source_feature 计数；不猜测费用。
- `distinct_models()` / `distinct_source_features()`：供 UI 筛选。
- target_refs 按 JSON 数组契约解析；解析失败 → `target_refs_parse_error=True`，不回写。
- target_refs 目标缺失：批量 IN 查询（按类型分表，最多 6 次查询），无 N+1；
  缺失项保留 stable_id 并标记 `unavailable_target_refs`。
- 错误摘要：仅由 `error_class` 生成，脱敏（Bearer/sk-/长 token → [REDACTED]）并截断 ≤120 字符。
- 非法 sort/limit/offset/provider/status → `AILedgerError`，不拼接任意 SQL。
