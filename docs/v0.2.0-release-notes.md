# Engineering Knowledge Base v0.2.0 发布说明

发布日期：2026-07-24

v0.2.0 是“超长工程文档与非标准页面处理底座”版本。本版本扩展的是本地 PDF 处理的底层能力，
不是 AI 版本：没有接入任何模型 API、OCR、Embedding 或向量检索，核心功能继续完全离线可用。
schema 仍为 v4，没有数据库迁移，正式服务仍只监听 `127.0.0.1:8501`。

## 核心变化

- 新增单页 PDF 处理接口 `PdfService.process_page()`。页面重新处理（`reprocess_page`）现在只
  渲染并提取目标页，不再整份重新渲染 PDF；非目标页的数据库记录和 PNG 文件保持不变。
- 建立 120 页真实长文档自动测试基线：运行时由 PyMuPDF 生成测试 PDF，验证页数、页码连续性、
  逐页 PNG、逐页唯一文本、进度回调与文档句柄关闭，不提交任何二进制测试文件。
- 建立确定性页面诊断 `PageDiagnostics`：每页记录显示宽高、归一化旋转角和有效字符数，并以
  空白、短文本、横向、旋转四个独立标志识别非标准页面。同一页面可以同时携带多个标志（例如
  旋转 90° 的页面按显示几何同时也是横向）；诊断与 needs_review 共用同一份有效字符统计，
  阈值不变。
- 验证页级失败隔离：多页 PDF 中单个页面渲染或文本提取失败时，失败页以 FAILED 状态和包含
  页码的错误信息入库，后续页面继续真实处理；文档使用既有 `PARTIALLY_COMPLETED` 状态，
  不会把部分失败显示为完全成功。
- 新增文档级诊断摘要 `DocumentDiagnosticsSummary`：一次导入的总页数、成功/失败/空白/
  短文本/横向/旋转/待复核计数，以及对应的升序、去重页码列表。聚合集中在唯一纯函数
  `summarize_page_diagnostics()` 中，只读取既有 `ProcessedPage`/`PageDiagnostics` 字段，
  不重新打开 PDF、不重读 PNG、不重算文本，也不写入数据库。摘要通过 `ImportResult.diagnostics`
  暴露，既有调用方不需要修改。
- 完成 300 页混合 PDF 实际规模验收（含横向、旋转、空白、短文本页与受控失败页），覆盖完整
  处理、完整导入、中间页失败隔离和失败页单页重处理。

## 兼容与数据安全

- 未修改数据库 schema，未新增迁移；既有 `page_count`、`processed_page_count`、
  `text_page_count`、`import_status` 等字段语义不变。
- 未改变 PDF 渲染 DPI、PNG 命名、图片覆盖/复用规则、文本提取方式、进度回调时机和正常导入
  流程。
- 单页重处理只更新目标页，不修改其他页面的文本、状态或图片哈希。
- 失败页只计入 failed 统计，不会因为默认诊断值被误计为空白页。
- 诊断摘要是服务层瞬态结果，不写入数据库，不要求跨重启保留。

## 验证结果

- 完整 pytest：335 passed，0 failed；ruff check：全部通过。
- 300 页验收环境：Python 3.11.9，PyMuPDF 1.28.0，Windows。
- 300 页完整处理约 11.726 秒；DocumentService 完整导入约 13.966 秒；PNG 产物共约
  5,121,584 字节；单页平均约 39 毫秒。
- 验收确认无缺页、无假成功、无跨页覆盖、无数据丢失、无文档句柄泄漏。

以上性能数据仅描述本次验收环境，不构成普遍性能承诺。

## 已知限制与延期事项

- `reprocess_page` 成功后不会自动刷新文档级 `import_status` 和统计；曾经部分失败的文档
  可能继续显示 `partially_completed`。该行为偏保守（不会把失败显示成成功），不影响页面
  数据本身，留待后续版本评估是否重算。
- 诊断摘要不持久化；重复导入路径直接返回既有记录，不重新生成摘要。
- 文本提取失败时，该失败页已生成的 PNG 会保留在磁盘，供后续单页重处理按既有规则复用；
  更精细的残留文件清理留待后续版本。
- 本版本不包含断点续传、检查点、自动恢复、自动重试、后台导入或并行处理。
- 本版本没有诊断 UI 面板、OCR 或 AI 页面识别。
- 500 页以上规模未纳入本版本验收。

人工验证步骤见 [v0.2.0 人工冒烟测试清单](v0.2.0-manual-test-plan.md)。
