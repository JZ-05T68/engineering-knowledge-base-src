## B. AI 调用架构变化

**Before（v0.5.2）**：`runtime.application_ai_provider()` 直接返回 `QwenProvider`，重试次数硬编码
`max_extra_attempts=0`；调用无台账、无预算、无结构化错误分类。

**After（v0.5.3 Phase 2-A）**：

```
Settings（ai_max_extra_attempts / ai_daily_token_budget / ai_monthly_token_budget）
        │
runtime.application_ai_provider()
        │  构造 QwenProvider（transport=urllib_transport, 重试来自配置）
        ▼
AuditedAIProvider（供应商无关，provider.py 契约层）
  ├─ 生成 call_uuid / prompt_sha256 / input_chars
  ├─ 预算守卫（超限 → status=rejected，零网络请求）
  ├─ 委托 wrapped.complete / wrapped.embed
  ├─ 记录 status/error_class/retry_count/latency/tokens/finish_reason
  └─ 台账写入（惰性 Database.insert_ai_call；写失败仅 critical 日志，不影响结果）
```

- 台账逻辑全部位于 `src/ai/provider.py` 契约层；`qwen_client.py` 只负责**报告**结构化错误信息，
  未来替换供应商时台账行为不变。
- 台账与预算守卫惰性解析数据库：构造 provider 不触碰数据库/OCR（测试固化）。
- `AIExecutionError` 现在携带 `error_class`（transport/http_4xx/http_429/http_5xx/parse/…）与
  `retry_count`；成功结果也携带 `retry_count`，成功重试同样可审计。

## C. `ai_calls` 设计与验证

- 字段：`id/call_uuid/capability/model/prompt_sha256/input_chars/status/error_class/retry_count/
  latency_ms/prompt_tokens/completion_tokens/total_tokens/finish_reason/source_feature/
  target_refs/created_at`。
- **append-only**：`Database` 只有 `insert_ai_call`/`list_ai_calls`/`total_ai_tokens_since`，
  无 update/delete（测试断言 `hasattr(Database, "update_ai_call")` 为 False）。
- 禁存：API Key、完整 prompt、完整 response（表列无 `prompt`/`response`/`api_key`；测试断言）。
- 约束：`prompt_sha256` 长度 64、`capability/status` 枚举、`retry_count >= 0`（CHECK 测试）。
- 验证：
  - success 全字段记录（含 model echo、tokens、finish_reason、target_refs 往返）。
  - error 记录 error_class 与 retry_count；unavailable 记录 error_class。
  - `total_ai_tokens_since` 按 success 调用汇总。

## D. `ai_outputs` 设计与验证

- 字段：`id/output_uuid/call_uuid/model/context_package_sha256/output_sha256/output_kind/
  source_feature/target_refs/recheck_path/created_at`。
- **只保存审计锚点**：不存输出全文（列无 `output_text`/`response`；测试断言）。
- **ai_outputs ≠ 知识**：登记不产生任何 KO/Memory/Note（测试断言插入后 `count_knowledge_objects()==0`）。
- 无自动写入路径：本阶段未新增任何"AI 输出→知识资产"的代码。

## F. Schema 变化

- `SCHEMA_VERSION = 12`（v1–v11 完全未改，未重排，未删除）。
- 纯增量迁移 `_apply_version_twelve`：
  - 新表 `ai_calls`、`ai_outputs`、`knowledge_project_links`；
  - `knowledge_memory_entries` 加列 `content_revision INTEGER NOT NULL DEFAULT 1`、
    `outcome TEXT NOT NULL DEFAULT ''`、`context_conditions TEXT NOT NULL DEFAULT ''`；
  - 索引：ai_calls(created_at)/(source_feature,created_at)/(status)、ai_outputs(created_at)、
    knowledge_project_links(target_type,target_id) + UNIQUE(project_id,target_type,target_id)。
- 迁移保护：迁移前自动备份；`_v12_data_fingerprint` 对 knowledge_objects/memory 旧列/sources/
  relations/revisions/documents/pages/notes/evidence_items 逐行比对（Memory 只比旧列，新列不算数据变化）；
  失败注入点 `v12_ai_calls/v12_ai_outputs/v12_project_links/v12_memory_columns/v12_version_record/
  v12_before_commit`。
- 禁止项遵守：不重建 FTS、不 drop/重排旧迁移、不根据历史内容自动填充 Memory 新列。
- `build_stable_id` 命名空间扩展 `page`/`evidence`（V53-ADR-07，纯函数层无 schema 变更）；
  `note`/`document` 明确拒绝。
