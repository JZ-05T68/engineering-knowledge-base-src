# Engineering Knowledge Base v0.1.0 第一次完整人工测试方案

## 1. 测试目标

本轮测试验证真实用户能否在本地、离线、单用户边界内完成一次可信且可恢复的工程资料工作流：

`导入资料 → 复核整理 → 浏览阅读 → 检索判断 → 收集证据 → 导出证据包 → 退出并恢复工作 → 维护与恢复`

测试关注完整任务能否完成、用户是否理解当前状态与下一步、信息能否追溯到原始资料，以及故障后能否安全恢复。自动化测试只作为回归证据，不替代人工体验结论。

本阶段不主动扩张搜索、阅读、证据篮或维护能力；只有人工测试确认的 `BLOCKER`、`HIGH`，或确实阻断完整闭环的 `MEDIUM` 才进入修复候选。不会创建或规划 v0.0.9。

## 2. 范围与准出判断

### 范围内

- 现有 v0.0.8 的首页、导入、浏览/阅读、检索、待复核、标签、项目、导入记录、运行说明、证据篮和系统维护页面。
- 正式库上的只读浏览、真实问题检索和可回收的测试证据操作。
- 隔离库中的导入、状态变更、异常注入、恢复和破坏性边界测试。
- 正式服务退出/重启后的持久化与完整性。
- 默认窗口与 `420×900` 窄窗口的真实浏览器交互。

### 范围外

- 未经人工测试证明必要的新功能。
- 云服务、账号、登录、联网依赖或付费 AI 接入。
- 直接手工修改正式数据库来制造通过结果。
- 在正式资料上执行损坏、路径逃逸、符号链接、强制恢复或不可逆删除测试。

### 发布门槛

只有完整闭环成功、无未解决 `BLOCKER` 和影响核心流程的 `HIGH`，并同时满足仓库 `AGENTS.md` 中的本地数据、完整性、监听、备份恢复、窄窗口、自动化检查和清理要求，才建议发布 v0.1.0。

## 4. 测试数据原则

- 正式库中的三份真实资料（STM32、PID、平衡车）用于真实问题检索、阅读判断和证据闭环。
- 导入、复核状态变更、标签/项目关联、失败注入、缺失文件、恢复、非法 manifest、路径逃逸和符号链接测试使用隔离数据目录。
- 导入样本优先从用户已有、明确授权的本地真实 PDF 中选择一份副本；不构造只为让按钮通过的单页玩具文档。
- 测试开始前创建并验证完整备份；恢复测试只写隔离目录。
- 不自动删除原 PDF 或页面 PNG，不直接改正式数据库，不覆盖用户笔记，不删除测试开始前已存在的文档、项目、标签、证据篮或证据。
- 正式库初始证据为 0；人工测试新增的证据必须能按测试记录识别，完成持久化和导出验证后再通过界面显式清理，并再次核对正式库统计。
- 所有临时测试目录放在仓库外的明确隔离根目录；清理前验证解析后的绝对路径仍位于该隔离根目录。

## 5. 记录与严重程度

每项测试在 `docs/v0.1.0-manual-test-results.md` 记录：编号、场景、前置条件、操作步骤、预期结果、实际观察、通过状态、截图或日志、影响程度、是否阻断、建议处理方式。

- `BLOCKER`：资料可能损坏、无法完成核心闭环、无法恢复或正式服务不可用。
- `HIGH`：核心流程明显错误，用户容易得出错误结论或无法继续。
- `MEDIUM`：可以绕过，但造成明显困惑、重复劳动或高判断成本。
- `LOW`：文案、布局或轻微体验问题，不影响闭环。
- `OBSERVATION`：暂不判定为缺陷，但值得记录。

状态使用 `NOT RUN`、`PASS`、`FAIL`、`BLOCKED`。`PASS` 仍必须写实际观察，不能只写“通过”。

## 6. 完整测试场景与用例

### 场景 A：首次进入和空状态理解

- `A-01` 正式库首页：核对资料数量、待复核量、最近导入、证据篮入口和“开始使用”流程是否一致且可理解。
- `A-02` 主要页面导航：从侧栏逐页进入导入、浏览、搜索、待复核、标签、项目、证据篮和维护，确认名称、关系和返回路径清楚。
- `A-03` 隔离空库：首页及主要页面空状态是否说明当前为什么为空、下一步是什么，并提供安全入口。
- `A-04` 用户心智检查：不阅读 README，仅依靠界面描述复述“导入—复核—搜索—证据—维护”的关系，记录任何隐藏规则或误导。

### 场景 B：PDF 导入

- `B-01` 在隔离库上传一份真实工程 PDF，检查标题、大小提示、导入过程、成功/部分完成文案和下一步入口。
- `B-02` 重复上传同一 PDF，确认 SHA-256 重复识别，不重写原件或重复生成页面记录。
- `B-03` 对比隔离库中的 PDF、PNG、页面记录、Markdown、导入记录和 FTS 数量；抽查页码、图像和文本对应。
- `B-04` 上传非 PDF、空文件或损坏 PDF，确认错误明确、失败记录可见、原成功资料不受影响、临时产物被隔离。

### 场景 C：页面复核和整理

- `C-01` 在隔离库覆盖 pending、draft、reviewed、skipped、failed 五种状态，并核对中文标签、队列范围和统计口径。
- `C-02` 使用“保存草稿”“保存并标记已复核”“保存、复核并进入下一页”，确认状态、文件和下一页切换一致。
- `C-03` 修改内容但不保存后切换页面，确认明确提醒、内容不丢失、放弃操作需要显式确认。
- `C-04` 验证 `Ctrl+S`、`Ctrl+Enter`、`Alt+Left`、`Alt+Right`；方向快捷键在文本编辑时不得误触发。
- `C-05` 修改 Markdown 笔记并关联页面/文档标签和项目，退出页面再进入后核对持久化和 FTS。
- `C-06` 中途关闭页面或浏览器，再进入“继续处理下一待复核页”，确认上下文和进度可信。
- `C-07` 对 failed 页验证失败原因、重试入口、编辑内容保护、其他已完成页不回滚。

### 场景 D：浏览和阅读

- `D-01` 核对文档列表、筛选、文档选择、页码跳转、上一页/下一页和双栏阅读。
- `D-02` 抽查三份正式文档至少各一页，核对页面图像、页码、PDF 文件名、提取文本/Markdown 和状态对应。
- `D-03` 记录最近查看；从搜索、标签、项目和证据篮进入阅读页后，核对返回和当前文档/页码上下文保持。
- `D-04` 在隔离库分别模拟缺失 PNG、PDF、Markdown 和记录坐标不一致，确认安全停止、中文错误和不自动修复/删除。

### 场景 E：搜索完整流程

- `E-01` 真实查询组：单个中文词、多关键词 OR、连续中文文本、特殊字符、无结果查询；记录耗时和结果理解成本。
- `E-02` 按文档、项目、标签、复核状态、命中字段、有笔记和当前证据篮筛选；核对候选计数与空结果解释。
- `E-03` 多标签、多项目 AND 与多搜索词 OR；在隔离库准备必要的可判定关联数据。
- `E-04` 相关度、文档与页码、最近查看、最近修改排序；核对排序是否符合界面含义。
- `E-05` 分页、加载上限和筛选面板开合；确认改变排序/筛选时页码行为可预测。
- `E-06` 搜索状态写入 URL、刷新恢复、浏览器前进/后退恢复。
- `E-07` 页面视图与按文档分组视图；核对完整命中页数、展开状态和组内顺序。
- `E-08` 多命中片段、命中字段、字面命中次数和快速预览；记录摘要是否准确或误导。
- `E-09` 从结果进入阅读页，验证全局命中导航、当前文档命中导航和普通相邻页反馈。
- `E-10` 从阅读页返回搜索、浏览器前进/后退，确认查询、筛选、排序、分页、分组、预览和焦点状态恢复。
- `E-11` 对每个真实问题分级记录：快速正确、正确但判断成本高、排名不合理、摘要误导、筛选不清、返回频繁或无结果原因不明。

### 场景 F：证据篮

- `F-01` 从正式搜索结果加入一条证据，核对默认选区和来源页。
- `F-02` 从正式阅读页加入另一文档/页面的自定义选区并添加备注。
- `F-03` 重复加入相同规范化选区，确认被拒绝；同页不同选区允许并存。
- `F-04` 分别验证“已匹配原始材料”和“用户摘录（未经原文匹配确认）”标记不混淆。
- `F-05` 修改排序、备注并退出/重新进入，核对本地 SQLite 持久化。
- `F-06` 返回来源、删除单条证据，确认原 PDF、PNG、页面、笔记和其他证据不受影响。
- `F-07` 生成至少跨两份文档、多个页面的 Markdown 证据包，检查顺序、状态警告、绝对本地路径和稳定引用。
- `F-08` 用真实问题完成“搜索—判断—收集—导出”闭环，并判断导出内容能否独立追溯到原文。
- `F-09` 显式确认清空本轮测试证据，核对只删除证据条目；正式库回到测试前证据数量。

### 场景 G：异常和恢复能力（仅隔离环境）

- `G-01` 创建人工测试前完整备份并验证 manifest、哈希、数据库、外键、统计和文件引用。
- `G-02` 对已有发布检查备份和人工测试前备份执行只读预检。
- `G-03` 将人工测试前备份恢复到新的隔离目录，核对文档、页面、FTS、浏览和证据篮。
- `G-04` 非法 JSON、缺失文件、哈希损坏和不完整 manifest 必须被拒绝，隔离目标不得被破坏。
- `G-05` manifest 中的路径逃逸与绝对路径必须被拒绝。
- `G-06` 备份源、manifest 目标或隔离目标中的符号链接必须被拒绝。
- `G-07` 正式服务运行时，正式恢复必须拒绝并提示先停 Streamlit；不实际覆盖正式库。
- `G-08` 在隔离对象上注入恢复后校验失败，确认自动回滚到恢复前资料。

### 场景 H：维护页面和诊断

- `H-01` 核对应用/schema/文档/页面/FTS/证据统计、路径、磁盘空间和服务地址。
- `H-02` 从页面创建并验证备份；核对耗时、备份候选列表和恢复说明。
- `H-03` 运行 13 项只读诊断，核对总体状态、每项摘要、正式监听和隔离端口。
- `H-04` 下载脱敏 Markdown 报告，检查没有正文、环境变量值、凭据、完整用户目录或敏感日志内容。
- `H-05` 在隔离环境验证低磁盘、目录权限、孤立文件和符号链接提示，不自动修改、删除或修复。
- `H-06` 诊断前后对比正式数据库和资料文件统计/哈希，确认只读。

### 场景 I：退出和恢复工作

- `I-01` 在有搜索 URL 状态、最近查看和测试证据时关闭浏览器，重新打开后核对可恢复状态与持久化边界。
- `I-02` 使用正式脚本停止服务并重新启动，再访问应用，核对数据库、搜索、最近查看、证据篮、监听和非正常退出安全性。

### 场景 J：420×900 窄窗口和交互质量

- `J-01` 首页。
- `J-02` 导入资料。
- `J-03` 浏览资料。
- `J-04` 检索资料。
- `J-05` 阅读页面。
- `J-06` 待复核页面。
- `J-07` 项目管理。
- `J-08` 标签管理。
- `J-09` 证据篮。
- `J-10` 系统维护。

每个窄窗口用例检查：全局/局部水平溢出、按钮遮挡、文本截断、表格可操作性、页面跳动、操作密度、当前状态、错误可理解性和返回路径。

## 7. 执行顺序与数据保护

1. 完成基线命令、Git/监听/数据库核对并记录 `AGENTS.md` 哈希。
2. 创建本方案与结果记录。
3. 创建命名的测试前完整备份并使用正式验证入口复验。
4. 执行正式库只读首页/浏览/搜索测试，建立真实问题与证据任务。
5. 在隔离服务完成空库、导入、复核、标签/项目、异常和恢复测试。
6. 在正式库完成可识别、可清理的证据闭环与退出/重启测试。
7. 执行窄窗口测试并恢复默认视口。
8. 仅修复人工测试明确确认且必要的问题；每次补测试并相关复测。
9. 运行 Ruff、完整 Pytest、`scripts/release_check.py`，清理隔离目录和端口。
10. 对比测试前后统计、`AGENTS.md` 哈希、Git 暂存区和工作区，给出发布结论。

## 8. 性能和安全观察点

- 记录首页、典型搜索、分组切换、快速预览、文档跳转、证据导出、备份、验证、恢复和诊断的主观等待与可测耗时。
- 不采集正文到外部服务，不上传用户文件到网络，不读取浏览器密码、Cookie、localStorage 或会话存储。
- 搜索特殊字符、Markdown 元数据和用户备注不得形成 SQL、HTML 或 Markdown 注入。
- 任何缺失文件、哈希变化、记录不一致或来源变化都应停止并给出明确错误，不得静默回退到相邻内容。
- 正式监听必须始终为 `127.0.0.1:8501`；隔离服务只能使用明确隔离端口并在结束时关闭。
