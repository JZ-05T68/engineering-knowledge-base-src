## 1. 冻结对象

- Query ID / exact query text / category / relevant pages / distractor notes：
  机器可读形式在 `benchmarks/queries_v1.json`（29 条，A–J 十类）；
  语料在 `benchmarks/corpus_synthetic_v1.json`（42 页，21 页嵌入）。
- 本文档冻结评分口径。两者共同构成合同，任一变更都视为新 benchmark 版本。

## 2. 排名口径

- **Keyword ranking** = `SearchService.search(query, limit=50)` 返回顺序（1-based 绝对位置）。
- **Hybrid ranking** = `HybridSearchService.search(query, limit=50)` 的 `HybridSearchOutcome.results`
  顺序（水合后、与 UI 一致的绝对位置；不过滤、不重排）。
- 两种模式使用**完全相同**的评分规则。
- `limit=50` ≥ 语料 42 页，保证「不在结果中」只由检索逻辑决定，不由截断决定。

## 3. 指标定义（非 F 类 query）

对每条 relevant 非空的 query：

- `best_rank(mode)` = relevant pages 在最终排名中的最小 1-based 位置；全部缺席记为 `ABSENT`。
- **Hit@1** = `best_rank == 1`；**Hit@3** = `best_rank ≤ 3`。
- **RR** = `1 / best_rank`（ABSENT 记 0）；**MRR** = 全部非 F query 的 RR 均值（两模式分别计算）。
- **Coverage@5** = Top 5 中不同 relevant 页数 / |relevant|（D、H 类重点指标，衡量集合覆盖而非唯一答案）。
- **delta** = `keyword_best_rank − hybrid_best_rank`：
  - `delta > 0` → **improved**；
  - `delta = 0`（含双方同位次）→ **unchanged**；
  - `delta < 0` → **regression**（Hybrid 把 Keyword 已经更好的结果拉低，重点暴露对象）；
  - keyword ABSENT 且 hybrid 命中 → **hybrid-only recall**（单列，不计入 improved 数值）；
  - 双方 ABSENT → **both-miss**。
- **Cross-document coverage**（D 类）：Top 5 中 relevant 页是否覆盖 ≥ 2 个不同文档。

整体不设预先 PASS 阈值。baseline 只报告分布，阈值由人工在 defect matrix 之后决定。

## 4. F 类（negative / no-good-answer）专门口径

- F 类 query 的 relevant set 为空，**没有 Top1 正确性可言**；「总有一个 Top1」不是成功。
- 每条 F query 记录：
  1. keyword 结果数与 Top 5 组成（预期：词面无命中或仅弱命中）；
  2. hybrid 结果数、Top 5 组成及 provenance 标签分布（`关键词匹配 / 混合匹配 / 语义召回`）；
  3. 是否有任何结果以「语义召回」身份被顶到前列（即系统把无答案问题伪装成有答案的程度）；
  4. UI/结果中是否存在任何「可能没有答案」的信号。
- 判定是**定性的**：`no-answer exposure = high / medium / low`，由人工阅读记录。
- 已知产品事实（Phase 1A 审计）：vector recall 无相似度阈值、UI 无弱结果表达。
  若 F 类暴露出「无答案时仍给出语义召回 Top1」，记录为**产品边界 limitation**，
  不得在报告中写成系统能判断无答案。

## 5. 每条 query 的固定记录字段

- query id / text / category；
- keyword ranking（Top 10，标出 relevant 页位置）与结果总数；
- hybrid ranking（Top 10，标出 relevant 页位置、provenance 标签）与结果总数；
- `vector_status`、`invalid_vector_candidates`、query embedding 调用次数（必须 = 1）；
- best_rank（两模式）、Hit@1 / Hit@3 / RR / Coverage@5 / delta 标签；
- observation（自由文本：误召回、跨文档排序异常、provenance 观感等）。

## 6. 成本与边界（本阶段硬约束）

- 0 real HTTP、0 Qwen 调用、0 LLM、0 rerank、0 新增真实 page embedding、无 retry 概念（无 transport）。
- fixture 向量只写入 runner 临时目录 DB；`data/` 与 `staging-data/` 只读都不得触碰。
- 本合同输出一律标注为 **algorithmic/offline evidence**。

## 7. 与 Decision Gate 的证据衔接

本合同产生的 baseline 分布、regression 清单、F 类 exposure 记录，
是后续 v0.5.1 收口 Decision Gate 中 Retrieval Quality 维度的直接输入；
成本维度输入为「每条 hybrid query 恰好 1 次 query embedding」的逐条计数。
