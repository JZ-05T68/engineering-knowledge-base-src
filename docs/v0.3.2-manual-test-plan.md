# Engineering Knowledge Base v0.3.2 人工测试计划

- 计划版本：1.0
- 适用分支：`kimi/v0.3.2-cross-document-aggregation`
- 依据设计：`docs/design-v0.3.2.md`(§17.1 聚合纳入规则、§18 聚合×删除一致性）
- 初始状态：全部场景 `NOT STARTED`
- 执行性质：隔离、本地、单用户、人工观察；本文件只定义矩阵，不代表已经执行
- 执行时机：S6 release gate；本轮（S5）只写计划

## 1. 范围与非目标

### 1.1 范围

v0.3.2 新增能力的用户视角验证：

A. 导入文档永久删除（含 crash recovery、证据篮独立确认、聚合影响展示）
B. 知识聚合页（项目/标签轴、筛选、分页、来源导航、只读纪律）
C. 关键回归（既有功能未被破坏）

### 1.2 非目标

以下内容以自动化结果为前置证据，本计划不逐项复述：

- 全量 `pytest`（当前 985 项）与 `ruff`;
- 删除服务的故障注入与残留校验（`test_document_deletion_service.py` 等）;
- 聚合 service 的语义矩阵（`test_aggregation_service.py` /
  `test_aggregation_impact.py`);
- 各页面 AppTest 行为断言。

本计划不验收 OCR 准确率、AI 能力、云服务、多用户或批量删除（本版均无）。

## 2. 前置条件

1. Git 分支为本文件开头所列分支；`git status --short` 为空；全量 pytest/ruff
   已通过并记录 commit。
2. 使用 `D:/Projects/engineering-kb-v0.3.2` 的 `.venv`(Python 3.11,
   streamlit `<1.61` 约束），不安装新依赖，不访问外网。
3. 正式数据不参与：使用独立测试数据目录（`EKB_*` 环境变量指向隔离目录），
   记录其路径；8501 被正式服务占用时改用 8502~8512 中空闲端口，只绑定
   127.0.0.1。
4. 测试资料：至少 2 份真实 PDF（建议一份 ≥10 页），记录文件名、页数、
   SHA-256 与来源。
5. 每个场景记录：执行日期、执行人、commit、浏览器、端口、隔离目录。
