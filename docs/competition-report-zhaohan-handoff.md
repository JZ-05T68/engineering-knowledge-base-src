## 1. 项目一句话

EKB（工程知识库）是一个**本地运行的个人工程知识管理系统**：把工程师手里的
PDF 资料、页面笔记和解决问题的经验组织成知识库，由知识 Agent 提供**带依据、
可回源**的问答；来源建档后如果内容变化，系统会如实提示重新核对。
一句话记忆点：**让工程经验可查、可复用、可回源、可核验。**

## 2. 为什么做

四个真实痛点：① 工程资料散落（PDF/笔记/聊天记录），查找靠翻；② 老工程师
解决问题的过程只在个人脑中，人走经验丢；③ 新人重复踩老坑；④ 通用 AI 能生成
流畅答案，但不了解"我们自己的设备和资料"，且答案难核验来源，工程上不敢采信。
（定性论述即可，报告不引用编造的市场统计。）

## 3. 产品怎么工作

一条主线：**资料进入 → 整理（页面/笔记/知识对象/知识记忆/证据）→ 检索 →
Agent 提问 → 有依据回答 → 引用编号 → 点击查看来源 → 来源变化提示（信任边界）**。
三场演示就是这条线的三个定格：A 看到回答有依据、B 找回历史经验、
C 看到来源变化被如实提示。演示操作顺序与口播见
`docs/v0.6.1-competition-demo-runbook.md`。

## 4. 最重要的三个创新点（都有实现与测试背书）

1. **回答-引用-来源的追溯闭环**：关键结论强制标注来源编号，引用逐条校验，
   校验失败宁可整体失败也不输出无依据文本；
2. **无依据时 fail-closed**：知识库中没有足够资料时明说"未找到可支持资料"，
   不编造（这是信任特性，不是缺陷）；
3. **来源完整性/信任边界**：资料建档后内容变化会被标注"来源发生变化"
   （=快照不一致，不代表被篡改），提示重新核对；本地优先、隐私友好、
   单步只读 Agent 的安全边界是支撑性设计。

## 6. 系统架构（报告两层级，勿混写）

- **评委版**：工程资料 → 知识组织 → 检索 → 只读 Agent → 回答 → 来源 → 完整性边界。
- **技术附录**：Local Streamlit + 知识/检索服务 + 单步 Agent 执行器（一次决策
  至多一个只读工具、不重试不循环）+ 七个只读工具（页面检索/知识检索/对象/
  记忆/溯源/完整性检查/证据）+ Final Answer 阶段（引用逐条校验）+ Hosted HTTP
  回环接口 + SQLite schema v12 + 请求上限 12 万字符。

## 11. 绝对不能写什么（红线，违反=返工）

- ✗ 公网 Agent 已上线 / 已部署生产 / WP6A 已通过（**事实：DEFERRED**）；
- ✗ 多用户 SaaS / 云平台 / 团队协作版；
- ✗ 实时联网校验所有来源 / 自动完整性刷新 / 自动更新知识；
- ✗ "来源发生变化"写成"检测到篡改/来源不可信"；
- ✗ 预置演示说成实时 AI / 真实模型回答 / 已批准正式语料；
- ✗ "所有回答必然正确""100% 准确""完全可信""零幻觉"；
- ✗ 产品已有大量生产客户 / 编造用户数与市场规模；
- ✗ 自动多步自主 Agent（当前是**有意的单步**设计）；
- ✗ "全程无需联网"（正确表述：核心知识管理能力与比赛预置演示可本地离线运行，
  真实 Agent 模式在启用云端模型时需要网络与 API 配置）。

推荐替代表达："依据可查、来源可回、变化会提示。"
