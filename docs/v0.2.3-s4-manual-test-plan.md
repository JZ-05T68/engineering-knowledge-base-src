## 1. S4 目标与非目标

### 1.1 目标

S4 从用户视角验证 v0.2.3 基线上的实际操作与界面体验：启动、导入、阅读、导航、
搜索、有限长文档路径、中断后恢复、少量高价值回归及错误诊断。每项测试都必须由执行者
亲自在界面观察；自动化结果只能作为前置证据，不能替代本计划的人工结论。

当前基线的生产界面仍显示 `v0.2.2`，这是 S3C 文档中已经明确的被测产品代码版本；
S4-01 只核对首页与“系统维护”中的版本显示一致且入口存在，不把显示值虚构为
`v0.2.3`，也不在本轮修改版本号。

### 1.2 明确非目标

以下内容已由 S3C 验证，本轮只引用
`docs/v0.2.3-s3c-final-results.md`，不重新执行或包装成人工测试：

- 300、1000、3000 页完整性能矩阵；
- 547 项全量 `pytest`；
- T25 的 19 例故障注入及各档 28 项终态不变量；
- 1000 页 OS 级强杀恢复证明；
- 多轮交错性能跑分；
- PNG 全量解码与文件哈希证明；
- 3000 页安全已验证上限的重新证明。

S4 不执行 3000 页导入。3000 页只作为 S3C 自动证据引用；S4 也不验收 OCR 准确率、
目录/书签、印刷页码、云服务或账号能力，不扩展为完整产品验收，不重新打开 S3C。

## 3. 测试环境与隔离要求

### 3.1 目录布局

在仓库外或仓库中已忽略的测试根目录创建本轮唯一目录，例如：

```text
<S4_ROOT>/
├── inputs/                 # 本轮 PDF 和无效样本
├── runs/
│   ├── startup/
│   ├── core/
│   ├── long/
│   ├── mixed/
│   ├── recovery/
│   └── errors/
├── quarantine/             # 恢复场景临时移出的隔离文件
├── records/                # 截图、操作记录、失败记录
└── archive/                # 已结束或重置的运行现场
```

每个 `runs/<group>/` 内使用独立的 `data/raw`、`data/pages`、`data/markdown`、
`data/database`、`backups`、`logs` 和 `runtime`。不得复制带绝对路径的成品 runtime
目录作为标准测试方法；数据库搬迁只能使用产品已有的正式备份和恢复路径。本计划不要求
搬迁数据库。

### 3.2 隔离启动方法

对每个运行组在同一 PowerShell 窗口设置完整路径变量；下面的 `<RUN_ROOT>` 必须替换成
当前组的绝对路径：

```powershell
$env:EKB_DATA_DIR="<RUN_ROOT>\data"
$env:EKB_RAW_DIR="<RUN_ROOT>\data\raw"
$env:EKB_PAGES_DIR="<RUN_ROOT>\data\pages"
$env:EKB_MARKDOWN_DIR="<RUN_ROOT>\data\markdown"
$env:EKB_DATABASE_DIR="<RUN_ROOT>\data\database"
$env:EKB_DATABASE_PATH="<RUN_ROOT>\data\database\knowledge.db"
$env:EKB_BACKUPS_DIR="<RUN_ROOT>\backups"
$env:EKB_LOGS_DIR="<RUN_ROOT>\logs"
$env:EKB_LOG_PATH="<RUN_ROOT>\logs\engineering-kb.log"
$env:EKB_RUNTIME_DIR="<RUN_ROOT>\runtime"
$env:EKB_PID_PATH="<RUN_ROOT>\runtime\engineering-kb.pid.json"
.\.venv\Scripts\python.exe -m streamlit run app.py `
  --server.address 127.0.0.1 --server.port $S4Port --server.headless true
```

这是真实仓库入口，不假设额外启动按钮。正式批处理启动器固定使用 8501，因此本轮隔离
实例不用 `启动工程知识库.bat`。界面“系统维护”仍可能按正式配置显示
`127.0.0.1:8501`，隔离进程的实际监听以启动命令和 PowerShell 只读端口检查为准；
该差异应记录，不得误判为隔离实例实际监听了 8501。

正常停止使用运行该命令的终端中的 `Ctrl+C`。停止后检查：

```powershell
Get-NetTCPConnection -LocalPort $S4Port -State Listen -ErrorAction SilentlyContinue
```

无输出才表示测试端口没有监听残留。不得清理或停止范围外进程。

### 3.3 隔离与重置规则

- 不使用正式数据库、正式资料、正式备份或用户唯一原件；C 级资料若获批，也只能使用
  只读副本。本矩阵默认只用 A 级合成资料。
- 测试资料只放在 `<S4_ROOT>\inputs`；应用产生的数据只放在对应 `runs/<group>`。
- 需要干净状态时：先正常停止隔离实例，确认测试端口无监听，再把当前组目录移动到
  `archive/<group>-<timestamp>`，创建新的空组目录。移动前后记录绝对路径。不得删除
  原 PDF、页面 PNG 或失败现场。
- 重复导入测试必须在同一个运行组、同一个数据库中连续执行；其他需要“首次导入”的
  场景使用新的组目录，避免旧 SHA-256 状态污染。
- 任何场景只准操作其记录的 `<RUN_ROOT>`；路径无法确认时立即停止该场景。
- 核心功能全程离线；不要求 VPN、云服务、账号登录、API Key 或外部联网。

## 5. 结果等级与停止策略

### P0

包括但不限于：正式或隔离数据静默丢失；操作影响测试范围外数据；界面明确显示成功但
核心数据实际未保存；无可靠恢复路径的数据破坏。

发现 P0：立即停止整个 S4，保留现场，不继续任何写操作。

### P1

包括但不限于：核心导入、阅读、搜索或恢复流程不可完成；长文档导入后无法打开；页码、
页面内容或搜索跳转系统性错位；可稳定复现的未处理异常；用户无法从 processing 或失败
状态恢复。

发现 P1：停止相关测试组，不扩大执行；依赖该组的场景标记 `BLOCKED`。

### P2

有替代路径的功能缺陷；明显但非阻断的界面或诊断问题；个别边界行为不符合预期；
不影响数据正确性的体验问题。记录后按矩阵继续，不立即进入修复—复测循环。

### P3

文案、提示、排版和轻微体验问题；不影响流程和正确性的低风险问题。记录后继续。

## 7. 详细测试场景

### S4-01 干净启动、主要入口与停止

- **测试目标**：确认空隔离状态可启动，主要页面可访问，停止后无测试进程监听残留。
- **对应版本能力**：本地启动、空库首页、Streamlit 多页面入口、只监听回环地址。
- **前置条件**：`runs/startup` 为空；测试端口空闲；环境变量按 §3.2 指向该目录。
- **数据或 PDF 类型**：无。
- **最少人工操作步骤**：
  1. 执行 §3.2 启动命令，浏览器打开 `http://127.0.0.1:<S4Port>`。
  2. 观察首页标题、空库提示和“导入第一份 PDF”入口。
  3. 依次打开侧栏实际存在的“导入资料”“文档与页面/浏览资料”“检索资料”
     “待复核页面”“标签管理”“项目管理”“导入记录”“证据篮”“系统维护”。
  4. 在“系统维护”记录“应用版本”；与首页版本显示比较。
  5. 回到终端按 `Ctrl+C`，执行端口只读检查。
- **用户界面预期**：首页和每个入口能渲染可理解的空状态；当前基线首页和系统维护均显示
  `v0.2.2`；不出现 traceback、白屏或“应用初始化失败”。页面名称以实际侧栏显示为准，
  不要求不存在的菜单。
- **数据、文件或状态预期**：只在 `runs/startup` 创建空数据库、日志和所需目录；
  端口停止后无 LISTENING。
- **不变量**：正式数据和 8501 零接触；不产生文档、页面或测试范围外文件。
- **PASS 判据**：全部列出的实际入口可打开；无未处理异常；版本显示一致；停止后测试端口
  无监听。
- **FAIL 判据**：任一主要入口无法打开、出现稳定未处理异常、实际绑定非
  `127.0.0.1`、访问了正式数据/8501，或正常停止后测试端口仍持续监听。
- **恢复或清理**：保留日志和截图；确认端口已停止后把 startup 目录移动到 archive。
- **阻断场景**：是；核心入口或隔离失败按 P1/P0。
- **失败后立即停止**：是；停止 A 组，隔离越界则停止整个 S4。

### S4-02 普通 PDF 核心闭环

- **测试目标**：确认 v0.1.2 既有普通导入、浏览、搜索和页面互跳没有被破坏。
- **对应版本能力**：PDF 导入、导入完成状态、文档列表、页面阅读、页码选择、本地搜索、
  搜索结果打开与返回。
- **前置条件**：`runs/core` 为干净空库；S4-01 通过；D01 哈希已记录。
- **数据或 PDF 类型**：D01，8 页普通文本 PDF，每页含唯一 TOKEN。
- **最少人工操作步骤**：
  1. 在“导入资料”选择 D01，保留默认标题，点击“导入 PDF”。
  2. 观察进度文本直到结束，记录成功摘要中的总页数、已处理数和待复核数。
  3. 打开首页“最近导入”或“文档与页面”，选择该文档。
  4. 用“页码”选择第 1、4、8 页；在第 4 页点击一次普通上一页和普通下一页。
  5. 在“检索资料”搜索第 4 页唯一 TOKEN，点击“搜索 / 应用筛选”，再点结果中的
     “打开页面”。
  6. 核对阅读页为第 4 页，点击“返回检索结果”，再从搜索结果返回阅读页一次。
- **用户界面预期**：进度显示“正在处理第 x/8 页”，结束显示“导入完成”；文档可选；
  页码选择、普通上一页/下一页和搜索结果“打开页面/返回检索结果”均可操作。
- **数据、文件或状态预期**：一个文档、8 个页面；文档状态已完成；页面图片存在；
  搜索唯一 TOKEN 只返回目标页。
- **不变量**：页码与图片上的 `PAGE n` 一致；相邻导航不跨文档；原输入 PDF 不被修改。
- **PASS 判据**：导入、列表、阅读、导航、搜索和双向跳转全部完成，页码均正确，无错误成功。
- **FAIL 判据**：导入无法完成、文档或页面缺失、唯一 TOKEN 错页/多页、跳转相邻错页、
  页面永久无响应或未处理异常。
- **恢复或清理**：保留 core 现场供 S4-09～S4-13；若需重测，停止实例并按 §3.3 归档后
  使用全新 core 目录，不删除原现场。
- **阻断场景**：是。
- **失败后立即停止**：是；停止 B/H 依赖组。

### S4-03 300 页完整人工流程

- **测试目标**：以可控成本验证数百页文档的完整用户关键路径，不重跑性能矩阵。
- **对应版本能力**：长 PDF 导入进度、完成摘要、文档打开、页码定位、搜索与跳转。
- **前置条件**：`runs/long` 为空；S4-01 通过；D02 页数、SHA-256 和 TOKEN 规则已记录。
- **数据或 PDF 类型**：D02，300 页普通文本 PDF。
- **最少人工操作步骤**：
  1. 导入 D02，记录开始/结束时间仅作现场说明，不与 S3C 性能阈值比较。
  2. 每当进度跨过约 1、100、200、300 页时各记录一次显示值；不高频刷新或重复点击。
  3. 完成后从文档列表打开，选择第 1、150、300 页，核对图片 `PAGE n`。
  4. 搜索第 1、150、300 页各自唯一 TOKEN，每次打开结果并返回。
  5. 返回文档列表，再次打开该文档并定位第 300 页。

  未处理异常。
- **恢复或清理**：在证据篮删除该测试条目或整体归档 core 现场；删除前记录条目 ID/页码。
- **阻断场景**：是；数据假成功或来源错位为 P1/P0。
- **失败后立即停止**：是；停止 H 组。

### S4-12 无效 PDF 明确失败

- **测试目标**：确认扩展名为 PDF 但内容无效的文件不会被错误显示为成功或暴露未处理异常。
- **对应版本能力**：导入错误捕获、中文失败反馈、导入失败记录。
- **前置条件**：独立干净 `runs/errors-invalid`；D06 哈希已记录。
- **数据或 PDF 类型**：D06，无效 PDF 内容。
- **最少人工操作步骤**：
  1. 在“导入资料”选择 D06，点击“导入 PDF”一次。
  2. 记录页面反馈；打开“导入记录”查看对应尝试。
  3. 返回首页和文档列表，确认没有可打开的已完成文档。
- **用户界面预期**：显示“导入失败：…”或等价明确错误，不出现“导入完成”；页面不显示
  traceback；导入记录显示失败及可理解原因。
- **数据、文件或状态预期**：不得产生已完成文档或可被误认作完整导入的页面。
- **不变量**：错误只影响 errors-invalid 组；正式数据及其他组不变。
- **PASS 判据**：失败反馈明确、无假成功、无未处理异常、无已完成文档。
- **FAIL 判据**：显示成功、产生可见已完成文档、错误被静默吞掉、出现 traceback 或应用
  进入不可恢复状态。
- **恢复或清理**：停止实例并归档完整错误现场；不手工修数据库。
- **阻断场景**：是；假成功按 P1，跨范围破坏按 P0。
- **失败后立即停止**：是；停止 I 组。

### S4-13 重复导入零增量提示

- **测试目标**：确认相同内容重复导入被 SHA-256 识别，用户能理解没有生成重复数据。
- **对应版本能力**：重复文件检测、重复导入提示、文档去重。
- **前置条件**：core 现场中 D01 已成功导入一次；记录当前文档条数和 D01 页数。
- **数据或 PDF 类型**：同一 D01，同一字节内容。
- **最少人工操作步骤**：
  1. 再次选择 D01，点击“导入 PDF”一次。
  2. 记录提示；打开文档列表和导入记录。
  3. 搜索 D01 的一个唯一 TOKEN 并打开结果。
- **用户界面预期**：显示“该文件已经导入…未生成重复数据”或当前实际等价警告；不显示为
  新文档导入成功。
- **数据、文件或状态预期**：文档仍为一个、页面仍为 8；可保留一条说明重复的导入记录；
  搜索结果仍指向原文档。
- **不变量**：重复操作不创建第二份 PDF、页面或文档，不覆盖原输入。
- **PASS 判据**：提示明确，文档/页面零增量，原文档仍可搜索和打开。
- **FAIL 判据**：创建重复文档/页面、提示成功但产生异常增量、原文档不可用或未处理异常。
- **恢复或清理**：不删除原文档；保留 core 现场至 H/I 组记录完成后整体归档。
- **阻断场景**：是；重复数据系统性产生按 P1。
- **失败后立即停止**：是；停止 I 组。

### S4-14 缺失源文件及诊断级别

- **测试目标**：确认隔离源文件缺失时阅读页和诊断明确区分 WARNING 与 ERROR，并提供可恢复
  的下一步，不错误显示全部正常。
- **对应版本能力**：缺失原始 PDF 警告、一键只读诊断、诊断总体等级。
- **前置条件**：独立 `runs/errors-diagnostic` 中只导入一份 D01 并完成；实例停止；确认
  `data/raw` 只有该测试文档的受管 PDF；`quarantine` 在同一 S4 根目录。
- **数据或 PDF 类型**：D01 导入后的隔离 raw 文件。
- **最少人工操作步骤**：
  1. 正常状态先在“系统维护”点击“运行完整只读诊断”。记录总体状态和各检查等级。
     无完整备份、正式监听未确认等当前基线条件可以产生 WARNING；确认界面没有把 WARNING
     写成“全部失败”。
  2. 停止实例，将唯一 raw PDF 移到
     `<S4_ROOT>\quarantine\S4-14\<原文件名>`；记录源和目标绝对路径，不改数据库。
  3. 重启同一实例，打开该文档，记录缺失原始 PDF 的警告；页面图片仍存在时打开第 1 页。
  4. 再次运行完整只读诊断，展开“原始 PDF”检查，记录总体 ERROR 及缺失项。
  5. 停止实例，把隔离 PDF 原样移回原路径；重启后再次运行诊断并打开文档。
- **用户界面预期**：正常现场的 WARNING 被标为“警告”且不是全部失败；缺失 raw 时阅读页
  明确警告，诊断“原始 PDF”为“错误”且总体错误；ERROR 不被降级为可忽略提示。
  恢复文件后缺失错误消失。界面不要求自动修复。
- **数据、文件或状态预期**：移动期间数据库和页面 PNG 保留；恢复后原路径和文件名完全
  还原，文档仍为一个且页面可读。
- **不变量**：只移动已核对的 errors-diagnostic 隔离 raw 文件；不触碰正式文件、不改
  SQLite、不删除任何文件、不用复制 runtime 代替恢复。
- **PASS 判据**：WARNING/ERROR 语义清楚，缺失被检测且不假正常，页面记录未丢，文件原样
  恢复后错误消失。
- **FAIL 判据**：缺失时仍显示全部正常、ERROR 被当作 WARNING、界面假称已修复、页面或
  数据丢失、无法恢复原路径或出现未处理异常。
- **恢复或清理**：无论场景是否通过，优先在实例停止状态将文件原样移回；若路径无法确认，
  不继续移动并保留现场上报。恢复成功后归档整个组。
- **阻断场景**：是；诊断误级可 P2，数据/恢复问题为 P0/P1。
- **失败后立即停止**：数据或恢复异常时立即停止整个 S4；仅诊断文案 P2/P3 时记录后继续。

## 8. 场景间重置流程

1. 在结果表写完当前场景的实际观察、截图路径、严重级别和结论。
2. 正常停止隔离实例，确认 `$S4Port` 无 LISTENING。
3. 若下一场景要求同一现场，记录“复用自 S4-XX”，不得重新导入或清空数据库。
4. 若下一场景要求干净现场，把完整组目录移动到 archive，创建新的空组目录，并重新设置
   所有 `EKB_*` 路径。不得只删数据库而留下 raw/pages 污染结果。
5. 若场景失败，不重置失败现场；先停止相关组并复制失败记录模板。只有获准复测后才创建
   新组目录，原现场继续保留。
6. 任何测试资料的 SHA-256 变化都视为新资料；必须重新记录，不能沿用旧场景结论。

## 11. 原地打转停止规则

- 不因一个问题连续重复执行同一场景超过两次。
- 第二次复现只用于确认稳定性，不开展第三次“再确认”。
- 不在人工测试阶段自行修改代码。
- 不因 P2/P3 立即开启修复—复测循环。
- 不重新证明 S3C 已经证明的性能和一致性结论。
- 不为了提高覆盖率无限增加相似场景。
- 相邻场景若验证的是同一风险，应合并，不新增同义编号。
- 发现超出 v0.2.3 范围的问题，记录并延期。
- 某场景需要引入新架构、新恢复机制或大范围改动时，立即停止并上报。
- 连续两个测试场景没有新增风险信息时，检查是否发生重复验证；若是，停止后续同类场景。
- 不把 S4 扩展成重新验证整个项目，不重新讨论或审计 S3C。
- 300 页完成主流程、1000 页只走有限路径、3000 页只引用证据；不得自行增加 2000、
  3000 或更大页数人工导入。

## 12. S4 完成与发布准入条件

S4 只有同时满足以下条件才可记为 `PASS`：

1. S4-01～S4-14 均有真实人工记录，结果为 PASS；或仅有经发布负责人书面接受、不影响
   数据正确性和核心流程的 P2/P3，且相应场景结论和延期责任明确。
2. 无未关闭 P0/P1；没有假成功、系统性错页、不可恢复 processing、重复文档或数据破坏。
3. 所有失败现场、实际 UI 文案、截图/日志位置和恢复结果已记录；没有虚填 PASS。
4. 正式数据、正式资料、正式备份和 8501 全程零接触；所有测试进程已停止。
5. S3C 证据边界保持不变，没有重跑 300/1000/3000 完整性能矩阵、T25、全量测试、
   千页强杀、PNG 全解码或 3000 页上限证明。
6. S4 结论只说明本矩阵的用户体验验证结果；它不替代其他发布门禁，也不把未验证能力
   宣称为已验证。

出现 P0 时结论必须为 `STOPPED`；出现未解决 P1 时结论为 `FAIL` 或 `STOPPED`，不得准入。
若因环境、隔离、真实 UI 无法确认或必须改代码才能继续，也应停止并如实记录，不能以
`NOT STARTED` 场景换取 PASS。
