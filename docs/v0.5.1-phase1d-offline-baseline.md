# EKB v0.5.1 Phase 1D — Offline Retrieval Baseline

- 日期：2026-08-17
- 分支：`kimi/v0.5.1-retrieval-stabilization`
- 性质：**algorithmic / offline evidence**。synthetic corpus + 确定性 latent-topic fixture 向量，
  只验证 lexical / vector recall / RRF / provenance / partial coverage 机制，
  **不构成真实模型（Qwen）语义质量证据**。
- 运行约束（实际执行）：0 HTTP、0 Qwen、0 LLM、0 rerank、0 新增真实 page embedding；
  fixture embedding 只写临时目录 DB；每条 hybrid query 恰好 1 次（fake）query embedding。
- 机器生成的逐 query 完整记录：`docs/v0.5.1-phase1d-offline-baseline-detail.md`
  （`scripts/retrieval_benchmark.py` 确定性输出，可逐字节复现，由
  `tests/test_retrieval_benchmark.py` 的确定性测试锁定）。

## 一、执行事实

- 语料：`synthetic-engineering-v1`，5 文档 / 42 页，21 页嵌入（50%，类别 J 设计）。
- Query 集：`v0.5.1-frozen-queries-v1`，29 条（A–J），relevance set 冻结于运行前，未回改。
- 双模式同一评分口径（Phase 1C 合同）：Keyword = `SearchService.search(q, limit=50)`；
  Hybrid = `HybridSearchService` 融合后水合顺序。limit=50 ≥ 42 页，无截断干扰。
- 29 条 query 的 `vector_status` 全部 `ok`，`invalid_vector_candidates` 全部 0，
  query embedding 调用全部恰好 1 次。

## 二、总体结果（非 F 类 26 条）

| 模式 | Hit@1 | Hit@3 | MRR |
|---|---|---|---|
| Keyword | **0.8846** | **0.9231** | **0.9183** |
| Hybrid | **0.7308** | **0.8462** | **0.8135** |

delta 分布：**improved = 2（C2、H2），unchanged = 17，regression = 7（A4、B4、C3、E1、I2、J1、J2）**，
hybrid-only recall = 0，both-miss = 0。

> 在本 fixture 语料上，Hybrid 整体指标**低于** Keyword。这不是「benchmark 没调好」，
> 而是 partial embedding coverage（50%）+ 无阈值向量召回的结构性结果（见 §四机制证据）。
> 数值幅度依赖 fixture 几何，但机制与模型无关。

## 四、回归机制证据（离线 probe，`recall_scored` 实测）

对 5 条代表性 query 直接打印向量侧候选（limit=50）：

| query | 向量候选数 | 其中 sim=0 | Top 候选（sim） | relevant 页嵌入？ |
|---|---|---|---|---|
| A4 | 21 | **21** | stm32/p1(0.0)、stm32/p2(0.0)… | comm/p3 ✗ |
| J1 | 21 | 18 | stm32/p1(0.936)、stm32/p2(0.936) | stm32/p3 ✗ |
| J2 | 21 | 18 | stm32/p5(0.493)、stm32/p1(0.287) | stm32/p9 ✗ |
| F1 | 21 | **21** | 全部 0.0 | （无答案） |
| C2 | 21 | 20 | stm32/p8(1.0)，其余全 0 | stm32/p8 ✓ |

机制链（每一环都是现行生产代码行为）：

1. **向量召回无相似度阈值**（`src/ai/vector_recall.py:20` 设计决定）：limit=50 ≥ 嵌入页数时，
   **全部 21 个嵌入页都获得 vector rank**，包括相似度恰好 0.0 的页。
2. **RRF 双来源累加**（`src/ai/retrieval.py` k=60）：一个有偶然词面命中的嵌入页拿到
   `1/(60+lex_rank) + 1/(60+vec_rank)` 两项，可以超过只有 `1/61` 的未嵌入 keyword 第 1 名。
3. **单来源 rank-1 平分**：未嵌入 keyword #1（1/61）与嵌入 vector #1（1/61）精确相等，
   tie-break 落到 `best_rank`（仍平）再落到 **page_id 升序**——J1 中 page_id 更小的
   stm32/p1 胜过 stm32/p3，纯粹由主键大小决定，与相关性无关。
4. 结果：**在 partial coverage 下，Hybrid 系统性偏袒已嵌入页，与语义相关性无关。**
   7 条 regression 中有 6 条（A4、B4、C3、E1、J1、J2）的 relevant 页未嵌入；
   唯一例外 I2 的 relevant 页也未嵌入（comm/p7）——即 **7/7 regression 的 relevant 页全部未嵌入**。

该机制的每一步（无阈值、双来源累加、page_id tie-break）都与 fixture 无关、是真实代码路径；
真实 Qwen 模型下相似度不会精确为 0，但「低相似页仍拿 rank、嵌入页被系统性加权」不变。
**幅度**需要真实模型证据才能量化（见 Phase 1E 的 paid-call 评估）。

## 五、F 类（negative / no-good-answer）记录

| query | keyword 结果数 | hybrid 结果数 | hybrid Top5 含「语义召回」 | 向量侧事实 |
|---|---|---|---|---|
| F1（Kubernetes） | 9 | 23 | False | 21 候选 sim 全 0，仍全部进入融合 |
| F2（锂电池） | 5 | 23 | **True** | 零相关 query 仍产出语义标签结果 |
| F3（ROS2） | 8 | 26 | **True** | 同上 |

- 系统**没有任何** rejection / confidence / 弱结果信号（Phase 1A 已确认无阈值、无弱结果 UI）。
- keyword 侧同样会误出结果（F1 有 9 条：「更新」「配置」等泛词命中），但全部以
  「关键词匹配」身份出现且用户能看到字面命中原因；hybrid 额外注入的「语义召回」标签
  对无答案问题更具误导性。
- 判定（人工阅读记录后）：**no-answer exposure = high**（F2/F3 的 Top5 出现语义召回标签，
  且无任何「可能无答案」提示）。这是产品边界 limitation，不得表述为系统能判断无答案。

## 六、其他观察

- **结果数膨胀**：keyword 2–11 条 → hybrid 21–34 条（无最终 fused top-k 上限 +
  无阈值召回叠加）。UI「已载入 N 条」在 hybrid 下几乎恒为 limit+嵌入页数。
- **Hybrid 的真实收益场景**：C2（语义改写、相关页已嵌入、keyword rank 2→1）、
  H2（多相关页、pid/p2/p4 提顶）、D3（跨文档 Top5 覆盖 False→True）——
  收益全部出现在「相关页已嵌入 且 keyword 词面不完美」的 query 上。
- **keyword 自身弱点**（与模式无关）：I2（概念对比类查询 best_rank=8）、
  H2（4）说明 lexical 对「概括/对比型」查询偏弱；F 类泛词命中产生宽候选池。
- **provenance 标签本身无错误标注**（混合/语义/关键词归属均符合规则），
  但「语义召回」出现在 sim=0 的页上时，标签语义与用户直觉不符（见 Phase 1E D-04）。

## 七、结论

1. Hybrid 在 fixture 上整体不优于 Keyword（MRR 0.81 vs 0.92），regression 7 倍于 improved；
2. 全部 7 条 regression 指向同一结构性根因：partial coverage × 无阈值向量召回 × RRF 累加/tie 规则；
3. F 类确认「无答案仍给语义召回 Top 结果」是高暴露产品边界；
4. Hybrid 的确定收益集中在「相关页已嵌入 + 语义改写/多页/跨文档」场景（C2、H2、D3）；
5. 以上全部为 offline 机制证据；真实模型下的幅度需单独 paid-call proposal 评估。

缺陷定级与处置建议见 `docs/v0.5.1-phase1e-defect-matrix.md`。
