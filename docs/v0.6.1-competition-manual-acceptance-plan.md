## 2. 产品定位（仅此一句，展开即超纲）

EKB：调用过去的自己，把零散的信息转化为长期可复用的经验。

当前 v0.6.1 比赛演示展示的是**基础能力与经验复用场景**（可回源、可核验、

## 5. P0 / P1 / P2 缺陷政策（比赛专用）

| 级别 | 定义 | 本项目示例（非穷举） |
| --- | --- | --- |
| **P0** | 比赛阻断 | 8501 无法启动；Agent 页打不开；Mode 2 A/B/C 任一无法完成；Mode 1 失败被静默替换为 mock 输出；把过期结果当当前结果展示（stale）；重置无法清除上一场景状态；来源 viewer 崩溃；出现明显虚假比赛声明；向评委暴露安全/隐私敏感信息（路径、内部 ID、堆栈）；比赛要求分辨率下页面不可用 |
| **P1** | 演示能跑但实质损害评审体验/信任 | 回答卡或来源面板低于可用折叠线；引用选中状态不清晰；模式标识含糊；A/B/C 视觉状态不一致；明显重叠/截断；信任警示读不清；失败状态令人困惑；主讲被迫即兴绕过 |
| **P2** | 打磨 | 轻微间距；动画品味；无语义后果的措辞润色；旧管理页样式统一 |

判定规则：与冻结期望画面（freeze manifest 的 A/B/C 期望值）不符 → 至少 P1；
违反「冻结语义清单」（§7）或评委可见文案红线 → P0。

## 6. P0 修复规则

发现 P0 时：**立即停止比赛 polish。**

1. 记录：构建 SHA、精确复现步骤、截图、浏览器分辨率、模式、场景、期望、实际。
2. 只修最小根因；禁止顺手重构。
3. 修复后按顺序执行：聚焦测试（§13 矩阵指定）→ 人工复现 → A/B/C 冒烟
   （MAT-SMOKE-04…06）→ 相关回归。
4. 全部通过才恢复 polish 工作。

## 7. 冻结语义清单（这些"看起来像问题"的东西不得被"修复"）

以下为冻结语义，前端 polish 不得改变其含义；测试发现与其冲突的改动按 P0 处理：

1. 「预置离线演示」页头徽章 + 回答卡「预置演示数据」chip —— mock 必须可识别，
   不得删除或弱化到不可辨识（P2-1 审计项只允许移动位置，语义必须保留）。
2. 场景 C 免责句「……不代表造假或被篡改……」必须存在；禁止出现
   「已被篡改」「来源造假」「不可信」等二元道德断言。
3. Mode 1 失败必须明示（「本机 Agent 服务当前不可用」）；「切换到预置离线演示」
   是显式动作（重跑当前问题并明示模式），绝不静默伪装。
4. B 场景限制横幅「来源存在限制，请核对引用资料。」语义必须保留。
5. 端点 `127.0.0.1:8501`、全局版本 `0.6.0`、比赛页 `v0.6.1` 里程碑行
   （`release_check` 规则）。
6. 三个主场景的问题文本与 fixture 绑定（`src/demo/` RED 区）。
7. Mode 1 已知限制（如实告知，不构成缺陷，不得在 UI 伪装修复）：
   正文 `#N` 与来源映射未公开（P1 DEMO-03）→ Mode 1 的 `#N` 保持字面文本、
   来源渲染为独立列表；无 per-source 完整性字段 → viewer 显示通用来源状态说明；
   需维护者手工启动本机 Hosted 服务。
8. 演示页侧边栏默认折叠、页内隐藏 Streamlit toolbar —— 冻结行为。
9. 状态文案为封闭目录（○ 未找到可支持资料 / × 本次请求未完成 / ⏳ 请求过于频繁 /
   ⏻ 本机服务不可用），不得出现 traceback / JSON / 内部 ID / 路径 / 数字置信度。
10. 诚实空态语义：`grounded=false` 是合法的"无证据完成"，不得渲染成系统失败。
